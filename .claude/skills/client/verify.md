# verify — 검증 운용 규칙

> `client` 스킬 5단계용. **명령줄 · 스니펫은 여기 없다** — [src/dev/README.md](src/dev/README.md) 가 SSOT 다. 그 문서를 열고, 이 페이지의 규칙을 얹어 쓴다.

## 1. 서버

- 사용자가 `start.bat` 으로 서버를 띄워 뒀으면 **그걸 쓴다** (포트 8777).
- 안 떠 있으면 `src/` 에서 `python -m http.server 8788` 을 background 로 띄운다. **8777 을 다시 쓰지 않는다** — 사용자가 나중에 `start.bat` 을 눌렀을 때 충돌한다.
- `file://` 로 열지 않는다 — ES Modules 가 CORS 로 막힌다.
- 검증이 끝나면 내가 띄운 서버는 내가 내린다.

## 2. 헤드리스 실행

- **PowerShell 도구로만 돌린다.** git-bash 에서는 `msedge` 가 즉시 반환하고 출력이 0바이트다.
- **캐시를 끈다** — 프로필 폴더를 지우고 `--disk-cache-size=1`. 안 그러면 CSV 가 캐시돼 손잡이를 돌려도 같은 표가 나온다.
- 절차(인자 · 리다이렉트 · 결과 파싱)는 [src/dev/README.md](src/dev/README.md) 의 헤드리스 절을 **그대로** 쓴다. 다시 타이핑해서 변형하지 않는다.

## 3. 통과 기준

둘 다 만족해야 통과다.

| 대상 | 기준 |
|---|---|
| `dev/test.html` 덤프 | `<title>` 이 `PASS n/n` (두 수가 같다) **이고** 실패 목록(`li.fail`)이 비어 있다 |
| `index.html?dev=battle&lang=ko` 덤프 | `class="report-head"` 가 있다 — 없으면 렌더 도중 예외가 났다는 뜻 |

- 보고에는 **`PASS n/n` 원문을 그대로** 옮긴다. "통과했다"로 바꿔 적지 않는다.
- 실패가 하나라도 있으면 실패 항목 이름을 전부 적는다.
- 렌더러를 안 건드렸어도 조립(`ui/data.js`)을 만졌으면 두 번째 덤프까지 돌린다.

## 4. 밸런스 손잡이를 돌렸을 때

`src/data/balance.csv` 의 값을 바꿨다면 **표를 다시 찍는 것까지가 작업이다.**

1. 캐시를 끈 채 `dev/test.html` 을 덤프해 캘리브레이션 표를 다시 얻는다.
2. [src/dev/README.md](src/dev/README.md) 의 "마지막 측정" 절을 새 표로 갈고, **어느 손잡이를 왜 얼마나 움직였는지**를 함께 적는다.
3. [DEV_PLAN.md §3-1](docs/client/DEV_PLAN.md) 아래의 캘리브레이션 주를 같은 내용으로 갱신한다.
4. 두 문서의 꼬리 `*마지막 업데이트: …*` 에 날짜를 앞에 붙인다.

손잡이의 뜻과 서로의 짝은 [src/dev/README.md](src/dev/README.md) 의 손잡이 표에 있다 — **읽고 나서 돌린다.** 성장 축 키는 스테이지 전체의 역산값이라 생존 축을 맞추려고 건드리면 전 구간이 함께 움직인다.

## 5. 검증을 건너뛸 수 있는 경우

없다. 주석만 고쳤어도 단정은 돌린다 — 비용이 거의 없고, 다른 세션의 변경이 섞여 들어왔는지도 여기서 드러난다.
