# 기획서 형식 규약

> `game-design` 절차 3(작성·개정)에서 쓴다. 아래 형식은 `docs/game_design/` 의 실제 문서에서 확인한 것이다.
> **형식만 여기 있다. 내용(무엇이 정해졌는가)은 GAME_DESIGN.md §9 · §10 이 유일한 출처다.**

목차 — 1 언어와 날짜 · 2 세부 문서 머리말 · 3 절 제목의 상태 태그 · 4 대체된 결정(취소선) · 5 확정이 아닌 것(⚠) · 6 수치 표기 · 7 §9 결정 로그 · 8 §10 미확정 과제 · 9 교차 링크 · 10 꼬리

## 1. 언어와 날짜

- 기획서는 **한국어** (CLAUDE.md 규칙 1)
- 문서를 바꾸면 **반드시 꼬리의 마지막 업데이트를 갱신**한다
- 날짜는 `YYYY-MM-DD`. 결정 로그 표 안에서만 `MM-DD` 로 줄여 쓴다

## 2. 세부 문서 머리말

`# 제목` 바로 아래에 인용구(`>`)로 **상위 문서**와 **SSOT** 를 밝힌다.

```
# <주제> 설계

> 상위: [GAME_DESIGN.md](GAME_DESIGN.md) §<번호> · SSOT: `<a>.csv` · `<b>.csv`
```

변형 — 실제로 쓰이는 세 가지:

- **SSOT 가 아직 없을 때** — `SSOT: **미발행** (…)` 또는 `**미발행**: <무엇이 아직 없는지 나열>`
- **`inherited/` 를 읽는 문서일 때** — `> 참조 테이블: `src/data/inherited/` (읽기 전용)` + `> 신규 SSOT: …` 두 줄
- **여러 절을 상위로 둘 때** — `상위: [GAME_DESIGN.md](GAME_DESIGN.md) §3, §7`

수치 금지를 문서 스스로 못박는 줄을 머리말에 두기도 한다 — `> 수치는 전부 CSV — 본 문서에 절대값을 기재하지 않는다`.

## 3. 절 제목의 상태 태그

절이 언제 어떤 상태로 정해졌는지를 제목 끝(또는 번호 뒤)에 대괄호로 붙인다.

| 태그 | 뜻 |
|---|---|
| `[확정 YYYY-MM-DD]` | 이 절의 내용이 결정됐다 |
| `[개정 YYYY-MM-DD]` | 전에 확정된 것을 고쳤다 |
| `[신설 YYYY-MM-DD — <사유>]` | 없던 절을 새로 뺐다 |
| `[재작성 YYYY-MM-DD — <사유>]` | 절을 통째로 다시 썼다 |
| `[초안 YYYY-MM-DD]` | 방향만 있고 확정이 아니다 |
| `[확정 YYYY-MM-DD · 골격만]` | 뼈대는 확정, 세부는 §10 |

- 개정·재작성 태그에는 **사유를 한 마디** 붙인다 (`— 수치 대역 재설계`)
- 태그를 절 번호 뒤에 두는 변형도 있다: `## 0. 확정 [YYYY-MM-DD — 전면 개정]`

## 4. 대체된 결정 — 지우지 않고 취소선

옛 결정을 삭제하면 왜 바뀌었는지가 사라진다. **취소선으로 남기고 무엇이 대체했는지 붙인다.**

```
| MM-DD | ~~<폐기된 결정>~~ — **MM-DD <새 결정>으로 대체**(<무엇으로 바뀌었는지>). <유지되는 부분은 명시> |
```

- 대체 문구는 `— **… 으로 대체**` · `→ **…**` · `— **… 개정으로 대체**` 를 쓴다
- **부분 대체면 살아남은 조항을 반드시 적는다** — "~는 유지" 한 마디가 없으면 전체가 폐기된 것으로 읽힌다
- 폐기된 **어휘**는 취소선으로 끝내지 말고 `「<옛 말>」 어휘 폐기 → 「<새 말>」` 형태로 §9 에 한 줄 남긴다 — 다른 문서를 grep 할 근거가 된다 (폐기 어휘 검사)

## 5. 확정이 아닌 것 — `⚠`

- `⚠제안` / `(⚠ 제안)` / 표 칸의 `⚠` = **프로토타입 산식 계수이거나 아직 제안**이다 ([src/data/README.md](src/data/README.md))
- 인용할 때 ⚠ 를 떼지 않는다. ⚠ 가 붙은 항목을 근거로 다른 결정을 쌓지 않는다
- ⚠ 를 떼려면 §9 에 확정 행이 먼저 생겨야 한다

## 6. 수치 표기 — 기획서에 절대 수치 금지

허용되는 것은 넷뿐이다 (CLAUDE.md 규칙 2 · [src/data/README.md](src/data/README.md)):

1. **키 참조** — `[<파일>.csv:<key>]` 형태. 예: `[balance.csv:party_size_max]` · `[balance.csv:roster_cap]`
2. **체감 범위** — "짧다 / 길다 / 대략 한 자릿수" 같은 서술
3. **공식 변수명** — `def_curve_k` · `power_growth_per_level` 처럼 CSV 키 이름 자체
4. **테이블 링크** — `SSOT: \`monster.csv\`` 로 넘긴다

새 수치가 필요하면 **키 이름만 발행**하고 값은 CSV 쪽 작업(`/client`)으로 넘긴다.

## 7. `GAME_DESIGN.md` §9 결정 로그

- 표 두 칸: `| 날짜 | 결정 |`
- **§9 에는 최근 결정만 둔다** [09-03 신설] — 오래된 행은 [`DECISION_LOG.md`](../../../docs/game_design/DECISION_LOG.md) §1 로 옮기고 §9 는 가볍게 유지한다. **지우는 게 아니라 옮기는 것** — 이력은 아카이브에 그대로 남는다
- **한 줄이다.** 근거 · 계산 · 대안 검토는 세부 문서로 내리고 여기엔 결론만
- 결론 뒤 괄호로 세부 문서를 가리킨다: `(battle_design.md §9)`
- 결정의 제목 부분은 **볼드**로 시작해 훑을 수 있게 한다

## 8. `GAME_DESIGN.md` §10 미확정 과제

- **확정되지 않은 것의 유일한 목록.** 확정되면 §9 로 옮기고 §10 에서 **지운다**
- 세 분류로 나뉜다: `### 큰 틀` / `### 시스템` / `### 수치 · 밸런스`
- 표 두 칸: `| 과제 | 상태 |`. "상태" 칸에는 **무엇이 걸려 있는지와 후보**를 적는다 — 빈 항목을 이름만 올려 두지 않는다
- 다른 과제와 물려 있으면 그 사실을 적는다 ("…에 물려 있다" · "…가 선행")
- 세부 문서에 근거가 있으면 절 번호로 가리킨다 (`skill_design.md §7`)

## 9. 교차 링크는 양방향

- GAME_DESIGN 쪽: §1 세부 문서 표에 한 행 + 해당 절의 `상세: [<파일>.md](<파일>.md)` 줄
- 세부 문서 쪽: 머리말의 `상위:` 줄
- 세부 문서끼리 걸치면 서로의 절 번호를 적는다 (`item_design.md §5` ↔ `base_expedition_design.md` 광석 행)

## 10. 꼬리 — 최신이 앞

```
---

*마지막 업데이트: YYYY-MM-DD (<이번에 바꾼 것>) · YYYY-MM-DD (<지난번>) · …*
```

- **앞에 누적하되 최근 3 개만 남긴다** [09-03 개정] — 새 항목을 맨 앞에 붙이고, 넷째부터는 [`DECISION_LOG.md`](../../../docs/game_design/DECISION_LOG.md) §2 의 해당 문서 절로 옮긴다. 꼬리 끝은 `· 이전 이력은 [DECISION_LOG.md](DECISION_LOG.md) §2*` 로 닫는다. ~~지우지 않는다~~ → **옮긴다**(지우는 것은 여전히 금지)
- 괄호 안은 "무엇을 바꿨나" 한 마디. 절 번호를 함께 적으면 나중에 추적된다
- 같은 날 여러 번 고치면 항목을 여러 개 만든다 (날짜가 겹쳐도 된다)
