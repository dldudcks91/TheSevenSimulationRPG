## 5. SSOT 위반 — 수치가 문서에 박혔나

기획서에서 숫자가 보이면 그건 값이 아니라 위반이다. 고친 문서에 대해 돌린다:

```bash
grep -nE "\b[0-9]+%|\b[0-9]+초|\b[0-9]+분|HP [0-9]+|\+[0-9]+" docs/game_design/<고친 문서>.md
```

허용(화이트리스트) — 걸려도 위반이 아닌 것:

- 날짜 · 절 번호 · 표의 행 번호
- **구조 카운트** — `7대 죄악` · `9라운드` 처럼 §9 가 확정한 구조값
- `[<파일>.csv:<key>]` 키 참조 안의 문자열
- 참고작 인용임이 그 자리에서 명시된 값

그 밖은 전부 CSV 로 내리고 문서에는 **키 이름만** 남긴다.

- [ ] grep 결과를 한 줄씩 판정했다
- [ ] 새로 필요한 수치는 **키 이름만 발행**하고 값은 `⚠제안` 으로 표시했다

## 6. 폐기 어휘 — 죽은 말이 다른 문서에 살아 있나

**절차** (목록을 외우지 말고 매번 뽑는다):

1. §9 에서 폐기 행을 뽑는다
   ```bash
   grep -n "~~\|폐기\|폐지\|→ 대체\|대체됨" docs/game_design/GAME_DESIGN.md
   ```
2. 각 행에서 **버려진 말**을 골라낸다 (취소선 안쪽 · `「…」 어휘 폐기` 의 앞말)
3. 그 말로 대상 문서를 grep 한다
   ```bash
   grep -rn "<버려진 말>" CLAUDE.md docs/game_design/ docs/client/
   ```
4. 걸린 자리를 판정한다 — **새 어휘로 교체**하거나, 남겨야 할 기록이면 취소선·"기록" 표기를 붙인다

**2026-08-27 기준 예시 — 출처 [GAME_DESIGN.md](docs/game_design/GAME_DESIGN.md) §9.** 스냅샷이므로 그대로 믿지 말고 위 절차로 다시 뽑는다.

| 버려진 말 | 대체 |
|---|---|
| 「시설」 | 「파견처」 |
| 「슬롯」(액티브 슬롯) | 「액티브」 |
| 세트효과 · 세트포인트 | 전술카드 |
| 명중 · 회피 | 레벨 차 적중 |
| 고유 패시브 | 고유 스킬 |

- [ ] 절차 1~4 를 돌렸다
- [ ] 이번에 내가 폐기한 어휘도 §9 에 **한 줄로 남겼다** (다음 사람이 grep 할 근거)

### 6-1. 뒤집힌 주장 — 단어로는 안 잡힌다 [2026-09-21]

위 절차는 **어휘**를 찾는다. 확정 **규칙**을 뒤집으면 같은 주장이 겹치는 단어 없이 여러 표현으로 퍼져 있다.

> 예시(2026-09-21 물약 소모품화) — 「닳지 않음」 · 「단계마다 한 번 만든다」 · 「런마다 회복에 자원을 물지 않는다」는 **같은 주장**인데 겹치는 단어가 없다. 셋째는 **다른 확정(09-06)의 근거**로 쓰이고 있었고, 단어 grep 으로는 안 걸렸다

**언제 돌리나 — 항상이 아니다.** 비용이 크다(한 번에 수 분 · 에이전트 도구 호출 수십 회).

```
결정이 확정 규칙을 뒤집는가?  (§9 에 취소선이 생기는가)
  ├ 아니다 — 새로 더함 · 값만 바꿈             → 여기서 끝
  └ 그렇다 → 핵심 단어로 grep 한 번 — 이력(DECISION_LOG · DEV_LOG · SCREEN_CHANGELOG) · adr/ 제외
              ├ 1~2 개 파일                    → 직접 고친다
              └ 3 개 이상                       → sonnet 에이전트로 주장 단위 전수 조사
```

퍼지는 것은 **다른 결정의 근거로 쓰이던 규칙**이다 — 기대는 문서가 많을수록 옛 말이 여기저기 남는다. 변경이 커도 **새로 더하는 결정**은 옛 말이 한곳에 몰려 있어 이 조사가 필요 없다.

**에이전트에 줄 것**

1. **편집이 다 끝난 뒤에 띄운다** — 편집과 동시에 돌리면 방금 고친 줄을 다시 보고한다
2. **읽기만 시킨다** — 병렬 세션이 같은 저장소를 고친다(CLAUDE.md 작업 규칙)
3. **주장마다 「옛 → 새」 한 줄 + 찾을 표현 예를 여럿** 준다 — 단어가 아니라 주장을 찾게 하고, 걸린 줄은 **문맥을 읽어 판정**하게 한다
4. **범위와 제외** — 범위는 CLAUDE.md · `docs/game_design/` · `docs/client/` · `src/*/README.md` · CSV 설명 칸 · `i18n.js`(화면 문구) · `game_logic` 주석 · `.claude/skills/`. 제외는 위 이력 셋과 **이미 고친 절**(취소선 + 개정 날짜가 붙은 줄)
5. **분류 셋** — **기획**(지금 고친다) / **화면 · 계약 · 코드**(뒤 단계) / **스킬**
6. **판정 기준 하나 — 「옛 기획 주장」과 「아직 안 바뀐 코드의 정확한 설명」을 가른다.** 코드가 아직 옛 규칙대로 돌면 그 주석 · 계약 문구 · 화면 문구는 틀린 게 아니라 **코드와 같이 바꿀 목록**이다
7. 보고 형식 — `파일:줄 | 지금 적힌 말 | 어느 주장 | 분류 | 고칠 방향` + 판정이 애매한 것 + 분류별 건수

**받은 뒤**

- 걸린 줄은 **지금 파일 상태로 다시 확인**한다 — 에이전트의 줄 번호는 낡을 수 있다
- 「기획」은 이번에 고친다 · 「화면 · 계약 · 코드」는 **작업 계획이나 [DEV_PLAN.md](docs/client/DEV_PLAN.md) §3-3 R 행에 체크리스트로** 넘긴다 — 흘려보내면 코드를 바꿀 때 잊는다

- [ ] 뒤집는 결정이면 핵심 단어 grep 으로 **크기를 쟀다**
- [ ] 3 개 파일 이상이면 **편집을 끝낸 뒤** 에이전트로 주장 단위 조사를 돌렸고, 뒤 단계 분류를 넘겼다

- [ ] **§9 는 30 행 이하** — 넘쳤으면 가장 오래된 날짜의 행을 날짜째 DECISION_LOG §1 로 옮겼다 (doc_conventions §7)
- [ ] **절 태그** — 새로 확정·개정한 절에 상태 태그를 붙였다
