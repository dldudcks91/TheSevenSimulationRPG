# qa-fun — 재미 · 콘텐츠 · 밸런스를 잰다

공통 규칙과 교훈 이월은 [qa/SKILL.md](.claude/skills/qa/SKILL.md) — 먼저 읽는다. 교훈 파일은 [metrics.md](.claude/skills/qa/metrics.md)(활성 · 구현 대기 · 기각).

## 한계

재미와 리텐션은 판정하지 않는다. **분포(숫자)와 의견(해석)을 나눠 적고**, 목표치가 없으면 「판정 불가 — 목표를 정해 달라」로 끝낸다. 판정 기준 수치는 적지 않는다 — 목표가 정해지면 CSV 키로 간다(CLAUDE.md 규칙 2).

## 볼 것

1. **기획 목표의 분포** — metrics 「활성」. 실행 전에 그 행의 근거 § 를 다시 읽는다(기획서가 자주 바뀐다)
2. **첫 1시간 속도** — 스테이지별 첫 클리어 시각과 도착 레벨(`campaign`). 출력에 없는 것(첫 장비 교체 · 첫 빌드 결정)은 `/client` 에 필드 추가를 제안
3. **밸런스는 PvP 기준** — 영웅 대 영웅을 먼저 본다. 대량 실행기에 결투장 모드가 없어 지금은 구현 대기
4. **퍼널** — `dev/funnel.html` 은 관리자 로그인이 필요하다. 사용자가 화면을 넘겨주면 읽는다. 유저가 적으면 통계가 아니라 사례로 읽는다

## 결론을 쓰는 법

- 시드 구간 둘(앞 절반 · 뒤 절반)이 같은 방향일 때만 결론으로 쓴다
- 봇이 끼는 지표에서 문제가 보이면 `bot=off` 나 규칙을 바꿔 한 번 더 — 그래도 남는 것만
- 결과의 `meta.bot` · `meta.assume` 을 보고에 옮긴다 — 가정이 곧 한계다
- 판정 한 줄은 [src/dev/README.md](src/dev/README.md) 「재미 검수 판정」에 덮어쓴다 · 사용자 채택 → `/game-design` 이 §10 에 · 기각 → metrics 「기각」
