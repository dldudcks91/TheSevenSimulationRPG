# qa-spec — 기획대로 만들었나

공통 규칙과 교훈 이월은 [qa/SKILL.md](.claude/skills/qa/SKILL.md) — 먼저 읽는다. 교훈 파일은 [spec_ledger.md](.claude/skills/qa/spec_ledger.md).

## 볼 것

1. **최근 결정 대조** — 범위를 안 주면 ledger 「마지막 대조」 다음부터(GAME_DESIGN §9 · DEV_PLAN R · `adr/`). 한 번에 전부 하지 않는다. 문장 하나 → 그 동작이 게임에서 나오나. **코드 읽기로 갈음하지 않는다** — 배선이 빠져도 코드는 맞아 보인다
2. **콘텐츠 완결성** — 데이터 행마다 짝이 있나: 몬스터 초상 · 스킬 아이콘 · 영어 이름 · 툴팁 · 스테이지 배경. 눈으로 넘기지 말고 스크립트로 센다
3. **방치형 계약** — 오프라인 정산이 상한에서 끊기나 · 끄면 원정이 끊기나 · 자리 비운 사이 영웅을 잃는 사건이 없나(근거 base_expedition_design §4)
4. **설명 문장** — 도움말 · 툴팁이 지금 규칙과 맞나. 틀린 문장과 개발 흔적만 올린다. 맞는 미구현 안내는 결함이 아니고, 도움말 전면 개편은 보류된 일이다(DEV_PLAN R257)

## 판정

- 기획서가 분명한데 게임이 다르다 → 결함(§4)
- 기획서가 모호하거나 서로 부딪히거나 코드가 먼저 정했다 → 기획 의문(`/game-design`)
- 기능이 아직 없다 → 올리지 않고 ledger 「구현 대기」에

`/game-design` 의 「기획↔코드 반영 대조」는 문서와 코드를 읽어서 하고, 여기는 게임을 돌려서 한다.
