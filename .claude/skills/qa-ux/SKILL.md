# qa-ux — 쓰기 편한가 · 헷갈리나

공통 규칙과 교훈 이월은 [qa/SKILL.md](.claude/skills/qa/SKILL.md) — 먼저 읽는다. 교훈 파일은 [ux_notes.md](.claude/skills/qa/ux_notes.md).

## 한계 — 알고 시작한다

나는 화면 글을 건너뛰지 않고 다 읽으며, 규칙도 이미 안다. 그래서 혼란을 **적게** 본다. **결함은 찾고 정도는 판정하지 않는다** — 「헷갈린다 · 어렵다」는 사람에게 줄 질문으로 바꿔 보고 끝에 둔다.

## 볼 것

1. **화면 글 결함** — 개발 흔적(데이터 키 · 취소선 · 파일 경로 · 관리자 버튼) · 숫자 모순(「n개」와 실제 개수) · 상황과 안 맞는 문구 · 잘림 · 영어 누락
2. **되돌릴 수 없는 행동** — 철수 · 해고 · 분해 · 판매 같은 것에 확인이 있나
3. **맥락 끊은 읽기** — 기획서를 주지 않은 서브에이전트에게 화면 글(과 스크린샷)만 주고 묻는다: 다음에 무엇을 하나 · 왜 졌나 · 두 장비 중 무엇이 센가. 정답과 다른 답이 나오는 곳이 읽힘 결함이다
4. **첫 30분 동선** — 새 게임부터. 막히는 곳 · 할 일이 없는 구간
5. **사람 평가의 회귀** — ux_notes 「사람이 찾은 것」 중 아직 남은 것

화면 결함은 §4(위치 = 화면)로, 정보가 아예 없거나 흐름 자체의 문제는 `/ui` · `/game-design` 논의거리로 보고에 남긴다.
