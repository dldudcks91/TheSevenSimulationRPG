# qa — 돌려서 찾는다

당신은 TheSevenSimulationRPG 의 **QA** 입니다. 게임을 실제로 돌려 문제를 찾고, 고칠 스킬에 넘기고, **이번에 배운 것을 다음 실행이 쓰게 남긴다.**

## 언제 사용

- **버그 모드** (`bug`) — 아직 모르는 고장을 찾는다: 탐색 테스트 · 스모크 · 큰 변경 뒤 회귀 점검
- **기획 모드** (`design`) — 기획서의 약속이 실제 플레이에서 지켜지는지 대량 실행으로 본다
- 모드를 안 주면 요청에서 고른다 — 「고장 · 에러 · 깨짐」이면 버그, 「밸런스 · 약속 · 쏠림 · 의미 있나」면 기획

**여기서 하지 않는 것** — 알려진 버그의 수정 · 단정 추가는 `/client` 디버그 모드 · 코드를 읽기만 하는 리뷰는 `/client` 리뷰 모드 · 문서만 읽는 기획 리뷰와 기획서 수정은 `/game-design` · 손잡이 조정은 `/client` 캘리브레이션 · 화면 규격은 `/ui`.

## 핵심 원칙

1. **교훈이 다음 실행을 바꾼다** — 이 스킬이 있는 이유다. 실행은 **브리핑(1단계)으로 시작해 회고로 끝난다.** 둘 중 하나라도 빠지면 실행이 끝난 게 아니다. 교훈도 검증 대상이다 — 브리핑에서 받은 교훈이 헛돌았으면 회고에서 고치거나 지운다
2. **돌려서 찾는다** — 근거는 실행 결과뿐이다. 코드 · 문서는 **어디를 찌를지** 고르는 데 읽는다
3. **고치지 않는다** — 게임 코드 · 단정 · CSV · 기획서는 넘긴다. **실패하는 단정을 먼저 넣지 않는다** — 병렬 세션의 검증이 전부 빨개진다
4. **한 번 본 것은 규칙이 아니다** — 버그는 두 번 일으킨 것만 §4 에 · 기획 발견은 봇 규칙을 바꿔도 남는 것만 보고에. 못 일으킨 것은 버리지 않고 [risk_map.md](risk_map.md) 의 관찰로
5. **구현 · 확정된 것만 검사한다** — 미구현 기능과 [GAME_DESIGN.md](docs/game_design/GAME_DESIGN.md) §10 미확정은 버그로도 기획 문제로도 올리지 않는다. 단 「⚠ 현행 코드(임시)」 표기는 코드가 먼저 정한 자리라 대상이다
6. **코드 상태를 적는다** — 작업 폴더를 여러 세션이 동시에 고친다. 커밋 해시와 미커밋 파일을 기록하고, 실행 도중 범위의 파일 mtime 이 바뀌면 그 실행은 버린다
7. **명령 원문은 [src/dev/README.md](src/dev/README.md)** — 헤드리스 · 개발용 URL · 대량 실행(`sim.html`). 여기 옮겨 적지 않는다
8. **판정 기준 수치를 적지 않는다** — 「몇 % 면 문제」는 목표가 정해지면 CSV 키로 간다(CLAUDE.md 규칙 2). 그 전까지는 분포와 의견을 나눠 적는다

### 작업 규칙

공통 규칙(병렬 세션 · 조사는 sonnet 서브에이전트 · 서브에이전트는 상황 판단 · 짧은 동의 · 커밋)은 [CLAUDE.md](CLAUDE.md) 「작업 규칙」 — 여기 옮겨 적지 않는다.

## 공통 머리 — 두 모드 모두

### 0. 모드 · 범위

- 모드와 이번 범위(영역 · 약속)를 한 줄로 정한다. 범위가 없으면 브리핑이 고른다
- 범위가 미구현이면 멈추고 그렇게 보고한다 — 판단은 매번 코드에서(`game_logic/` 에 그 동작이 있나)

### 1. 브리핑 — 지난 실행이 남긴 것을 읽는다 (건너뛸 수 없다)

| 읽을 것 | 꺼낼 것 |
|---|---|
| [risk_map.md](risk_map.md) | 먼저 찌를 곳 · 못 일으킨 관찰 — 이번 범위에 겹치면 그 영역을 한 번 더 |
| [angles.md](angles.md) (버그) · [metrics.md](metrics.md) (기획) | 위에서부터 — 순서가 곧 적중 순이다 · **기각된 지표는 다시 올리지 않는다** |
| [pitfalls.md](pitfalls.md) | 이번 실행에 걸릴 함정 |
| [DEV_PLAN.md](docs/client/DEV_PLAN.md) §4 | 이미 올라간 결함 — 같은 것을 다시 올리지 않는다 |
| [src/dev/README.md](src/dev/README.md) 「기획 모드 판정」 (기획) | 지난 판정 — 이번과 달라지면 그것이 회귀 신호다 |
| [GAME_DESIGN.md](docs/game_design/GAME_DESIGN.md) §9 · §10 (기획) | 약속이 바뀌었나 · 미확정으로 갔나 |

**출력** — 보고 맨 위에 「반영한 지난 교훈」: `파일 · 항목 → 그래서 이번에 무엇을 다르게 하나`. 처음이면 「첫 실행」.

### 2. 기준선

- `git rev-parse --short HEAD` · `git status --short` 요약 · 범위에 걸린 파일의 mtime 을 적는다
- `dev/test.html` 을 덤프한다 — `PASS n/n` 이 아니면 **멈추고** 실패 목록 원문을 보고한다(내 발견과 남의 작업 중 변경을 가를 수 없다)
- 서버 · 헤드리스 운용은 [client/verify.md](.claude/skills/client/verify.md) §1 · §2 와 같다 — 헤드리스 프로필은 **실행마다 새 이름**

## 버그 모드

### 3. 관점 고르기

[angles.md](angles.md) 위에서 둘 이상 + risk_map 의 영역 + **목록 밖 새 관점 하나**(탐색 몫 — 목록만 돌면 목록이 아는 버그만 찾는다).

### 4. 실행

- 도달은 개발용 URL(`?dev=` · `?tab=`) · 조작은 Playwright · 상태 판독은 세이브(localStorage)와 DOM
- **상태 불변식을 같이 본다** — 가방 ≤ 칸 수 · 리포트 ≤ 상한 · 한 아이템은 한 곳에만(착용 · 가방 · 창고) · 착용 uid 가 `items` 에 있다 · 자원에 NaN · 음수가 없다 · **화면 수치도** — 현재 HP ≤ 최대 HP (세이브에 없는 전투 안 값은 화면으로만 보인다)

### 5. 재현

- **「dev 주소 + 조작 한 문장」**으로 두 번 일으킨다. 형식 예: `?dev=play&rep=1` 에서 시계를 180초씩 두 번 → 리포트 줄 수가 상한을 넘는다
- 한 문장으로 못 적으면 그 상태로 가는 dev 주소가 없다는 뜻이다 → `/ui` 에 주소 추가를 제안
- 끝내 못 일으키면 [risk_map.md](risk_map.md) 「못 일으킨 관찰」에 적는다

### 6. 분류 · 기록

- 분류는 아래 규칙. 기획 의문은 보고의 「기획 모드로 넘길 것」에 둔다
- 버그는 [DEV_PLAN.md](docs/client/DEV_PLAN.md) §4 에 — **먼저 같은 결함이 있나 본다.** §4 표만이 아니라 `docs/client/adr/` · [src/dev/README.md](src/dev/README.md) 를 증상 · 주소 · 함수 이름으로 검색한다 — 알려진 한계가 ADR 에만 적혀 있기도 하다. 없으면(ADR 에만 있었으면 그 번호를 조치 칸에 적고) 한 행 한 줄: 종류 `버그(QA)` · 내용 = 증상 + 재현 문장 · 위치 = 의심 파일(모르면 화면) · 영향 · 조치 = `미조치 — QA <날짜> <커밋>`. 편집은 정확한 old 문자열로(병렬 세션)

## 기획 모드

### 3. 약속 → 지표

- [metrics.md](metrics.md) 「활성」에서 고른다. 행의 「근거」 § 를 **다시 읽어** 약속이 아직 그 말인지 확인하고, 바뀌었으면 행을 고치거나 옮긴다
- 새 약속을 잴 때는 행을 먼저 만든다 — 측정 방법 · 봇 결정이 끼는지

### 4. 대량 실행

- `dev/sim.html` — 모드 · 파라미터 · 출력은 [src/dev/README.md](src/dev/README.md) 「대량 실행」
- 결과의 `meta.bot` · `meta.assume`(봇 규칙과 가정)을 보고에 옮긴다 — 가정이 곧 결과의 한계다
- **시드 구간 둘**(요약의 앞 절반 · 뒤 절반)이 같은 방향일 때만 결론으로 쓴다 — 시드 20 표는 rng 순서만 바뀌어도 크게 흔들린다([src/dev/README.md](src/dev/README.md) 「마지막 측정」)

### 5. 판독 · 봇 탓 점검

- 목표치가 있으면 대조한다. 없으면 **분포**(숫자)와 **의견**(해석)을 나누고 「정답 없음」이라 적는다
- 봇 결정이 끼는 지표에서 문제가 보이면 `bot=off` 대조나 규칙 변형으로 한 번 더 돌린다. 그래도 남는 것만 올린다

### 6. 보고 · 기록

- 판정 표는 [review_fanout.md](.claude/skills/game-design/review_fanout.md) §5 의 형식을 빌린다 — 칸은 「약속 위반」 · 「기존 과제(§10 에 있음)」 · 「판정 불가(목표치 없음 → 목표를 정해 달라는 질문)」 · 「구현 대기」
- 약속별 판정 **한 줄**을 [src/dev/README.md](src/dev/README.md) 「기획 모드 판정」에 덮어쓴다 — 수치는 여기까지, 기획서로 옮기지 않는다
- 사용자가 **채택**한 발견 → `/game-design` 이 §10 에 올린다 · **기각** → [metrics.md](metrics.md) 「기각」에 사유 한 줄 · **보류** → 남기지 않는다(시드가 고정이라 다음에 같은 결과가 다시 나온다)

## 회고 — 교훈을 다음 실행으로 (건너뛸 수 없다)

1. **사실을 모은다** — 적중한 관점 · 지표 / 헛돈 것 / 새로 밟은 함정 / 못 일으킨 관찰 / 기각 사유 / **브리핑에서 받은 교훈이 실제로 도왔나**
2. **행선지로 보낸다**

| 사실 | 가는 곳 | 방식 |
|---|---|---|
| 관점 · 지표의 적중 · 헛돎 | [angles.md](angles.md) · [metrics.md](metrics.md) 「최근」 칸 | 덮어쓰고 순서를 고친다 — 적중은 위로, 세 번 연속 헛돈 것은 아래로 |
| 새 관점 · 새 지표 | 같은 파일의 새 행 | 바로 추가 |
| 자주 깨지는 영역 · 못 일으킨 관찰 | [risk_map.md](risk_map.md) | 덮어쓴다 · 다시 일으켰거나 §4 로 간 관찰은 지운다 |
| 처음 밟은 함정 | [pitfalls.md](pitfalls.md) | 한 줄 추가 |
| 두 번째 밟은 함정 · 반복된 수작업 | 스크립트 · README 명령 · dev 주소로 흡수 | **제안만** — 사용자 확인 후. 흡수되면 pitfalls 에서 지운다 |
| 헛돈 교훈 | 그 교훈이 적힌 행 | 고치거나 지운다 |
| 목표가 정해진 약속 | CSV 키 + 단정 | **제안만** (`/client`) |

3. **보조 파일 위생** — 파일마다 10KB 를 넘으면 합치거나 낡은 행을 지운다 · 이력은 남기지 않는다(git 이 든다 · [DEV_PLAN.md](docs/client/DEV_PLAN.md) §7)
4. **보고 끝에 「다음 실행에 넘긴 것」** — 파일 · 항목 한 줄씩. 비어 있으면 회고를 안 한 것이다
