# qa — 검수 입구

## 네 갈래

| 스킬 | 묻는 것 | 출발점 | AI 가 하는 데까지 |
|---|---|---|---|
| `/qa-spec` 기획 검수 | 기획대로 만들었나 | 기획서 · ADR · R 의 문장 | 끝까지 — 대조 · 누락 |
| `/qa-bug` 개발 검수 | 고장이 없나 | 잘 깨지는 곳 | 끝까지 — 움직이는 연출의 시각 결함엔 약하다 |
| `/qa-ux` 사용자 검수 | 쓰기 편한가 · 헷갈리나 | 처음 하는 사람의 동선 | **결함 찾기까지** — 얼마나 헷갈리나는 사람 몫 |
| `/qa-fun` 재미 검수 | 재미 · 콘텐츠 · 밸런스 | 기획 목표 · 대량 실행 · 퍼널 | **측정까지** — 재미 · 리텐션 판정은 사람 몫 |

- 인자나 요청에서 고르고, 고르면 그 스킬을 부른다. 못 고르면 이 표를 보여 주고 묻는다
- 옛 이름 — 다른 문서의 「`/qa` 기획 모드」 = `/qa-fun`(대량 실행) · 「버그 모드」 = `/qa-bug`. **「기획 모드」는 `/qa-spec` 이 아니다**

## 공통 규칙 — 네 스킬 모두

1. **돌려서 본다** — 근거는 실행 결과와 화면이다. 코드 · 문서는 어디를 볼지 고르는 데 쓴다
2. **고치지 않는다** — 게임 코드 · CSV · 기획서 · 단정은 넘긴다. 실패하는 단정을 먼저 넣지 않는다(병렬 세션의 검증이 전부 빨개진다)
3. **구현 · 확정된 것만** — 미구현과 [GAME_DESIGN.md](docs/game_design/GAME_DESIGN.md) §10 미확정은 결함으로 올리지 않는다
4. **기준선** — 시작할 때 커밋 해시 · `git status` · `dev/test.html` 이 `PASS n/n` 인지 적는다. 아니면 멈추고 보고한다. 도중에 범위 파일의 mtime 이 바뀌면 그 실행은 버린다
5. **두 번 일으킨 것만 결함** — 못 일으킨 것은 [risk_map.md](risk_map.md) 「못 일으킨 관찰」로
6. **행선지** — 결함 → [DEV_PLAN.md](docs/client/DEV_PLAN.md) §4 한 행(종류 `버그(QA)` · 재현 문장. 먼저 §4 · `docs/client/adr/` · [src/dev/README.md](src/dev/README.md) 에서 같은 것을 찾는다) · 기획 의문 · 기획 문제 → `/game-design` · 화면 설계거리 → `/ui` · 사람이 봐야 할 것 → 보고 끝 「사람 플레이에서 볼 것」
7. **명령 원문은 여기 적지 않는다** — dev 주소 · 대량 실행 · 퍼널은 [src/dev/README.md](src/dev/README.md), 서버 · 헤드리스는 [client/verify.md](.claude/skills/client/verify.md)

## 교훈 이월 — 건너뛸 수 없다

세션 사이엔 기억이 없다. 이 파일들이 없으면 매번 같은 쉬운 곳만 보고 같은 함정을 다시 밟는다.

- **시작** — 그 스킬의 교훈 파일과 [pitfalls.md](pitfalls.md) 를 읽고, 보고 첫머리에 「반영한 지난 교훈」을 한 줄씩
- **끝** — 적중 · 헛돎 · 새 함정 · 다음에 볼 곳을 써 넣고, 보고 끝에 「다음 실행에 넘긴 것」. 헛돈 교훈은 고치거나 지운다
- 덮어쓴다(이력은 git) · 파일마다 10KB 이하 · 두 번 밟은 함정을 스크립트로 흡수하는 건 **제안만**

| 파일 | 스킬 |
|---|---|
| [spec_ledger.md](spec_ledger.md) | qa-spec |
| [angles.md](angles.md) · [risk_map.md](risk_map.md) | qa-bug |
| [ux_notes.md](ux_notes.md) | qa-ux |
| [metrics.md](metrics.md) | qa-fun |
| [pitfalls.md](pitfalls.md) | 모두 |

끝낼 때 「다음으로 실행할까요?」라고 묻지 않는다 — 다음 추천만 적는다.
