# metrics — 재미 검수의 약속 → 측정

> `qa-fun` 이 「활성」을 고른다. **약속 원문은 옮겨 적지 않는다** — 「근거」의 § 를 **실행 전에** 다시 읽고, DECISION_LOG 에서 폐기(~~취소선~~)됐는지도 본다(기획서는 자주 바뀌고, GAME_DESIGN 요약이 옛말을 인용하고 있기도 하다).
> **판정 기준 수치(몇 % 면 문제)는 적지 않는다** — 목표가 정해지면 CSV 키로 가고 단정으로 승격한다([qa-fun](.claude/skills/qa-fun/SKILL.md) 「한계」).
> 실행 파라미터 · 출력 필드는 [src/dev/README.md](src/dev/README.md) 「대량 실행」 · 마지막 판정 수치는 같은 문서 「재미 검수 판정」. 회고에서 「최근」을 덮어쓰고 쓸모 있던 지표를 위로 올린다.

## 구현 대기 — 지금은 잴 수 없는 약속

막힌 곳이 풀리면 「활성」으로 올린다. 판단은 매번 `game_logic/` 과 `src/dev/sim.js` 봇 규칙에서 한다. 자리 비워도 안전(방치형 계약)은 분포가 아니라 규칙이라 `qa-spec` 이 본다.

| 약속 | 근거 | 막힌 곳 |
|---|---|---|
| 밸런스는 PvP 기준 — 영웅 팀 대 영웅 팀 | CLAUDE.md 「설계의 큰 틀」 · GAME_DESIGN §1 | 대량 실행기에 결투장 모드가 없다 |
| 난이도 바퀴의 소요 — 노말 → 나이트메어 → 헬 | GAME_DESIGN §1 (엔드게임 = 난이도 바퀴) · §10 「성장곡선 숫자」 | `campaign` 에 난이도 인자가 없다 · 장 해금을 손으로 짓는 동안의 챕터보스 반복(사람 흉내에서 사탄 7회 · 레비아탄 13회)도 `build=` 가 건너뛰어 골드 곡선에 없다 |
| 병렬 가동 — 모든 영웅이 뭔가 한다 | GAME_DESIGN §2 설계 검증 기준 | 로직은 있다(파견 · 수색 · 탐험) — 봇이 안 한다 |
| 순환 구조 — 비전투가 전투 파밍을 민다 | GAME_DESIGN §2 설계 검증 기준 | 로직은 있다(파견 · 건설 · 제작) — 봇이 파견 · 제작을 안 하고 건설은 `build=` 로 미리 지어 둘 뿐이다 |
| 긴 체이스 — 유니크 · 빌드 완성 | GAME_DESIGN §2 설계 검증 기준 | 봇이 전술 리롤 · 강화 · 제작 · 크래프트를 안 한다(마스터리는 `mastery=1` 로 첫 칸에 몰아 찍을 뿐) |
