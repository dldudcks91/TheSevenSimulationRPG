# 모바일 제스처 개편 — 2026-11-14

사용자 요청: 클릭을 강요하지 않는 모바일 화면. 능력치에서 오른쪽으로 밀어 상세를 보는 흐름, 다른 키우기 게임 조사, 구현과 실제 조작 검증까지 진행한다.

## 조사와 적용 판단

공식 배포 페이지와 공개 스크린샷을 확인했다. 아래는 관찰과 이번 게임의 설계를 구분한 기록이다. 다른 게임이 특정 스와이프를 지원한다고 추정하지 않는다. 외부 게임 이미지는 조사 자료이며 게임 자산으로 사용하지 않는다.

- [AFK Journey / FARLIGHT](https://play.google.com/store/apps/details?id=com.farlightgames.igame.gp&hl=en): 영웅 중심의 표현, 공유 장비/레벨과 편성 변경을 강조한다. 이번 게임에서는 선택한 영웅을 유지한 채 능력치와 장비 정보를 오가는 구조에 적용한다.
- [Legend of Slime / LoadComplete](https://play.google.com/store/apps/details?id=com.loadcomplete.slimeidle&hl=en): 공개 채굴 화면에서 상단 진행 상태, 넓은 중앙 플레이 영역, 하단 도구를 구분한다. 관련 정보 탐색이 주요 행동의 자리를 밀어내지 않도록 적용한다.
- [Idle Slayer / Pablo Leban](https://play.google.com/store/apps/details?id=com.pabloleban.IdleSlayer&hl=en): 공개 오프라인 보상 화면은 결과를 하나의 카드에 모은다. 현재 대상의 상세를 한 장에 유지하고 비교할 때 장을 넘기는 방식에 적용한다.

실제 관리 화면도 추가 비교했다. [Legend of Slime 화면 모음](https://gamedesignernawe.tistory.com/214)은 캐릭터·스킬·특성·설정·연구소를 나눠 보여준다. [스킬 화면](https://www.levelwinner.com/legend-of-slime-idle-rpg-beginners-guide-tips-tricks-strategies-to-get-stronger/)의 장착 상태·보유 목록·하단 실행 버튼 구분을 참고해 현재 카드 안에 상태와 행동을 함께 유지했다. [AFK Journey 영웅 안내](https://www.levelwinner.com/into-esperia-a-beginners-guide-to-afk-journey/)는 기본/공격/방어 등의 상세를 구분하고 별도 설명으로 펼치는 흐름을 확인하는 자료다. 이 게임에서는 기본 능력치 옆에 상세 두 장을 두되 사용자가 요청한 오른쪽 드래그로 접근한다. 이 자료들은 클릭 UI의 사례이며 스와이프 동작의 증거로 쓰지 않는다.

## 구현 계획

1. 재사용 가능한 포인터 제스처를 만든다. 가로 의도가 분명할 때만 화면 전환을 잡고, 세로 스크롤·다중 터치·pointercancel·짧은 이동을 처리한다. 고정 PC 미리보기 배율도 계산한다.
2. 기능 선택 줄을 한 줄로 줄이고, 양옆 목적지/현재 위치를 표시한다. 본문이 손을 따라 움직이고 놓으면 전환 또는 복귀한다. 동작 감소 설정을 따른다.
3. 캐릭터는 능력치 기본 진입, 상세 II–상세 I–능력치–장비–창고–가방 순서로 배치한다. 따라서 능력치를 오른쪽으로 밀면 상세 I, 다시 밀면 상세 II가 나온다. 기존 패널 및 행동은 보존한다.
4. 고용·의뢰·전술·전직의 카드 본문에서도 좌우로 비교한다. 중첩 화면은 가장 가까운 카드만 처리하고 끝에서 부모 화면으로 넘기지 않는다.
5. 실행 버튼, 입력, 편성 드래그, 아이템 칸, 가로 목록, 공간형 판의 기존 조작은 보호한다. 버튼을 누르지 않아도 본문의 넓은 영역과 전환 안내 줄에서 넘길 수 있다.
6. 실제 브라우저의 터치/마우스 이동으로 검증한다. 양방향·취소·작은 미리보기·세로 스크롤·중첩·긴 누르기·실제 행동·PC 회귀를 확인한다. 다섯 지역 무스크롤과 390×844 고정 미리보기를 유지한다.

## 검증 산출물

최종 통합에서는 새 담금질 기능도 강화의 오른쪽 드래그로 연결했다. 담금질–강화–장비 순서이며, 재료 선택·실행·강화 시 보너스 소모는 기존 게임 함수를 사용한다. 최신 ADR-1138의 3×3 판을 유지하고 짧은 가로 화면은 판과 재료/실행 영역을 두 열로 나눈다. 편성의 가로 화면에 남아 있던 210px 여백도 제거해 대장 지정 버튼까지 보이도록 한다.

초상 위에서 시작하는 PC 드래그는 브라우저 기본 이미지 끌기와 충돌했으므로 모바일 탐색 영역의 이미지 끌기를 막고 실제 마우스 검사에 포함했다. 고용·수색 카드의 행동 줄에는 PC용 위쪽 패딩이 들어오지 않도록 모바일 규칙을 명시했다. 없어진 HP/합계 정보가 쓰던 가로 화면의 빈 행도 제거했다. 재료/강화는 실제 소모까지, 후보는 고용/보관/돌려보내기까지 원본 행동으로 확인한다.
