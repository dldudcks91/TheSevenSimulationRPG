# 온라인 모드 — 서버가 세이브와 굴림을 쥔다

**한 줄 요약** — 게임 계산 코드(`src/game_logic/`)를 서버에도 똑같이 올리고, **세이브 원본과 굴림(주사위)은 서버만 갖는다.** 브라우저는 서버가 정한 결과를 보여 주는 화면이고, 원정 전투만 브라우저가 직접 계산한다.

- 이 문서 = **구조와 의도**(무엇을 왜 어떻게 바꾸나) · 결정 목록과 상태 = [PLAN_server_seed.md](../../PLAN_server_seed.md) §0 · §3 · 업계 근거 = [idle_server_authority_survey.md](../reference/idle_server_authority_survey.md)
- 아직 아무것도 만들지 않았다. 지금 코드의 서버 연결은 §9 에 적는다

---

## 1. 왜 바꾸나

### 1-1. 결투장이 있어서 조작이 남에게 닿는다

혼자 하는 게임이면 세이브를 고친 사람만 손해다. 그런데 결투장은 **다른 사람의 팀(고스트)과 싸우고 레이팅이 오르내린다.** 조작한 영웅 · 장비로 이긴 만큼 정직한 사람의 레이팅이 깎이고, 순위표 위가 조작한 팀으로 채워진다. 「모든 밸런스의 기준은 PvP」(CLAUDE.md)인 게임이라 결투장이 흔들리면 밸런스 판단도 흔들린다.

### 1-2. 지금 구조로는 무엇이 뚫리나

지금은 세이브와 시드가 둘 다 브라우저에 있다.

| 조작 | 지금 |
|---|---|
| 세이브를 고쳐 골드 · 아이템 · 레벨 바꾸기 | 뚫림 — 결투장이 받을 때 「범위 밖 수치」만 거른다(`arena.js` `validateTeam`) |
| 시드로 결과를 미리 계산하고 고르기(어느 아이템을 강화할지 · 어느 스테이지를 돌지) | 뚫림 — 마스터 시드가 세이브 안에 있다(`state.seed`) |
| 기기 시계를 당겨 연구소 · 탐험 · 수색 빨리 받기 | 뚫림 |
| 결투 결과 · 레이팅 · 방어 기록 위조 | 뚫림 — 공격하는 쪽 게임이 싸우고 기록한다 |

### 1-3. 「시드만 서버에서 받는 것」으로는 안 막힌다

처음 떠올린 안은 「시드를 서버가 주면 된다」였다. 막히지 않는 이유는 셋이다.

1. **세이브는 여전히 브라우저에 있다** — 시드와 상관없이 골드 · 아이템을 고치면 끝난다
2. **지금 시드 파생식은 거꾸로 풀린다** — `rng.js` `deriveSeed` 는 파생 시드 하나와 번호만 알면 마스터 시드가 한 줄 계산으로 나온다(2026-11-24 계산 확인). 서버가 마스터 시드를 쥐고 파생값을 내려 주면 첫 번에 마스터가 새고, 그 뒤 모든 굴림이 미리 계산된다(§5)
3. **결과를 게임이 신고하면 지어낼 수 있다** — 시드를 받아도 「이 아이템이 나왔다」를 게임이 보내면 그만이다

결론 — **서버가 세이브를 쥐고 굴림을 직접 해야** 막힌다.

### 1-4. 업계는 어떻게 하나

모바일 방치형 · 수집형 RPG 의 공통된 분업은 이렇다([조사 문서](../reference/idle_server_authority_survey.md) 「PvE 전투는 기기가 계산하고, 서버는 말이 되는지만 본다」).

| 대상 | 업계 | 이 게임 |
|---|---|---|
| 재화 · 뽑기 · 강화 확률 | 서버 | 서버 |
| PvE 스테이지 전투 | 기기가 계산 · 서버는 결과가 말이 되는지만(클리어 시간 · 보상 상한) | 같다 |
| 순위 · PvP 에 닿는 판 | 서버가 다시 계산 | 서버가 직접 계산 |

반대 사례 — 니케(2026)는 순위에 닿는 레이드 결과를 기기 신고로만 받다가 조작 기록이 올라왔고, 운영사가 「핵인지 버그인지 입증할 근거를 확보하지 못했다」고 밝혔다.

### 1-5. 목표와 하지 않는 것

**목표**

- **위조를 막는다** — 「없는 것을 있다고 하기」(지어낸 아이템 · 영웅 · 골드 · 결투 결과)가 통하지 않는다
- **조작으로 얻는 최대 이득을 묶는다** — 막지 못하는 것(§7 「이긴 척」)도 「한 판도 지지 않는 플레이어의 속도」를 넘지 못한다
- **비용은 데모 규모에서 거의 0** — §10
- **방치형 계약을 지킨다** — 연결이 끊겨도 진행이 사라지지 않는다(§4-8)

**하지 않는 것**

- **원정 전투를 서버가 돌리지 않는다** — 업계 관행과 같고, 돌리려면 브라우저 · 서버 계산이 끝자리까지 같아야 하는 큰 작업이 붙는다(§6 「다시 돌려 보기」는 의심 판만)
- **결투장에서 레벨 · 강화를 고정값으로 맞추지 않는다** — 10-26 사용자 「정규화는 불가능해 게임구조적으로」
- **게임 계산을 서버용으로 새로 짜지 않는다** — 같은 `game_logic` 을 서버에서 그대로 돌린다(다른 언어로 짜면 두 벌을 비트 단위로 맞춰야 한다)

| 세이브 원본 | 기기 | 서버(브라우저는 사본) |
| 굴림 | 세이브 시드(지금과 같다) | 서버가 굴린다 |

## 3. 온라인 모드 — 누가 무엇을 계산하나

```
브라우저(화면)  ── 명령 ──▶  서버(심판)
                              · 세이브 원본
                              · 게임과 같은 계산 코드(game_logic + CSV)
                              · 주사위 = 서버만 아는 비밀값
                              · 서버 시계
브라우저(화면)  ◀── 결과(바뀐 것만) ──
```

| 무엇 | 누가 | 브라우저가 하는 일 |
|---|---|---|
| 세이브 · 골드 · 재료 | 서버 | 사본을 들고 화면을 그린다 |
| 굴림 — 장비 강화 · 인챈트 · 제작 · 상자 · 상점 목록 · 고용 · 수색 · 전술 리롤 | 서버 | 버튼을 누르고 결과를 보여 준다 |
| 굴림 없는 행동 — 장착 · 진형 · 마스터리 · 건설 | 서버가 같은 명령을 실행해 확정 | 화면에 바로 반영하고 모아 보낸다 |
| 원정 전투(누가 누구를 때리나 · 승패) | 브라우저 | 직접 계산해 보여 준다 |
| 원정 드롭 · 경험치 · 골드 | 서버(시드로 확정) | 「몇 번 자리를 잡았다」만 알린다 |
| 탐험 결과 | 서버(끝나는 시각에 굴림) | 보내고 기다린다 |
| 결투 | 서버 | 같은 시드로 재생만 한다 |
| 꺼진 동안(연구소 · 탐험 · 도서관) | 서버(서버 시계) | 다시 켜면 받는다 |

## 4. 주고받는 흐름

### 4-1. 굴림 행동 — 누를 때 바로

강화 · 인챈트 · 제작 · 상자 · 상점 · 고용 · 수색 · 전술 리롤.

1. 게임 → 서버 「이 아이템 강화」
2. 서버가 자기 세이브로 조건(골드 · 재료 · 강화 한도)을 보고, 비밀값으로 만든 시드로 굴린다 — 지금과 같은 `game_logic` 함수(`upgradeItem` 등)를 서버 시각으로 부른다
3. 서버 → 게임 「결과 + 바뀐 것」(0.2 ~ 1초)

결과를 브라우저가 미리 알 방법이 없다 — 시드가 브라우저에 내려가지 않는다. 안 되는 명령(골드 부족 등)은 서버가 같은 규칙으로 거절한다.

### 4-2. 굴림 없는 행동 — 모아 보내기

장착 · 진형 · 마스터리 · 건설 · 편성 · 물약 칸.

- 브라우저가 화면에 바로 반영하고(기다리지 않는다) 명령을 쌓는다
- 2분마다(§4-7) 또는 굴림 요청에 실어 보낸다 — 서버가 순서대로 같은 함수를 실행한다
- 서버가 거절하면(조작 · 시각 차이) **서버 세이브로 통째로 되돌린다** — 처음엔 이 규칙 하나로 시작한다

명령마다 **시각**을 붙인다 — 원정 중 장비 교체는 그 시각부터 전투에 먹는다(09-21 규칙). 서버가 찾기 수치를 계산할 때도 이 시각표를 쓴다(PLAN D6).

### 4-3. 원정 — 출발 때 시드 · 2분마다 확정

게임은 「몇 번 자리를 잡았다」만 말하고, 무엇이 떨어졌는지는 서버가 시드로 정한다.

1. **출발** — 게임 → 서버 「1부대 · 3-2 · 노말 출발」. 서버가 그 판의 시드(전투 시드 + 라운드별 만남 시드)를 비밀값으로 만들어 장부에 적고 내려 준다. 이미 있는 입구를 쓴다 — `departRun(..., seedGrant)` · `stageSeedRequest` · `validateStageGrant`(R405 · INTERFACE §2-7)
2. **전투** — 브라우저가 그 시드로 전투를 그린다. 드롭도 화면에 바로 보인다 — 브라우저도 같은 계산을 하므로
3. **신고** — 2분마다 「2라운드 이김 · 0 · 1 · 3번 자리 잡음」을 보낸다
4. **확정** — 서버가 같은 시드로 그 라운드의 편성 · 몬스터 차림 · 드롭 여부를 계산한다. **전투는 안 돌린다** — 편성과 차림이 시드만으로 정해진다(R405 로 만남 · 드롭 줄을 전투 줄에서 뗐다 · `battle.js` `wearGear` · `dropSeed` — 자리마다 제 줄). 경험치 · 골드도 잡은 몬스터로 계산한다. §6 검사에 걸리면 보류
5. **답** — 「확정 — 이 아이템들」 · 아이템 번호(uid)는 서버가 준다

확정 전까지 그 드롭은 화면에만 있다. 화면과 서버가 다르면 서버를 따른다 — 같은 계산이라 보통은 같다.

| 조작으로 안 되는 것 | 되는 것(상한 안) |
|---|---|
| 시드에 없던 아이템 · 옵션 바꾸기 · 더 좋은 것 고르기 | 안 잡은 자리를 잡았다고 하기 — 받는 것은 그 몬스터가 원래 입던 장비뿐 |
| 한 마리에서 여러 개 · 실제 시간보다 빨리 | |

### 4-4. 탐험 — 보낼 때 · 끝날 때

탐험 결과는 전투와 상관없이 **탐험 번호만으로** 정해진다(`state.js` `exploreRoll` — `seed ^ 0xE7A1` · `explore.no`). 그래서 시드를 내려 줄 필요가 없다.

1. 보낼 때 — 게임 → 서버 「동굴 · 2장 · 이 편성」 · 서버가 서버 시각을 적는다
2. 끝나는 시각(서버 시계)이 지나면 — 서버가 직접 굴려 결과를 세이브에 넣는다

### 4-5. 결투장

- **방어 등록** — 게임은 「이 편성을 방어로」만 보낸다. 서버가 **자기 세이브에서** 영웅 · 장비를 꺼내 팀을 만든다 — 지어낸 장비가 들어갈 수 없다
- **대결** — 게임 → 서버 「이 상대와」. 서버가 상대를 고른 **뒤에** 시드를 정하고 싸운다(`arena.fight` · 판당 5 ~ 7ms). 레이팅 · 방어 기록은 서버가 쓴다. 게임은 같은 시드로 재생만 한다
- **상대 고르기** — 후보 새로 고침 횟수를 묶는다. 브라우저에 계산 코드가 다 있어 후보마다 승률을 미리 재 볼 수 있기 때문이다

### 4-6. 꺼진 동안 — 다시 켤 때

연구소 · 탐험 · 도서관 · 수색은 시간으로 진행된다. 다시 켜면 서버가 **서버 시계**로 지난 시간을 재서 정산한다. 기기 시계를 당겨도 소용없다.

### 4-7. 2분 신호와 창을 닫을 때

2분마다 한 번 보내는 묶음에는 셋이 실린다.

| 실리는 것 | 왜 |
|---|---|
| 「켜 둠」 신호 | 원정은 켜져 있을 때만 돈다 — 서버가 언제까지 켜져 있었는지 안다 |
| 쌓인 굴림 없는 행동 | §4-2 |
| 원정 라운드 신고 | §4-3 |

창을 닫을 때(`pagehide`) 못 보낸 것을 마지막으로 보낸다. 그래도 못 보냈으면 브라우저에 남겼다가 다음에 켤 때 보낸다 — 서버가 시간 검사 뒤 확정한다.

2분 간격인 이유 — Firestore 는 데이터 크기가 아니라 **쓰기 횟수**로 돈을 받는다. 서버가 출발 파티와 시각이 찍힌 명령을 다 갖고 있어 2분치를 한 번에 확정할 수 있고, 그 사이 화면은 브라우저가 그리므로 플레이어가 기다리지 않는다.

### 4-8. 연결이 끊기면

정할 것(PLAN D4) — 추천은 「새 출발 · 굴림 버튼만 멈춘다 · 도는 원정은 이미 받은 시드로 계속 · 신고는 쌓았다가 다시 붙으면 정산」이다. 서버가 멈추면 게임도 멈춘다 — 온라인 모드의 대가다.

## 5. 시드 — 서버만 아는 비밀값

- **지금 방식은 서버용으로 못 쓴다** — `deriveSeed(master, stream)` 는 곱셈 한 번과 덧셈 한 번이라 거꾸로 풀린다. 마스터 시드도 32비트라 역산을 막아도 결과를 보고 40억 개를 다 대입해 찾을 수 있다(PC 몇 시간 · 추정)
- **굴림마다 독립 시드 — HMAC** — 서버만 아는 긴 비밀값에 계정 · 줄(용도) · 번호를 섞어 32비트 숫자를 만든다. 같은 입력이면 같은 숫자라 서버가 언제든 다시 만들 수 있고, 비밀값이 없으면 다음 숫자를 못 맞춘다
- **브라우저에 내려가는 시드는 원정 시드뿐** — 받은 시드 하나로는 다른 굴림을 알 수 없다
- **`game_logic` 쪽** — 세이브 시드에서 나오는 굴림(`state.js` 26곳 · 원정 판 장부의 만남 뿌리 · 전투 시드)은 **주입받는 함수 하나 `deps.seedOf(state, 솔트, 번호)`** 를 지난다(R580 · INTERFACE §5-1 「시드 공급자」). 로컬(오프라인 모드 · 지금 웹판)은 지금과 같은 값을 내므로 골든이 안 바뀐다. 서버는 HMAC 을 준다. `game_logic` 은 여전히 DOM · 시계 · `Math.random` 을 모른다

## 6. 서버 검사 — 「말이 되나」

원정 전투를 서버가 안 돌리므로, 라운드 신고가 말이 되는지만 본다.

| 검사 | 내용 |
|---|---|
| 시간 | 신고 간격 ≥ 그 라운드의 실제 시간(출시판 배속 ×1 · 서버 시계) — 「너무 짧은 클리어」는 업계가 가장 많이 쓰는 검사다(LINE · 레이드) |
| 전투력 | 파티 전투력이 그 스테이지에 비해 터무니없이 낮은데 이겼다면 보류 — 기준선은 `dev/sim` 봇으로 잡는다(PLAN §5) |
| 기록 | 원정마다 시드 · 출발 파티 · 시각이 찍힌 명령을 남긴다 |
| 다시 돌려 보기 | 의심 판은 기록으로 **그대로 다시 돌려** 확인한다 — 니케처럼 「핵이냐 버그냐」를 사람이 추측하지 않는다. 끝자리까지 같으려면 전투 경로의 `Math.pow` · `**` · `exp` 를 정리해야 한다(엔진마다 끝자리가 다를 수 있다 · 조사 문서) |

데모에서는 시간 검사와 기록부터 넣고, 전투력 기준과 수학 함수 정리는 뒤로 미룰 수 있다.

## 9. 지금 구조 — 바꾸기 전

서버 코드는 없다. 게임이 Firestore 에 직접 쓴다(`src/ui/cloud.js` · 부르는 곳 `app.js` `trackPush` · `arenaPull`).

| 무엇 | 언제 | 어디 |
|---|---|---|
| 진행 요약(퍼널용) | 켤 때 · 첫 클리어 · 탭 숨김(10분 간격 · `TRACK_HIDE_MS`) · 닫을 때 — 세이브가 바뀌었으면(R579) | `players/<계정>` |
| 세이브 사본(통째) | 진행 요약과 한 묶음 | `saves/<계정>` |
| 결투장 방어 편성 · 레이팅 | 같은 때 — 편성이 바뀌었으면 | `arenaTeams/<계정>` |
| 고스트 받기 | 결투장 탭 진입 · 새 상대 · 결투 뒤(1분 간격) | 팀 30개 + 내 방어 기록 10개 읽기 |
| 방어 기록 | 결투가 끝날 때 — **공격자가 상대 기록함에 직접 쓴다** | `arenaLog/<상대>/hits` |
| 계정 | 만들기 · 로그인 · 불러오기 · 주인 표식 | `saves/<계정>` |
| 방문 집계 | 켤 때 | Google Analytics |

문제 — ① 결투장을 게임이 쓴다(§1-2) ② 보안 규칙이 저장소에 없다. 익명 계정의 세이브 사본은 관리자 퍼널 [세이브](ADR-0633)가 읽으므로 남긴다.

**쓰기 줄이기**(R579 · ADR-1377) — 1분마다 올리기를 걷고 켤 때 · 첫 클리어 · 탭 숨김(10분 간격) · 닫을 때만 올린다 → 플레이 한 시간에 많아야 스무 건 남짓. 온라인 모드를 막지 않는다 — 세이브 사본은 온라인 모드가 들어오면 서버 원본으로 바뀌고, 「창을 닫을 때 보내기」는 온라인 모드가 그대로 쓴다.

## 10. 부하와 비용

**측정**(2026-11-24 · 이 PC · Node 18 · 작업 폴더 사본 · 노말 · 시드 6 · 4,126판 · 봇 = `dev/sim` greedy)

| 항목 | 값 |
|---|---|
| 전투 1초를 계산하는 데 | 0.11 ~ 0.28ms — 플레이 1시간 · 부대 셋 = CPU 1 ~ 3초 |
| 결투 한 판 | 5 ~ 7ms · 느린 판 18ms |
| 서버 준비(CSV 읽기 · 조립) | 0.14초 |
| 세이브 | 42 ~ 69KB · 아이템 한 개 0.3KB · 읽고 쓰기 1ms |

**비용**(구글 단가 페이지 · 요청 하나의 서버 대기 0.1초는 추정)

| 하루 총 플레이 | 한 달 |
|---|---|
| 100시간(테스터 100명 × 1시간) | $0 — 무료 몫 안 |
| 1,000시간 | $1 안팎 |
| 2,400시간(동접 100명 · 24시간) | 약 $5 ~ 10 |

- 가장 먼저 차는 무료 몫은 Firestore 쓰기(하루 2만 건) — 플레이 1시간에 30 ~ 60번이면 하루 330 ~ 660 플레이시간까지 무료
- 비용이 커지는 것은 정상 플레이가 아니라 **요청 폭탄** — 계정당 요청 제한 · App Check · 예산 알림으로 묶는다
- 답은 **바뀐 것만** 보낸다 — 세이브를 통째로 돌려주면 전송량이 수백 GB 단위로 붙는다
- AWS 와 비교 — DynamoDB 는 1KB 마다 과금이라 60KB 세이브 한 번 쓰기가 60단위다(Firestore 는 문서당 1건). 로그인 · 저장소 · 퍼널을 옮기는 일도 붙는다 → Firebase 를 쓴다(PLAN D9 · 추천)
