# SCREEN_DESIGN — 화면 설계

> **무엇을 보여주고 어떤 결정을 받는가.** DOM·CSS 가 아니다 — 그건 `src/ui/` 의 구현이고 Phase 2 에서 버려진다. 여기 적힌 것은 엔진이 바뀌어도 **그대로 들고 간다.**
> 화면을 바꾸려면 **이 문서를 먼저** 고친다 (TheSevenSimulation 관례 — 씬 변경은 문서가 코드보다 앞선다).
> **이 문서는 「지금」만 적는다** — 폐기된 규칙과 그 근거는 여기 남지 않는다. **왜 이 모양인가**는 [adr/](adr/README.md), **언제 무엇이 바뀌었나**는 [SCREEN_CHANGELOG.md](SCREEN_CHANGELOG.md) 가 든다 — 절 끝의 「결정 기록」이 그 길이다.
> 폭·배율·최소 크기 같은 구현 정책은 [src/ui/README.md](../../src/ui/README.md).

관련: [adr/](adr/README.md)(이 규격이 왜 이 모양인가) · [SCREEN_CHANGELOG.md](SCREEN_CHANGELOG.md)(언제 바뀌었나) · [ARCHITECTURE.md](ARCHITECTURE.md) · [INTERFACE.md](INTERFACE.md)(호출하는 함수의 계약) · 큰 틀 [GAME_DESIGN.md](../game_design/GAME_DESIGN.md) §1·§3

## 1. 화면 지도

```
시작 ──(새 게임 / 이어하기)──▶ 게임 ── 탭 10 ─┬ 원정       : 편성 ⇄ 관전 ⇄ 리포트          ← 접속 중의 본편 (GAME_DESIGN §3)
                                            ├ 캐릭터     : 장비·능력치·가방 + 액티브 스킬 → [스킬 트리 열기] 창 (§6·§7)
                                            ├ 강화       : 제련소 — 배치 줄 + 제작·강화 (§8-2)
                                            ├ 선술집     : 영입 후보(명단·수색·리롤) + 의뢰 게시판 (§8-1·§14)
                                            ├ 상점       : 상단 — 기본상단·특수상단 (§8-3)   ⚠ 목업
                                            ├ 자원       : 파견처 카드 3(채광·채집·벌목) → 고른 것의 속 (§8)  ← 1인 배치, 보내 놓고 기다린다
                                            ├ 탐험       : 파티 파견 — 지도 (§8-4)   ⚠ 미착수 (지도 아트만)
                                            ├ 연구       : 연구(☐ 미착수) + 파티전술 7칸 (§13)
                                            ├ 도감       : 세그먼트 4 — 몬스터(카드) · 캐릭터 · 아이템 · 스킬 (§9·§9-1)   ← 수집 + 아트 확인

```

## 2. 공통 셸

| 요소 | 내용 |
|---|---|
| **한 장** | 화면은 **1600×800 한 장**이다 — 창에 맞춰 **통째로** 줄이고 늘린다(가로 · 세로 중 모자란 쪽에 맞춘다). 남는 가장자리는 배경 그림이 채운다 · 툴팁과 창 레이어도 한 장 안에 선다. 값은 [src/ui/README.md](../../src/ui/README.md) 크기 정책 |
| 브랜드 | 상단 좌측 |
| 상단바 | 현재 위치(crumb) · 자원 3종(골드 · 가루 · 낙인) · **언어 토글**(ko/en) |
| 탭 내비 | **목록과 순서는 §1 화면 지도가 든다** — 여기서 되풀이하지 않는다. 게임 화면에서만 선다 |
| 메인 | 탭 내용. **항상 전체 다시 그림** |
| 저장 | 상태가 바뀌면 `game.serialize` 로 직렬화해 저장소 어댑터에 넘긴다 — **직렬화는 `game_logic`, 저장소 접근은 `ui/storage.js` 한 곳** |
| **아이템 그림** | 착용 칸 · 가방 칸 · 제련소 목록·머리가 **같은 규칙 하나**를 탄다 (`ui/mock.js:itemArt`). **무기 = 무기군 그림** 한 장(`<group_id>.png`) · **방어구 = 부위당 한 장**(⚠ 임시 — 개체가 `base_id` 를 안 들고 다닌다) · **투구·목걸이 = 그림 없음**(부위 이모지로 떨어진다).<br>**예외 하나 — 양손검은 베이스 7장 중 하나를 든다** [2026-09-10]: `weapon_base` CSV 가 없어 개체가 베이스를 안 들고 다니므로 **`uid` 해시로 고른다**(`<uid>:<group>` · 7장은 §9-1 · `icons/items/unused/sword2h/`). ⚠ **rng 가 아니다** — 그리는 시각의 해시라 `game_logic` 난수 수열에 안 닿고(골든 불변), **개체마다 고정**이라 다시 그려도 껐다 켜도 안 바뀐다. ⚠ **이름은 안 따라온다** — 툴팁·이름은 여전히 「양손검」이라 그림과 이름이 어긋난다(알고 켠 임시 · [DEV_PLAN R62](DEV_PLAN.md) 가 닫으면 굴림이 `game_logic` 으로 간다) |
| 툴팁 레이어 | 아이템 비교 툴팁 (마우스 따라다님, 화면 밖 넘침 보정) · **스킬 설명창**(아래 「스킬 설명창 규격」) |
| **창 레이어** | 탭 위에 겹쳐 뜨는 판 하나. 지금 쓰는 곳은 **스킬 트리**(§7) · **출정 창**(§4-1) · **관전의 로그 창**(§4-2) 셋이다. ⚠ 둘은 **같은 규격이되 같은 레이어가 아니다** — 스킬 창은 셸의 `#modal` 을 쓰고, 로그 창은 **재생기가 자기 DOM 안에 든다**(2026-09-03). 로그와 누적은 재생기가 살아 있는 동안 계속 쓰이는 판이라 재생기 밖에 두면 mount 마다 넘겨줘야 한다. 바깥을 누르거나 `Esc` 를 누르면 닫힌다 — **닫기가 세 갈래**(닫기 버튼 · 바깥 · `Esc`)인 이유는 창이 화면을 덮기 때문이다. 창을 두 장 겹치지 않는다.<br>**머리는 대개 이름 하나**지만 **출정 창은 고른 스테이지의 신원**을 든다(§4-1) — 목록에서 떨어져 뜨는 창이라 무엇에 딸린 판인지를 머리가 말해야 한다.<br>**닫기 버튼 = 정사각 X · 머리 오른쪽** — **창이 여럿이 돼도 모양도 자리도 같다.** 창마다 다르면 닫는 법을 창마다 다시 배워야 한다. 글자가 아니라 글리프라 ko/en 에서 폭이 안 흔들린다 — 이름(`ui.close`)은 `title` 이 든다(문구를 지운 게 아니라 옮겼다) |
| 플래시 | 한 번만 보이는 안내/오류 한 줄 (i18n 키 + 파라미터). 다음 렌더에 사라진다 |
| **도움말 탭** | 규칙·안내 문구는 전부 여기(§12). 인게임 패널에는 설명 문장을 두지 않는다 — 숫자·상태·오류만 (2026-08-26 사용자 지시). **옵션 표기도 같다** — 유저에게 보이는 옵션 줄은 **이름 + 값**만 찍는다. 「+3강에서 옵션 상승」 같은 조건·규칙 주석을 옵션 줄에 붙이지 않는다 — 그건 도움말의 내용이다 |

**다국어** — 화면의 모든 문자열은 `t(key)`(문구) 또는 `L({ko,en})`(데이터). 렌더러에 한국어 리터럴 없음.

**스킬 설명창 규격** [2026-09-10 · [ADR-0089](adr/0089-스킬-설명창은-한-장이다-Alt-를-누르는-동안-숫자-뒤에-계산식이-선다.md)] — 설명창은 **한 장**이고 문장 속 **숫자 자리만** 상태에 따라 바뀐다. 서는 자리는 다섯 — 캐릭터 탭 액티브 카드(§6) · 스킬 창 액티브 줄(§7) · 관전 스킬 칸(§4-2) · 후보 카드 고유 스킬(§3) · 도감 스킬 세그먼트(§9-1). 카드는 `tip.js:skillTipCard` 하나다.

| 줄 | 내용 |
|---|---|
| 머리글 · 이름 · 칩 | 「스킬」 · 아이콘 + 이름 · 출처 칩(영웅 · 무기 · 전직) + 태그 칩 |
| 문장 | `kind` × `target` 이 고른 틀 하나. **숫자만 강조색** |
| 추가 피해 문장 | 확률로 터지는 추가 피해가 있는 공격만 — **완결된 둘째 문장**이다(앞 문장에 조각을 잇지 않는다) |
| 설명 | `skill.csv:desc_*` |
| 각주 | 「Alt 계산식」 — **기본 상태**이고 **괄호가 붙을 숫자가 하나라도 있을 때만** 선다 |

숫자 자리의 상태는 셋이다.

| 상태 | 언제 | 숫자 자리 | 예 |
|---|---|---|---|
| 기본 | 값이 있다 | 값 | `1,290` |
| **Alt** | 값이 있고 **Alt 를 누르는 동안** | 값 + 괄호 식 — **값은 강조색 · 식은 흐린 색** | `1,290 (공격력 × 300% + STR × 2)` |
| 값 없음 | 값을 모른다(`previewOf` 가 `value: null`) | **식만** — 식이 숫자 자리를 대신하므로 흐리게 두지 않고 **식 속 숫자가 강조색** | `(공격력 × 300% + STR × 2) 만큼 피해` |

괄호는 **슬롯이 미는 숫자에만** 붙는다 — `skill.csv` 의 스케일링 슬롯이 그 field 를 하나라도 가리킬 때다. 슬롯이 없는 숫자는 어느 상태에서도 값 그대로다.

| 숫자 | 슬롯 field | 식의 첫 항 |
|---|---|---|
| 피해 · 회복량 · 벽 HP | `mult_pct` | **밑수 이름 × 배율%** — 공격 = 공격력(`st.atk`) · 회복 = 마법 공격력 · 벽 = 최대 HP(둘 다 `combat_stat.csv` 이름) |
| 타수 | `hits` | 원값 |
| 효과값 — 버프 · 오오라 · 디버프 · 결투의 피해 감소 | `effect_value` | 원값(디버프는 절댓값 — 방향은 틀이 든다) |
| 지속 | `duration_sec` | 원값 |
| 감쇠 · 광역 약화 · 방어 감소 | `decay_pct` | 원값 |
| 추가 피해 확률 · 배수 | `proc_chance_pct` · `proc_mult_pct` | 원값 |
| 쿨 | — | **괄호 없음** |

- **식의 뒤 항은 그 field 의 슬롯마다 `약어 × 계수`** — 약어는 `hero_attribute.csv:abbr`. **계수 0 인 항도 찍는다**
- **단위는 숫자 자리 안에 든다** — `25%` · `8초` · `3번`. 값 없음이면 식 뒤에 선다 — `(8 + VIT × 0)초`. 그래서 틀은 단위를 안 든다(`{s} 동안` · `{h} 때려`)
- **Alt 는 누르는 동안만** — 토글이 아니다. 떠 있는 설명창도 **즉시** 바뀌고, 떼거나 창이 포커스를 잃으면 돌아간다. **스킬 설명창에서만** 동작한다 — 영웅 · 아이템 툴팁은 안 바뀐다
- **별도 능력치 줄은 없다** — 괄호 식이 「어느 능력치가 얼마나」를 대신 말한다
- **줄 문장은 Alt 에 반응 안 한다** — 스킬 창 액티브 줄(§7) · 아이템 툴팁의 담은 스킬 줄(§6)은 `tip.js:skillLineHtml` 을 지나 **기본 · 값 없음** 두 상태만 탄다. 담은 스킬 줄은 영웅 맥락이 없어 **식만** 찍는다. 추가 피해 문장은 줄바꿈으로 가른다
- **렌더러는 식을 계산하지 않는다** — 값과 식 재료(원값 · 배율 · 능력치 · 계수)는 전부 `skill.previewOf(def, ctx).parts` 가 낸다([INTERFACE §2-8](INTERFACE.md)). 맥락 `ctx = {atk, matk, hpMax, period, stats}` 는 부르는 자리가 싣는다:

| 자리 | 맥락 | 값 없음이 되는 숫자 |
|---|---|---|
| 캐릭터 탭 · 스킬 창 (§6 · §7) | `game.heroCombat` 의 공격력 · 마법 공격력 · 최대 HP · 행동 주기 + 영웅 `stats` | 마법 공격력이 없는 영웅(물리 무기)의 회복량 |
| 관전 (§4-2) | 전투 결과 `out.party[]` 의 `atk` · `matk` · `hpMax` · `period` · **`stats`**(전투 시작 시점 복사본) | 없음 — 전투가 쓴 밑수를 그대로 싣는다 |
| 후보 카드 (§3 · 선술집 §8-1) | 후보의 `stats` 뿐 — 무기가 없다 | 피해 · 회복량 · 벽 HP |
| 도감 (§9-1) · 담은 스킬 줄 (§6) | 없음 | 슬롯이 미는 숫자 전부 |

스킬 변경 넷의 틀 — 문구 원문은 `i18n.js`:

| 스킬 | 틀 | ko | en |
|---|---|---|---|
| 가이디드 애로우 — 단타 · 방어 감소 | `sk.line.guided` | {n}초마다 방어가 가장 두꺼운 적에게 {d}를 가하고 그 적의 방어를 {k} 깎는다 | Every {n}s, deals {d} to the best-armored enemy and strips {k} of its defense |
| 멀티샷 — 주 대상 외 약화(`enemy_all` 이면서 감쇠가 있다) | `sk.line.allDecay` | {n}초마다 적 전원을 맞혀 주 대상에게 {d}를 가한다 — 나머지 적은 {k} 덜 받는다 | Every {n}s, hits every enemy — {d} to the main target, {k} less to the rest |
| 듀얼 — 피해 감소 | `sk.line.duel` | {n}초마다 적 하나를 지목해 라운드가 끝날 때까지 자신만 노리게 한다 — 그동안 받는 피해 −{v} | Every {n}s, marks one enemy to attack only you until the round ends — −{v} damage taken meanwhile |
| 확률로 터지는 추가 피해 — 차지 · 라이트닝 · 체인 라이트닝 | `sk.line.proc`(둘째 문장) | 타격마다 {c} 확률로 피해가 {x} 가 된다 | Each hit has a {c} chance to deal {x} damage |

| 세이브 요약 (저장 시각 · 영웅 수 · 클리어 수 · 골드) | **이어하기** | **열 수 없는 세이브**일 때만 이어하기 대신 사유를 보여준다. 이관 가능한 옛 버전(v2·v3)은 그냥 열린다 — 판정은 화면이 아니라 `game.canLoad` 가 한다 ([INTERFACE §2-7](INTERFACE.md)). v1 은 스키마 단절이라 계속 거부 |
| 후보 카드 3장 — 초상(§5 영웅 초상 규격) · **등급 → 죄종 칩(윗줄, 나란히) · 이름(아랫줄)** · 직업 · 역할/무기군 · **고유 스킬 칸**(네모 + 이름) · 기본 능력치 7 막대 · 최대 HP · 합계 | **리롤** (무제한, 횟수 표시) | 같은 리롤 횟수 = 같은 3명 (고정 시드) |
| | **시작** | 세이브가 있으면 **두 번 눌러야** 덮어쓴다 — 되돌릴 수 없는 행동은 오클릭 한 번으로 일어나지 않는다 |

**초상 크기** — 후보 카드의 초상은 **카드에서 가장 큰 조각**이다. 시작 화면은 그림을 처음 보는 자리이고 고르는 근거의 절반이 인상이라, 이름·직업 줄에 딸린 아이콘 크기(52px)로는 얼굴이 안 읽힌다. 고정 px 이 아니라 **카드 폭을 따라간다**(`clamp()` 안의 `cqw` — 카드 안쪽 폭 기준 · ADR-0076) — 크기 정책은 [src/ui/README.md](../../src/ui/README.md).
- **선술집 명단(§8)은 안 따라간다** — 같은 `.ng-card` 를 쓰지만 거기는 카드가 셋 나란히 서고 위에 로스터 띠가 얹혀 세로 예산이 다르다. `.tv-cands` 가 자기 크기를 계속 든다
- **세 장은 여전히 같은 무게다** — 하나만 키우면 그쪽이 정답처럼 읽힌다 (`.ng-row` 규칙)
- **선술집 명단도 같은 카드다** — 「선술집은 세로 예산이 달라 안 따라간다」는 08-31 판단을 뒤집는다. 카드가 **한 벌**이면 시작 화면에서 익힌 읽는 법이 선술집에서 그대로 통하고, 초상이 작아 인상을 못 읽던 자리가 없어진다. 선술집 전용으로 남는 것은 **고용 버튼 하나**뿐이다 (§8-1)

### 3-1. 프롤로그

**목적** — 시작 파티를 확정한 직후, **왜 이 파티가 나가는지**를 5씬으로 준다. 원문은 [prologue.md](../game_design/story/prologue.md) 이고 화면은 그 글을 그대로 든다 — 화면이 문장을 새로 쓰지 않는다.

| 보여준다 | 결정 | 규칙 |
|---|---|---|
| 씬 하나 — 제목(왕좌 · 배신의 밤 · 추락 · 마을 · 불길) + 본문. 5씬을 순서대로 | **다음** — 마지막 씬에서는 「시작한다」 | **새 게임 직후 한 번만.** 이어하기는 안 지난다 — 진행은 세이브에 안 들어가는 화면 상태다(`state.proScene`) |
| 진행 `n / 5` | **건너뛰기** — 언제든 바로 원정 탭 | **뒤로는 없다.** 대신 건너뛰기가 모든 씬에 서 있다 |
| 마지막 씬의 인용 한 줄 + 다음 챕터 이름 | | 인용은 본문과 층이 다르다 — 바알이 처음 입을 여는 자리다 |

- **세이브가 프롤로그보다 먼저 쓰인다** — `startGame()` 이 `newGame` → `save()` 를 끝낸 **뒤에** 이 화면이 뜬다. 읽다가 창을 닫아도 게임은 이미 만들어져 있어 이어하기로 돌아온다. 되돌릴 수 없는 행동(세이브 덮어쓰기)의 확인은 §3 의 두 번 누르기가 이미 받았다
- **셸은 시작 화면과 같다**(`pregame`) — 탭 바도 자원 띠도 없다. 프롤로그는 게임 화면이 아니라 **시작 화면의 연장**이다. crumb 만 「프롤로그」로 바뀐다
- ⚠ **본문은 한국어뿐이다** — 5씬 본문·씬 제목은 `ko` 만 넣어 영어에서도 한국어가 나온다(`en` 폴백). 조작 문구(다음 · 건너뛰기 · 시작한다 · 진행)는 ko/en 둘 다 있다. 「ko/en 나란히」의 **의도된 예외**이고 번역은 나중에 채운다 ([DEV_PLAN §4](DEV_PLAN.md) 부채 #30)
- ⚠ **다시 보기 자리가 없다** [나중에] — 한 번 넘기면 그 게임에서는 다시 못 본다. 개발용 경로는 `?dev=prologue` (§10)

호출: 없음 — 이 화면은 `SYS` 를 부르지 않는다. 넘기는 것은 화면 상태(`state.proScene`)뿐이다

## 4. 원정 탭

세그먼트 3 — **편성 / 관전 / 리포트.** 관전은 재생 중인 전투가 있을 때만, 리포트는 마지막 리포트가 있을 때만 활성.

**출발한 런은 어느 탭에 있든 계속 간다** — 재생 시계는 관전 화면이 아니라 **앱이 든다.** 캐릭터 탭에서 장비를 갈아입히든 강화 탭에 들어가 있든 시각이 흐르고, 끝에 닿으면 **반복 원정 ON + 승리면 다음 런이 출발한다**(영웅 띠의 「원정 중」이 그 자리에서 「대기」로 바뀌거나 다음 런으로 이어진다 · §5). 규칙 셋이 이것을 떠받친다:
- **시계를 멈추는 것은 유저가 세웠을 때 하나다** — 관전의 일시정지·배속은 탭을 떠나도 그대로 걸린다
- **관전 중에는 재생기가 시계다** — 아레나가 떠 있는 동안은 재생기의 틱이 시각을 몬다. 리포트의 기여 표(§4-3)는 시각을 **읽어 그리기만** 한다
- **끝났다고 보던 화면을 뺏지 않는다** — 백그라운드에서 런이 끝나 세그먼트가 리포트로 옮겨 가는 것은 **관전을 보고 있었을 때만**이다

### 4-1. 편성

**어디를 갈지 먼저, 누구를 보낼지 나중** (2026-08-27) — **탭은 스테이지 목록 하나**이고, **지역을 누르면 출정 창이 뜬다**(탭 위에 겹쳐 뜨는 판 · §2). 창 머리가 **어느 지역인가**를 들고, 속은 **이름 붙은 칸 넷이 2×2** 로 선다 — **위 줄**이 「누구를 보내나 ↔ 누구와 싸우나」(마주 선다), **아래 줄**이 「어떻게 세우나 → 갈까」로 읽힌다. **영웅 띠가 서는 자리는 창 안 하나다** — 갈 곳이 안 정해진 편성은 결정이 아니라서, 목록 위에 띠를 상시로 띄우면 화면 첫 줄이 「지금 누를 것」이 아닌 것에 먹힌다.
**창을 자동으로 열지 않는다** — 마지막 런으로 미리 골라 두는 안은 08-27 에 넣었다가 사용자 지시로 철회했다: 누르지 않았는데 떠 있으면 "고르면 뜬다"는 인과가 안 읽힌다.

| 영역 | 보여준다 | 결정 |
|---|---|---|
| 재접속 알림 (있을 때) | "꺼져 있던 사이 런이 마무리됨" + 스테이지 | 리포트 보기 / 닫기 |
| **출정 창** (지역을 골랐을 때만 · 탭 위에 겹쳐 뜬다) | **머리가 스테이지의 신원을 든다** — 죄종 칩 · `Ch1-1 이름` · 잔글씨로 위험도 · 소요 · 원소(스테이지 행이 찍는 것과 같은 값). 목록에서 떨어져 뜨므로 무엇에 딸린 판인지를 머리가 말한다. 속은 **칸 넷이 2×2** — 위 줄에 캐릭터 선택 · 적 구성, 아래 줄에 진형 · 출정 방식. 두 줄은 **가로 가림막**으로, 두 열은 **세로 구분선**으로 갈리고, 한 격자라 **세로 구분선이 두 줄을 관통한다** | **닫는 길 셋** — 정사각 X · 판 바깥 · `Esc` (§2 창 공통). **폭이 못박혀 있다** — 판 크기를 내용에 맡기면 경고 줄의 글자 하나에 칸 폭이 바뀌어 창이 통째로 넓어졌다 좁아졌다 한다(값은 [src/ui/README.md](../../src/ui/README.md) 크기 정책) |
| | **캐릭터 선택** — **위 줄 왼쪽**. 로스터 전원이 한 줄에 서고(§5 규격 그대로 · 캐릭터 탭과 같은 카드) **파티에 든 영웅은 반투명**이다 — 바로 아래 진형 보드에 내려가 있다는 뜻이다 · 첫 슬롯은 **리더** 표시. 위칸 글씨는 **원정 중 / 대기** 둘뿐이다 | 카드 클릭 = **파티에 넣고 뺀다** · 카드를 진형 칸으로 **끌어다 놓으면** 그 자리에 들어간다. 창이 화면을 덮는 동안 눌리는 띠는 이것 하나다 |
| | **적 구성** — **위 줄 오른쪽 · 파티 띠 오른쪽**. 왼쪽 위에 **칸 이름**(네 칸이 **같은 규격**을 쓴다 · 칸 안 잔글씨보다 한 단 크다). 이 스테이지에서 기다리는 것들이 **정사각 칸 넷이 가로 한 줄로** 선다 — **진형 칸과 같은 크기**(`--fm-slot`)에 같은 생김새(얇은 테두리 + 윗변 3px)이고, **띠와 같은 줄에서 마주 선다**. **보스는 윗변이 붉다**(등급을 윗변이 든다 · 관전 카드와 같은 문법). ⚠ 여기서는 몬스터가 **원형이 아니다** — 관전 유닛 카드가 이미 몬스터를 정사각으로 그린다(§4-2). 도감(§9)의 원형은 그대로다 | **읽는 자리다 — 클릭이 없다.** 고르는 것은 스테이지 행이 이미 했다. **이름은 안 적는다** — 호버가 든다(칩의 규칙 그대로). 덕분에 칸 폭이 몬스터 이름 길이에 안 매인다. **칸 크기가 안 흔들린다** — 전 스테이지가 일반 셋 + 보스 하나로 같다 |
| | **진형** — **아래 줄 왼쪽 · 캐릭터 선택 바로 아래**. 자리는 **세이브 값**이고 **전투가 읽는다**(「앞부터 때린다」 · battle_design §3-1). **왼쪽 = 정사각 템플릿 아이콘 셋을 가로로**(2·1 / 1·2 / **3**(한 줄에 셋) — 모양을 점으로 그린다. 글자가 없어 언어 중립이고 i18n 키가 없다 · 고른 것은 강조색) · **오른쪽 = 보드**(랭크 줄 = 라벨(전열/후열 · 칸 쪽으로 오른쪽 정렬) + 정원만큼 **칸**). **칸은 정원 최대(3칸) 폭의 축 위에서 가운데 정렬**된다 — 2·1 이면 앞 둘이 양옆, 뒤 하나가 그 사이에 와서 **관전 아레나와 같은 모양**으로 읽힌다(§4-2). 축이 3칸으로 고정이라 템플릿을 바꿔도 가운데가 안 흔들린다. **왼쪽 위에 칸 이름**(「진형」) — 상자 **위**가 아니라 **템플릿 아이콘 열의 맨 위**에 얹혀 보드와 **같은 줄**에 선다(그 열은 보드보다 짧아 위가 비어 있으므로 **창이 안 자란다** · ADR-0080). 칸은 정사각(초상 + 이름 띠 + 리더 태그) — 빈 칸도 같은 크기라 「여기에 영웅이 들어간다」가 크기로 읽힌다 | 템플릿 아이콘 클릭 = 전환(재배치는 「나중에 배치된 쪽부터 밀려난다」) · **드래그 = 자리** — 끄는 곳이 둘이다: **띠 카드 → 칸**(벤치 영웅이면 파티에 들어오고, 그 칸에 주인이 있으면 **주인이 파티에서 나간다** = 교체) · **칸 → 칸**(빈 칸이면 이동 · 주인이 있으면 자리 맞바꿈). **클릭은 소속(띠) · 드래그는 자리**로 동사를 가른다 — 끈 뒤의 클릭 한 번은 삼켜 둘이 겹치지 않는다 |
| | **출정 방식** — **아래 줄 오른쪽 · 적 구성 아래**. 칸 이름 + 경고 줄 + **같은 크기 버튼 둘이 세로로** 쌓인다(가로로 나란하면 이 열이 300px 넘게 벌어진다). 폭은 **그 열이 정한다**(적 구성의 내용 폭) | **반복 원정**(ON/OFF) · **보내기**(고른 지역으로 출발 — 누르면 창이 닫히고 관전으로 넘어간다) |
| **챕터 세그먼트** (목록 위) | `Ch1 이름` … `Ch7 이름` — **글자색 = 그 챕터의 죄종 색**이고 고른 칸은 **테두리까지** 그 색이다(「기본은 무채색이되 챕터 줄은 죄종 색으로 덮는다」 · §5). **전 챕터가 선다**(잠긴 챕터도 눌러 볼 수 있다 · 「어디까지 가야 하는지가 보여야 한다」의 확장). 기본값은 **다음에 갈 곳**의 챕터(해금됐고 안 깬 첫 스테이지) · 없으면 마지막 해금 챕터 | **어느 챕터를 볼까.** 넘기면 고른 지역이 풀린다 |
| 스테이지 목록 | 화면 전폭 — **고른 챕터 하나**(4스테이지)만. **행은 제목 줄 + 부제 줄 둘뿐이라 전부 같은 높이**이고, **골라도 그 높이가 안 바뀐다**. **높이는 접이식이 있던 시절 그대로 못박혀 있다** — 걷어낸 줄만큼 행이 짧아지면 **배경 아트가 잘리고**, 그림은 스테이지를 알아보는 단서다(값은 [src/ui/README.md](../../src/ui/README.md) 크기 정책이 아니라 `style.css .zone`). 잠긴 스테이지도 보인다. 죄종 · Ch-스테이지 · 이름 · 클리어 표시 · dlvl · 예상 소요(분) · **스테이지 원소** · 배경 · 오른쪽에 「원정」 칩 | 행 클릭 = **이 지역으로 간다**(출정 창이 열린다). 고른 행은 칩과 테두리로 표시가 남는다 — **창을 닫아도 남는다**. 잠긴 행은 거절 → 플래시 |

창이 없는 상태(아무 지역도 안 누른 상태)가 이 화면의 **기본**이다. 한 번 고른 선택은 탭에 머무는 동안 남는다 — 전투를 마치고 편성으로 돌아오면 방금 간 지역이 그대로 골라져 있다.

**창 크기는 상태에 흔들리지 않는다** (2026-08-28 사용자 지시) — 열려 있는 한 언제나 같은 크기다. 흔들던 것 셋을 구조에서 걷어냈다:
- 폭은 **못박혀 있다** — 경고 줄의 글자 길이가 출정 칸 폭을 정하던 것을 격자가 걷었다(오른쪽 열은 적 구성의 내용 폭 · 왼쪽 열이 남는 폭 — 출정 칸은 그 오른쪽 열 폭을 받는다)
- 파티 없음 경고 → **줄은 항상 잡고** 글자만 있고 없다 — 전투 밖에 쓰러져 있는 영웅이 없으므로 경고는 이것 하나다
- 반복 원정 → 별도 줄이 아니라 **액션 버튼**. 옛 줄은 「런의 스테이지일 때만」 붙어서 칸이 커졌다 작아졌다

### 4-2. 관전 (재생기)

**정산은 출발 순간 끝났다.** 이 화면은 결과를 시간에 맞춰 보여줄 뿐이다.

| 영역 | 내용 |
|---|---|
| 헤드 | **한 줄** — 화면 전환 세그먼트 · **챕터 — 스테이지 이름** · **라운드 트랙**(1..9, 정예·보스 색) ─ (밀어내기) ─ **컨트롤 전부**. **라운드 n / 총 · 라운드 종류 · 경과 시계는 삭제**됐고, 비어난 그 자리로 컨트롤 줄이 통째로 올라와 **2줄 → 1줄**이 됐다. 목적은 **아레나와 그 아래 가방을 줄 하나만큼 위로 올리는 것** — 세로 예산 700 에서 가방 칸이 화면 아래로 잘리고 있었다 |
| 컨트롤 | **헤드 오른쪽 끝 한 묶음** — 배속 ×1 / ×2 / ×4 · 일시정지 · **건너뛰기** `│` **[배치]** · **[전투 로그] [누적 데미지]** — 배치는 **버튼 하나로 넓게↔나눔**, 뒤 둘은 **판을 고른다** (2026-09-03) |

XP 바는 두지 않는다 — XP 는 리포트가 정산한다. 세로 예산은 카드 두 줄 + 구분선 높이 — 아래에 가방이 오므로 줄였다 (2026-08-27). 피해/**빗나감**/치명/카드 팝업 (`dodge` 이벤트 = 적중 실패. 회피 스탯은 폐지됐다) |

| 결과 띠 | 재생 끝 → 승/패 띠 → [리포트로]. **반복 ON + 승리면 잠깐 세고 다음 원정 자동** |
| 가방 | 아레나 아래에 §6 가방 패널 그대로(**장비/재료 탭** · 분해 모드 · 비교 툴팁 · 클릭 = 장착). 장착 대상 = 현재 선택 영웅(머리에 이름). **접속 중 = 원정 전투 + 아이템 정리**를 한 화면에 — 정산은 출발 순간 끝났으므로 여기서 정리해도 이 전투는 안 바뀐다 (2026-08-27) |

| **런 목록** (왼쪽 열) | 최근 런이 위에서부터 한 줄씩 — **판정 색 점** · Ch-스테이지 이름 · 소요 · 지난 시간 · 골드 · 드롭 수. **열 높이는 오른쪽 상세가 정하고** 넘치는 줄은 **목록 안에서 스크롤**한다 | 줄 클릭 = 오른쪽 상세가 그 런으로 바뀐다. **새 런은 맨 위에 들어오며 저절로 골라진다**. 줄은 상한([balance.csv:report_keep])까지 쌓이므로 **목록은 높이를 정하지 않는다** — 목록이 정하면 런이 쌓일수록 두 열이 같이 길어져 화면 전체가 늘어난다 |
| 판정 (상세 머리) | **클리어 / 철수(전투불능 발생 · 시간 초과) / 패배(전멸)** · 스테이지 · 소요 · 사유 | |
| 획득 | 골드 · XP(1인당) · 라운드 n / 9 · 전투불능 수 · 카드 수 · **빗나감**. **여섯 칸은 자리가 고정**이다 — 값의 글자 길이에 옆 칸이 안 밀린다 | **가루 칸은 없다** — 처치가 가루를 안 뱉는다(item_design §5-3 확정 2026-09-09). 언제나 `0` 인 칸은 정보가 아니다 |
| **획득 장비** | **아이콘 격자** — 가방 칸과 같은 그림 · 같은 희귀도 테두리 · 같은 비교 툴팁 · 강화 단계는 모서리에 (§6). **가방에서 사라진 것**(분해했거나 다른 데로 갔거나)은 **흐린 빈 칸**으로 남는다 — 「그 런이 준 것」은 지난 사실이라 목록에서 빼지 않는다. **격자 자리는 한 줄 높이로 못박힌다** — 「없음」도 그 안에 서고, 한 줄을 넘치는 런만 그 칸 안에서 스크롤한다. 가방 초과로 버린 수는 **머리 줄 오른쪽**(분해 모드 옆) | **분해 모드 토글** 하나 — 켜야 클릭이 분해다(가방과 같은 문법 · 되돌릴 수 없는 행동은 두 번 누르게 한다 §3). 장비가 없는 런에도 **자리는 잡는다**(안 보일 뿐). 옛 행별 [분해] 버튼은 격자에 자리가 없다 |
| **기여 표** | **영웅 한 줄 · 수치 한 칸씩** — `영웅 / 가한 피해 / 받은 피해 / 처치`. 이름 칸은 **초상 + 오른쪽에 이름**(§5 얼굴 규격 · 크기는 이 칸이 정한다 — 상세는 세로가 남아 **띠 카드보다 작고 아이콘보다 큰** 크기로 든다). **영웅에게 일어난 일은 이 칸이 든다** — 이름 아래에 **레벨업** `▲ Lv.a → b`(오른 영웅만 · **레벨만** 적는다 — 기본 능력치 7은 캐릭터 탭이 든다 §6) · **전투불능이면 초상이 회색**(관전의 쓰러진 카드와 같은 문법). 쓰러진 것은 **그 런 안의 사실**이고 다음 런에는 다시 나간다(GAME_DESIGN §9 09-08) — 상태가 아니라 기록이라 색 하나로 끝난다. 줄 높이는 초상이 정하므로 표시가 붙어도 줄이 안 자란다. **줄은 파티 정원([balance.csv:party_size_max])만큼 늘 잡는다** — 빈자리는 빈 줄. 「가한」·「받은」은 **같은 폭 · 같은 모양**으로, 수치 + 묶음 안 점유율에 **막대가 그 칸의 배경으로** 깔린다 — **칸 전체가 100%(그 칸의 파티 합계)라 막대 폭이 곧 점유율**이고, 두 칸은 **색으로 갈린다**. 맨 아래 **합계** 줄(가한 · 받은 · 처치). 값은 **정산이 실어 보낸 집계**(`report.contrib`)이고, 관전의 누적 데미지 판(§4-2)과 **같은 값**이다.<br>**재생이 안 끝난 런이면 표가 그 재생 시각까지만 찬다** — 머리 오른쪽에 `재생 중 {경과} / {전체}`. 시계는 **앱이 들고**(§4 머리 · 일시정지·배속이 그대로 걸린다) 이 표는 그 시각을 읽어 그릴 뿐이라, 두 화면을 오가도 탭을 옮겨도 이어진다. 영웅 줄의 표시도 그 시각을 따른다 — 회색은 **쓰러지는 순간**, 레벨업은 **재생 끝**에 선다. 옛 줄을 고르면 정산본 그대로다 | 재생이 끝에 닿으면 **어느 화면에 있든 같은 규칙** — 반복 원정 ON + 승리면 다음 런이 출발하고 목록 맨 위에 새 줄이 선다 | 0 인 영웅도 줄을 지우지 않는다 — 「안 나갔다」와 「못 때렸다」는 다른 사실이다 |
| 카드 | 몬스터별 장수, 이번 카드로 도감 레벨이 올랐으면 ▲. **줄은 늘 선다**(없으면 「없음」) · **한 줄에서 끊고** 전체는 호버가 든다 | |
| 액션 | | **다시 출발**(고른 줄의 스테이지로) / **편성으로** / 반복 토글 |

**철수는 실패가 아니다** — 전투불능자가 하나 나오면 파티가 그 자리에서 돌아온다(base_expedition_design §1-1 귀환 룰). 루팅은 전량 보존되므로 판정 색은 패배(전멸)와 갈라 놓는다 — 같은 색으로 칠하면 "졌다"로 읽혀 중도 귀환이 성장 사다리라는 사실이 안 보인다.

**빗나감** — 파티 기준 `{빗나간 수} / {직격 시도 수} ({비율}%)`. 적중은 레벨 차 하나로만 정해지므로(§9-4) 이 칸은 **"레벨이 모자란다"의 전용 신호**다 — 패배 원인이 화력인지 자격인지를 가른다.
- 아무것도 안 빗나가도 `0 / N (0%)` 로 **항상 숫자를 찍는다** — 칸이 비면 "안 재고 있다"로 읽힌다
- "없음"은 `strikes` 가 아예 없는 리포트에만 — v3 이전 세이브에서 이관된 옛 리포트뿐이다 ([INTERFACE §2-7](INTERFACE.md))

**상세는 어느 런을 골라도 같은 크기다** — 런마다 생겼다 없어지는 줄을 두지 않는다. 영웅에게 일어난 일(레벨업 · 전투불능)은 **기여 표의 그 영웅 줄**이 들고, 나머지(획득 줄의 칸 · 장비 격자 · 기여 표 줄 수 · 카드 줄)는 **자리를 늘 잡는다**. 런 목록도 높이를 정하지 않는다(위 표).

**상세는 절마다 선으로 끊는다** — 덩어리가 끝나는 자리 셋(획득 줄 · 장비 격자 · 기여 표) 아래에 구분선이 선다. 표 안의 줄 구분보다 **한 단계 진하게** 그어 「줄 사이」와 「절 사이」를 가른다.

**상세는 「이 파티가 어땠나」만 든다** — 라운드마다 무엇을 잡았는지는 관전(§4-2)의 로그가 든다. 리포트가 답하는 질문은 **누가 얼마나 했나**이고, 그 답은 기여 표 하나가 낸다.

**기여의 0 은 두 가지다** — 집계가 아예 없는 옛 리포트(이관본)는 **자리만 잡고 안 그리고**(그 런은 영웅 줄이 없어 레벨업 · 회색도 안 선다), 집계가 있는데 값이 0 이면 **0 을 찍는다**. 「안 재고 있다」와 「못 때렸다」를 같은 빈칸으로 보여주지 않는다.

호출: `game.salvage` · `game.codexLevel` · `game.upgradeState` · `game.resolveBattle`(다시)

## 5. 공통 영웅 띠 (원정의 출정 창 · 캐릭터 탭 상단)

**두 자리**가 같은 띠, 같은 순서로 로스터를 보여준다 — 원정은 **출정 창 안**(§4-1 「캐릭터 선택」 칸), 캐릭터 탭은 **상단**이다. **카드 = 초상이 전체를 채우는 정사각** (2026-08-27) — 글자는 초상 위에 얹는 **위칸** 하나뿐이다. 유니크는 표시 구분. 빈 칸은 `+` 로 `roster_cap` 까지.

| 영역 | 보여준다 | 규칙 |
|---|---|---|
| 초상 | 카드 전체(정사각). **아트 없으면 빈 칸** | 얼굴 그림은 아래 **영웅 초상 규격** 그대로 — 관전·후보 카드와 같은 그림, 크기만 다르다 |
| 위칸 | 왼쪽: **지금 하는 일**(**원정 중** 주황 / **대기** 회색 — 둘뿐이다) · 오른쪽: 이름 | 초상 위에 반투명 띠로 얹는다. **한 줄 고정 — 이름은 절대 아랫줄로 안 내려간다**. 좁으면 **「하는 일」이 먼저 말줄임된다**(`On expedition` → `On expe…`) — 이름은 카드를 고르는 키이고 상태는 색이 이미 말한다 · 고정 px 없음 |

## 6. 캐릭터 탭 — "아이템 정리"

세로 3단: ① 영웅 띠 ② **같은 폭 · 같은 높이의 4칸** — 장비 / 기본 옵션 / 세부 옵션 1 / 세부 옵션 2 (2026-08-27) ③ 가방(전폭). **장착·해제·분해가 실제로 일어나는 곳.**

해고 창 — **한 줄 + 버튼 줄**. 문구는 사용자 지시 그대로다.

| 상태 | 창이 보여준다 | 버튼 |
|---|---|---|
| **장비를 걸치고 있다** | 「영웅을 해고하려면 모든 장비를 해제해야 합니다.」 | **[확인]** — 벗으러 가는 곳이 같은 화면의 페이퍼돌이라 창을 닫으면 바로 손이 닿는다 |
| 다 벗었다 | 「영웅을 해고합니다.」 | **[확인]**(위험 색) **[취소]** |

## 7. 스킬 창 (캐릭터 탭에서 연다)

> **탭이 아니라 창이다.** §6 「기본 옵션」의 [스킬 트리 열기]가 이 판을 띄운다. 대상 영웅은 **캐릭터 탭이 이미 고른 그 영웅**이라 창은 영웅 띠를 다시 그리지 않는다 — 탭이었을 때 필요했던 띠 한 벌이 통째로 없어진다.
> - **닫기는 세 갈래** — 닫기 버튼 · 판 바깥 클릭 · `Esc` (§2 창 레이어). 창은 화면을 덮으므로 나가는 길이 하나뿐이면 갇힌 것처럼 읽힌다
> - **창 안에서 랭크를 찍어도 창은 닫히지 않는다** — 찍기는 되돌릴 수 있고(초기화 무료·전액 환급) 연속으로 찍는 것이 정상 흐름이다. 화면은 통째로 다시 그려지지만 창은 열린 채 남는다
> - **되돌릴 때도 닫히지 않는다** — [ADR-0042](adr/0042-액티브-줄-세-열이고-셋째-열이-두-줄이다.md)도 같다. 찍기와 되돌리기를 번갈아 누르는 것이 배분의 정상 흐름이다
> - **아래 배치·규칙은 탭이던 시절 그대로다** — 판 셋이 나란히, 판 안에서 단계가 세로. 창으로 옮겨도 「한 화면에 전부」는 유지된다
> - **판 셋은 아래로 꽉 찬다** — 아랫변이 왼쪽 칸(포인트 · 액티브)과 나란히 맞는다. 판마다 아랫변이 다른 데서 끝나면 「나란히」가 위쪽에서만 성립하고 창 아래가 뜯긴 것처럼 읽힌다.<br>**칸이 같이 부풀지는 않는다** — 남는 자리는 판 안 아래쪽 여백이 된다. ⚠ **칸 높이는 2026-09-09 로 고정 62px 이 아니라 `aspect-ratio: 1`(정사각)** 이다 [사용자 지시] — 폭은 판 폭이 정하므로 높이도 그것을 따라간다(1600×800 에서 88px). 옛 고정값의 목적(칸이 판 높이를 나눠 가져 세로로 부푸는 것을 막는다)은 **줄이 안 늘어나는 규칙**이 이미 지킨다. 기획이 아랫줄을 채우면 그 여백부터 찬다

**한 화면에 전부** (2026-08-28 사용자 지시) — 왼쪽 한 칸(포인트 · 액티브 3) + **판 셋이 나란히**. 판 안에서는 **단계가 위에서 아래로 쌓인다** (2026-08-28 사용자 지시): 마스터리는 가지가 갈리는 트리가 아니라 쌓는 구조다(skill_design §3-4). **줄 하나 = 한 단계**이고, 줄 안의 칸이 그 단계의 노드다. **윗줄이 먼저 열리고 아랫줄일수록 늦게 열린다.**

- **「T1 · T2 · T3」는 화면에 쓰지 않는다** — 내부 어휘다. 도움말 탭도 마찬가지로 「맨 윗줄 / 그 아랫줄」로 부른다. 단계 번호를 지우면 그 번호가 들던 정보(해금 · 미작성)가 갈 곳을 잃으므로 **아래 두 줄이 그 자리를 대신한다**
- **잠금은 칸이 말한다** — 아직 못 여는 칸은 랭크 자리에 **필요 레벨**을 찍는다. 잠김을 숨기면 "없는 것"으로 읽힌다(§4-1)
- **미작성은 점선 프레임이 말한다** — 빈 칸에 「미작성」이라 적지 않는다. 설명 문구는 도움말 탭 전용이다(ui 원칙 4). **3줄 × 3칸 프레임은 비어 있어도 그린다** — 어디까지 갈 수 있는지가 보여야 한다(§4-1 스테이지 목록과 같은 이유)
- 칸은 **축 이름 · 현재 총합 · 랭크 n/최대** 셋을 찍는다. 랭크 0 이어도 `0 / 5` 와 `+0%` 를 찍는다 (§4-1 "값은 항상 찍는다"). 총합과 랭크는 **한 줄**에 둔다 — 칸을 낮게 유지하려는 것
- **축 이름과 단위는 `mastery_node.csv:stat` 에서 파생한다** — 접사 채널이면 접사 이름, 아니면 `combat_stat.csv`. 화면이 노드 이름 사전을 따로 갖지 않는다(가지면 CSV 와 갈린다)
- 칸 폭은 판 폭이 정한다(고정 px 없음). 긴 이름은 두 줄에서 잘리고 툴팁이 전문을 든다

## 8. 자원 탭 — 보내 놓고 기다리는 채취

> **** 옛 탭 셋(거점 · 탐험 · 선술집)이 여기 모였다. 근거와 대가는 §1.
> **선술집 · 제련소 · 상단이 자기 탭으로 나갔다** (§1 탭 7 → 9 — 탭 이름은 선술집 · **강화** · **상점**). 절 번호는 §8-1~§8-3 자리를 그대로 쓴다 — 문서 전체의 상호 참조를 흔들지 않기 위해서다.
> **탭 이름이 「마을」 → 「자원」이고 탐험이 자기 탭으로 나갔다** (§1 탭 9 → 10 · §8-4). 남는 것은 **1인 배치**뿐이다(같은 날 개정으로 **채광 · 채집 · 벌목** 셋 — 아래). 절 번호 §8-1~§8-3 은 **그대로 두고** 탐험을 **§8-4** 로 뒤에 붙인다 — 09-03 과 같은 이유(상호 참조를 흔들지 않는다).
> **세로 카드 3장 · 각 카드에 단계 7** — 가로 칸 목록이 **카드 3장**(**채광** · **채집** · **벌목**)이 되고, 카드마다 **단계 7줄**이 선다. 「광산」은 화면에서 **「채광」**(활동)으로 바뀌고 **「벌목」**은 신규 등재다.

**목록 → 고른 것의 속.** §4-1 원정 탭이 쓰는 문법과 **같다**(지역 목록을 누르면 그 아래에 편성 패널이 열린다). 새 문법을 만들지 않는다.

| 영역 | 보여준다 | 결정 |
|---|---|---|
| **파견처 단 3** | **채광 · 채집 · 벌목**. 단마다 이름 + **미착수 배지**(같은 줄) · **담당 능력치** · **인원**(1인) · **단계 7**. 세 단이 **`.main` 높이를 다 쓴다** | **단 클릭 = 그 파견처를 연다** |
| 단 안의 **단계 7** | **상자 일곱**이 단의 남은 세로를 균등 분할한다. 상자마다 순서 번호 · 단계 이름 · **산출물 이름**. **셋 다 속이 있다** [2026-09-10] — `mine_node`(광석) · `gather_node`(약초) · `log_node`(목재) | 없음 — 조회. 해금 조건은 안 그린다 |
| 열린 파견처의 속 | 셋 다 미착수 안내 (§11) — **제 높이만** 쓰고 단 아래에 선다 | 그 파견처의 결정 |

- **3장 나란히는 `.ng-row` 문법을 그대로 쓴다** — 시작 화면(§3)과 선술집 명단(§8-1)이 이미 쓰는 「같은 무게 3열」 격자다. 새 격자 문법을 만들지 않는다 — 세 파견처는 **같은 무게**이고, 하나를 크게 하면 그쪽이 정답처럼 읽힌다
- **세로 배분은 단이 갖는다** — 단 3 이 `1fr`, 미착수 안내가 `auto` 다(`.res-stack`). 안내는 늘어난다고 더 말해 주지 않고, 이 탭이 드는 것은 파견처 셋 × 단계 일곱이다. ⚠ **1600×800 에서 `.main` 이 약 25px 스크롤한다** — 상자 일곱의 최소 높이 합과 안내가 한 장을 그만큼 넘는다
- **단계 7칸은 세 단 모두 그린다** — 구조가 같다는 것이 읽혀야 한다. 채집 · 벌목에서 트랙을 지우면 「이 파견처는 단계가 없다」로 읽힌다 (§4-1 물리 스테이지의 원소 칸과 같은 판단)
- **한 단계가 상자다** — 단계는 레벨이 아니라 **선택지**로 확정돼 있다(base_expedition §2-1). 고를 것이 한 줄짜리 텍스트로 서면 목록으로 읽힌다. 상자 개수는 CSS 가 아니라 CSV 표가 정한다
- **클릭을 받는 것은 단 하나뿐이고, 그래서 단만 눌러 보인다** — 단계 상자는 단의 **선택 문법을 안 빌린다**(왼쪽 강조선 = 열렸다 · `--bg-tertiary` = 골라졌다). 상자는 **파인 칸**이라 단 안의 내용으로 읽히고, 손가락 커서와 hover 는 단만 든다. ⚠ 단계를 고르는 결정은 배치·산출 정산이 있어야 성립하고 그건 `game_logic` 에 없다 — 누른 뒤 일어날 일이 없는 손잡이를 먼저 그리지 않는다 → `/client`
- **상자 속 글씨는 본문 크기다** — 단계 이름 `--fs-md` · 산출물 `--fs-xs`. `--fs-2xs`(9px)는 「칸 안 초소형 라벨 전용」이라 상자처럼 큰 칸에 쓰면 안 읽힌다 (src/ui/README 글씨 크기)
- **표가 셋이 됐다** [2026-09-10] — 기획이 채집(약초) · 벌목(목재)의 산출 계열을 확정하면서 `gather_node.csv` · `log_node.csv` 가 서고, **화면은 표가 늘어난 만큼만 바뀌었다**(`POSTS` 에 필드 이름 한 줄씩). 셋이 같은 모양이라 조립이 산출물을 `yield*` 한 이름으로 모으고 **렌더러는 파견처별 분기를 갖지 않는다**. ⚠ **세 표 다 값은 ⚠임시**다 — 확정된 것은 계열 · 담당 능력치 · 단계 수이고 이름과 시간당 수량은 밸런스 작업에서 다시 잡는다 (GAME_DESIGN §9 09-10)
- **산출물은 이름만 찍고 시간당 산출은 안 찍는다** — 상자의 둘째 줄은 `mine_node.csv:ore_name_*` 다. `yield_per_hour` 를 같이 찍지 않는 이유는 **이름과 수치의 무게가 다르기 때문**이다 — 임시 표의 수치가 화면에 서면 확정으로 읽힌다 (§8-2 「없는 기능에 가짜 수치를 그리지 않는다」)
- **해금 조건은 그리지 않는다** — `mine_node.csv:tier` 는 **열리는 순서**만 정하고, 무엇으로 여는지(챕터? 재화? 배치 누적?)는 기획 백지다. 문턱 키가 없으면 문턱을 그리지 않는다 (§4-1)
- **들어오면 첫 단(채광)이 골라져 있다** — 목록만 있고 아무것도 안 열려 있으면 첫 화면이 빈다. 09-01 의 「선술집이 골라져 있다」가 들던 근거(고용이 숨는다)는 선술집이 탭을 되찾으며 소멸했고, 남는 근거는 빈 화면 하나다. 09-03 아침의 순서 개정(「지금 할 일 / 맡길 일」 갈림)은 탭 순서가 이어받았다 (§1)
- **미착수 칸도 그린다** — 어디까지 열리는지가 보여야 한다(§7 마스터리 빈 프레임 · §4-1 스테이지 목록과 같은 이유). 다만 **누르면 안내가 뜨므로** 「고장」으로 읽히지 않는다 — 누를 수 없는 칸을 그리지 않는다는 §8 옛 규칙(수색 칸)과 어긋나지 않는다
- **단을 눌러도 여는 것은 미착수 안내다** — 배치가 미착수라 아직 결정을 받을 자리가 없다. 단이 커져도 이 동작은 그대로다
- **인원 표기(「1인」)는 값이 하나뿐이어도 계속 찍는다** — 탐험이 나가면서 이 탭의 인원은 **전부 1인**이 됐다. 그래도 지우지 않는 이유는 ① 파견처 배치의 문법이 **1인이라는 것 자체가 결정**이라 칸에서 읽혀야 하고 ② 값이 하나뿐이라고 칸을 비우면 「안 재고 있다」로 읽히기 때문이다 (§4-1). 옛 「파티」 표기가 들던 일(문법 차이를 칸에서 읽힌다)은 이제 **탭 자체가** 한다 — 자원 탭은 1인, 탐험 탭은 파티다
- **담당 능력치를 칸에 찍는다** — 배치 결정의 근거가 그 하나다(base_expedition §2-2). **셋 다 값이 선다** [2026-09-10] — 채광 STR · 채집 **INT** · 벌목 **VIT**. 배정표는 화면이 갖지 않는다 — `hero_attribute.csv:dispatch` 를 거꾸로 읽을 뿐이라 **CSV 가 비어 있으면 `—` 가 나오는 것이 옳은 결과**이고, 이번에 값이 선 것도 화면이 아니라 **CSV 가 채워졌기 때문**이다
- **영웅 띠는 두지 않는다** — 로스터 전원(최대 `[balance.csv:roster_cap]`)이 목록 위에 한 줄로 서면 **정작 고를 것(파견처)이 화면 아래로 밀린다.** 이 탭에서 영웅을 고르는 자리는 파견처를 연 **다음**이고(배치 화면 — 미착수), 띠는 그때 그 안에 든다
- ⚠ **기획의 파견처 6 중 셋이 이 탭 밖에 있다** — 기획도 **파견처 6**(선술집 · 제련소 · 상단 · 채광 · 채집 · 벌목 — base_expedition §2-2)으로 개정됐고, 남은 것은 **화면 배치**의 흩어짐뿐이다. 그래서 **배치 줄은 나간 탭이 각자 들고 간다**(강화 탭의 배치 줄 — §8-2). ⚠ **「열린 파견처 수 = 동시 파견 상한」(§2-1)을 읽는 자리가 화면에 흩어졌다 — 09-04 개정으로 그 흩어짐이 탭 넷**(선술집 · 강화 · 상점 · 자원)**이 됐다.** 지금은 배치가 미착수라 드러나지 않지만, 배치가 구현되면 **상한과 현재 배치 수를 한 곳에서** 보여줄 자리가 필요하다. 그 자리를 어디에 둘지는 미확정 (→ `/game-design`)
- **「채광」은 기획에도 반영됐다** — 기획서가 「광산」을 폐기하고 **「효율형은 장소, 생산형은 활동」** 이라는 이름 축을 확정했다 (base_expedition §2-2 · GAME_DESIGN §9). ⚠ 다만 **데이터 키는 옛 장소 id 그대로다** — i18n 키(`dp.post.mine`)와 `hero_attribute.csv:dispatch` 의 값(`mine`). 기획이 **「어휘는 죽어도 데이터 키는 산다」**로 명시했으므로 키 리네임은 **하지 않는다**
- **벌목은 기획에 등재됐다** — 화면이 먼저 서고 기획이 뒤따랐다. 이 프로젝트는 기획이 화면보다 앞서는 것이 규칙이라 이번은 **의도된 역방향**이었고, 그 사실은 base_expedition §2-2 와 GAME_DESIGN §9 에 기록으로 남는다
- ⚠ **파견처가 6 이 되면서 능력치 배정이 모자란다** — 기획도 6 으로 개정됐지만(base_expedition §2-2) **채집 · 벌목 둘 다 담당 능력치가 미정**이다. **통화 비중복** 배치 규칙상 같은 능력치로 배정되면 **하나는 반드시 열등해진다**(어느 파티에나 같은 답이 나오면 배치 결정이 사라진다). 미배정 능력치 넷 중 셋이 이미 탐험 판정 후보라 재설계가 필요하다 — 미확정 (→ `/game-design` · GAME_DESIGN §10)
- ⚠ **단계 축은 기획에 들어갔지만 표가 채광뿐이다** — 기획이 **「파견처 안에 단계가 있고 챕터가 연다」**를 확정했고, 단계는 **레벨이 아니라 선택지**라 「레벨업 없음」과 공존한다(base_expedition §2-1). 남은 공백은 둘 — **채집 · 벌목의 단계 표가 없고**(산출물이 백지라 만들 수 없다) **단계를 여는 조건**이 미정이다(`mine_node.csv:unlock_chapter` 가 확정인지 자리채움인지 정해진 적 없다). 그래서 화면은 **순서만 그리고 해금 조건을 안 그린다** (→ `/game-design` · GAME_DESIGN §10)

호출: **없다 — 미착수.** 화면이 새로 읽는 데이터는 `D.mineNodes`(`mine_node.csv` — tier 순) 하나이고, 값을 **그대로 찍기만** 한다. 배치 · 산출 정산에 필요한 함수는 `game_logic` 에 아직 없다 → `/client`.

|---|---|---|
| 명단 | 후보 카드 `[balance.csv:tavern_candidates]`장 — 시작 화면(§3)과 **완전히 같은 카드**다. 영웅을 고르는 일이 두 화면에서 같고 초상이 그 판단의 절반이라, 명단에서도 같은 무게로 읽힌다. **같은 것은 규격과 비율이다** — 초상은 **카드 안쪽 폭의 44%** 라는 같은 규칙을 타고(ADR-0076 · 상한은 [src/ui/README.md](../../src/ui/README.md)), 카드 **폭 자체**는 시작 화면이 `.ng-wrap` 1060px 에서 잘려 선술집보다 좁다. ⚠ **대가는 세로다** — 카드가 ~120px 자라 **1600×800 에서 의뢰 줄이 한 장 아래로 걸리고 `.main` 이 약 65px 스크롤한다**(ko/en 같다 · src/ui/README 크기 정책). 더해지는 것은 고용 버튼뿐. **고용한 칸은 빈 칸으로 남는다** | **고용** (골드 · 로스터 정원 검사) |
| **수색 칸 — 대기** | 명단 **맨 오른쪽**, 후보 카드와 **같은 크기**의 칸. 제목 + 사양(인원 `[balance.csv:tavern_search_slots]` · 소요 `[balance.csv:tavern_search_hours]`) + **소문 한 줄**(이번에 만날 사람의 **죄종 칩 + 문장** — 숨기지 않는다) + **대기 영웅 칩 격자**(초상 · 이름 · **매력 값** · 죄종). 원정 파티는 안 뜬다 | 영웅 선택 → **[수색 보내기]** |
| **수색 칸 — 수색 중** | 보낸 영웅 · **남은 시간** · 「이 선택이 산 것」 한 줄(레어 확률 · 같은 죄종 확률 — 둘 다 `searchState` 가 낸다) · **열린 이야기 줄**(막마다 하나 · 소요 시간을 막 수로 균등분할해 하나씩 열린다) | **[취소]** |
| **수색 칸 — 만남** | `[balance.csv:tavern_search_meet_at_pct]` 지점부터 이야기 줄 **아래**에 선다 — 만난 사람의 죄종 칩 + 질문 한 줄 + 답 버튼 몇 개. **열쇠 답**(보낸 영웅의 죄종이 연 것)은 테두리가 다르고 **왜 열렸는지를 그 줄이 든다**. 답한 뒤엔 고른 답 + 깎인 값 한 줄로 접힌다 | **[답]** — 되돌릴 수 없고 한 번뿐 |
| **수색 칸 — 완료** | 마지막 이야기 줄 + **결과 후보 카드**(명단과 **같은 카드**). 결과 카드가 만남·이야기를 이고 있어 후보보다 긴데, **후보 카드는 거기 맞춰 안 늘어난다** — 제 높이에서 끊는다 (ADR-0077) | **[고용]**(명단과 같은 값) · **[돌려보내기]** |
| 도구 | 리롤 버튼 — 쿨다운이 끝났으면 **무료**, 남아 있으면 **골드 + 남은 시간** | **리롤** |
| **의뢰 게시판** | 도구 줄 다음, 패널 **맨 아래** — 제목(`nav.commission` 재사용) + 「미착수」 배지 + 카드 7장 가로 한 줄. 규격·데이터·규칙은 **§14 그대로** | **수락** — 지금은 미착수 안내 |

**명단은 저절로 갈리지 않는다** (base_expedition_design §2-4 확정 2026-08-26) — 자동 갱신이 없으므로 자리를 비운 사이 등장이 사라지지 않는다(방치형 계약). 화면이 그 계약을 읽히게 하는 방법은 둘이다.
- **빈 칸을 그대로 둔다** — 고용한 자리는 채워지지 않고 빈 칸으로 남는다. 명단이 통째로 갈리면 "고용이 곧 리롤"로 읽혀 쿨다운이 무의미해진다
- **버튼이 쿨다운을 든다** — 무료로 열려 있으면 비용을 적지 않고, 쿨다운 중이면 즉시 리롤 비용과 남은 시간을 함께 적는다. 남은 시간을 숨기면 "왜 골드를 내야 하는지"가 안 읽힌다

**수색은 판정을 하나도 안 그린다 — `searchState` 가 다 낸다** (2026-09-09 실동작). 화면이 아는 것은 넷뿐이다.
- **소문은 죄종을 숨기지 않는다** [ADR-0068] — 죄종 칩을 그대로 찍는다. 정답을 숨기고 고르게 하면 운이고, **보여준 다음** 고르게 해야 결정이다(삼국지 11 설전이 화제를 화면 중앙에 띄운 자리와 같다). 읽어야 하는 것은 죄종이 아니라 **어느 답이 그 죄종에 먹히는가**다
- **열쇠 답은 왜 열렸는지를 스스로 말한다** — 「{죄종} 전용 — 보내서 열렸다」. 열렸다는 사실만으로는 인과가 안 읽힌다(KoDP 가 조언자의 직위를 늘 보여주고 FTL 이 파란 글씨를 쓰는 이유)
- **답에 확인을 안 붙인다** — 잃는 것이 없다(할인 0 이 바닥이다). §3 이 걸리는 자리가 아니다
- **고르는 자리에 결정 입력이 보인다** — 칩이 **매력 값**과 **죄종**을 든다. 그 둘이 결과를 미는 전부이므로(매력 → 레어 확률 · 죄종 → 같은 죄종이 나올 확률) 다른 곳을 열어 보지 않고 고를 수 있다
- **산 것을 수색 중에 다시 찍는다** — 「레어 35% · 같은 죄종 50%」. 보내고 나면 왜 그 사람을 보냈는지가 화면에서 사라지는 것을 막는다 (§4-1 「값은 항상 찍는다」)
- **[돌려보내기]·[취소]에 확인을 안 붙인다** — §3 「되돌릴 수 없는 행동은 두 번 누르게 한다」가 걸리는 자리가 아니다: 버리는 것은 **아직 사지 않은 후보**라 플레이어가 치른 값이 없고(고용비는 수령할 때 나간다), 다시 보내는 데 드는 것도 시간뿐이다. 명단 리롤이 후보를 통째로 버리면서도 확인을 안 받는 것과 **같은 문법**이다 — 확인이 붙는 것은 해고처럼 **이미 산 것**을 지우는 자리다
- **결과 카드는 명단 카드와 같다** — 영웅을 고르는 일이 두 자리에서 같기 때문이다(명단 행의 근거와 같은 이유). 수색 전용으로 남는 것은 **[돌려보내기]** 하나뿐이다

호출: `game.tavernState` · `game.hire` · `game.tavernReroll` · **`game.searchState` · `game.searchSend` · `game.searchTake` · `game.searchDrop` · `game.searchAnswer`**. 명단은 시드+카운터라 저장하지 않아도 같은 사람들이 다시 나온다 — 저장하는 것은 **리롤 시각과 산 칸 번호**뿐이고, 수색도 같은 문법이다(저장하는 것은 **누가 · 언제 · 몇 번째**뿐이고 결과와 이야기는 시드가 재현한다). 의뢰 게시판은 아무것도 안 부른다 (§14).

### 8-2. 강화 탭 — 제련소 · 제작 · 강화 · **구현 — `+`강화만**

> **마을의 칸에서 자기 탭이 됐다** (§1 탭 7 → 9). **탭 이름은 「강화」(활동), 패널 머리는 「제련소」(장소 — `dp.post.forge` 유지)** — 시설 어휘를 바꾸는 결정은 기획 소관이라 화면이 앞서가지 않는다 (§1).

> 기획: [base_expedition_design.md §2-5](../game_design/base_expedition_design.md) · [item_design.md §1](../game_design/item_design.md).
>
> **실제로 도는 것은 `+`강화 하나다.** 옵션강화 · 제작 · 배치는 `game_logic` 에 없어 「미착수」 배지 + 안내(`todo.lead`)로 선다 — 기획에 미확정이 넷 남아 있다 (GAME_DESIGN §10 「강화 두 갈래의 미확정」). **없는 기능에 가짜 수치를 그리지 않는다.**

| 영역 | 보여준다 | 결정 |
|---|---|---|
| **배치 줄** | 배치된 영웅 1인(초상 · 이름) · **운** 값 · **품질** 계수. 비었으면 `배치 없음` + 기본 계수 | **[배치 변경]** → 배치 화면 |
| **세그먼트 2** | `제작` / `강화` | 어느 작업을 하는가 |
| 제작 — 목록 | 레시피 이름 · 부위 · ilvl · 필요 재료 요약. 재료가 모자란 줄은 **흐리게**(숨기지 않는다) | 레시피 선택 |
| 제작 — 패널 | **고정되는 옵션**(결과 미리보기) · 재료 `보유 / 필요` · 부족분은 빨강 | **[만들기]** |
| 강화 — 목록 | **착용 + 가방 전부** · 이름(희귀도 색) `+n` · 부위 · ilvl · `착용 중`/`가방` · 상한이면 `MAX` | 강화 대상 선택 |
| 강화 — **`+`강화** | 핍 `[balance.csv:equip_upgrade_max]`칸 · 베이스 능력치 **`현재 → 다음`** · **다음 비용(골드)** | **[강화]** |
| 강화 — **옵션강화** | 보유 옵션 전부(값 · **올린 횟수**) · **비용** | **[옵션강화]** |

- **비용은 누르기 전에 보인다** — 두 버튼이 **각자 자기 비용**을 든다. 모자라면 빨강. 얼마가 나가는지 모르고 누르는 것이 사고라는 규칙은 전술 리롤(§13-2)·옛 강화 툴팁과 같다
- **오른 옵션은 플래시로 말한다** — 옵션강화가 **무작위 1개**인 한 필수다. 안 알려주면 목록을 눈으로 대조해야 한다. 오른 줄은 잠깐 초록으로 남는다(플래시와 줄 강조가 같은 사건을 두 번 말하는 것이 아니라, 하나는 **무엇이** 하나는 **어디가**를 답한다)
- **상한은 칸에 적는다** — 핍이 `+`강화의 진행을 대신 말하고, 닿으면 버튼이 **`MAX`** 로 잠긴다(`ch.err.maxUp` 재사용). ⚠ **옵션강화 상한은 키가 미발행**이라 지금은 잠기는 자리가 없다 — 발행되면 핍 줄이 하나 더 붙는다
- **목록·머리의 아이콘도 아이템 그림이다** (§2) — 가방·페이퍼돌과 같은 규칙을 탄다. 방어구가 부위당 한 장인 것도 그대로라, 제련소 목록에서는 **다른 갑옷 셋이 같은 그림으로 늘어선다**(이름·ilvl 로 가른다)
- **착용 중인 장비도 강화된다** — §6 이 「가방 칸만 누를 수 있다」였던 것은 **착용 칸 클릭 = 해제**라 겸칠 수 없어서였다. 여기는 **목록**이라 그 제약이 없다 — 착용품은 태그만 단다
- **세그먼트 2 를 쓴다** — §13 연구 탭이 세로 2단을 고른 근거(둘이 배타가 아니다 · 자리가 이미 있다)가 여기서는 **반대로 선다**: 제작과 강화는 **배타적 작업**이고 양쪽 다 큰 목록을 요구해 세로로 쌓으면 화면이 두 배가 된다
- **미착수인데 규격을 적는 이유** — §11 의 「마을 탭의 칸 5」 중 이 칸만 기획이 화면까지 확정했다. 나머지 넷은 여전히 골격뿐이다
- **아직 못 그리는 것 둘** — ① `+`강화의 **「베이스 능력치 현재 → 다음」**: `upgradeState` 가 다음 값을 안 주고 렌더러는 공식을 갖지 않는다(ui 원칙 2). **현재 값만** 찍는다 ② 옵션의 **「올린 횟수」**: 세이브가 그 수를 안 든다. 둘 다 `game_logic` 쪽 일이라 [DEV_PLAN R34](DEV_PLAN.md) 에 있다
- **`+`강화의 결과 문구는 캐릭터 탭이 쓰던 키 그대로다**(`ch.upgraded` · `ch.upgraded.affix` · `ch.err.*`) — 같은 사건이라 문구를 새로 쓰지 않는다

호출: `game.upgradeState` · `game.upgradeItem` · `item.effective` · `item.groupOf`. 옵션강화 · 제작 · 배치는 부를 함수가 아직 없다 → `/client` ([DEV_PLAN R34](DEV_PLAN.md)). 도달 경로는 `?tab=forge` — 탭이 되면서 `?dev=forge` 는 삭제됐다(§10 의 `?dev=*` 는 클릭으로만 만들어지는 상태에 길을 내는 장치인데, 탭은 `?tab=` 이 바로 닿는다).

> **회복 표시 규칙** — 회복은 **전투 안에서만** 일어나고 **전투 밖으로 나오면 전원 회복 완료**다(base_expedition_design §1-1).
> **그래서 화면에 회복 상태 표시가 하나도 없다.** 아웃이 런을 넘지 않으므로(GAME_DESIGN §9 09-08) 런이 끝나는 순간 전원이 회복하고, 런은 출발 순간 통째로 정산되므로 **화면이 볼 수 있는 시점에는 아웃된 영웅이 존재하지 않는다.**
> 리포트의 전투불능 상자도 **이름만** 적는다 — 「그 출정이 끝났는가」라는 질문 자체가 사라졌다. **편성을 막는 것은 파티 0 하나다.**
> ⚠ 이 자리에 있던 **「화면에서 폐기된 것」 다섯 줄**(치료 타이머 · 부상 경고 · 부상자 줄 · 출정 아웃 표시 · 귀환 문구)은 **걷었다** — 폐기된 것을 규격에 적어 두지 않는다. 이력은 [SCREEN_CHANGELOG.md](SCREEN_CHANGELOG.md) 가 든다

### 8-3. 상점 탭 — 상단 · 기본상단 · 특수상단 · ⚠ 목업

> **마을의 칸에서 자기 탭이 됐다** (§1 탭 7 → 9). **탭 이름은 「상점」(활동), 패널 머리는 「상단」(장소 — `dp.post.trade` 유지)** — 강화 탭(§8-2)과 같은 갈림이다. 도달 경로는 `?tab=shop` — `?dev=trade` 는 삭제됐다(§10).
> 기획: [base_expedition_design.md §2-6](../game_design/base_expedition_design.md). **수치가 하나도 확정되지 않았다** — 방문 주기 · 체류 · 가격 · 재고가 전부 미정이라(GAME_DESIGN §10 「상단의 수치 전부」) 이 화면의 숫자는 **전부 거짓**이고 `mock.js:TRADE` 가 든다. 누르면 미착수 안내만 뜬다.

**세로 2단** — 위 기본상단 · 아래 특수상단.

| 영역 | 보여준다 | 결정 |
|---|---|---|
| **기본상단** (위) | **고정 목록** — 품목 이름 · 수량 · **가격(골드)** · 살 수 없으면 가격이 빨강. 「언제 가도 같다」가 읽혀야 하므로 **재고 타이머를 안 그린다** | **[사기]** |
| **특수상단** (아래) | **방문 상태 줄이 머리에 선다** — 와 있으면 `체류 남은 시간`, 없으면 `다음 방문까지`. 그 아래 굴려 나온 재고 | **[사기]** |

- **세로 2단을 쓰는 이유는 §13 연구 탭과 같다** — 둘은 **배타가 아니다**(기본상단은 늘 열려 있고 특수상단은 그 위에 얹힌다). 세그먼트로 가르면 상주하는 창구가 클릭 뒤로 숨는다. 제련소(§8-2)가 세그먼트인 것과 갈리는 지점이 여기다 — 그쪽은 제작과 강화가 **배타적 작업**이었다
- **방문 상태 줄은 비어 있어도 자리를 지킨다** — 「지금 아무도 없다」와 「이 칸이 고장났다」가 갈려야 한다 (§4-1 「값은 항상 찍는다」)
- **「놓쳤다」를 화면이 만들지 않는다** — 기획의 계약 규칙 셋(§2-6)이 화면에 걸리는 자리다. **지나간 상인을 세지 않고**(「놓친 방문 3회」 같은 표기 금지), 남은 시간은 **재촉이 아니라 정보**로 쓴다 — 빨강·깜빡임·카운트다운 강조를 붙이지 않는다
- **장비는 안 판다** — 목록에 장비 부위 아이콘이 뜨면 안 된다 (기획 §2-6 · §5 스코프 가드)
- ⚠ **수치가 정해지면 목록·가격은 CSV 로 가고 `mock.js:TRADE` 는 삭제한다** — 연구 섹션(§13-1)이 걸어 둔 길과 같다 (DEV_PLAN 부채)

호출: **없다 — 목업.** 구현 시 필요한 것은 방문 상태(시계) · 재고 굴림 · 구매 정산이고 셋 다 `game_logic` 에 없다 → `/client`.

- **아트 = `src/assets/art/backgrounds/explore_chapter_1.webp`** — 챕터 1(분노 · 불타는 전장 — `chapter.csv:1`)의 지형을 담은 **신규** 아트다. 계승 배경 4장과 달리 **픽셀아트가 아니라서 `image-rendering: pixelated` 를 걸지 않는다**(§5 얼굴이 스타일마다 갈리는 것과 같은 갈림). 챕터마다 한 장이 목표지만 **지금 있는 것은 챕터 1 하나**라 탭은 그 하나를 고정으로 건다 — 진행 챕터를 따라가는 규칙은 지도의 알맹이와 함께 정해진다 (→ `/game-design`)
  - **1판은 「지옥」으로 그려져 폐기했다** — 챕터 1 은 지옥이 아니라 **아우레아(인간의 땅)** 이고, 불은 사탄의 군세가 지른 것이지 땅이 용암인 게 아니다(`story/prologue.md` 씬 4·5 — 바알이 추락해 인간 마을이 거뒀고 그 마을이 습격당한 것이 챕터 1 진입 계기다). 2판은 **불타는 농지 · 강 · 침엽수림**으로 다시 그렸다
  - **담은 자리 일곱** — 가운데 **마을**(귀환·회복 지점 — `base_expedition_design.md` §1-1) · 원정 스테이지 넷(`stage.csv` 101 파멸의 진영 = 마귀 야영지 / 102 핏빛 교전지대 / 103 원한의 묘지 / **104 사탄의 제단** — 유일하게 불의 고리를 두르고 가장 크다) · **동굴 둘**(왼쪽은 `mine_node.csv:ember_pit` 잿불 갱도 = 광석 수레가 선 갱도 · 오른쪽은 **이름 없는 자리**). ⚠ **동굴 오른쪽에 이름을 안 붙인 것이 의도다** — 탐험 노드가 앉을 자리인데 기획이 백지다
  - ⚠ **원정 스테이지 넷이 탐험 지도 위에 서 있다** — 탐험 ≠ 원정은 용어까지 분리 확정인데(base_expedition §3-1) 한 장이 둘을 다 담는다. **클릭을 안 받는 동안은 「지역 지도」로 읽혀 문제가 안 된다**. 노드에 손잡이가 붙을 때 갈라야 하는지 다시 본다 (→ `/game-design`)

**초상이 카드의 주인이다** (2026-08-30 개정 — 사용자 지시). 도감은 **모으는 화면**이고 모으는 대상은 몬스터다. 종전 카드는 초상이 38px 칩이라 수치가 주인공이었고, 그 크기에서는 몬스터가 서로 구분되지 않았다 — 「무엇을 모으고 있나」가 안 읽히면 도감이 표가 된다.
- **크기는 초상이 정한다** — 카드 높이 = 초상 높이. 영웅 띠 · 관전 유닛 카드와 같은 규칙이다(§5 · §4-2 「초상은 카드에서 가장 큰 칸이고 본문 높이를 정한다」)
- **원형 마스크는 유지한다** — 몬스터는 원형, 영웅은 네모라는 구분이 화면 전체에 걸려 있다(편성 화면의 구성 칩도 원형이다). 초상이 커져도 그 구분은 안 바꾼다
- **여전히 한 챕터(4스테이지)가 한 화면**이다 — 세로는 한 장의 **800px** 이다([src/ui/README.md](../../src/ui/README.md) 크기 정책). **이 제약이 초상 크기의 상한을 정한다**: 더 키우면 스테이지 4가 접힌다
  - **1600×800 에서 ko/en 둘 다 스크롤 없이 선다** — 챕터 세그먼트(Ch1~7)가 영어에서도 한 줄이다
- **이름이 줄어들고 장수는 안 줄어든다** — 카드 수(`0장` / `0 cards`)는 줄바꿈 금지, 폭이 모자라면 **이름이 말줄임**된다. 영어에서 숫자가 두 줄로 접히면 그 카드만 높이가 달라져 줄이 어긋난다
- **안 켜진 레벨 핍도 보인다** — 「몇 번 더 올릴 수 있나」가 도감의 목표치라, 빈 칸이 안 보이면 목표가 안 보인다
- 아트가 없는 몬스터는 **글자 없는 죄종 색 원판** — 커진 자리에서도 같다 (`monster.csv:face` · 이니셜 폐지 2026-09-06 · §5)
- **초상 툴팁이 파일명이다** — 옛 이미지 도감의 「몬스터 초상」 묶음이 이 화면에 흡수되며(§1) 타일이 들고 있던 파일명 줄만 여기로 옮겼다. 같은 그림을 한 탭에서 두 번 그리지 않으면서 「어느 파일이 안 들어왔나」는 남긴다. 아트가 없으면 종전대로 `face.noArt` 가 뜬다

**잠금을 그리지 않는다 — 전부 보인다** (2026-09-06 개정 — 사용자 지시). 종전에는 미해금 스테이지의 몬스터가 이름 `???` · 점 하나짜리 초상 · 처치/다음 레벨 줄 공백으로 나왔고, 챕터 전체가 잠기면 죄종 대신 「미해금 챕터」 안내가 섰다. 지금은 **해금 여부와 무관하게 모든 챕터 · 스테이지 · 몬스터를 그대로 그린다** — 도감이 부르던 `game.stageUnlocked` 는 사라졌다.

| 얼굴 스타일 세그먼트 | `FACE_STYLES` 폴더 이름 — **캐릭터 세그먼트에서만** 선다 (몬스터 세그먼트에도 같은 것이 선다 — §9) | 얼굴 스타일 (전역) |
| 그룹 머리 | 그룹 이름 · 폴더 경로 · 장수. **캐릭터 · 스킬은 직업 하나가 묶음 하나**(`class.csv` 행 순 · 「{직업} 초상」 · 「{직업} 스킬」) — **빈 묶음은 안 그린다**(초상 0장인 직업 · 확장 직업 둘이 여기서 빠진다) | |
| 격자 | 캐릭터 · 아이템은 **고정 크기**, 스킬은 **조밀 격자**(좁은 여백 · **그림 칸 고정 48px**) — 스킬은 **직업 다섯이 한 장 안에 다 선다**(묶음마다 한 줄 · ko/en 스크롤 없음 · 값은 [src/ui/README.md](../../src/ui/README.md)). ⚠ **캐릭터 세그먼트는 아직 한 화면이 아니다** — 초상은 크게 보는 것이 목적이라 같은 처방을 안 썼다 | 없음 |
| 타일 | 그림 · 쓰임 이름(**초상 이름** · 무기군 · 부위 · 스킬 이름 — **직업은 안 적는다**, 그룹 머리가 이미 말한다) · 파일명(**스킬 · 무기 베이스는 확장자를 뗀다** — 이름이 길어 칸에서 두 줄이 된다) · **스킬은 툴팁**(마우스를 올리면 스킬 카드) | 없음 |
| 아이템 세그먼트의 묶음 | 무기(무기군 8) · **무기 베이스(양손검 7 — 「id 대기」)** · 방어구·장신구 · 빈 칸 실루엣 | 없음 |
**초상은 이름을 든다** [2026-09-10] — 캐릭터 세그먼트의 타일 이름은 **그 초상의 이름**(`mock.js:HERO_FACE_NAMES` — 「막시무스」 · 「검황」 · 「한니발」 …)이고, **이름이 안 붙은 초상만 풀 번호**로 남는다. **영웅의 이름이 아니다** — 굴려서 이 얼굴을 받은 평범한 영웅은 제 이름(`hero_name.csv` 풀)을 그대로 쓴다. 이름을 박아 두는 이유는 **나중에 유니크가 그 얼굴을 가져가기 위해서**이고, 그 개체 테이블은 아직 없다 ([ADR-0082](adr/0082-초상은-이름을-든다.md)). 번호는 안 사라진다 — 셋째 열의 파일명(`hero_warrior_1.png`)이 계속 든다.

**무기 베이스 묶음은 재고를 편다** [2026-09-10] — 그림은 `icons/items/unused/sword2h/` 에 있고 **파일명이 id 가 아니다**(`weapon_base` CSV 미발행 · [item_design.md](../game_design/item_design.md) §1). 이름도 CSV 가 아니라 `i18n:ix.b.*` 가 든다 — 둘 다 그 테이블이 서면 걷는다. **실제 양손검 개체는 이 7장 중 하나를 든다**(§2) — 여기는 `uid` 없이 부르므로 **7장이 전부** 서고, 그것이 이 묶음의 쓸모다(어느 개체에 무엇이 붙었는지가 아니라 **무엇이 그려져 있는지**를 본다). ⚠ **7장은 40px 실측을 통과 못 했다**(경계밀도 17~26% vs 합격선 6~16% — 날이 가늘다) — 재발주 전까지는 임시본이다 ([art/README.md](../../src/assets/art/README.md) 「양손검 베이스 7종」).

호출: **스킬 세그먼트의 툴팁만** `skill.defs` · `skill.tagsOf` · `skill.previewOf` — `tip.js:skillTipCard` 를 그대로 부르므로 캐릭터 탭 · 관전과 같은 계약이다 (§4-2 · [INTERFACE.md](INTERFACE.md) §2). 영웅 맥락이 없어 슬롯이 미는 숫자는 **식만** 찍힌다(§2 「스킬 설명창 규격」 값 없음). 나머지 셋은 **없음** — 조회 화면이고 목록의 출처는 `mock.js` 상수와 `skill.csv` 뿐이다 (몬스터가 빠지며 `monster.csv` 도 이 절에서는 안 읽는다 — §9 가 읽는다).

## 12. 도움말 탭

**목적** — 규칙·설계 근거·미구현 안내를 **한 곳에 모은다.** 인게임 패널은 숫자·상태·오류·버튼·툴팁만 남긴다 (2026-08-26 사용자 지시). **옵션 줄의 조건·규칙 주석도 여기로 온다** — 「+3강에서 옵션 상승」 같은 문구를 옵션 표기에 붙이지 않는다. 옵션은 이름 + 값만 (§2).

**한 페이지 스크롤.** 읽기 폭 상한만 잡고 장식은 없다. 결정 없음 — 조회 화면.

| 영역 | 내용 |
|---|---|
| 제목 | 도움말 |
| 점프 세그먼트 | 섹션 버튼 — 누르면 해당 `<h2>` 로 스크롤 |
| 섹션 (`<h2>`) | **탭 순서를 따른다** — ① 원정 ② **캐릭터** ③ **스킬** ④ **선술집** ⑤ **자원** ⑥ **탐험** ⑦ 연구 ⑧ 도감 ⑨ 새 게임. 마을 섹션이 **자원**과 **탐험** 둘로 갈렸다(§1 탭 9 → 10) — 벤치(파견 대기)는 자원으로, 탐험 묶음은 자기 섹션으로. **캐릭터가 앞으로 온 것은 탭 순서를 그대로 따른 결과**이고, **스킬**은 탭을 잃고도 섹션으로 남아 캐릭터 바로 뒤에 선다 — 게임의 개념이지 탭 이름이 아니고, 여는 자리가 캐릭터 탭 안이라 이웃한다. **강화·상점 탭은 여전히 섹션이 없다** — 도움말로 옮겨 둔 문구가 아직 없다(패널의 미착수 배지가 그 일을 한다) |
| 소제목 (`<h3>`) | 패널 이름 그대로 + (있으면) 그 패널이 쓰던 부제 |

| 섹션 | `<h3>` 묶음 |
|---|---|
| 원정 | (머리글) 전투 파티는 한 팀 · 파티 · 벤치 · 원정 지역 · 반복 원정 · 전투 관전 · 리포트(전투불능 포함) |
| 캐릭터 | 장비 · 접사 죄종 · 기본 옵션 · 세부 옵션 · 아이템(가방) |
| 스킬 | (머리글) 트리 격자 규약 · 스킬 포인트 · 액티브 슬롯 · 죄종 트리 · 마스터리 · 전직 트리 |
| 선술집 | 영입 후보(등급) · 후보 교체(리롤) · 유니크 영웅 · 의뢰 |
| 자원 | 벤치(파견 대기) |
| 탐험 | 탐험 (§8-4) |
| 도감 | 몬스터 도감 |
| 새 게임 | 첫 파티 |

**텍스트 출처 = 기존 i18n 키.** 도움말은 문구를 새로 쓰지 않는다 — 인게임에서 걷어낸 `*.note` / `*.sub` / `*.hint` 를 **같은 키 그대로** 렌더한다. 수치 파라미터(`{n}` `{cap}` `{e}` `{b}` `{pct}` 등)도 인게임과 같은 값(`D.balance.*` · `D.eliteRounds` · `D.bossRound` · `D.codexLevels`)을 넣는다. 죄종·직업이 들어가는 스킬 트리 제목은 **현재 선택된 영웅**의 값을 쓴다.

새 키는 넷뿐 — `nav.help` · `help.title` · `help.newgame`(섹션 제목용) · `help.exp.party` / `help.exp.bench`(인게임에서 숫자만 남기며 원문이 옮겨온 자리).

## 13. 연구 탭 — 연구 + 파티 전술

> **연구 탭은 「연구」 + 「파티전술」 두 섹션이다** (GAME_DESIGN §9 08-31). **연구**(스킬 노드·레시피 해금 · 채집 재료 소모 · **영웅 파견 없음**)는 비용 곡선·해금 순서가 미정이다.

**왜 이 모양인가 — 결정 기록**

- [ADR-0006](adr/0006-두-섹션은-세그먼트가-아니라-한-화면에-세로로-선다.md) 두 섹션은 세그먼트가 아니라 한 화면에 세로로 선다 — 2026-09-01

### 13-1. 연구 — ⚠ 목업

> **⚠ 화면에 보이는 연구 항목은 전부 목업이다.** 기획이 이름도 비용 곡선도 해금 순서도 안 정했으므로(GAME_DESIGN §10) **자리와 읽는 법만 먼저 세운 것**이다. 데이터는 `ui/mock.js:RESEARCH` 에 있고 **CSV 로 가지 않았다** — 확정 전에 SSOT 를 만들면 그 CSV 가 기획을 앞질러 굳는다. 스킬 트리 목업(`SKILL_TREES`)이 같은 길을 갔다가 실동작이 오면서 삭제됐다. **부채로 등재한다** (DEV_PLAN §4).

| 영역 | 보여준다 | 결정 |
|---|---|---|
| 진척 | 완료 n / 전체 · **가진 재료**(⚠ 채집 재료는 이름도 자원 칸도 아직 없다 — 목업이 숫자를 지어낸다) | — |
| 칸 (완료) | 이름 · 해금한 것 한 줄 · **완료** 표시 | — |
| 칸 (열림) | 이름 · 해금할 것 · **비용**(재료 + 골드) | **연구** — 목업이라 누르면 미착수 안내 |
| 칸 (잠김) | 이름 · **선행 연구 이름** — 비용은 안 보인다 | — |

- **파티전술 칸(§13-2)과 같은 생김새를 쓴다** — 한 탭 안의 두 섹션이 서로 다른 카드 문법을 쓰면 같은 화면으로 안 읽힌다. 다른 것은 칸이 답하는 질문뿐이다(전술 = 「지금 켜졌나」 / 연구 = 「살 수 있나」)
- **비용은 잠긴 칸에 안 찍는다** — 「값은 항상 찍는다」(§4-1)의 예외다. 잠긴 연구의 비용은 **아직 굴려지지 않은 값**이라 찍으면 확정으로 읽힌다. 대신 **선행 조건**을 찍는다 — 그게 잠긴 칸이 답해야 할 질문이다
- **누르면 미착수 안내** — 문구는 새로 쓰지 않고 `todo.lead` 를 그대로 부른다 (§11 · §8-1 수색 버튼과 같은 처리)

### 13-2. 파티 전술

**목적** — 파티 단위 「조건 → 효과」를 고르는 자리. **카드를 줍는 화면이 아니다**: 칸은 합산 레벨이 열고, 칸의 내용은 재화로 간다 ([tactic_card_design.md §5](../game_design/tactic_card_design.md)).

**한 화면에 전부.** 세로 2단 — ① 진척 줄(합산 레벨 · 열린 칸 수) ② 칸 `[tactic_slot.csv]` 개의 격자. 영웅 띠는 **두지 않는다** — 전술은 영웅 하나가 아니라 편성 전체에 걸리므로 고를 영웅이 없다 (§5 의 띠가 붙는 탭 목록에 연구가 없는 이유).

| 영역 | 보여준다 | 결정 |
|---|---|---|
| 진척 | **합산 레벨**(로스터 전원의 레벨 합) · 열린 칸 n / 전체 · 다음 칸까지 남은 레벨 · **잠근 칸 n** ⚠ | — |
| **리롤 줄** ⚠ | 버튼 하나 — **전체 리롤 + 비용.** 비용은 잠근 칸 수가 정하고 **버튼에 적는다**. 굴릴 칸이 없으면(전부 잠금) 꺼진다 | **전체 리롤** (골드) |
| 칸 (열림) | 칸 번호 · **등급 칩**(일반 · 매직 · 레어) · **조건 문장 + 카운터 「지금 / 필요」** · **효과**(축 이름 + 값) · 켜짐/꺼짐 · **잠금 토글** ⚠(구현 전) | **잠그기 / 풀기** (무료) |
| 칸 (잠김) | 칸 번호 · **필요 합산 레벨** — 내용은 안 보인다 | — |

**규칙**

- **잠긴 칸도 그린다** — 칸 수는 CSV 행 수이고 프레임은 항상 `[tactic_slot.csv]` 행만큼 그려진다. 어디까지 열리는지가 안 보이면 "없는 것"으로 읽힌다 (§4-1 · §7 과 같은 이유)
- **조건은 카운터를 달고 나온다** — 「분노 접사 3개 이상」 옆에 지금 값 `2 / 3`. 조건이 참인지 **화면에서 세어 볼 수 있어야** 하고, 안 보이면 함정이다 ([tactic_card_design §4](../game_design/tactic_card_design.md) 「화면 요구」). 카운터의 출처는 `game.tacticState` 하나다 — 렌더러가 파티를 세지 않는다
- **켜짐/꺼짐이 칸의 첫인상이다** — 꺼진 칸은 흐리게, 켜진 칸은 죄종 색이 아니라 **강조 테두리**로. 효과 수치는 켜짐과 무관하게 **항상 찍는다** (§4-1 "값은 항상 찍는다")
- **등급 칩은 칸 번호 옆에 선다** — 등급이 가르는 것은 **값 하나뿐**이고 조건도 축도 그대로다 ([tactic_card_design §5-5](../game_design/tactic_card_design.md)). 그래서 조건 줄이나 효과 줄이 아니라 **칸의 머리**에 붙는다 — 「이 칸이 무엇이냐」가 아니라 「얼마나 잘 굴렸냐」이기 때문이다. 안 보이면 리롤의 목표 절반(조건 적합 + **등급**)이 화면에서 사라진다 ([tactic_card_design §4](../game_design/tactic_card_design.md) 「안 보이면 함정」)
  - 색은 아이템 희귀도의 **파랑(매직) · 노랑(레어)** 을 빌리고 일반은 무채색이다. ⚠ **축은 다르다** — 전술 등급은 아이템 희귀도와 별개 SSOT 이고 이름만 같다(§5-5). 이름을 이미 빌린 마당에 색까지 갈라 놓으면 같은 단어가 화면에서 두 색으로 나온다
  - **첫 배정은 언제나 일반**이라 새 칸이 열리면 무채색으로 들어온다 — 칸이 늘 때마다 굴릴 이유가 같이 생기는 것이 화면에서 읽힌다
- **효과의 축 이름과 단위는 `tactic_option.csv:stat` 에서 파생한다** — 접사 채널이면 접사 이름, 아니면 `combat_stat.csv`. 마스터리 칸(§7)과 같은 규칙이고, 화면이 옵션 이름 사전을 따로 갖지 않는다
- **리롤은 한 번 클릭** — 되돌릴 수 없지만(§3) 잃는 것이 정해진 비용 하나이고 결과는 즉시 다시 굴릴 수 있다. 다만 **비용을 버튼에 적는다** — 얼마가 나가는지 모르고 누르는 것이 진짜 사고다
- **같은 옵션이 다시 나오지 않는다** — 잠긴 칸의 옵션 · 굴리기 직전에 들고 있던 옵션 · 이번에 뽑은 것은 후보에서 빠진다(`game.rerollTactic`). 돈을 내고 아무 일도 안 일어나는 경우를 구조로 막는다

호출: `game.tacticState` · `game.rerollTactic` · **`game.toggleTacticLock`** ⚠(신설 · 구현 전) — **연구 섹션은 아무것도 부르지 않는다**(목업이라 부를 계약이 없다 · §13-1)
오류 → 플래시: `rs.err.<code>` (`gold` 골드 부족 / `locked` 잠긴 칸)

## 14. 의뢰 게시판 — 선술집 탭 안 · ⚠ 목업

> **의뢰 탭은 폐지됐다** (§1 탭 7 → 9) — 게시판이 **선술집 탭의 맨 아래 섹션**(§8-1 · 영입 후보 아래)으로 들어갔다. 이 절은 **게시판 자체의 규격**을 계속 든다 — 자리는 §8-1, 규격은 여기. ⚠ 탭과 함께 「의뢰 탭 관전」의 자리도 비었다 — 약탈(실시간 전투) 구현 시 관전이 어디 서는지는 미확정 (§1).
> 기획: [base_expedition_design.md §1-3](../game_design/base_expedition_design.md). **2026-09-03 사용자 확정으로 종류가 4종으로 좁혀졌다** — 약탈 · 보호 · 사냥 · 파견 의뢰. 옛 셋(보스/던전 지목 · 탐험 의뢰 · 수색 의뢰)은 버렸다.
> **데이터는 CSV 두 표다** — `commission_kind.csv`(**종류 4종 · 확정 기획**)와 `commission.csv`(**게시판 행 · ⚠임시 자리채움**). 층을 가른 이유는 둘의 지위가 달라서다 — 종류는 결정이고 행은 아직 굴림이 없어 손으로 박아 둔 것이다.
> **수치는 하나도 확정되지 않았다** — 동시 수락 상한의 개수 · 보상 · 명성 폭 · 쿨다운이 전부 미정이라 `commission.csv` 의 목표·보상은 **전부 임시**다(`description_kr` 에 ⚠임시로 표기 · `mine_node.csv` 와 같은 처지). 누르면 미착수 안내만 뜬다.

**게시판 한 판.** 의뢰 카드가 **가로 한 줄로 7장** 선다.

| 영역 | 보여준다 | 결정 |
|---|---|---|
| 게시판 | 의뢰 카드 — **가로 한 줄.** **칸 수 = `commission.csv` 행 수**(지금 7장)라 화면이 개수를 박지 않는다 (`tactic_slot` 과 같은 문법) | **수락** — 지금은 미착수 안내 |
| 카드 | **종류 배지**(약탈 · 보호 · 사냥 · 파견 의뢰) · **어떻게 도는가** 한 줄 · 목표 · 보상(골드 · 명성) · [수락] | |

**규칙**

- **일곱이 언제나 한 줄에 다 보인다** — 「7장이 가로로 쭉」이 이 화면의 형태다. 줄바꿈도 **가로 스크롤도 쓰지 않는다** — 마지막 장이 스크롤 뒤에 있으면 「7개가 쭉」이 아니다. 카드는 폭이 고정된 것이 아니라 **줄을 나눠 갖는다**(하한 폭에서 한 장 ≈ 140px). 그래서 카드 안의 글은 접히는 것을 전제로 쓴다
- **종류가 카드의 첫인상이다** — 넷은 하는 일이 완전히 다르다. **세는 형**(사냥 · 파견 의뢰)은 받아두면 평소 활동이 알아서 채우고, **가는 형**(약탈 · 보호)은 파티를 짜서 보낸다. 그래서 카드는 이름보다 **종류 배지**를 먼저 든다
- **「어떻게 도는가」를 한 줄로 적는다** — 넷의 시간축이 전부 다르다: 약탈 = 실시간 전투(관전) · 보호 = **오프라인 전투**(리포트 재생 · GAME_DESIGN §9 09-03) · 사냥 = 원정에서 처치 수를 센다 · 파견 의뢰 = 파견이 채운다. 배지만으로는 이 차이가 안 읽힌다
- **수락 상한을 숫자로 안 찍는다** — 상한을 둔다는 것은 2026-09-03 확정이지만 **개수가 미정이고 CSV 키가 없다.** 없는 문턱을 화면이 지어내지 않는다 (§4-1 · 옛 §8-1 도박장 줄과 같은 처리 — 그 줄은 09-03 삭제됐다)
- **진행 중 목록도 아직 안 그린다** — 수락한 의뢰가 어디 서는지는 상한·유한성이 정해진 뒤다. 지금 잡는 것은 **게시판 한 줄**뿐이다
- **누르면 미착수 안내** — 문구는 새로 쓰지 않고 `todo.lead` 를 그대로 부른다 (§11 · §8-1 수색 버튼과 같은 처리)

- **종류의 이름과 「어떻게 도는가」는 i18n 이 아니라 CSV 다** — `commission_kind.csv` 의 `_kr`/`_en` 쌍이고 화면은 `L()` 로 푼다. i18n 에 남는 것은 데이터가 아닌 화면 라벨 둘(`cm.fame` · `cm.accept`)뿐이다 — **mock 과 CSV 가 겹치면 CSV 만 둔다**

호출: **없다 — 데이터만 CSV 로 서 있고 기능이 없다.** 구현에 필요한 것은 의뢰 굴림 · 수락/진행 상태 · 처치 카운터(세는 형) · 명성 정산이고 **넷 다 `game_logic` 에 없다** → `/client`.
