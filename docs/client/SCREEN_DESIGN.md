# SCREEN_DESIGN — 화면 설계

> **무엇을 보여주고 어떤 결정을 받는가.** DOM·CSS 가 아니다 — 그건 `src/ui/` 의 구현이고 Phase 2 에서 버려진다. 여기 적힌 것은 엔진이 바뀌어도 **그대로 들고 간다.**
> 화면을 바꾸려면 **이 문서를 먼저** 고친다 (TheSevenSimulation 관례 — 씬 변경은 문서가 코드보다 앞선다).
> 폭·배율·최소 크기 같은 구현 정책은 [src/ui/README.md](../../src/ui/README.md).

관련: [ARCHITECTURE.md](ARCHITECTURE.md) · [INTERFACE.md](INTERFACE.md)(호출하는 함수의 계약) · 컨셉 락 [CLAUDE.md](../../CLAUDE.md)

## 1. 화면 지도

```
시작 ──(새 게임 / 이어하기)──▶ 게임 ── 탭 6 ──┬ 원정   : 편성 ⇄ 관전 ⇄ 리포트   ← 접속 중의 본편 (컨셉 락)
                                            ├ 캐릭터 : 장비·능력치·가방          ← "아이템 정리"
                                            ├ 스킬   : 액티브 3 · 마스터리 2 + 전직 특화 (목업)
                                            ├ 선술집 : 고용
                                            ├ 도감   : 몬스터 카드
                                            └ 도움말 : 규칙·안내 전문 (§12)      ← 인게임 패널에서 걷어낸 설명의 종착지
                        (미구현 — 컨셉 락 "오프라인 = 비전투") ▶ 거점/파견 · 탐험 · 제련소 · 상단 · 연구소 · 광산
```

**전투 창구는 하나** — 원정 탭 하나가 편성·관전·리포트 세 상태를 갖는다. 탭을 늘려 전투를 복제하지 않는다 (따름정리 2).

## 2. 공통 셸

| 요소 | 내용 |
|---|---|
| 브랜드 | 상단 좌측 |
| 상단바 | 현재 위치(crumb) · 자원 3종(골드 · 가루 · 낙인) · **언어 토글**(ko/en) |
| 탭 내비 | 원정 · 캐릭터 · 스킬 · 선술집 · 도감 · 도움말 (게임 화면에서만) |
| 메인 | 탭 내용. **항상 전체 다시 그림** |
| 툴팁 레이어 | 아이템 비교 툴팁 (마우스 따라다님, 화면 밖 넘침 보정) |
| 플래시 | 한 번만 보이는 안내/오류 한 줄 (i18n 키 + 파라미터). 다음 렌더에 사라진다 |
| **도움말 탭** | 규칙·안내 문구는 전부 여기(§12). 인게임 패널에는 설명 문장을 두지 않는다 — 숫자·상태·오류만 (2026-08-26 사용자 지시) |

**다국어** — 화면의 모든 문자열은 `t(key)`(문구) 또는 `L({ko,en})`(데이터). 렌더러에 한국어 리터럴 없음.

## 3. 시작 화면

**목적** — 새 게임의 첫 결정(시작 파티 3명)과 이어하기.

| 보여준다 | 결정 | 규칙 |
|---|---|---|
| 세이브 요약 (저장 시각 · 영웅 수 · 클리어 수 · 골드) | **이어하기** | 세이브 버전이 다르면 이어하기 대신 사유를 보여준다 (v1 은 이관 없음) |
| 후보 카드 3장 — 초상(§5 영웅 초상 규격) · 이름 · 등급 · 직업 · 역할/무기군 · 죄종 · 시작 특성 · 기본 능력치 7 막대 · 최대 HP · 합계 | **리롤** (무제한, 횟수 표시) | 같은 리롤 횟수 = 같은 3명 (고정 시드) |
| | **시작** | 세이브가 있으면 **두 번 눌러야** 덮어쓴다 — 되돌릴 수 없는 행동은 오클릭 한 번으로 일어나지 않는다 |

호출: `hero.rollStartParty` · `game.newGame` · `game.deserialize` · `game.closeRun`

## 4. 원정 탭

세그먼트 3 — **편성 / 관전 / 리포트.** 관전은 재생 중인 전투가 있을 때만, 리포트는 마지막 리포트가 있을 때만 활성.
**공통 영웅 띠(§5)는 편성의 편성 패널 안에만** — 관전·리포트에는 두지 않는다. 전투가 시작되면 전투 화면만 본다 (2026-08-27).

### 4-1. 편성

**어디를 갈지 먼저, 누구를 보낼지 나중** (2026-08-27) — 스테이지 목록이 이 화면의 본문이고, **지역을 누르면 그때 그 행 바로 아래로** 편성 패널이 펼쳐진다(2026-08-28 — 목록 위에 따로 뜨던 것을 접이식으로 바꿨다: 위에 뜨면 어느 지역의 편성인지 눈이 잇지 못한다). 왼쪽 굵은 선을 위 행과 같은 죄종 색으로 이어 두 칸을 한 덩어리로 묶는다. 영웅 띠는 그 패널 안에만 있다. 갈 곳이 안 정해진 편성은 결정이 아니라서, 띠를 상시로 띄우면 화면 첫 줄이 "지금 누를 것"이 아닌 것에 먹힌다.
**패널을 자동으로 열지 않는다** — 마지막 런으로 미리 골라 두는 안은 08-27 에 넣었다가 사용자 지시로 철회했다: 누르지 않았는데 떠 있으면 "고르면 뜬다"는 인과가 안 읽힌다.

| 영역 | 보여준다 | 결정 |
|---|---|---|
| 재접속 알림 (있을 때) | "꺼져 있던 사이 런이 마무리됨" + 스테이지 | 리포트 보기 / 닫기 |
| **편성 패널** (지역을 골랐을 때만 · 그 행 바로 아래) | **머리가 없다** (2026-08-28) — 무엇에 딸린 패널인지는 바로 위 행이 말한다 | **같은 행을 다시 누르면 접힌다** (닫기 버튼 폐지 — 여는 자리와 닫는 자리가 같다) |
| | 영웅 띠 (§5) — 로스터 전원을 한 줄에. **전투 파티는 카드 겉 테두리**로 보인다(2026-08-28). 위칸 글씨는 **대기 / 치료 중**만 — 「보낼 수 있는가」와 「골랐는가」는 다른 정보라 자리를 나눈다. 파티 첫 슬롯은 **리더** 표시 | 카드 클릭 = **파티에 넣고 뺀다**. 넣을 수 있는 건 **대기**뿐 — 치료 중은 거절(플래시)이고 커서로도 미리 막는다 |
| | 파티 없음 / 부상자 있음 경고 (띠 아래 · **줄은 항상 잡는다**) | |
| | 액션 — **같은 크기 버튼 둘** | **반복 원정**(ON/OFF) · **보내기**(고른 지역으로 출발) |
| 스테이지 목록 | 화면 전폭 — 해금된 챕터까지 전부, 잠긴 스테이지도 보인다 ("어디까지 가야 하는지가 보여야 한다"). 죄종 · Ch-스테이지 · 이름 · 클리어 표시 · dlvl · 예상 소요(분) · **스테이지 원소** · 배경 · 오른쪽에 「원정」 칩 | 행 클릭 = **이 지역으로 간다**(편성 패널이 열린다). 고른 행은 칩과 테두리로 표시가 남는다. 잠긴 행은 거절 → 플래시 |
| | 접이식 "구성 보기": 등장 몬스터 얼굴·이름 · 보스 · 정예 라운드 · 보스 라운드 | 펼치기는 선택과 별개다 |

패널이 없는 상태(아무 지역도 안 누른 상태)가 이 화면의 **기본**이다. 한 번 고른 선택은 탭에 머무는 동안 남는다 — 전투를 마치고 편성으로 돌아오면 방금 간 지역이 그대로 열려 있다.

**패널 크기는 상태에 흔들리지 않는다** (2026-08-28 사용자 지시) — 열려 있는 한 언제나 같은 크기다. 흔들던 것 셋을 구조에서 걷어냈다:
- 머리(제목 · 닫기) → **통째로 삭제** (2026-08-28). 스테이지 이름이 접히며 높이가 늘던 것도 같이 사라졌다
- 파티 없음 / 부상자 경고 → **줄은 항상 잡고** 글자만 있고 없다
- 반복 원정 → 별도 줄이 아니라 **액션 버튼**. 옛 줄은 「런의 스테이지일 때만」 붙어서 패널이 커졌다 작아졌다

**반복 원정은 출발 전에도 켤 수 있다** — `run.repeat` 은 「진행 중인 런」의 값이라 첫 출발 전에는 쓸 곳이 없다. 그래서 화면이 의사를 들고 있다가 출발할 때 런에 옮긴다. 이미 그 지역을 도는 런이 있으면 누르는 즉시 런에도 쓴다(관전의 자동 진행이 그 값을 읽는다).

**스테이지 원소** — 그 스테이지가 어느 저항을 요구하는지를 편성 **전에** 보여준다 (battle_design §9-8). 값은 `battle.stageElement(stage)` 가 정한다 — 화면이 몬스터 테이블을 훑지 않는다.
- **물리 스테이지도 그대로 찍는다** — `stageElement` 는 원소 몬스터가 없으면 `physical` 로 떨어지므로 Ch1 은 전부 "원소 물리 / Element Physical" 로 보인다. 숨기지 않는 쪽을 택했다: 칸이 사라지면 "아직 안 정해졌다"로 읽힌다
- **저항 미달 경고는 하지 않는다** — 문턱을 정하는 CSV 키가 없다. 경고를 넣으려면 기획이 먼저 문턱을 정해야 한다

호출: `game.toggleParty` · `game.stageUnlocked` · `battle.stagePool` · `battle.stageElement` · `game.resolveBattle`(출발) · `game.dismissNotice`
오류 → 플래시: 잠김(잠긴 행 클릭 · 출발) / 파티 없음 / 출발 불가(부상) / 파티 정원

### 4-2. 관전 (재생기)

**정산은 출발 순간 끝났다.** 이 화면은 결과를 시간에 맞춰 보여줄 뿐이다.

| 영역 | 내용 |
|---|---|
| 헤드 | 챕터 — 스테이지 이름 · 라운드 n / 총 · 라운드 종류 · 경과 시계 · **라운드 트랙**(1..9, 정예·보스 색) |
| 컨트롤 | 배속 ×1 / ×2 / ×4 · 일시정지 · **건너뛰기** |
| 아레나 | **적(위) / 파티(아래) 상하 대치** — 카드가 진영마다 한 줄로 나란히 (좌우 대치는 2026-08-27 사용자 지시로 철회) · 배경 = 스테이지 배경. **유닛 카드 = 이름 위칸 + 가로형 본문** (2026-08-27 개편 · 참고: Lootun 카드) — 위칸에 이름(적: 죄종 칩 · 정예 · 보스 태그), 본문은 왼쪽 초상(§5 얼굴 규격) · 오른쪽에 위에서부터 (정예 특성) / HP 바(**수치는 바 가운데**) / 행동 게이지(마지막 행동 이후 경과 ÷ 주기) / **스킬 쿨 3칸**(가로). 카드는 **몬스터·영웅·보스가 전부 같은 고정 크기**(옛 폭의 약 2/3). XP 바는 두지 않는다 — XP 는 리포트가 정산한다. 세로 예산은 카드 두 줄 + 구분선 높이 — 아래에 가방이 오므로 줄였다 (2026-08-27). 피해/**빗나감**/치명/카드 팝업 (`dodge` 이벤트 = 적중 실패. 회피 스탯은 폐지됐다) |
| 우측 탭 | **로그** — 라운드 시작(편성) · **모든 타격**(공격자 → 대상 · 피해 · 쓴 스킬) · 빗나감 · 치명 · 반사 · 처치/전투불능 · 카드 · 종료. **누적 데미지** — 유닛별 가한 피해 합계: 파티 / 적 두 묶음 · 막대(묶음 안 최대 기준) · 묶음 안 점유율 · 스킬별 내역. 재생기가 이벤트의 `dmg` 를 더한 **표시값**이다(정산 아님). 두 탭은 재생 중 자유롭게 오간다 (2026-08-27) |
| 결과 띠 | 재생 끝 → 승/패 띠 → [리포트로]. **반복 ON + 승리면 잠깐 세고 다음 원정 자동** |
| 가방 | 아레나 아래에 §6 가방 패널 그대로(부위 필터 · 분해 모드 · 비교 툴팁 · 클릭 = 장착). 장착 대상 = 현재 선택 영웅(머리에 이름). **접속 중 = 원정 전투 + 아이템 정리**를 한 화면에 — 정산은 출발 순간 끝났으므로 여기서 정리해도 이 전투는 안 바뀐다 (2026-08-27) |

**유닛 카드 = 위칸 + 본문** (2026-08-27) — 위칸은 §5 영웅 띠와 **같은 배치**다: 왼쪽에 태그(적: 죄종 칩 · 정예 · 보스), **오른쪽에 이름**. 본문 오른쪽 열에는 수치 칸만 남는다.

**카드 크기는 몬스터·영웅·보스가 전부 같은 고정값** (2026-08-27 사용자 지시) — 진영마다 카드 수가 달라도, 정예 특성 줄이 붙어도, 보스여도 같은 박스다. 위아래 두 진영이 같은 격자로 읽히는 것이 카드가 자기 내용에 맞춰 커지는 것보다 낫다. 그래서 **보스의 초상 확대도 폐지**했다 — 보스 표시는 태그와 테두리가 든다. 넘치는 내용(긴 이름 · 정예 특성 3줄)은 잘리고 툴팁이 전문을 든다.
- 폭 고정은 [src/ui/README.md](../../src/ui/README.md) 화면 폭 정책(라벨 칸 고정 px 금지)의 **의도된 예외**다. 한 진영 최대 3장(`balance.csv:party_size_max` · `balance.csv:wave_monster_max`)이라 하한 폭 1280 의 아레나에 3장이 들어간다. 상한이 늘면 이 고정을 다시 본다
- **초상은 카드에서 가장 큰 칸**이고 본문 높이를 정한다 — 카드 높이가 초상 하나로 결정되므로 진영이 달라도 같은 높이가 된다

**스킬 쿨 = 가로 3칸 아이콘** (2026-08-27 · 세로 3줄에서 개정). 슬롯 순 = 우선순위, **왼쪽부터** 1·2·3번. **이름도 % 도 찍지 않는다** — 이름과 표기 쿨은 툴팁에 남는다(값을 지운 게 아니라 옮겼다).
- **눕힌 이유** — 세로로 쌓으면 오른쪽 열의 가로 폭 중 아이콘이 한 뼘만 쓰고 세로만 먹는다. 아이콘이 안 읽히던 건 자리가 없어서가 아니라 배치가 세로였기 때문이다. 눕히면 같은 자리에서 아이콘이 커지고(13 → 32px) 세로 예산은 오히려 준다
- **남은 쿨** = 아이콘을 덮은 어두운 판이 위에서부터 걷힌다. 다 걷히면 준비 완료(테두리가 산다). 옛 바가 들던 "얼마나 남았나"를 아이콘 자신이 든다

**올려놓으면 뜬다** (2026-08-28) — 유닛 카드에 커서를 올리면 **영웅 기본 능력치**(§5 영웅 띠와 **같은 카드**), 스킬 칸에 올리면 **그 스킬**(이름 · 표기 쿨 · **실효 쿨** · 설명)이 뜬다. 몬스터 카드에는 영웅 카드가 없다.
- **실효 쿨** = `올림(표기 쿨 ÷ 행동 주기) × 행동 주기` (battle_design §6) — "표기 5초"만 봐서는 주기 2.4초인 영웅이 실제로 7.2초마다 쓴다는 걸 못 읽는다. 스킬 탭이 이미 쓰던 표기(`sk.base` · `sk.eff` · `sk.aligned`)를 그대로 쓴다
- 스킬 칸 툴팁은 카드 툴팁 **안에** 겹쳐 있다 — 칸에서 나오면 카드 툴팁으로 되돌아간다
- 툴팁 문구는 인게임 패널의 설명 문장 금지(§12)에 걸리지 않는다: 툴팁은 그 규칙이 허용하는 자리다

**「방금 뭘 썼나」는 게이지가 아니라 팝업이 답한다** (2026-08-27) — 준비 상태는 **상태**라 게이지가 맞지만, 발동은 **사건**이라 게이지로는 안 보인다(조용히 리셋될 뿐). 그래서 발동하면 그 칸이 한 번 튀고 **스킬 이름이 카드 위로 떠오른다** — 피해 숫자와 같은 팝업 층이되 자리가 다르다(피해는 초상 위 · 스킬은 카드 가운데 위). 몬스터는 스킬이 없어 이 연출도 없다.

아이콘 표는 `mock.js MOCK_ACTIVES` — 이름·쿨·**설명**과 같은 목업이고, 툴팁이 그 사실을 한 줄로 적는다(`tip.skill.mock`). 발행된 스킬 텍스트는 `skill.csv` 에 있으나 기획 개정 전이고 로더에도 없다([DEV_PLAN §3-3 R19](DEV_PLAN.md) · 부채 #15) — 그게 들어올 때 이 표는 지운다. **아이콘을 키운 만큼 세트의 통일이 과제로 남았다**: 지금은 흑백 글리프와 컬러 이모지가 섞여 있어 커지자 무게 차가 드러난다 ([DEV_PLAN 부채 #13](DEV_PLAN.md)).

**스킬 쿨 게이지는 목업이다** — 스킬 미작성이라 타임라인에 스킬 이벤트가 없다. 재생기가 영웅의 실제 행동 이벤트마다 슬롯 순으로 준비된 것 하나를 리셋만 한다(결과 무관 · [DEV_PLAN 부채 #13](DEV_PLAN.md)). 스킬 이벤트가 계약에 들어오면 그 이벤트로 교체한다. 몬스터는 스킬이 없어 쿨 칸이 없다. 로그·누적 데미지의 스킬명도 같은 목업이다.

**재렌더에도 재생은 이어진다** (2026-08-27) — 가방 클릭 · 언어 전환 · 세그먼트 이동이 화면을 통째로 다시 그려도, 렌더러가 재생 위치(t · 배속 · 일시정지 · 탭)를 받아 뒀다가 다음 mount 에 넘긴다. 재생기는 그 시각까지 이벤트를 팝업 없이 되감는다 — 로그 · 게이지 · 누적은 다시 쌓이므로 언어를 바꿔도 같은 자리에서 같은 내용이 나온다.

재생기가 아는 이벤트 7종과 순서 보장은 [INTERFACE.md §2-6](INTERFACE.md#2-6-battlejs--헤드리스-전투). 언어를 바꿔도 같은 타임라인을 다시 재생한다.

## 5. 공통 영웅 띠 (원정 편성 · 캐릭터 · 스킬 · 선술집 상단)

네 탭이 **같은 띠, 같은 자리, 같은 순서**로 로스터를 보여준다. **카드 = 초상이 전체를 채우는 정사각** (2026-08-27) — 글자는 초상 위에 얹는 **위칸** 하나뿐이다. 유니크는 표시 구분. 빈 칸은 `+` 로 `roster_cap` 까지.

| 영역 | 보여준다 | 규칙 |
|---|---|---|
| 초상 | 카드 전체(정사각). 아트 없으면 직업 글리프를 카드 절반 크기로 | 얼굴 그림은 아래 **영웅 초상 규격** 그대로 — 관전·후보 카드와 같은 그림, 크기만 다르다 |
| 위칸 | 왼쪽: **지금 하는 일**(치료 중(남은 시간) 빨강 / 대기 회색) · 오른쪽: 이름 | 초상 위에 반투명 띠로 얹는다. 안 들어가면 두 줄로 접힌다 — 고정 px 없음 |
| 테두리 | 상단 죄종 색 · **겉 테두리 = 전투 파티**(2026-08-28) · 안쪽 하이라이트 = 지금 보고 있는 영웅 · 부상 흐림 · 유니크 하단 색 | 두 표시는 뜻이 달라 겹쳐도 서로 안 먹는다 — 하나는 밖, 하나는 안 |
| 툴팁 | 이름 · 직업 · 레벨 · 죄종 · 등급 + **기본 능력치 7** (2026-08-28). 옛 브라우저 기본 툴팁(`title` 한 줄)을 카드로 바꿨다 — 값이 늘어 한 줄에 안 들어간다. 파생 전투치는 넣지 않는다(캐릭터 탭의 몫) | |

**전투 파티는 「하는 일」이 아니라 「고른 것」이다** (2026-08-28 사용자 지시) — 옛 화면은 카드를 누르면 위칸 글씨가 「대기」→「전투 파티」로 바뀌었다. 그러면 클릭이 고른 티가 안 나고, 그 한 줄이 「보낼 수 있는가」와 「골랐는가」 두 가지를 겸해 읽힌다. 파티는 카드 **겉 테두리**로 옮기고 위칸은 서 있는 상태(대기 / 치료 중)만 말한다. 파견이 들어오면 파견지가 그 자리에 앉는다.

**리더 = 파티에 제일 먼저 넣은 영웅** — `party` 배열이 넣은 순서 그대로이고 화면은 `party[0]` 에 리더 표시를 붙인다. 리더를 빼면 다음 사람이 리더가 되고, 다시 넣으면 맨 뒤로 간다. 로스터 순서로 다시 줄 세우지 않는다 (단정: `dev/test.js` 「toggleParty: 파티 순서 = 넣은 순서」).

이름과 지금 하는 일은 뺄 수 없다 — 같은 직업은 같은 얼굴이고(아트 전) 리포트·로그가 이름으로 말한다 / 이 띠가 접속·오프라인 상태를 한눈에 보는 자리다(아래). 다만 둘 다 주인공 자리에서 내려와 위칸의 라벨이다.
관전 유닛 카드(§4-2)는 **얼굴 그림만 같고 구성은 가로형**이다 — HP·쿨 3줄 같은 수치가 본체라 초상을 왼쪽에 두고 오른쪽에 세로로 쌓는다.
클릭 = 그 영웅 선택 (선술집에서는 캐릭터 탭으로 이동). **원정 편성만 예외 — 클릭이 파티 넣고 빼기다** (2026-08-27): 그 화면의 결정이 편성이고, 띠가 옛 파티·벤치 두 패널을 대신한다. 원정에서 띠가 서는 곳은 편성 패널 안뿐이다 (§4-1) — 스테이지를 골라야 열리고, 관전·리포트는 전투 화면만 본다.
파견이 생기면 "지금 하는 일"에 파견지가 들어온다 — 이 띠가 컨셉 락의 접속/오프라인 상태를 한눈에 보여주는 자리다.

**영웅 초상 규격 (2026-08-27) — 영웅의 생김새는 어디서나 같다.** 영웅 띠 · 후보 카드(§3 · §8) · 관전 유닛 카드(§4-2)가 **같은 네모 박스 + 같은 직업 글리프**를 쓴다 (글리프 표는 한 곳 — `mock.js classGlyph`). 원형은 몬스터 얼굴 전용이다. 죄종 색은 카드 상단 테두리가 들고 초상은 색을 갖지 않는다. 아트가 들어오면 글리프 자리에 그대로 앉는다 — 규격은 바뀌지 않는다.

## 6. 캐릭터 탭 — "아이템 정리"

세로 3단: ① 영웅 띠 ② **같은 폭 · 같은 높이의 4칸** — 장비 / 기본 옵션 / 세부 옵션 1 / 세부 옵션 2 (2026-08-27) ③ 가방(전폭). **장착·해제·분해가 실제로 일어나는 곳.**

| 패널 | 보여준다 | 결정 |
|---|---|---|
| 장비 | **페이퍼돌** — 신체 위치대로 착용 위치 9 (부위 8, 반지 ×2). 3열 × 4행: 투구·목걸이 / 무기·갑옷·보조 / 장갑·(빈)·신발 / 반지·(빈)·반지 (2026-08-27 재배치). 희귀도 색 테두리 · 양손 무기면 보조 칸 잠김 표시 · 착용 n / 9 | 착용 칸 클릭 = **해제** |
| | 접사 죄종 **태그** 집계 — 세트포인트 아님(폐기). 전술카드 조건이 이 숫자를 읽으므로 **카운터는 필수**다 (tactic_card_design.md §2-1) | |
| 기본 옵션 | 기본 능력치 7 막대 (범위 표시) · 그 아래 **현재 스킬** — 액티브 3 을 **정사각 카드**로(번호 · 이름 / 빈 슬롯) + 행동 주기 | → 스킬 탭 |
| 세부 옵션 1 · 2 | 전투 능력치 25 를 **두 칸에 나눠 스크롤 없이** — **카테고리 제목 없이** CSV 순서 그대로. 1 = 공격 9 + 최대 HP + 물리 방어, 2 = 저항 4 부터 끝까지 (저항 묶음을 가르지 않는 자리에서 끊는다). 칸마다 값 있는 것 n / 그 칸의 행 수, 담당 기본 능력치 약어. 저항 4행은 **값 + 현재 상한** · 물리 방어 행은 **값 + 감쇠율 %** | |
| 가방 | 칸 `inventory_cap` 개 · 부위 필터 · **분해 모드 토글** · 비교 툴팁(이 아이템 vs 교체될 착용품 — 반지는 빈 칸 우선) | 칸 클릭 = **장착** (분해 모드면 **분해**) |

옛 "핵심 전투치 4"(공격력 · 방어 · 최대 HP · 행동 주기) 줄은 세부 옵션이 흡수했다 — 공격력·최대 HP·행동 주기는 같은 이름의 행이 있고, 감쇠율은 물리 방어 행에 병기한다. 공격 타입(원소)은 무기 툴팁이 든다.

**감쇠율** — `formula.mitigation(방어값)` 하나로 계산한다. 인자는 방어값뿐 — **공격자 레벨이 곡선을 흔들지 않는다**(K 상수, battle_design §9-3). 그래서 이 %는 상대가 누구든 같은 값이고, 시트에 적어 둘 수 있다.

**저항 4행의 상한 표기** — `res_fire/cold/lightning/poison` 은 값 뒤에 `/ 상한 {cap}%` 를 붙인다. `cap = formula.resCap(res_max_bonus)` — 저항은 상한형이라(§9-5) 값만 보이면 "더 쌓으면 되는지"를 읽을 수 없다.
- 이 네 행은 **값이 0이어도 상한이 붙는다.** `computeCombat` 이 `res_*` 4개를 항상 내므로 "값 있는 것 n / 25" 집계에서도 **항상 채워진 행**이다 — 다른 행처럼 비는 일이 없다는 뜻이고, 의도된 예외다
- 최대 저항 증가(`res_max_bonus`)는 아직 드롭 접사 풀에 없어 상한은 사실상 `res_cap_base` 고정으로 보인다 ([INTERFACE §2-4](INTERFACE.md))

호출: `game.equip` · `game.unequip` · `game.salvage` · `game.equipTarget` · `game.heroCombat` · `formula.mitigation` · `formula.resCap` · `item.groupOf`
오류 → 플래시: `ch.err.<code>` (직업 전속 / 양손 / 가방 초과 / 없음)

**툴팁 규격** — 이름(희귀도 색) · 희귀도 · 부위 · ilvl · (무기) 무기군 + 착용 직업 + 공격력 + 타입/원소 + 주기 · Implicit · 접사 목록 · 죄종 태그 · 힌트. 비교 시 "이 아이템 / 착용 중" 두 장.

## 7. 스킬 탭

**한 화면에 전부** (2026-08-28 사용자 지시) — 왼쪽 한 칸(포인트 · 액티브 3) + **트리 판 셋이 나란히**. 판 안에서는 **가지가 세로로 흐른다**: 데이터의 행 하나가 가지(무기군 · 계열)이고 열이 깊이라, 옛 화면은 행을 그대로 가로줄로 그려 판이 옆으로 길었다. 판 셋을 세로로 쌓으니 세로 예산(700) 안에 한 판 반밖에 안 들어와 스크롤이 생겼다 — 가지를 세워 판을 좁고 길게 만들면 셋이 한 화면에 선다.
- 선행 연결선도 세로다. 깊이 d+1 칸의 `link` 는 여전히 "바로 앞 깊이에 매인다"는 뜻이라 데이터는 그대로다
- **가지 3 × 깊이 5 프레임은 비어 있어도 그린다** — 어디까지 갈 수 있는지가 보여야 한다(§4-1 스테이지 목록과 같은 이유)
- 칸 폭은 판 폭이 정한다(고정 px 없음). 세로만 최소를 잡아 다섯 깊이가 예산 안에 들어가게 한다 — 긴 이름은 세 줄에서 잘리고 툴팁이 전문을 든다

| 패널 | 보여준다 | 상태 |
|---|---|---|
| 포인트 | 마스터리 풀 + 전직 전용 풀 **둘** (쓸 곳 없음) | 목업 — **구조 변경 필요** |

## 12. 도움말 탭

**목적** — 규칙·설계 근거·미구현 안내를 **한 곳에 모은다.** 인게임 패널은 숫자·상태·오류·버튼·툴팁만 남긴다 (2026-08-26 사용자 지시).

**한 페이지 스크롤.** 읽기 폭 상한만 잡고 장식은 없다. 결정 없음 — 조회 화면.

| 영역 | 내용 |
|---|---|
| 제목 | 도움말 |
| 점프 세그먼트 | 섹션 6개 버튼 — 누르면 해당 `<h2>` 로 스크롤 |
| 섹션 (`<h2>`) | ① 원정 ② 캐릭터 ③ 스킬 ④ 선술집 ⑤ 도감 ⑥ 새 게임 |
| 소제목 (`<h3>`) | 패널 이름 그대로 + (있으면) 그 패널이 쓰던 부제 |

| 섹션 | `<h3>` 묶음 |
|---|---|
| 원정 | (머리글) 전투 파티는 한 팀 · 파티 · 벤치 · 원정 지역 · 반복 원정 · 전투 관전 · 리포트(부상 포함) |
| 캐릭터 | 장비 · 접사 죄종 · 기본 옵션 · 세부 옵션 · 아이템(가방) |
| 스킬 | (머리글) 트리 격자 규약 · 스킬 포인트 · 액티브 슬롯 · 죄종 트리 · 마스터리 · 전직 트리 |
| 선술집 | 영입 후보(등급) · 후보 교체(리롤) · 유니크 영웅 |
| 도감 | 몬스터 도감 |
| 새 게임 | 첫 파티 |

**텍스트 출처 = 기존 i18n 키.** 도움말은 문구를 새로 쓰지 않는다 — 인게임에서 걷어낸 `*.note` / `*.sub` / `*.hint` 를 **같은 키 그대로** 렌더한다. 수치 파라미터(`{n}` `{cap}` `{e}` `{b}` `{pct}` 등)도 인게임과 같은 값(`D.balance.*` · `D.eliteRounds` · `D.bossRound` · `D.codexLevels`)을 넣는다. 죄종·직업이 들어가는 스킬 트리 제목은 **현재 선택된 영웅**의 값을 쓴다.

새 키는 넷뿐 — `nav.help` · `help.title` · `help.newgame`(섹션 제목용) · `help.exp.party` / `help.exp.bench`(인게임에서 숫자만 남기며 원문이 옮겨온 자리).
