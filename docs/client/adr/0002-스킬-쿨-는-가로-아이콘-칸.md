## 결정

스킬 쿨 = 가로 아이콘 칸 (2026-08-27 · 세로 3줄에서 개정). 슬롯 순 = 우선순위, 왼쪽부터 1·2·3번.  아레나도 빈 칸을 그린다 — 칸 수는 언제나 `` 이고, 액티브가 둘뿐인 영웅(전사 ③ 미정)은 셋째 칸이 빈 채로 남는다. 옛 결정(「빈 칸을 그리지 않는다 · 셋 중 하나가 비었다는 스킬 탭이 답한다」)은 폐기한다 — 칸이 사라지면 카드마다 아이콘 줄의 길이가 달라져 같은 격자로 읽히지 않고, 「이 영웅은 스킬이 둘」과 「셋째가 아직 안 정해졌다」가 화면에서 구분되지 않는다. 빈 칸은 §4-1 의 「값은 항상 찍는다」와 같은 이유로 자리를 지킨다. 이름도 % 도 찍지 않는다 — 이름과 표기 쿨은 툴팁에 남는다(값을 지운 게 아니라 옮겼다).

## 근거 · 맥락

> 아래는 [SCREEN_DESIGN.md](../SCREEN_DESIGN.md) §4-2 본문에서 **그대로 옮긴 것**이다 (2026-09-09 이관). **쓰인 날의 문장이라 고치지 않는다** — 뒤집히면 새 ADR 이 이것을 대체한다.

**스킬 쿨 = 가로 아이콘 칸** (2026-08-27 · 세로 3줄에서 개정). 슬롯 순 = 우선순위, **왼쪽부터** 1·2·3번. **[개정 2026-08-31 사용자 지시] 아레나도 빈 칸을 그린다** — 칸 수는 언제나 `[balance.csv:active_slots]` 이고, 액티브가 둘뿐인 영웅(전사 ③ 미정)은 **셋째 칸이 빈 채로 남는다.** 옛 결정(「빈 칸을 그리지 않는다 · 셋 중 하나가 비었다는 스킬 탭이 답한다」)은 폐기한다 — 칸이 사라지면 **카드마다 아이콘 줄의 길이가 달라져** 같은 격자로 읽히지 않고, 「이 영웅은 스킬이 둘」과 「셋째가 아직 안 정해졌다」가 화면에서 구분되지 않는다. 빈 칸은 §4-1 의 「값은 항상 찍는다」와 같은 이유로 자리를 지킨다. **이름도 % 도 찍지 않는다** — 이름과 표기 쿨은 툴팁에 남는다(값을 지운 게 아니라 옮겼다).
- **눕힌 이유** — 세로로 쌓으면 오른쪽 열의 가로 폭 중 아이콘이 한 뼘만 쓰고 세로만 먹는다. 아이콘이 안 읽히던 건 자리가 없어서가 아니라 배치가 세로였기 때문이다. 눕히면 같은 자리에서 아이콘이 커지고(13 → 32px) 세로 예산은 오히려 준다
- **남은 쿨** = 아이콘을 덮은 어두운 판이 위에서부터 걷힌다. **마스크가 다 걷힌 것 자체가 준비다** — 준비 완료의 파란 테두리(`ready`)는 2026-09-03 사용자 지시로 삭제했다(찼을 때마다 칸이 번쩍여 소란스러웠다). 옛 바가 들던 "얼마나 남았나"를 아이콘 자신이 든다

**올려놓으면 뜬다** (2026-08-28) — 유닛 카드에 커서를 올리면 **영웅 기본 능력치**(§5 영웅 띠와 **같은 카드**), 스킬 칸에 올리면 **그 스킬**이 뜬다. 몬스터 카드에는 영웅 카드가 없다.

**스킬 툴팁은 수치표가 아니라 문장이다** [전면 개정 2026-09-08 사용자 지시] — ~~`표기 6초 · 실효 7.2초 (+20%)` 한 줄~~ 을 버리고 **데이터로 조립한 한 문장**을 낸다: 「**7.2초**마다 적 하나를 강하게 공격해 **1,240** 의 물리 피해를 가한다」. 숫자만 강조색(`.tip-hl`)으로 뽑는다.

| 조각 | 어디서 | 규칙 |
|---|---|---|
| **{n}초** | `skill.previewOf().baseSec` = **표기 쿨**(`skill.csv:cool_sec`) | ⚠ **[개정 2026-09-08 · 2차 사용자 지시]** 종전엔 `everySec`(실효 쿨)이었다. **공격 속도를 올리면 이 숫자가 움직여** 「스킬 쿨이 왜 공속을 타나」가 됐다 — 쿨 자체는 주기와 무관한데(`readyAt = t + cool × 쿨감소`, 주기가 안 들어간다) 움직인 것은 **다음 행동 차례까지의 대기**였고, 화면이 그 합을 쿨 자리에 찍고 있었다. 이제 **스킬이 가진 값 하나**만 찍는다 — 어느 영웅이 들든 같은 수다 |
| **피해 · 회복 수치** | `previewOf().amount` = 공격력 × 배율 | **감소·치명 전의 값**이다(방어·저항은 대상이 정해져야 나온다). 공격력을 모르는 자리는 **「공격력의 300%」** 배율로 접는다 |
| 물리 / 마법 | 그 유닛의 `attack_type` | 무기군이 정한다(battle_design §2-1). 모르면 배율 표기로 접히므로 이 단어가 안 나온다 |
| 문장 틀 | `kind` × `target` | 공격 단일 / 단일다단 / 전원 / 순회 / 관통 · 회복 파티 · 버프 파티 / 자기 / 도발 = **9틀**. `i18n` 이 ko/en 을 각각 든다 — 조각을 이어붙이지 않는다 |
| 효과 구절 | `effect_stat` + `effect_value` | 「공격력 +25%」처럼 **이름 + 값**만 (§12 원칙) |

- **머리에 출처·태그 칩** — 고유/무기/전직(칸이 아는 값) · 태그는 `skill_tag.csv` 가 이름을 든다(파생 태그 광역·단일·다단히트 포함)
- **붙는 자리 셋** — 관전 유닛 카드의 쿨 칸 · 후보 카드의 고유 스킬 줄 · **캐릭터 탭 「액티브 스킬」 3칸**(2026-09-08 신설 — 그 목록에는 툴팁이 없었다)
- **문장은 렌더러가 계산하지 않는다** — 쿨도 피해도 `game_logic/skill.js:previewOf` 가 낸다 (부채 #3 을 늘리지 않는다)
