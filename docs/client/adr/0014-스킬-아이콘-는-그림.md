## 결정

스킬 아이콘 = 그림  — 스킬을 아이콘으로 그리는 칸 전부(§3 후보 카드 고유 칸 · §4-2 쿨 칸·창 칩 · §6 액티브 스킬 카드 · §7 슬롯 목록 · 스킬 툴팁)는 `skill.csv:icon` 이모지 대신 그림(`src/assets/art/icons/skills/<skill_id>.png`)을 쓴다. 제 그림이 있는 스킬은 그것, 없는 스킬은 id 안정 해시로 있는 그림 중 하나 — 영웅 초상(`heroFace`)과 같은 문법이라 같은 스킬은 어디서나 같은 그림이다. 파일 목록은 `mock.js:SKILL_ICON_FILES`(지금 전사류 4종 — `war_warcry`·`war_bash`·`wg_sword2h`·`wg_axe`)가 들고, 자산이 늘면 목록에만 더한다. img 가 `onerror` 로 빠지면 빈 칸이다 — 밑에 이모지를 깔지 않는다(§5 직업 글리프 폐지와 같은 이유 — 그림이 투명 PNG 라 있어도 비친다). `skill.csv:icon` 이모지 컬럼은 데이터로 남는다(화면이 안 읽을 뿐).

## 근거 · 맥락

> 아래는 [SCREEN_DESIGN.md](../SCREEN_DESIGN.md) §2 본문에서 **그대로 옮긴 것**이다 (2026-09-09 이관). **쓰인 날의 문장이라 고치지 않는다** — 뒤집히면 새 ADR 이 이것을 대체한다.

**스킬 아이콘 = 그림 [신설 2026-09-03 사용자 지시]** — 스킬을 아이콘으로 그리는 칸 전부(§3 후보 카드 고유 칸 · §4-2 쿨 칸·창 칩 · §6 액티브 스킬 카드 · §7 슬롯 목록 · 스킬 툴팁)는 `skill.csv:icon` 이모지 대신 **그림**(`src/assets/art/icons/skills/<skill_id>.png`)을 쓴다. 제 그림이 있는 스킬은 그것, 없는 스킬은 **id 안정 해시로 있는 그림 중 하나** — 영웅 초상(`heroFace`)과 같은 문법이라 같은 스킬은 어디서나 같은 그림이다. 파일 목록은 `mock.js:SKILL_ICON_FILES`(지금 전사류 4종 — `war_warcry`·`war_bash`·`wg_sword2h`·`wg_axe`)가 들고, 자산이 늘면 목록에만 더한다. img 가 `onerror` 로 빠지면 **빈 칸**이다 — 밑에 이모지를 깔지 않는다(§5 직업 글리프 폐지와 같은 이유 — 그림이 투명 PNG 라 있어도 비친다). `skill.csv:icon` 이모지 컬럼은 데이터로 남는다(화면이 안 읽을 뿐).
**아이템 아이콘 = 그림 [임시 2026-09-03 사용자 지시]** — 아이템을 아이콘으로 그리는 칸 전부(§6 페이퍼돌 **착용** 칸 · §6 가방 칸 · §8-2 제련소 목록·머리)는 `equip_slot.csv:icon` 이모지 대신 **그림**(`src/assets/art/icons/items/`)을 쓴다. 규칙은 `mock.js:itemArt` 한 곳이고, 스킬 아이콘(위)과 같은 문법이다.

- **무기는 제 그림이다** — 무기의 베이스가 곧 무기군이라(`item.group`) `<group_id>.png` 가 정확히 그 무기다. `release=main` 8종이 전부 있다
- **⚠ 방어구는 임시다 — 부위 하나에 그림 하나.** 개체가 **베이스 id 를 안 들고 다니기 때문**이다(`item.js:build` 는 이름만 조립하고 어느 베이스였는지를 안 남긴다). 그래서 판금·사슬·가죽·유령 갑옷이 **전부 같은 그림**(`armor_1.png`)으로 나온다. 파일 이름은 이미 `base_id` 축이라, 개체가 베이스를 들게 되면 `mock.js` 의 부위→파일 표 한 줄만 걷으면 갈아탄다
- **투구 · 목걸이는 그림이 없어** 옛 이모지로 떨어진다. 미장착 칸(§6)과 같은 처지고 같은 이유로 **해시 폴백을 안 쓴다** — 부위는 틀린 그림이 곧 틀린 정보다
- img 가 `onerror` 로 빠지면 **빈 칸**이다 — 밑에 이모지를 깔지 않는다(스킬 아이콘·직업 글리프와 같다)
