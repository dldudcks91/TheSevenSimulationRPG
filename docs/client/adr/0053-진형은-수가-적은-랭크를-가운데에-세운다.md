# ADR-0053 — 진형은 수가 적은 랭크를 가운데에 세운다

| | |
|---|---|
| **상태** | 확정 · 2026-09-09 (신설) |
| **화면** | [SCREEN_DESIGN §4-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | — *(ADR-0045 를 뒤집지 않는다 — 세로 어긋남은 그대로 두고 **가로 차례**를 더한다)* |
| **대체됨** | — |

## 결정

관전 아레나의 파티 카드는 **가로 차례도 진형이 정한다.** 각 랭크를 같은 너비에 고르게 편 x 값으로 전원을 줄 세운다 — k 명짜리 랭크의 i 번째가 `x = (i + 0.5) / k`.

| 템플릿 | 왼쪽 → 오른쪽 | 읽히는 모양 |
|---|---|---|
| 2·1 | 앞(0.25) · **뒤(0.5)** · 앞(0.75) | 앞 둘이 양옆, 뒤 하나가 그 사이 — 삼각 |
| 1·2 | 뒤(0.25) · **앞(0.5)** · 뒤(0.75) | 그 뒤집힌 꼴 |
| 3 | 0.17 · 0.5 · 0.83 | 한 줄이라 파티 순서 그대로 |

수가 적은 랭크가 계산에서 저절로 가운데로 온다 — 「가운데」를 따로 특례로 두지 않는다.

## 맥락

[ADR-0045](0045-진형이-파티-카드를-위아래로-민다.md) 로 랭크가 카드를 **세로로** 밀기 시작했지만, 가로 차례는 여전히 파티 순서 그대로였다. 기본 템플릿 2·1 에서 `reconcileForm` 이 앞 랭크부터 채우므로 화면은 **앞 · 앞 · 뒤** 순으로 섰고, 후열 한 명이 **오른쪽 끝**에 붙었다.

세로로는 어긋나 있으니 규칙 자체는 맞게 돌고 있었지만, 보이는 모양은 진형이 아니라 「맨 오른쪽 카드만 아래로 처진 한 줄」이었다 (사용자 지적).

## 근거

**랭크를 줄로 안 그리기로 한 대가를 여기서 치른다.** 이 화면은 카드가 진영마다 **한 줄**에 서고([ADR-0018](0018-아레나가-메인-칸을-꽉-채운다-높이는-420-고정.md) 의 높이 예산 안에서 두 줄을 겹쳐 놓을 자리가 없다), 랭크는 줄이 아니라 **세로 어긋남**으로만 보인다. 그러면 세로만으로는 부족하다 — 사람이 진형을 알아보는 단서는 **어긋남 + 가로 배치**가 같이 있을 때 생긴다. 앞 둘 사이에 뒤 하나가 들어가야 삼각으로 읽히고, 끝에 붙으면 그냥 어긋난 줄로 읽힌다.

**「가운데」를 특례로 안 쓴다.** 「후열이 하나면 가운데」 같은 규칙은 템플릿이 늘면 곧 예외 표가 된다. 각 랭크를 같은 너비에 **고르게 편다**는 한 줄이 세 템플릿을 다 설명하고, 랭크가 셋이 되거나 정원이 바뀌어도 그대로 돈다.

**DOM 순서가 아니라 flex `order` 로 옮긴다.** 카드를 실제로 재정렬하면 로그·누적 데미지가 읽는 파티 순서와 갈린다. 배열은 그대로 두고 화면 차례만 `order` 로 준다.

**대안 — 파티 순서 자체를 진형 순으로 바꾼다.** 안 골랐다. 파티 순서는 리더(`party[0]`)를 정하는 세이브 값이라, 화면을 위해 그것을 건드리면 **진형을 만지다 리더가 바뀐다.**

## 파급

- `formSnapshot()` 이 `orderByUid` 를 같이 실어 보낸다 — 값은 출발 순간에 찍히고([ADR-0045](0045-진형이-파티-카드를-위아래로-민다.md)), 재생기는 그대로 쓴다
- 관전 카드 칸(`.unit-slot`)에 인라인 `order` 가 붙는다 — 유닛마다 다른 값이라 CSS 상수로 못 옮긴다
- ⚠ **진형 보드(§4-1)는 안 바뀐다** — 그쪽은 랭크가 실제로 줄이라 이 문제가 없다
- ⚠ 여전히 **자리뿐이다** — 타겟팅·피해·정산은 진형을 모른다([ADR-0044](0044-진형은-목업이다.md))
