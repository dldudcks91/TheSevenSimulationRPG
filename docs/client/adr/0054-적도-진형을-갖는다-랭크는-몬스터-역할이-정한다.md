# ADR-0054 — 적도 진형을 갖는다 · 랭크는 몬스터 역할이 정한다

| | |
|---|---|
| **상태** | 확정 · 2026-09-09 (신설) |
| **화면** | [SCREEN_DESIGN §4-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | — *(ADR-0045 · ADR-0053 을 뒤집지 않는다 — 그 규칙을 적 진영으로 넓힌다)* |
| **대체됨** | — |

## 결정

**두 진영이 같은 규칙으로 선다.** 세로 어긋남([ADR-0045](0045-진형이-파티-카드를-위아래로-민다.md))과 가로 차례([ADR-0053](0053-진형은-수가-적은-랭크를-가운데에-세운다.md))를 적 진영에도 그대로 적용한다.

**랭크가 어디서 오는지만 다르다.**

| 진영 | 랭크의 출처 |
|---|---|
| 파티 | 편성 화면의 진형 (§4-1) — 출발 순간에 찍는다 |
| 적 | **몬스터 역할** `monster.csv:role` — 후열은 `ranged` · `caster` · `skirmish`, 나머지(`line` · `heavy` · `elite_line` · `boss`)가 전열 |

**방향은 진영이 뒤집는다.** 「전열 = VS 쪽」은 규칙 하나인데 파티는 아래 진영, 적은 위 진영이라 같은 랭크 0 이 파티에선 위로, 적에선 아래로 간다. 결과는 **거울로 마주 선 두 삼각**이다.

**깊이는 정원이 아니라 실제로 찬 랭크 수다.** 한 랭크에 다 몰리면(전원 근접인 웨이브 · 템플릿 `3`) 깊이 1 이 되어 **아무도 안 밀린다** — 있지도 않은 후열 때문에 전열이 올라가 있는 그림을 막는다.

## 맥락

[ADR-0045](0045-진형이-파티-카드를-위아래로-민다.md) · [ADR-0053](0053-진형은-수가-적은-랭크를-가운데에-세운다.md) 은 파티 진영에만 걸려 있었다. 적은 언제나 평평한 한 줄이라, 마주 선 두 진영 중 한쪽만 진형을 가진 그림이었다.

## 근거

**적의 랭크를 굳이 만들어 낼 필요가 없었다** — `monster.csv:role` 이 이미 있었다. 마릿수를 반으로 가르는 식(앞 `ceil(n/2)`)도 가능했지만 안 골랐다: 그건 **뜻이 없는 배치**라 같은 몬스터가 웨이브마다 앞뒤로 옮겨 다닌다. 역할로 가르면 「궁수·시전자는 뒤에 선다」가 화면에서 그대로 읽히고, 몬스터가 늘어도 표를 안 고친다.

**계산은 재생기 한 곳에 모았다.** 적의 랭크는 웨이브가 뜰 때 정해지므로 편성 화면이 관여할 수 없다. 그래서 가로 차례·깊이 계산을 `formSnapshot()`([ADR-0053](0053-진형은-수가-적은-랭크를-가운데에-세운다.md) 당시의 자리)에서 재생기의 `layoutRanks` 로 옮기고, 편성 화면은 **랭크만** 넘긴다. 규칙이 둘로 갈리면 두 진영이 다른 모양으로 선다.

**역할 → 랭크 표를 CSV 로 안 뺀다.** 진형이 아직 ⚠ 목업([ADR-0044](0044-진형은-목업이다.md))이라 `monster.csv` 에 컬럼을 늘리면 확정으로 읽힌다. 파티 쪽 템플릿(`app.js:FORM_TPLS`)을 화면에 둔 것과 같은 이유고, 진형이 확정되면 둘이 함께 CSV 로 간다.

**대안 — 적도 두 줄로 그린다.** 안 골랐다. 실측(1280×700)으로 진영 하나가 두 줄이 되면 아래로 41px 넘치고 반대 진영이 아레나 위로 12px 밀려 나간다. 여는 길은 VS 여백(2026-09-08 결정) 되돌리기나 아레나 높이 키우기(가방 자리)뿐이라 **별도 결정**이다.

## 파급

- `.side-enemy` 에도 `data-depth` · 칸마다 `data-rank` · `order` 가 붙는다. CSS 손잡이 `--form-step` 은 `.side-party` 에서 **`.side`** 로 올라갔다(양 진영 공통)
- ⚠ **뱃지 줄 여유를 이제 양 진영이 다 먹는다** — 1280 창 실측 여유가 위아래 각각 21px 이라, `--form-step` 을 올릴 땐 파티 후열과 **적 후열**을 같이 찍는다
- ⚠ 여전히 **자리뿐이다** — 타겟팅·피해·정산은 양쪽 다 진형을 모른다([ADR-0044](0044-진형은-목업이다.md))
- ⚠ `skirmish`(척후)를 **후열로** 놨다 — 가볍고 줄을 지키는 역할이 아니라는 판단이다. 뒤집을 값이면 `ENEMY_BACK_ROLES` 한 줄이다
