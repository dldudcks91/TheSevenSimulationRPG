# ADR-0055 — 가방의 최상위 축은 장비 / 재료다 — 부위 필터를 없앤다

| | |
|---|---|

| **화면** | [SCREEN_DESIGN §6](../SCREEN_DESIGN.md) · [§4-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | — |
| **대체됨** | — |

## 결정

가방을 거르는 최상위 축을 **부위**에서 **갈래**로 바꾼다. 탭은 **「장비」와 「재료」 둘**이고 **「전체」는 만들지 않는다.** 부위 필터(전체 + 부위 7)는 **통째로 없앤다** — 장비 탭 안에도 두지 않는다.

「장비」는 지금까지의 격자 그대로다(칸 상한 `inventory_cap` · 분해 모드 · 비교 툴팁 · 클릭 = 장착). 「재료」는 **종류 하나가 칸 하나**이고 그림 + 개수를 찍는다 — 개체가 아니라 수량이라 **칸 상한을 먹지 않는다.**

## 맥락

가방은 장비만 담는 납작한 목록 하나였고, 거르는 축이 부위 필터(`state.slotFilter`) 하나뿐이었다. 재화는 가방 밖의 `resources`(골드 · 가루 · 낙인)에 숫자로 살면서 셸 머리의 자원 줄이 상시로 찍었다.

같은 날 기획이 **처치는 가루를 안 뱉는다**를 확정하면서 재료 경제를 다시 짜기 시작했고(GAME_DESIGN §9 2026-09-09), 가루 말고도 생산형 파견처 셋(채광 · 채집 · 벌목)이 물어올 재료가 붙을 자리가 필요해졌다. 그런데 화면에는 **재료가 앉을 칸 자체가 없었다.**

## 근거

- **재료를 장비 격자에 섞으면 칸 상한이 망가진다.** `inventory_cap` 은 「좋은 장비를 두고 무엇을 버릴까」를 만드는 압력 장치인데, 수량형 재료가 그 칸을 먹으면 압력이 엉뚱한 데서 온다
- **장비와 재료는 칸의 뜻이 다르다.** 장비는 칸 하나 = 개체 하나(전부 다르게 굴려진다)이고 재료는 칸 하나 = 종류 하나 + 개수다. 같은 격자에 섞으면 칸을 두 가지로 읽어야 한다
- **「전체」를 안 만드는 이유** — 갈래가 둘뿐이면 「전체」는 두 격자를 이어 붙인 세 번째 모양을 만들 뿐이고, 그 모양에서는 위의 「칸의 뜻이 다르다」가 다시 살아난다
- **부위 필터를 남기지 않는 이유** [사용자 지시] — 축을 둘로 겹치면 도구 줄이 두 단이 된다. 부위는 칸 아이콘이 이미 말하고 있고, 정렬·검색이 필요해지는 시점은 부위 수(7)가 아니라 **보유량**이 정한다. 필요해지면 그때 정렬 축으로 다시 연다
- 참고작 Lootun 도 가방을 하나로 뭉치지 않고 성격별(젬 · 유물 · Divine)로 저장 탭을 쪼갠다 (`docs/reference/lootun/03_buildings.md` §6)

## 파급

- `state.slotFilter` 삭제 · `state.bagTab` 신설. **제련소(§8-2)의 `state.forgeFilter` 는 별개 변수라 그대로 둔다** — 거기 부위 필터는 살아 있다
- i18n 신규 둘 — `ch.bag.equip` · `ch.bag.material`. `eq.filter.all` 은 제련소가 계속 쓰므로 **지우지 않는다**
- 관전 화면(§4-2)이 같은 패널을 품으므로 거기서도 탭 둘로 바뀐다 — 함수가 하나라 자동이다
- ⚠ **재료 탭이 지금은 얇다** — 가루 · 낙인 둘뿐이다. 광석 · 약초 · 목재는 이름조차 미정이고(GAME_DESIGN §10 「크래프트 경제 전부 — 백지」), 그게 닫혀야 이 탭이 찬다
- ⚠ **자원 줄과 겹친다** — 셸 머리가 가루 · 낙인을 이미 찍고 있어 같은 값이 두 곳에 뜬다. 머리를 화폐(골드)만으로 좁힐지는 **열린 채로 둔다** — 셸은 이 결정의 범위 밖이다
