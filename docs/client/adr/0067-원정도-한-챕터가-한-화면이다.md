# ADR-0067 — 원정도 한 챕터가 한 화면이다

| | |
|---|---|
| **상태** | 확정 · 2026-09-09 (신설) |
| **화면** | [SCREEN_DESIGN §4-1](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | — *(스테이지 목록의 **범위**만 바꾼다 — 행의 생김새·클릭 동작·전진 패널은 그대로)* |
| **대체됨** | — |

## 결정

원정 스테이지 목록 위에 **챕터 세그먼트**가 서고, 목록은 **고른 챕터 하나**(4스테이지)만 그린다.

- **전 챕터가 선다** — `Ch1 이름` … `Ch7 이름`. 잠긴 챕터도 눌러서 볼 수 있다
- **기본값은 「다음에 갈 곳」** — 해금됐고 아직 안 깬 첫 스테이지의 챕터. 없으면 마지막 해금 챕터
- **챕터를 넘기면 전진 패널이 닫힌다** (`state.expStage = null`)

## 맥락

목록은 **해금된 챕터까지 전부** 한 줄로 폈다. 챕터 1개면 4행이지만 진행할수록 길어져 후반에는 16행 이상이 한 화면에 쌓이고, 「지금 갈 곳」이 스크롤 안에 묻혔다.

**도감 몬스터 세그먼트가 이미 답을 갖고 있었다** — 거기도 「여전히 한 챕터(4스테이지)가 한 화면」이고 챕터 세그먼트로 넘긴다([SCREEN_DESIGN §9](../SCREEN_DESIGN.md)). 원정만 다른 규칙을 쓰고 있었다.

## 왜 잠긴 챕터도 누를 수 있나

이 절은 원래부터 **잠긴 스테이지를 그린다** — 근거가 「어디까지 가야 하는지가 보여야 한다」다. 챕터 세그먼트는 그 범위를 챕터 단위로 넓힌 것뿐이다.

- 잠금을 막는 자리는 이미 있다 — **보내기**가 `canDepart` 로 막는다. 세그먼트에서 한 번 더 막으면 이중 처리다
- 도감이 같은 판단을 먼저 했다 — 「잠금을 그리지 않는다 · 전부 보인다」(2026-09-06)

## 왜 챕터를 넘기면 패널이 닫히나

전진 패널은 **스테이지 행에 딸려** 그 아래로 펼쳐진다. 다른 챕터로 넘어가면 그 행이 화면에서 사라지는데, 고른 값(`expStage`)을 남겨 두면 **영웅 띠는 흐린 채**(파티가 진형 보드에 내려가 있다는 뜻 — [ADR-0058](0058-파티-카드의-반투명은-전진-패널이-열려-있을-때만이다.md)) **보드는 없는** 상태가 된다. 흐림이 가리키는 것이 화면에 없으면 인과가 끊긴다.

## 안 한 것

- **스크롤을 없애지 않았다** — 1280×700 실측에서 **4번째 행은 여전히 잘린다**(행이 배경 아트를 물고 있어 한 행이 ~117px). 줄어든 것은 **한계**다: 진행해도 목록이 4행에서 안 자란다(옛 판은 챕터마다 4행씩 쌓여 후반에 16행 이상이었다). 행 높이를 줄여 4행을 다 담는 것은 배경 아트를 포기하는 것이라 **여기서 정하지 않았다**
- **챕터 세그먼트는 한 줄에 들어간다** — 1280 에서 ko/en 둘 다 Ch1~7 이 접히지 않는 것을 실측했다(영어가 더 길지만 통과한다)
- **고른 챕터를 세이브에 넣지 않았다** — 화면 상태(`state.expChapter`)다. 도감의 `state.codexChapter` 와 같은 취급
