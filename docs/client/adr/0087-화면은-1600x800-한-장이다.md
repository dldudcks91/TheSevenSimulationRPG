## 결정

화면은 **1600×800 한 장**이다. 창이 그보다 크든 작든 **한 장을 통째로** 줄이거나 늘려 창 가운데에 세운다.

- **크기의 SSOT 는 CSS 하나** — `#stage { width: 1600px; height: 800px }`. JS 는 숫자를 적지 않고 `offsetWidth/offsetHeight` 로 읽는다
- **배율** `s = min(창 폭 / 1600, 창 높이 / 800)` — 줄이기 · 늘리기 둘 다, **상한 · 하한 없음**. 한 장은 창 가운데(`translate` 는 반올림) · 남는 가장자리는 전역 배경(`body::before/::after`)이 채운다
- **구조** — `index.html` 의 `#app` · `#tooltip` · `#modal` 이 `#stage` 안으로 들어가고, `app.js:fitStage` 가 부팅 맨 앞(시작 화면도 한 장이다)과 창 크기가 바뀔 때 `transform: translate() scale()` 을 건다
- **좌표 두 곳** — 마우스 좌표로 붙는 것(툴팁 `moveTip` · 진형 드래그 고스트)은 `tip.js:stagePoint` 로 **한 장 단위**가 된다. 드래그의 4px 임계와 `elementFromPoint` 는 창 좌표 그대로다
- **창 크기를 읽는 CSS 는 1600×800 에서의 값으로 고정한다** — `vw` · `vh` · 미디어 쿼리는 한 장이 아니라 실제 창을 봐서, 남겨 두면 창마다 한 장 안의 크기가 흔들린다
- **1280 에 맞춰 줄여 둔 조정은 그대로 둔다** — 1600 에서 안 깨진다. 화면별로 나중에 푼다

## 맥락

폭 정책은 **「상한 1600 / 하한 1280 · 세로 예산 700(1366×768 노트북 기준)」** 이었다(2026-08-23 · src/ui/README.md). 그 사이를 **동시에** 맞추느라 비용이 났다:

- 출정 창의 칸이 화면 폭을 따라 자라는 공식이 붙었다 — `--fm-slot: clamp(96px, 96px + (100vw − 1280px) × 0.07, 124px)`
- 1280 에서 띠 카드가 줄어드는 문제 · 넓은 화면에서 창이 비는 문제
- 리포트 상세가 세로 700 을 넘는다(ADR-0086)
- 도감 스킬 그림 칸(`--ix-art`) · 스킬 창 폭 · 새 게임과 프롤로그의 여백이 각자 `vw`/`vh` 공식을 들었다

웹 화면(DOM/CSS)은 Phase 2 이식에서 버려지고 **SCREEN_DESIGN 만 넘어간다**(CLAUDE.md 아키텍처 원칙).

## 근거

- **엔진이 같은 방식이다** — Godot 의 stretch · Unity 의 Canvas Scaler 가 「기준 해상도 + 배율」이라, 문서에 적힌 수치가 이식 뒤에도 **그대로** 뜻을 갖는다
- **세로를 900 이 아니라 800 으로** — 윈도우 브라우저는 탭 · 주소창 · 작업표시줄이 세로를 약 130px 먹어, **노트북에서는 세로가 배율을 정한다**. 대략값:

  | 화면 | 900 기준 | 800 기준 |
  |---|---|---|
  | 1920×1080 · 배율 100% | 105% | 118% |
  | 1920×1080 · 배율 125% | 81% | 91% |
  | 1366×768 | 71% | 80% |

- **`transform` 을 고른 이유** — 고정 위치 자손(툴팁 · 창 레이어 · 드래그 고스트)의 기준이 한 장이 되는 동작이 **명시적**이다. 창 레이어가 한 장만 덮는 것도 의도다(가장자리 여백은 눌러도 아무 일 없다). 대가는 마우스 좌표 두 곳의 환산이고, 그것이 `stagePoint` 하나다

**버린 안**

1. **「1600 만 만들고 아래 해상도는 나중에」** — 1920×1080 배율 125% 가 CSS 폭 1536 이라 **첫날부터 기준 밖**이다. 「나중에」는 화면마다 쌓이는 빚이다
2. **1600×900** — 노트북(1920×1080 · 배율 125%)에서 글자가 81% 로 준다
3. **CSS `zoom`** — 골랐다면 좌표 보정 방식이 달라진다

## 파급

- `index.html` — `#stage` 신설(`#app` · `#tooltip` · `#modal` 이 그 안) · `style.css` 셸 절 — `html, body { height: 100%; overflow: hidden }` · `#stage` 신설 · `#app` 의 `height: 100vh` · `max-width` · `min-width` · `margin` → `height: 100%`
- `app.js:fitStage` 신설 · `tip.js:stagePoint` 신설(export) — `moveTip` 과 `app.js:bindFormDrag` 가 그것을 거친다(고스트는 `#stage` 에 붙는다)
- **창 크기 CSS 12곳 고정** — `--fm-slot` 118 · `#app` 100% · 나눔 배치 아레나 304 · 스킬 창 폭 1508 · `--ix-art` 48 · 새 게임 · 프롤로그 여백 7곳. **미디어 쿼리 2곳 삭제**(제련소 `.fg-work` · `.fg-split`)
- 검증 해상도가 **1600×800**(배율 1)이 된다 — 배율 확인은 1280×700 · 1920×1080 (`.claude/skills/ui/verify.md`)
- src/ui/README 「화면 폭 정책」 → **「화면 크기 정책」** · SCREEN_DESIGN 에서 창 크기에 따라 달라진다고 말하던 문장은 1600×800 실측으로
- 그날 1600×800 실측으로 `.main` 이 스크롤하는 화면 — 선술집 65 · 자원 25 · 탐험 56 · 캐릭터 79 · 관전(넓게) 132px. 고정값이 1600×800 창에서의 공식값이라 그 창에서는 고치기 전과 배치가 같다
- ⚠ **열린 것** — **1280 용 조정이 남아 있다**(선술집 카드 · 관전 헤드 등 — 화면별로 푼다) · **최소 배율이 없다**(작은 노트북에서 글자가 작아진다 — 필요하면 그때 정한다)
