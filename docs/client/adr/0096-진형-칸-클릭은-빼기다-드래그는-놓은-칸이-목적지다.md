# ADR-0096 — 진형 칸 클릭은 파티에서 빼기다 · 드래그의 목적지는 놓은 그 칸이다

| | |
|---|---|
| **상태** | 확정 · 2026-09-11 (신설) |
| **화면** | [SCREEN_DESIGN §4-1](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (「재클릭하면 거기서 삭제, 드래그하면 위치 변경」) |
| **대체** | — *(옛 규칙은 ADR 이 아니라 §4-1 진형 행과 `game.placeFormation` 의 계약에 있었다)* |
| **대체됨** | — |

## 결정

출정 창의 진형 보드에서 두 동사를 고친다.

- **칸 클릭 = 그 영웅을 파티에서 뺀다.** 띠 카드를 다시 누른 것과 같은 문(`game.toggleParty`)이다. 빈 칸은 안 눌린다
- **드래그의 목적지는 놓은 그 칸이다.** 주인이 있으면 **그 주인과** 자리를 맞바꾸고(같은 줄 안에서도), 비었으면 그 줄로 옮긴다. 벤치 영웅을 주인 있는 칸에 놓으면 주인이 파티에서 나가고 새 영웅이 **그 칸**에 앉는다

「클릭은 소속 · 드래그는 자리」는 그대로다 — 클릭이 서는 곳이 띠 하나에서 **띠와 칸 둘**이 됐을 뿐이다.

## 맥락

2026-09-11 사용자 지적 — 「한번 진형에 들어간 영웅이 다른 영웅으로 교체가 되지 않는다」. 헤드리스 Edge 에서 영웅 5명 세이브로 눌러 잰 그날의 동작:

| 해 본 것 | 결과 |
|---|---|
| 진형 칸의 영웅 클릭 | 아무 일도 없다 |
| 파티가 찬 채 벤치 영웅 클릭 | 「파티 정원」 플래시 |
| 칸 → 같은 줄의 다른 칸 드래그 | 아무 일도 없다 |
| 후열 → 전열 첫 칸 드래그 | 첫 칸 주인이 아니라 **전열 마지막**과 바뀐다 |
| 벤치 → 전열 첫 칸 드래그 | 주인은 나가지만 새 영웅이 **둘째 칸**에 앉고 옆 영웅이 첫 칸으로 당겨진다 |

빼는 길이 띠 카드 하나였고, 드래그는 `game.placeFormation(state, uid, rank)` 이 **랭크만** 받아 칸 번호를 버렸다 — 정원이 찼으면 「그 랭크의 마지막 하나와 맞바꾼다」(2026-09-09 · 거절보다 맞바꿈이 인과를 읽힌다는 근거).

같은 보고에 편성 띠의 반투명([ADR-0058](0058-반투명은-전진-패널이-열려-있을-때만이다.md))이 꺼져 있던 것도 실렸다 — CSS 주석 사고였고 버그라 [DEV_PLAN §4 #40](../DEV_PLAN.md) 이 든다.

## 근거

**보드가 자리의 실물이면 거기서 뺄 수 있어야 한다.** 파티가 차 있으면 새 영웅의 클릭은 거절된다 — 교체는 「하나 빼고 하나 넣기」인데, 빼는 손이 보드가 아니라 위 띠로 올라가야 했다.

**놓은 칸과 결과가 다르면 드래그가 아니다.** 첫 칸에 놓았는데 다른 영웅이 움직이면 「어디에 놓는가」가 결과를 안 정한다. 맞바꿈의 원 근거(거절보다 인과가 읽힌다)는 **누구와 바뀌었는지가 보일 때만** 선다 — 놓은 칸의 주인과 바뀌어야 그것이 보인다.

**대안 — 칸 클릭 = 고르기(고른 뒤 다른 칸을 눌러 옮긴다).** 안 골랐다. 지시가 「재클릭 = 삭제」이고, 이 창에서 클릭은 이미 소속의 동사다(띠). 같은 창 안에서 클릭이 두 뜻을 가지면 「눌렀더니 빠졌다」와 「눌렀더니 골라졌다」를 가를 표시가 따로 필요해진다.

**대안 — 벤치 드래그의 교체를 걷기(드래그 = 자리만).** 안 골랐다. 「띠 카드 → 주인 있는 칸 = 교체」는 09-09 부터 선 규격이고, 지시는 **파티에 든 영웅**의 동사를 말했다. 걷으면 교체가 클릭 두 번(빼기 · 넣기)으로만 남는다.

**빈 칸은 줄 끝에만 선다 — 구멍을 안 만든다.** 칸 번호를 받게 됐어도 줄은 앞부터 찬다(`normalizeFormation`). 빈 칸에 놓으면 그 줄 끝으로 가고, 칸을 빼면 같은 줄의 뒤가 당겨진다. 구멍을 허용하려면 세이브의 `ranks` 가 빈 자리를 들어야 하는데, 전투는 줄만 읽으므로 얻는 것이 없다.

## 파급

- `game.placeFormation(state, uid, rank, idx?)` — **선택 인자 `idx`** ([INTERFACE §2-7](../INTERFACE.md)). 안 주면 옛 동작(랭크 마지막과 맞바꿈) 그대로 · rng 0 · 세이브 무관 · 단정 +1
- `ui/app.js` — `formDrop` 이 칸 번호를 넘기고, `formBox` 의 찬 칸에 `onclick`(끈 뒤의 클릭은 `formDragEnded` 로 삼킨다 — 띠와 같다)
- CSS · i18n 무변동 — 칸의 커서는 `grab` 그대로다
- ⚠ **같은 줄 안의 순서는 보드에만 선다** — 전투는 줄(랭크)만 읽고, 관전 아레나의 가로 차례(`battle.js:layoutRanks`)는 **파티 순서**를 따른다. 보드에서 같은 줄의 두 영웅을 맞바꿔도 아레나의 좌우는 안 바뀐다
- ⚠ 벤치 영웅을 주인 있는 칸에 끌었는데 새 영웅의 입대가 거절되면(`searching`) **주인은 이미 빠진 채** 남는다 — `formDrop` 이 주인을 먼저 내보내는 순서 탓이고, 이 결정 전부터 그랬다
