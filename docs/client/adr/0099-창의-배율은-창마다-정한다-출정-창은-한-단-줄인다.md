## 결정

- **창은 메인 배율을 물려받지 않고, 배율을 창마다 정한다.** 창은 한 장 직속이라 정하지 않은 창은 100% 다
- **출정 창은 줄인다** — 창 전체(판 · 칸 넷 · 글자)에 배율 `.9` 를 건다. 띠 카드가 **캐릭터 탭의 띠 카드와 같은 크기**로 보인다. 값의 SSOT 는 [src/ui/README.md](../../../src/ui/README.md) 크기 정책
- 스킬 트리 · 해고 창은 100% 그대로다 — 지시는 출정 창 하나였다
- 메인과 **같은 값이지만 한 변수로 묶지 않는다** — 메인 배율이 바뀌어도 출정 창은 제 값을 지킨다

## 맥락

그날 1600×800 실측 — 캐릭터 탭의 띠 카드는 메인 배율 안이라 **108×109**, 출정 창의 띠 카드는 창 레이어라 **120×122** 로 보였다. 같은 카드 규격(`.hs-card` 상한 120)인데 배율 한 겹 차이다. 창은 1520×548, 진형 · 적 칸은 118.

[ADR-0090](0090-메인은-한-번-더-줄인다-줄어든-폭은-탭-내비가-갖는다.md) 은 「안 줄이는 것」 목록에 창 레이어를 넣고, 「창(100%)과 탭(90%)의 글자 크기가 갈린다」를 열린 것으로 남겼다. 이 조항을 확정 사항으로 경고했더니, 사용자가 **그날 목록에 딸려 들어간 것이지 창 크기를 정한 결정이 아니며 창마다 직접 정한다**고 답했다.

## 근거

**같은 부품은 같은 크기로 읽혀야 한다.** 띠는 캐릭터 탭과 같은 카드라서 같은 규격을 쓴다(§5 · 2026-09-10 에 창 안 특례 160 을 철회한 이유). 그런데 배율 한 겹 때문에 출정 창에서만 11% 크게 보였다.

**카드만 줄이지 않고 창을 통째로 줄인다.** 대안은 창 안에서만 띠 카드 상한 108 · `--fm-slot` 106 처럼 숫자를 따로 두는 것이었다. 안 골랐다 — 09-10 에 걷은 창 안 특례가 되살아나고, 글자 · 여백은 그대로라 창이 거의 안 준다. 배율 한 줄이면 판 · 칸 · 글자가 같은 비로 준다.

**메인과 한 변수로 묶지 않는다.** 묶는 안도 냈다(메인 배율을 바꾸면 출정 창만 어긋나는 것을 막는다). 안 골랐다 — 묶으면 「창마다 정한다」가 깨진다. 메인이 바뀔 때 출정 창도 따라갈지는 그때 정한다.

## 파급

- `style.css` `.modal-box.depart-box` 에 `zoom` — 그날 실측 판 1520×548 → 화면 1368×493 · 띠 카드 108×109 · 진형 / 적 칸 106 · ko/en 넘침 0
- `app.js:bindFormDrag` — 고스트가 **감싸개 + 클론**이 됐다. 클론은 레이아웃 크기 그대로 두고 보이는 폭 ÷ 레이아웃 폭만큼 `zoom`, 위치는 감싸개가 든다. 안 고치면 고스트가 레이아웃 폭(118)으로 서서 원본(106)보다 11% 컸다
  - 같이 드러난 결함 — **띠 카드에서 끈 고스트가 안 보였다.** 클론에 단 `.fm-ghost { position: fixed }` 를 뒤에 선언된 `.hs-card { position: relative }` 가 이겨 한 장 아래(+800px)로 떨어졌다. 배율과 무관하게 이전부터였고 버그라 [DEV_PLAN §4 #41](../DEV_PLAN.md) 이 든다
- SCREEN_DESIGN §2 「메인」의 안 줄이는 것 목록 · 「창 레이어」 · §4-1 출정 창 · src/ui/README 크기 정책
- ⚠ 출정 창과 다른 창(스킬 트리 · 해고)의 글자 크기가 갈린다 — 창마다 정한다는 결정의 결과다
- ⚠ 판 폭 1520 · 칸 118 은 **설계 크기**로 남는다 — README 의 설계 px 와 화면 px 가 이 창에서도 갈린다(메인과 같은 사정)
