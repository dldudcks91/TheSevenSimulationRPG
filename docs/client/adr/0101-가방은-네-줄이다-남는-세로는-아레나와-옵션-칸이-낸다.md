# ADR-0101 — 가방은 네 줄이다 · 남는 세로는 아레나와 옵션 칸이 낸다

## 결정

가방은 **네 줄**이다. **칸과 그림 크기는 안 바뀐다** — 가로 **24열 · 한 변 52 · 그림 40** 그대로고, 네 줄은 **칸 수**가 만든다: `[balance.csv:inventory_cap]` **70 → 96**(24 × 4). 관전과 캐릭터 탭이 같은 크기인 것도 그대로다.

한 줄 자란 몫(가방 219 → **275**)은 **위가 낸다** — 관전에서는 **아레나**(502 → 446), 캐릭터 탭에서는 **네 칸**(412 → 356)이다. 캐릭터 탭에서 **양보하는 쪽이 뒤집혔다** — 종전엔 네 칸이 하한 412 를 지키고 가방 칸이 가방 안에서 스크롤했는데, 이제 **가방이 제 높이를 받고 네 칸이 칸 안에서 스크롤한다**. 내용이 356 보다 긴 칸(기본 옵션 388)은 아래쪽이 스크롤 아래로 들어간다.

## 맥락

사용자 요청 — **「원정-전투와, 캐릭터창의 아이템창을 4칸으로 바꿔줄 수 있을까? 1. 원정-전투에서는 위 전투 씬 높이를 맞춰서 줄이고 2. 캐릭터 창에서는 위의 옵션쪽 높이를 줄여줘」**.

그날 1600×800 실측(설계 px) — 가방 24열 × **3줄** · 칸 52 · 그림 40 · 높이 219(칸 수 70 = 24 × 2.9). 관전 아레나 1337×502(넓게) · 989×502(나눔) · 캐릭터 탭 네 칸 412(내용 하한 401 — 기본 옵션 칸: 막대 7 + 범위 + 액티브 스킬 + [스킬 트리 열기]).

작성자는 이것을 **「칸을 키워 4줄을 만든다」**(18열 · 칸 70 · 그림 54)로 읽고 그렇게 구현했다. 사용자 지적 둘로 되돌렸다 — **「각 아이템 크기는 건드렸으면 안되는데 왜 키운거야」**(그림 54 → 40) · **「원래 40x40에 3칸일때 가로에 24칸이 들어갔는데 지금은 18칸씩 들어가있잖아 · 가로에 24칸이 들어가도록 해줘야지」**(칸 70 → 52 · 18열 → 24열). 「4칸」은 **칸 크기가 아니라 줄 수**였고, 24열에서 4줄이 되려면 칸 수가 73 이상이어야 해서 확인을 구했다 — 답이 **「24칸에 4줄이니까 일단 96으로 만들어 나중에 수정할게」**.

## 근거

- **「N칸」은 격자의 줄 수다** — 칸 크기는 유저가 보는 아이템 그림의 크기라 배치 작업이 건드릴 축이 아니다. 폭(24열)이 유지돼야 같은 가방으로 읽힌다
- **줄 수를 만드는 것은 CSS 가 아니라 칸 수다** — 격자는 `inventory_cap` 개를 그린다. 24열에서 70칸은 3줄(마지막 22칸)이고, 4줄은 73칸부터다. 빈 4번째 줄을 CSS 로 그리면 **없는 칸을 있는 것처럼** 보여준다
- **96 = 24 × 4** — 줄이 딱 떨어져 마지막 줄에 빈 꼬리가 안 남는다. 상한은 「무엇을 버릴까」를 만드는 압력 장치라([ADR-0055](0055-가방의-최상위-축은-장비-재료다.md)) 값 자체는 기획이 다시 볼 수 있다(사용자 「일단 … 나중에 수정할게」)
- **관전은 값이 공짜다** — 아레나는 남는 세로를 먹는 칸이라(ADR-0095) 가방이 자라면 저절로 줄고, 446 은 하한 350 위다
- **캐릭터 탭은 누가 양보할지의 문제였다** — 박스 세로는 못 늘린다(ADR-0097). 가방이 4줄을 받으면 네 칸이, 네 칸이 하한을 지키면 가방이 준다. 사용자가 **「옵션칸을 일단 줄여봐 · 아닌 것 같으면 롤백하게」**로 전자를 골랐다
- **스크롤 위치는 되찾는다** — 네 칸이 스크롤 자리가 되면 [스킬 트리 열기]까지 내려간 뒤 무엇을 눌러도 맨 위로 튄다. `data-keep`(ADR-0097 의 장치)을 네 칸과 세부 옵션 목록에 달았다

**버린 안**

1. **칸을 키워 4줄**(18열 · 칸 70 · 그림 54) — 같은 날 구현했다가 사용자 지시로 되돌렸다. 가로 칸 수가 24 → 18 로 줄어 같은 가방으로 안 읽히고, 아이템 그림까지 커졌다
2. **칸 수를 그대로 두고 빈 줄을 CSS 로 만든다** — 못 쓰는 칸이 그려진다. 가방의 `n / cap` 표기와도 어긋난다
3. **네 칸을 `overflow: hidden` 으로 자른다** — 숨은 [스킬 트리 열기]에 닿을 길이 없어진다. `auto` 면 휠로 닿는다(막대는 §2 로 안 그린다)
4. **칸 안의 `overflow-y` 만으로 네 칸을 줄인다** — 안 줄어든다. 1fr 행의 바닥을 잡고 있는 것은 칸이 아니라 **칸들을 담은 격자**(`.cols.c-char`)여서, 그 격자에 `min-height: 0` 이 있어야 가방이 제 높이를 받는다(09-11 실측)
5. **기본 옵션 칸을 먼저 개편해 내용을 356 안에 넣는다** — 아무것도 안 숨는 유일한 안이지만 이번 작업이 캐릭터 탭 개편까지 번진다. 사용자가 「일단 줄여보고 롤백」을 택했다

## 파급

- `balance.csv` — `inventory_cap` **70 → 96** (⚠ 기획 값이다 · 사용자 「일단 … 나중에 수정할게」)
- `style.css` — `.cols.c-char` 에 `min-height: 0` · `.cols.c-char > .panel` 하한 412 → **0 + `overflow-y: auto`** · `.char-stack > .bag > .inv-cells` 가 제 높이(`flex: 0 0 auto`). **가방 칸 · 그림 크기는 무변동**
- `app.js` — 네 칸과 세부 옵션 목록에 `data-keep`(`char-gear` · `char-attr` · `char-cs1` · `char-cs2`)
- SCREEN_DESIGN §4-2 가방 · §6 머리말 · 네 칸 · 세부 옵션 1·2 · 가방 · [src/ui/README.md](../../../src/ui/README.md) 크기 정책
- **i18n · 세이브 · 재생기 · 전투 로직 무변동**
- ⚠ **열린 것**
  - **기본 옵션 칸의 액티브 스킬 카드와 [스킬 트리 열기] 가 기본 화면에서 안 보인다** — 휠로 내려야 나온다. 스킬 트리로 가는 유일한 버튼이다
  - **세부 옵션 1 은 13행 중 12행**만 선다 — §6 의 「21행을 두 칸에 나눠 스크롤 없이」가 깨졌다
  - **넘친다는 표시가 없다** — 막대를 안 그리므로(ADR-0097) 칸 아랫변에서 잘린 내용만이 신호다
  - **가방 상한 96 은 임시값이다** — 드롭 압력 · 분해 경제가 이 값을 읽는다(item_design §5)
  - **골든 스냅샷은 다시 찍어야 한다** — `meta.balance` 가 칸 수를 든다. 09-11 15:40 현재 `golden.json` 은 다른 세션의 작업 중이라 이 작업에서 찍지 않았다

> ⚠ **2026-09-11 철회** — 사용자 지시(「오늘 3칸인거 4칸으로 늘린거 … 롤백해줄 수 있어?」)로 **같은 날 전부 되돌렸다** — 가방은 24열 × **3줄**(칸 수 70) · 캐릭터 탭 네 칸은 하한 **412** · 관전 아레나 502. 코드 · 문서 · `balance.csv` 모두 09-11 이전 상태다. 아래 정정 기록과 본문은 그날의 사실로 남긴다.

> ⚠ **2026-09-11 정정** — 이 파일의 첫 판은 결정을 **「18열 · 칸 70 · 그림 54 로 키워 4줄」**로 적었다. 그것은 사용자 지시가 아니라 작성자의 오독이었고, 같은 날 지적 둘(「각 아이템 크기는 건드렸으면 안되는데」 · 「가로에 24칸이 들어가도록」)로 되돌려 **커밋 전에** 본문을 실제 결정으로 다시 썼다. 버려진 그 안은 위 「버린 안 1」에 남는다.
