## 결정

스테이지 레벨(화면 어휘로 **위험도**)을 바꾸는 자리는 **출정 창 오른쪽 아래 「출정 방식」 칸의 맨 위**다 — 칸 이름 바로 아래, 경고 줄 · 반복 원정 · 보내기보다 위.

- 윗줄 = 「위험도」 + 잔글씨 범위(`기본 ~ 최대`) · 아랫줄 = `«` `‹` **지금 레벨** `›` `»`
- `‹` `›` = 1씩 · `«` = 기본 레벨로 · `»` = 최대로. 끝에 닿은 쪽 버튼은 흐려진다
- 올린 레벨이면 숫자가 **강조색**이다. 창 머리 잔글씨와 스테이지 목록 행의 위험도도 **지금 레벨**을 찍고, 목록은 올린 스테이지의 숫자를 같은 강조색으로 찍는다
- 못 올리는 상태(아무것도 안 깬 초반 · 최대가 기본과 같을 때)에서도 **줄은 선다**
- 규칙 한 줄은 「위험도」 라벨과 숫자의 툴팁이 들고, 도움말(§12) 원정 섹션이 같은 키를 재사용한다

## 맥락

그날 base_expedition_design §1-4 가 던전 레벨 조절을 확정했고(범위 = 기본 레벨 ~ 클리어한 최고 레벨 · 1레벨 단위 · 비용 없음 · 되돌리기 자유), 같은 날 로직이 들어왔다(`state.stageLevelState` · `setStageLevel` · DEV_PLAN R87). 해금은 기획서에 「2장 진입」으로 적혀 있었으나 사용자가 **「처음부터 열어 두고 나중에 연구로」**로 바꿨다. 난이도 3단은 보류됐다(사용자가 구성을 정해 넣는다).

화면에는 위험도(= `stage.csv:dlvl`)가 스테이지 행 부제와 출정 창 머리 잔글씨에 **읽기 전용**으로만 찍혀 있었다. 출정 방식 칸은 칸 이름 · 경고 줄 · 버튼 둘(반복 원정 · 보내기)이 세로로 쌓인 칸이었다.

## 근거

- **출정 방식 칸인 이유** — 레벨은 「어떻게 갈까」의 선택이고, 보내기 바로 위라 **고른 레벨로 떠난다**가 한 칸 안에서 읽힌다
- **창 머리에 붙이지 않은 이유** — 머리는 목록에서 떨어져 뜬 창이 무엇에 딸렸나를 말하는 **신원 줄**이다(ADR-0084). 결정이 들어가면 그 역할이 흐려진다. 머리는 값만 따라간다
- **스테이지 목록 행에 붙이지 않은 이유** — 행 클릭이 곧 창을 여는 동사라(ADR-0084) 행 안 버튼은 클릭이 겹치고, 행 높이는 배경 아트 때문에 못박혀 있다(ADR-0080). 목록은 **어디를 올려 뒀나**만 강조색으로 알린다
- **버튼이 넷인 이유** — 기획 단위가 1레벨이라 `‹` `›` 가 기본인데, 범위가 챕터 여럿에 걸치면 수십 번 눌러야 한다. 기획이 「언제든 · 비용 없이 되돌린다」라 기본 레벨로 가는 길이 한 번에 닿아야 하고, 그 짝으로 최대도 한 번에 닿는다
- **줄이 늘 서는 이유** — 창 크기는 상태에 흔들리지 않는다(§4-1 · 2026-08-28). 못 올릴 때 줄이 사라지면 칸이 줄었다 늘었다 한다
- **기호를 쓰는 이유** — 진형 템플릿 아이콘과 같이 언어 중립이고, 뜻은 버튼의 `title` 이 든다. 기호 칸이 영어 길이에 안 매인다

**버린 안**

1. **창 머리 줄 안의 조절기** — 신원 줄에 결정이 섞인다(위)
2. **목록 행 안의 조절기** — 행 클릭과 겹치고 행 높이가 못박혀 있다(위)
3. **숫자 입력칸** — 게임 화면에 텍스트 입력 문법이 없다(시작 화면의 이름 입력도 없다)
4. **`‹` `›` 둘만** — 챕터 여럿을 건너뛸 때 클릭 수가 레벨 차만큼 든다
5. **`Shift`+클릭 = 10씩** — 보이지 않는 조작이라 알려줄 자리가 도움말뿐이다
6. **해금 전에는 줄을 숨긴다** — 해금 조건이 없어졌고, 숨기면 창 크기가 흔들린다
