# ADR-0124 — 제련소는 제작 · 강화 · 크래프트 세 칸을 좌우로 나란히 둔다

| | |
|---|---|
| **상태** | 확정 · 2026-09-15 |
| **화면** | [SCREEN_DESIGN §8-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 제안 — 사용자 지시(크래프트는 「지금은 그냥 탭만 만들어봐」)의 화면 처리. 사용자가 뒤집을 수 있다 |
| **대체** | — |
| **대체됨** | [ADR-0142](0142-제련소는-제작-강화-크래프트를-위쪽-탭으로-가른다.md) (2026-09-15) |

## 결정

강화 탭(제련소)의 작업 칸을 **제작 · 강화 · 크래프트 셋**으로 늘리고, 셋을 **좌우로 나란히** 박스 끝까지 세운다. 칸을 고르는 세그먼트는 두지 않는다. 칸 안의 「목록 | 작업 패널」 2단은 세로로 접힌다. 크래프트 칸은 로직이 없어 제목 + 「미착수」 배지 + 안내만 선다.

## 맥락

2026-09-15 기획이 제련소의 작업을 셋으로 확정했다(GAME_DESIGN §9 09-15 — 제작은 장비를 새로 만들고 · 강화는 베이스 능력치를 올리고 · 크래프트는 매직 장비에 옵션을 붙인다). 옵션강화는 폐기됐다.

그날 규격의 §8-2 표는 「세그먼트 2 — `제작` / `강화`」라고 적고 있었지만, 화면은 2026-09-03 사용자 요청 시안으로 **좌우 두 박스**(제작 | 강화)가 서 있었다 — `style.css` 주석이 「제련소 시안 — 세그먼트 대신 좌우 두 박스 · 개정 검토 중」이었고, §2 박스 표도 「제작 · 강화 두 칸이 박스 끝까지 선다」로 시안 쪽을 적었다. 규격 안에서 두 문장이 갈려 있었다.

## 근거

- **시안의 방향을 잇는다** — 사용자가 고른 것은 「한 화면에 같이 놓는다」였다. 세그먼트로 되돌리면 그 선택을 뒤집는다. 칸을 하나 더 세우는 것이 시안의 확장이다
- **크래프트가 제 칸을 갖는다** — 「탭만」을 **제 이름의 칸 하나**로 받는다. 강화 칸 안에 크래프트 블록을 넣는 안(옛 옵션강화 블록 자리)은 **가진 장비 목록을 공유한다**는 이점이 있었지만, 크래프트가 제 자리를 잃고 대상(매직만)이 강화의 대상(목걸이 · 반지 제외)과 달라 한 목록에 두 판정을 겹쳐야 했다
- **세그먼트 3 안을 버린 이유** — 작업마다 폭을 온전히 쓰는 이점은 있지만, 그날 셋 중 둘이 미착수라 세그먼트를 넘기면 대부분 빈 화면이다. 칸이 좁아지는 비용은 **제작 · 크래프트 칸에 실제 목록이 들어설 때** 다시 본다
- 폭이 줄어도 강화 칸은 이미 「목록 | 작업 패널」을 세로로 접고 있었다(시안 때 절반 폭에서 접었다) — 새로 접을 것이 없다

## 파급

- CSS — `.fg-split` 이 세 칸 격자가 된다 · 시안 주석(「개정 검토 중」)을 걷는다 · 쓰는 곳이 없어진 `.fg-opts` 를 걷는다
- i18n — `fg.seg.craft` 의 뜻이 **제작 → 크래프트**로 옮기고 제작은 `fg.seg.make` 가 든다
- app.js — 화면 상태 `forgeSeg`(쓰이지 않던 세그먼트 자리)를 걷는다
- 강화 칸 패널의 옵션강화 블록(`fg.opt.h` · `fg.optGo` · `fg.noAffix`)과 소제목 `fg.plus.h` · 플래시 `ch.upgraded.affix` 를 걷는다 — 기획 폐기(옵션강화 · 옵션 계단)에 따른 삭제다
- ⚠ 제작 칸이 실제 목록을 받는 날(DEV_PLAN R96) 폭이 모자라면 이 결정을 다시 연다
