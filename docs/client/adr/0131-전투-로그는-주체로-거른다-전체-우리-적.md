## 결정

나눔 보기의 **로그 판 위에 탭 셋 — 전체 · 우리 · 적**. 줄을 **주체**(그 일을 한 쪽)로 거른다.

- 타격 · 치명 · 빗나감 · 반사 · 회복 = 한 쪽(반사는 되받아 친 쪽) · **처치 = 우리 · 전투불능 = 적** · 창(버프 · 방벽 · 종료) = 걸린 유닛 쪽 · 라운드 시작 · 종료 = 셋 다
- 탭은 로그 판에만 선다 — 누적 데미지 판은 이미 파티 / 적 두 묶음이다
- 탭은 **거르기만** 한다 — 줄은 다 쌓이고, 남기는 줄 수는 주체마다 센다
- 고른 탭은 재생 위치(`logf`)에 실려 재렌더 · 반복 원정을 넘는다

## 맥락

그날 로그는 모든 타격을 한 목록에 한 줄씩 쌓았고, 60줄을 넘으면 오래된 줄부터 지웠다. 파티 셋이 치는 줄과 적이 치는 줄이 섞여 「적이 얼마나 세게 치나」를 보려면 파티 줄 사이에서 골라 읽어야 했다.

로그 위 탭으로 무엇을 넣을지 물은 사용자에게 **획득 탭**(이번 원정의 드롭 · 경험치)과 **받은 피해 전환**을 제안했고, 사용자가 그것은 리포트가 들고 관전의 로그는 「얼마나 치나」를 보는 자리라고 정했다.

## 근거

- **관전의 로그는 「얼마나 치나」를 읽는 자리다** — 획득 · 경험치 · 받은 피해 합계는 원정이 끝난 뒤 리포트가 든다(ADR-0123). 관전에 같은 표를 또 두지 않는다
- **주체로 가른다** — 「우리가 얼마나 치나(화력)」와 「적이 얼마나 치나(위협)」는 다음 행동이 다르다(공격 장비 / 방어 · 진형). 맞은 쪽으로 가르면 같은 질문에 답하지 못한다
- **처치는 우리 · 전투불능은 적** — 쓰러짐 이벤트에는 친 쪽이 없다. 적이 쓰러진 것은 우리 타격의 결과이고, 파티가 쓰러진 것은 적 타격의 결과다
- **라운드 줄은 셋 다** — 거른 목록에서도 몇 라운드인지 끊어 읽혀야 한다
- **줄 수는 주체마다** — 한 목록에서 세면 파티 셋의 줄이 적의 줄을 밀어내 「적」 탭에 몇 줄만 남는다
- **거르기는 CSS 가 한다** — 줄마다 주체를 달아 두고 목록의 표시만 바꾼다. 탭마다 다시 그리면 쌓아 둔 줄과 스크롤이 날아간다

**버린 안**

1. **획득 탭 · 받은 피해 전환** — 리포트가 든다(사용자)
2. **맞은 쪽(대상)으로 가른다** — 사용자가 주체로 정했다

## 파급

- `battle.js` — `.log-filter`(버튼 `.b-logf` · `data-f`) · `pushLog` 가 줄에 `data-side`(party / enemy / sys)를 달고 주체마다 최근 줄만 남긴다 · `state.logf` · `paintPane` 이 탭의 표시와 목록의 `data-f` 를 칠한다
- 재생 위치에 `logf` — `{t, speed, running, tab, logf, wall, auto}` (`ui_conventions.md`)
- i18n `bt.logf.all` · `bt.logf.party` · `bt.logf.enemy` · CSS `.log-filter` · `.battle-log[data-f] li[data-side]`
- 개발용 `?dev=play&logf=party|enemy` (SCREEN_DESIGN §10 · src/dev/README)
- `game_logic` · 세이브 · 단정 무관
- ⚠ 열린 것 — 「전체」 목록의 맨 위(오래된 쪽)는 주체마다 남는 줄 수가 달라, 한쪽 줄이 먼저 끊겨 보일 수 있다
