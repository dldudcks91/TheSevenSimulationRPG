# ADR-0136 — 캐릭터 탭 영웅 띠는 드래그로 두 영웅의 자리를 맞바꾼다

| | |

| **화면** | [SCREEN_DESIGN §5](../SCREEN_DESIGN.md) 「순서 바꾸기」 · §6 |
| **정한 사람** | 사용자 지시 |
| **대체** | — |
| **대체됨** | — |

## 결정

캐릭터 탭 상단 영웅 띠에서 카드를 끌어 다른 영웅 카드에 놓으면 **두 영웅의 자리를 맞바꾼다.** 순서는 세이브 값(`state.heroes` 의 배열 순서 · `game.swapHeroes`)이라 출정 창의 띠도 같은 순서로 선다. 클릭은 그대로 「영웅 고르기」이고, 끈 뒤의 클릭 한 번은 삼킨다.

## 맥락

사용자가 「캐릭터 화면의 캐릭터를 드래그하면 서로 위치를 바꿀 수 있도록」 지시했다. 이날 띠의 순서는 로스터에 들어온 순서(시작 파티 → 고용 · 수색) 그대로였고 바꿀 길이 없었다. 드래그는 출정 창에만 있었다 — 띠 카드 · 진형 칸을 진형 보드로 끌어 **진형 자리**를 정하는 손이다(ADR-0096 · 고스트는 ADR-0099).

## 근거

- **맞바꾸기이지 끼워 넣기가 아니다** — 지시가 「서로 위치를 바꾼다」였다. 진형의 칸 → 칸 드래그도 주인이 있으면 맞바꾸므로(ADR-0096) 같은 손이 같은 결과를 낸다
- **순서를 화면 상태가 아니라 세이브에 둔다** — 화면 상태면 새로고침마다 풀리고 「두 자리가 같은 띠 · 같은 순서」(§5)가 깨진다. 순서 배열을 따로 두는 안은 버렸다 — 영웅이 늘고 줄 때마다 두 목록을 맞춰야 한다. `heroes` 배열 순서가 곧 띠 순서였으므로 그 배열을 바꾼다
- **파티 · 리더 · 진형은 안 따라온다** — 리더는 `party[0]`, 자리는 `formation` 이 따로 든다. 로스터 순서에 묶으면 띠를 보기 좋게 줄 세우려다 리더가 바뀐다
- **편성 띠에는 안 건다** — 거기서 드래그는 이미 진형 자리다. 한 띠에서 같은 손이 두 뜻을 가지면 놓기 전까지 무엇이 일어날지 못 읽는다
- **드래그 손은 편성과 하나다** — 고스트 · 임계 · 클릭 삼키기를 한 함수가 들고 진형과 띠는 놓을 곳만 다르게 준다. 따로 짜면 한 장 배율(ADR-0087) · 창 배율(ADR-0099) 보정이 한쪽만 고쳐진다

## 파급

- `game.swapHeroes` 신설([INTERFACE §2-7](../INTERFACE.md)) · 세이브 스키마 무변경 · 단정 1
- `app.js` — `bindFormDrag` 의 몸체가 `bindCardDrag(node, sel, onDrop)` 로 나왔다 · `heroStrip` 의 `reorder` 옵션 · 카드의 `data-uid` · 카드 안 버튼(해고)에서 누른 것은 드래그로 안 잡는다
- i18n 키 · CSS 추가 없음 — 고스트는 편성의 `.fm-ghost` 를 쓴다
- ⚠ 끄는 동안 원본 카드는 흐려지지 않는다 — 편성 띠의 드래그와 같다(진형 칸만 흐린다)
