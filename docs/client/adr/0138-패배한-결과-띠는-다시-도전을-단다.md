# ADR-0138 — 패배한 결과 띠는 [다시 도전]을 단다

| | |
|---|---|
| **상태** | 확정 · 2026-09-15 |
| **화면** | [SCREEN_DESIGN §4-2](../SCREEN_DESIGN.md) 「결과 띠」 |
| **정한 사람** | 사용자 지시 |
| **대체** | — |
| **대체됨** | — |

## 결정

원정 관전의 결과 띠가 **패배**를 찍으면 [리포트 보기] 옆에 **[다시 도전]** 버튼을 단다. 누르면 **같은 스테이지로 지금 파티 · 진형을 곧바로 보낸다** — 반복 원정이 다음 런을 이어 보내는 길과 같아서 배속 · 배치 · 로그 탭은 잇고 시각만 0 에서 시작한다. 반복 설정은 건드리지 않는다. 한 번에 눌린다. 승리 띠에는 달지 않는다.

## 맥락

사용자가 「원정에서 패배했을 때 view report 옆에 다시 도전 버튼도 추가」를 지시했다. 이날 결과 띠는 판정 + [리포트 보기] 하나였고, 패배 뒤 같은 곳에 다시 보내려면 리포트로 가서 [같은 곳으로 다시](`rep.again`)를 눌러야 했다 — 두 번 누르고 화면이 한 번 바뀐다. 이날 원정 중에도 편성을 바꿀 수 있어서(ADR-0111) 관전 아래 보관 칸에서 장비를 갈아 끼운 뒤 곧바로 다시 보내는 흐름이 가능했다.

## 근거

- **패배 직후가 다시 보낼 결정이 서는 자리다** — 관전 아래 보관 칸에서 장비를 고치고 같은 스테이지를 다시 치는 것이 패배의 전형적인 다음 행동이다. 리포트를 거치게 하면 그 사이에 화면이 한 번 바뀐다
- **승리 띠에는 안 단다** — 승리 뒤 같은 곳을 다시 보내는 길은 반복 원정이 이미 든다(띠가 세고 자동으로 보낸다). 둘을 다 달면 반복 OFF 인 승리 띠에서 버튼이 반복 토글의 뜻을 겹쳐 든다
- **리포트의 `rep.again` 을 옮기지 않는다** — 리포트의 버튼은 **고른 줄의 스테이지로** 보내는 것이라 뜻이 넓다. 결과 띠의 버튼은 방금 끝난 원정 하나를 가리키고 문구도 사용자가 정한 「다시 도전」이라 키를 따로 둔다(`bt.retry`)
- **두 번 누르기가 아니다** — 끝난 원정이라 잃는 것이 없다(§3 「되돌릴 수 없는 행동」이 아니다). 도는 원정을 끊는 보내기(ADR-0111)와 달리 끊을 것이 없다
- **리포트는 그대로 남는다** — 패배한 원정의 기록은 목록에 서 있어 나중에 리포트 세그먼트로 열 수 있다

## 파급

- i18n 키 `bt.retry` 추가
- `battle.js` `mountBattle` opts 에 `onRetry()` — 출발은 앱이 한다(재생기는 계산하지 않는다) · 버튼 클래스 `.b-retry`
- `app.js` 는 반복 원정의 이어 달리기와 같은 `runBattle(stageId, { resume })` 를 부른다 — 출발이 거절되면 그 함수의 플래시 · 편성 복귀가 그대로 든다
