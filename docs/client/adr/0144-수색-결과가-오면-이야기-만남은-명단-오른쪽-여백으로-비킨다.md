# ADR-0144 — 수색 결과가 오면 이야기 · 만남은 명단 오른쪽 여백으로 비킨다

## 결정

수색이 끝나 셋째 칸이 결과 카드가 되면 「수색 완료」 줄(마지막 이야기 줄)과 만남 블록(질문 + 답)을 **카드 위에서 떼어 명단 격자 오른쪽의 남는 자리**에 위아래로 세운다. 결과 카드는 명단 후보 카드와 **같은 윗선**에서 시작한다. 대기 · 수색 중(이야기 줄이 칸 안에 쌓이는 상태)은 그대로다.

## 맥락

완료 상태의 결과 카드는 「수색 완료」 줄과 만남 블록을 머리에 이고 있었다. 1600×800 실측에서 그 둘이 결과 영웅의 초상을 **~175px 아래로** 밀었다 — 같은 행의 후보 둘과 초상 · 이름 · 능력치 줄이 어긋났고, 행이 길어져 도구 줄(리롤)이 패널 바닥에 붙고 의뢰 줄은 스크롤 밖으로 나갔다. 명단 격자는 2026-09-14 에 시작 화면 카드 줄과 같은 폭에서 잘려(src/ui/README 크기 정책) 격자 오른쪽이 비어 있었다.

## 근거

- **결과 카드는 명단과 같은 줄에서 읽혀야 비교가 선다** — ADR-0077 이 결과 카드를 격자 안에 남긴 이유가 「이 고용비를 어디 쓸까」를 나란히 견주는 것이었다. 결과 영웅만 한참 아래서 시작하면 초상 · 능력치 줄이 옆 카드와 안 맞아 눈이 한 번 더 내려가야 한다
- **남는 자리가 이미 있다** — 새 칸이나 접기를 만들지 않고, 격자를 자른 대가로 비어 있던 여백을 쓴다
- **이야기 · 만남은 영웅이 아니라 수색의 것이다** — 카드 테두리 안에 있으면 그 영웅의 일부로 읽힌다. 빠지면 결과 카드가 명단 카드 규격 그대로 선다(§8-1 「결과 카드는 명단 카드와 같다」)
- ⚠ **읽는 순서가 뒤집힌다** — 완료 줄을 카드 위에 둔 이유는 「무엇이 돌아왔나」보다 「어떻게 찾았나」가 먼저 읽히는 것이었다(style.css 주석에만 있던 근거 — ADR 은 없다). 가로로 놓이면 카드가 먼저 읽힌다. 영웅 칸이 밀리는 문제가 더 크게 걸렸다(사용자 지시)
- **버린 안 ① — 이야기 · 만남을 카드 아래로 내린다.** 윗선은 맞지만 행이 여전히 길어 도구 줄 · 의뢰 줄이 밀리는 것은 그대로다
- **버린 안 ② — 결과가 오면 이야기를 접고 버튼으로 연다.** 만남은 답을 누르는 자리라, 접으면 수령 전까지 열려 있는 답할 기회가 한 번 더 눌러야 보인다

## 파급

- 새 CSS `.tv-row`(명단 격자 + 여백 칸을 한 줄로 묶는 flex) · `.tv-side`(여백 칸 — 남는 폭을 다 받는다). `.tv-cands` 의 아래 여백은 `.tv-row` 로 옮겨 갔다
- `searchCell(side)` 가 여백 칸을 받아 **완료일 때만** 채운다 — 비어 있으면 붙이지 않는다
- i18n 키 추가 없음
- ADR-0077 은 그대로 산다 — 결과 카드는 여전히 후보보다 길고(버튼 둘) 후보 카드는 제 높이에서 끊긴다. 그 파급의 「행 높이는 결과 카드가 정한다」에서 결과 카드가 이야기 · 만남만큼 짧아졌다
- ⚠ 여백 칸 폭은 격자가 남긴 만큼이다 — 영어나 답이 긴 만남은 줄이 여러 번 접힌다
