# ADR-0152 — 정식 스테이지 배경은 일러스트다 · 도트는 비교용으로 남는다

## 결정

- **스테이지 배경은 스타일 폴더 하나 = 스타일 하나다** — `src/assets/art/backgrounds/<스타일>/background_stage_<id>.webp`. 화면은 고른 폴더 **하나만** 읽는다(`mock.js:bgDir()`). `faces/` 와 같은 규칙이고, 고르는 순서도 같다: URL `?bg=<스타일>` → localStorage → `BG_STYLES` 첫 항목
- **정식 = `illustrate`** — `BG_STYLES` 의 첫 항목이라 아무 것도 안 걸면 일러스트로 돈다. **도트(`pixel`)는 지우지 않고 비교용으로 남는다** — `?bg=pixel`
- **축소 보간은 스타일이 정한다** — 토큰 `--bg-render` 가 `:root` 에서 `auto`(일러스트 — 기본값이자 안전한 쪽), `:root[data-bg="pixel"]` 에서 `pixelated`. `.arena.has-bg` · `.zone.has-bg` 가 그 토큰만 읽는다
- **한 스타일이 전 스테이지를 다 갖출 필요는 없다** — 그림이 없는 자리는 CSS 그라디언트로 떨어진다. 얼굴이 없는 몬스터가 죄종 색 원판으로 떨어지는 것과 같은 규칙이고, **스타일 사이의 폴백은 없다**
- **스타일을 안 타는 자리 둘** — 거점 배경(`#stage::before`)과 탐험 지도(`.ex-map`)

## 맥락

배경은 원래 계승 포크 넷(`backgrounds/`)이었고, 2026-09-11 에 생성기 워터마크(✦)를 잘라 낸 사본이 형제 폴더 `backgrounds_clean/` 로 갈라져 화면은 그쪽을 읽었다. 그 뒤 신규 도트 아트 열셋이 들어와 챕터 1~3 이 채워졌고(09-15), 같은 구도를 일러스트로 다시 그린 열 장이 들어왔다(09-16 — 챕터 1 · 2).

그때 폴더가 셋(`backgrounds/` · `backgrounds/source/` · `backgrounds_clean/`)이었고, **`_clean` 형제 폴더는 `faces/` · `icons/` 어디에도 없는 모양**이었다 — 그 둘은 「게임이 읽는 그림은 제 폴더 안, 손 안 댄 원본은 그 안의 `source/`」 하나로 서 있었다.

## 근거

- **형제 폴더를 없애는 것이 통일이다** — 이름을 `backgrounds_installed/` 같은 것으로 바꿔도 다른 아트에 선례가 없어 「통일」이 안 된다. 설치본을 `backgrounds/` 안으로 올리면 세 폴더가 같은 문장 하나로 설명된다
- **스타일 축을 `faces/` 에서 베낀 이유** — 도트와 일러스트를 **둘 다 들고 있고** 어느 쪽으로 갈지가 그 시점에 미정이었다. 스타일 폴더면 갈아타기가 `BG_STYLES` 첫 항목 한 줄이고, 비교는 `?bg=` 한 번이다. 파일을 옮기거나 CSS 를 고칠 일이 없다
- **`--bg-render` 를 신설한 이유** — 그날까지 `pixelated` 가 세 자리에 못박혀 있었고(「스타일과 상관없이 늘 픽셀아트다. 걷어내지 말 것」), 일러스트에 그것을 걸면 축소할 때 선이 끊긴다(§5 초상에서 이미 겪은 함정). 초상의 `--face-render` 와 같은 문법으로 갈랐다
- **스타일 사이 폴백을 안 만든 이유** — 얼굴의 선례가 「없으면 제자리 표시로 떨어진다」이고 다른 스타일에서 빌려오지 않는다. 빌려오면 한 화면에 두 그림체가 섞여 **정식이 무엇인지가 화면에서 안 읽힌다**

**버린 안**

1. **폴더 이름만 바꾼다**(`backgrounds_installed/` 등) — 다른 아트에 같은 모양이 없어 통일이 안 된다
2. **설치본 한 벌만 둔다**(icons 식) — 일러스트로 완전히 갈아탈 결심이 선 뒤에 맞는 모양이다. 그날은 도트 15장 · 일러스트 6장이 공존했고 102 의 그림체가 나머지와 달라 비교가 필요했다
3. **그림이 없는 스테이지는 도트로 떨어뜨린다** — 위 「근거」의 마지막 줄

## 파급

- `mock.js` — `BG_CLEAN_DIR` 삭제 · `BG_STYLES` · `setBgStyle` · `bgStyle` · `applyDocumentBg` · `bgDir()` 신설(`faces/` 와 같은 문법) · `stageBg` 가 `bgDir()` 을 탄다 · `TOWN_BG` 는 `pixel/` 을 박는다
- `app.js` — `render()` 에서 `M.applyDocumentBg()` 를 `M.applyDocumentFace()` 옆에 부른다
- `style.css` — 토큰 `--bg-render` 신설 · `.arena.has-bg` · `.zone.has-bg` 의 `pixelated` 를 토큰으로 · 거점 경로가 `backgrounds/pixel/town.webp`
- `data.js` — `stageBgOf` 주석: `stage.csv:bg` 는 **자리를 여는 것**이고 스타일 폴더의 재고가 아니다
- 자산 — `backgrounds_clean/` 소멸 · `backgrounds/pixel/`(16) · `backgrounds/illustrate/`(10) · 원본은 `backgrounds/source/<스타일>/`. `explore_chapter_1.webp` 는 루트로 돌아왔다(폴더 개편 중 `source/` 로 들어가 **탐험 지도가 깨져 있었다**)
- CLAUDE.md 규칙 3 — 읽기 전용의 범위가 `backgrounds/` 전체에서 **`source/pixel/` 의 계승 원본 셋**(101 · 102 · `town`)으로 좁았다
- ⚠ **열린 것 — 챕터 3(301~305)은 일러스트본이 없다.** 정식 스타일로 돌면 그 다섯 스테이지가 배경 없이(그라디언트) 선다. 도트본은 실재하므로 `?bg=pixel` 로는 보인다
- ⚠ **열린 것 — 거점 배경만 도트로 남았다.** `town.webp` 는 도트 한 벌뿐이라 `#stage::before` 가 `pixel/` 을 직접 박는다. 거점 일러스트가 나오면 `bgDir()` 로 돌린다
- ⚠ **열린 것 — 102 의 그림체가 나머지와 다르다.** 101 · 103 · 104 · 105 · 201~205 는 검은 외곽선의 또렷한 만화풍인데 102 만 외곽선 없는 유화풍이다
