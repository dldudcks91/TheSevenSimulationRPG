# ADR-0162 — 제 그림이 없는 스킬은 검은 칸이다

| | |
|---|---|
| **상태** | 확정 · 2026-09-18 |
| **화면** | [SCREEN_DESIGN §2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시(「스킬 그림은 없으면 그냥 검은색으로 나오도록」) |
| **대체** | [ADR-0014](0014-스킬-아이콘-는-그림.md) 중 **「제 그림이 없는 스킬은 id 안정 해시로 있는 그림 중 하나」** |
| **대체됨** | — |

## 결정

스킬을 그림으로 그리는 칸 전부(관전 쿨 칸 · 후보 카드 고유 칸 · 액티브 스킬 카드 · 스킬 설명창 · 도감 스킬 세그먼트 등 — `mock.skillIcon` 을 타는 곳)는 **제 그림(`icons/skills/<skill_id>.png`)이 없으면 검은 칸**이다. 남의 그림을 빌려 오지 않는다. 그림이 있는 스킬은 종전 그대로다.

## 맥락

2026-09-18 몬스터 전용 스킬 「고블린 소환」이 생기며 그림 없는 스킬이 다시 나왔다(그 전날까지는 직업 스킬 전부가 제 그림을 가져 해시 폴백이 쓰이지 않았다). 해시 폴백은 그림 없는 스킬에 **다른 스킬의 그림**을 붙인다 — 주술사의 소환 칸에 궁수 스킬 그림이 서는 식이다.

## 근거

- **틀린 그림이 곧 틀린 정보다** — 부위 실루엣(§6)이 해시 폴백을 안 쓰는 것과 같은 이유다. 스킬도 그림으로 「무슨 스킬인가」를 읽으므로 남의 그림은 오독을 만든다
- **빈 칸이 아니라 검은 칸인 이유** — 빈 칸은 「칸이 비었다(스킬 없음)」로 읽힌다. 검은 칸은 「스킬은 있는데 그림이 아직 없다」로 읽힌다
- 그림이 들어오면 `mock.js:SKILL_ICON_FILES` 에 이름만 더한다 — 규칙은 그대로다

## 파급

- `mock.skillIcon` 이 목록에 없는 id 에 `null` 을 낸다 · 그리는 쪽(`skillImg` 셋)이 `null` 이면 검은 칸을 깐다 · CSS 한 줄
- 도감 자산 세그먼트(§9-1)의 스킬 칸도 게임이 부르는 그대로라 검은 칸이다
