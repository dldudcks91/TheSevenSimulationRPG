# ADR-0165 — 띠 카드 위칸은 이름 뒤에 레벨을 든다

| | |
|---|---|
| **상태** | 확정 · 2026-09-18 |
| **화면** | [SCREEN_DESIGN §5](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시(「캐릭터 탭을 눌렀을 때 나오는 위의 영웅 칸의 이름 옆에 Lv. 이 나오도록」) |
| **대체** | — |
| **대체됨** | — |

## 결정

영웅 띠 카드 위칸의 오른쪽이 **이름 + `Lv.n`** 을 든다 — 레벨은 **이름 뒤**다. **두 자리 다** 그렇다(캐릭터 탭 상단 띠 · 출정 창의 「캐릭터 선택」 칸). 줄어드는 쪽은 여전히 「하는 일」 하나고, 레벨은 이름과 함께 안 줄어든다.

## 맥락

위칸은 왼쪽 「지금 하는 일」 · 오른쪽 이름 둘이었다. 영웅의 레벨을 읽는 자리는 캐릭터 탭에서 **한 명을 고른 뒤** 기본 옵션 칸 맨 위 한 곳뿐이었고([ADR-0129](0129-레벨-경험치는-기본-옵션-칸-맨-위-능력치-막대-위에-선다.md)), 캐릭터 탭 띠는 툴팁을 안 띄우므로([ADR-0116](0116-캐릭터-탭의-영웅-띠는-툴팁을-띄우지-않는다.md)) 띠에서 레벨을 보는 길이 없었다. 출정 창 띠는 툴팁이 뜨지만 그 카드도 레벨 줄을 안 든다([ADR-0134](0134-유닛-툴팁은-이름-소속-줄을-안-든다.md)).

## 근거

사용자 지시다. 자리(이름 앞/뒤)와 범위(한 띠/두 띠)를 물어 정했다.

- **이름 뒤인 이유** — 이름이 카드를 고르는 키라 먼저 읽혀야 한다. 앞에 두면 일곱 카드의 눈이 숫자 열에 먼저 걸린다
- **두 띠 다인 이유** — §5 의 규격이 「두 자리가 같은 띠, 같은 순서」다. 한쪽만 바꾸면 같은 카드가 자리마다 달라져 규칙이 하나 늘고, 출정 창에서 **누구를 데려갈지 고를 때** 레벨이 바로 안 읽힌다
- **버려진 안 — 캐릭터 탭 띠만**: 지시가 가리킨 것은 캐릭터 탭이지만, 한 벌을 가르는 쪽이 새 규칙을 만든다(같은 판단이 [ADR-0155](0155-후보-카드의-죄종-칩은-그-죄종-색을-입는다.md) 에도 있다)
- **말줄임 우선순위는 안 바뀐다** — 레벨은 두세 글자라 줄일 것이 없고, 상태는 색이 이미 말하므로 좁아지면 「하는 일」이 먼저 잘린다

## 파급

- `app.js:heroStrip` 위칸에 `.hs-lv` 한 조각 · `style.css .hs-lv`(`flex: 0 0 auto`)
- **새 i18n 키가 없다** — 기본 옵션 칸이 쓰던 `ch.lv`(`Lv.{n}`)를 그대로 부른다. 두 자리가 같은 표기를 쓰므로 키를 나누면 한쪽만 고쳐진다
