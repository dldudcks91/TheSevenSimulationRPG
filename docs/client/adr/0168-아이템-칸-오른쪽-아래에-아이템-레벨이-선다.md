# ADR-0168 — 아이템 칸 오른쪽 아래에 아이템 레벨이 선다

| | |
|---|---|
| **상태** | 확정 · 2026-09-18 |
| **화면** | [SCREEN_DESIGN §6](../SCREEN_DESIGN.md) · [§4-3](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | [ADR-0122](0122-페이퍼돌-칸에는-글자가-없다.md) 중 **찬 칸에 글자가 없다** — 이 배지 하나만. 부위 이름 줄 폐기 · 빈 칸 실루엣 · 찬 칸의 `title` 금지는 그대로 산다 |
| **대체됨** | — |

## 결정

아이템 그림이 서는 칸은 **오른쪽 아래에 그 개체의 아이템 레벨**을 `Lv.n` 으로 단다. 자리는 셋 — 보관(창고 · 인벤토리) · 원정 리포트의 획득 장비 격자 · 캐릭터 탭 페이퍼돌의 착용 칸. 오른쪽 위의 강화 `+n` 과 **대각으로 마주 본다**.

## 맥락

아이템 레벨은 개체가 드롭될 때 정해져(`battle.js:spawnRound` — 스테이지 레벨 + `gear_ilvl_add`) 무기 피해 · 방어구 방어 · 접사 값이 전부 그 위에서 파생된다. 그런데 화면에서 그 수를 볼 수 있는 곳은 **툴팁의 소속 줄 하나**였다 — 칸을 하나씩 짚어 봐야 어느 것이 새 것인지 알 수 있었다.

칸의 모서리는 오른쪽 위만 쓰이고 있었다(강화 `+n` · 재료 칸의 개수). 페이퍼돌 착용 칸은 ADR-0122 로 **글자를 전부 걷은** 상태였다.

사용자 지시: 「아이템 오른쪽 아래에 조그맣게 아이템 레벨을 넣어 달라 — `Lv.11` 이런 식으로」, 자리를 묻자 「장착 칸까지 전부」.

## 근거

- **정렬 없이 훑을 수 있는 유일한 수** — 희귀도는 테두리 색이, 강화는 오른쪽 위가 이미 든다. 남은 축이 ilvl 이고, 격자를 눈으로 쓸어 「이게 더 나중 것」을 가리는 데 쓰인다
- **위와 아래가 서로 다른 말을 한다** — 오른쪽 위 `+n` 은 **유저가 쌓은 것**(0 이면 안 선다), 오른쪽 아래 `Lv.n` 은 **개체가 태어날 때 박힌 것**(언제나 있다). 같은 모서리에 겹쳐 쌓으면 둘을 읽는 규칙이 하나로 섞인다
- **페이퍼돌만 빼면 비교가 끊긴다** — 가방 칸의 `Lv.14` 를 보고 지금 낀 것과 견주려는데 착용 칸이 값을 안 들면 툴팁을 다시 열어야 한다. ADR-0122 가 걷은 것은 **칸마다 같은 말을 반복하던 부위 이름**이고(자리가 곧 부위였다), 개체마다 다른 이 수는 그림도 자리도 대신 말해 주지 못한다
- **툴팁의 `ilvl n` 과 표기가 갈린다** — 칸은 `Lv.11`, 툴팁 소속 줄은 `ilvl 11` 이다. 사용자가 고른 표기를 칸에 그대로 쓴다. ⚠ 한 화면에 두 이름이 서는 것은 남는 흠이다
- 버린 안 — **호버 때만 띄운다**: 훑어보는 용도가 죽는다. **툴팁 소속 줄을 키운다**: 칸을 하나씩 열어야 하는 문제가 그대로다

## 파급

- i18n — `ch.itemLv`(`Lv.{n}`) 한 키. 영웅 레벨 `ch.lv` 와 글자가 같아도 **가리키는 것이 달라** 키를 나눈다
- CSS — `.inv-lv` · `.pd-lv`. 오른쪽 위 `.inv-up` 과 같은 문법(절대 배치 · `--fs-2xs`)
- 재료 칸은 안 단다 — 수량이지 개체가 아니라 ilvl 이 없다(오른쪽 위 개수를 그대로 쓴다)
- 제련소 · 도감의 **줄 목록**은 그대로다 — 글자 줄이라 `ilvl n` 을 이미 본문에 든다
