# ADR-0186 — 리포트는 보기 전용이다 · 획득 장비 칸에서 조작을 걷는다

| | |
|---|---|

| **화면** | [SCREEN_DESIGN §4-3](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (「리포트는 그냥 보는 용도야 → 리포트칸에서는 어떠한 조작도 불가능하게」) |
| **대체** | — |
| **대체됨** | — |

## 결정

리포트 상세의 **「획득 장비」 칸에서 조작을 전부 걷는다.** 분해 토글도, 칸 클릭도 없다 — **툴팁만** 뜬다.

장비를 만지는 일(분해 · 잠금 · 장착 · 창고 이동)은 **캐릭터 탭 하나**([SCREEN_DESIGN §6](../SCREEN_DESIGN.md))가 든다.

## 맥락

그날 「획득 장비」 칸에는 **가방과 독립된 분해 모드 토글**이 하나 더 있었고(`state.repSalvage`), 켜면 칸 클릭이 분해였다. 토글을 둘로 나눈 것은 한쪽을 켜 둔 채 다른 화면에서 오클릭하는 사고를 막으려는 장치였다.

같은 날 분해 조작이 **고르고 나서 실행하는 방식**으로 바뀌면서([ADR-0184](0184-분해는-골라서-버튼으로-한다-분해-모드-토글을-버린다.md)) 그 사고 자체가 없어졌고, 리포트에 같은 방식을 복제할지 남길지가 열린 채였다.

## 근거

- **리포트가 답하는 질문은 「이 파티가 어땠나」다**([SCREEN_DESIGN §4-3](../SCREEN_DESIGN.md)) — 끝난 원정의 기록이고, 값이 전부 지난 값이다. 기록을 읽는 자리에 파괴 버튼이 서면 읽는 행위와 바꾸는 행위가 같은 화면에서 섞인다
- **조작 문법이 한 벌로 남는다** — 같은 일을 하는 길이 두 화면에 있으면 규격도 코드도 두 벌이 된다. 그날 이미 토글이 둘이라 그 비용을 치르고 있었다
- **정보는 하나도 안 준다** — 격자 · 희귀도 테두리 · 배지 둘 · 비교 툴팁이 그대로 있고, **가방을 떠난 것이 흐린 빈 칸으로 남는 규칙**도 그대로다. 없어지는 것은 클릭 하나뿐이다
- **캐릭터 탭이 그 일을 이미 다 할 수 있다** — 창고에서도 바로 장착 · 분해되고(item_design §1), 관전 화면(§4-2)도 같은 보관 두 칸을 품는다. 리포트에서만 할 수 있는 일은 없었다

**버린 안**

1. **리포트에도 [분해] 버튼과 고르는 중을 복제한다** — 같은 문법이 두 곳에 서고, 「이 런에서 얻은 것」이라는 단위는 조건 저장형 자동 분해가 서면 리포트에 뜨기 전에 이미 걸러진다
2. **툴팁까지 뺀다** — 툴팁은 조작이 아니라 표시다. 무엇을 주웠는지 읽지 못하면 칸이 그림 벽이 된다

## 파급

- `state.repSalvage` 삭제 · `app.js` `dropSection` 에서 토글 버튼과 `cell.onclick` 제거
- i18n — `rep.salvage` 삭제
- `SCREEN_DESIGN §4-3` 호출 줄에서 `game.salvage` 가 빠진다 (`game.holderOf` 는 흐린 칸 판정으로 남는다)
- 「가방 초과로 버린 수」의 자리 설명이 **머리 줄 오른쪽 끝**으로 바뀐다 — 옆에 서던 토글이 없어졌다
