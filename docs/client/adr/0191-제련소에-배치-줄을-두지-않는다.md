# ADR-0191 — 제련소에 배치 줄을 두지 않는다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §8-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 — 「배치 없음 일단 삭제해봐 뭔가 행동을할떄 영웅이 배치되도록 만들거라서」 |
| **대체** | — *(배치 줄은 09-03 탭 분리 때부터 §8-2 규격에 있었고 ADR 이 되지 않았다)* |
| **대체됨** | — |

## 결정

제련소 탭의 **배치 줄**(배치된 영웅 · 담당 능력치 · 품질 계수 · [배치 변경])을 걷는다. 제련소 화면에 영웅 칸이 없다.

영웅은 제련소에 늘 앉혀 두는 것이 아니라 **작업을 할 때 배치되는** 쪽으로 간다 — 그 규칙은 기획이 정하고, 서면 모양도 그 규칙을 따라 새로 정한다.

## 맥락

그날 배치 줄은 `배치 없음` · 담당 능력치 `LCK`(`hero_attribute.csv:dispatch` 의 `forge`) · `품질 —` · 「미착수」 배지 · [배치 변경](누르면 미착수 안내 한 줄)으로 섰다. `game_logic` 에 배치가 없었다.

기획(base_expedition_design §2-5)은 「영웅 1인 배치(운)는 효율형이라 방치로 돈다」고 적었지만 **운이 무엇을 미는가**는 09-15 옵션강화 폐기로 대상이 사라져 미확정이었다(후보 — 제작 희귀도 · 크래프트 값 굴림). 사용자가 이 줄이 어디에 쓰이는지 물었고, 답을 듣고 걷기로 했다.

## 근거

- **사용자 지시가 결정의 본체다** — 배치를 「늘 앉혀 두는 칸」이 아니라 「행동할 때 붙는 것」으로 만들 계획이다. 상시 1인 칸 + [배치 변경]이라는 줄의 모양 자체가 그 계획과 다르다
- **잴 값이 하나도 없는 줄이었다** — 이름 칸은 `배치 없음`, 품질은 `—`, 버튼은 미착수 안내. §4-1 「값은 항상 찍는다」가 지키는 것은 **재고 있는 값**이고, 여기는 재는 것이 없었다
- **되돌리기 쉽다** — 「일단 삭제」다. i18n 키 넷과 CSS 몇 줄이 전부다

**버린 안**

1. **줄은 두고 미착수로 남긴다** — 버리기로 한 모양을 계속 보여 준다

## 파급

- app.js `renderForge` — 배치 줄 삭제
- i18n — `fg.assign` · `fg.none` · `fg.quality` · `fg.reassign` 삭제. `dp.attrTitle` · `postAttr()` 는 자원 탭이 쓰므로 남는다
- CSS — `.fg-assign` · `.fg-who` · `.fg-stat` · `.fg-sp` 삭제
- SCREEN_DESIGN — §8-2 표의 배치 줄 행 · 머리 안내의 「배치는 미착수」 · 호출 줄 · §8 「배치 줄은 나간 탭이 각자 들고 간다」에서 제련소가 빠진다 · §11 의 남은 것에서 배치가 빠진다
- ⚠ **기획과 어긋난다** — base_expedition_design §2-5 의 「영웅 1인 배치(운)」와 `hero_attribute.csv:dispatch` 의 `forge` 가 상시 배치를 전제로 남아 있다. 기획 개정은 `/game-design`
