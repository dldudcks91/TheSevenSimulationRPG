## 결정

물약 칸 구성은 **편성마다** 딸리고 편성 탭에서 채운다.

- **가진 물약 클릭 = 앞의 빈 칸에 넣는다 · 칸 클릭 = 비운다**
- **드래그** — 가진 물약 → 칸(그 칸에 넣는다) · 칸 → 칸(맞바꾼다)
- **같은 물약을 여러 칸에 넣어도 된다 · 재고보다 많이 넣어도 막지 않는다** — 모자란 칸은 **「모자람」** 으로 보이고, 런에서는 빈 채로 시작한다

**제련소 물약 머리 줄은 칸 대신 물약별 재고(개수)를 든다.** 관전 아레나의 칸 줄은 그대로다 — **나간 편성의 구성대로 재고에서 찬 칸**을 보인다.

## 맥락

그날까지 물약은 종류를 한 번 만들면 영구히 갖고, 칸은 **얻은 순서대로 앞 칸부터** 자동으로 찼다(ADR-0148 · DEV_PLAN R104). 칸을 고르는 화면은 없었다. 같은 날 기획이 물약을 **개수를 가진 소모품**으로 바꾸고 칸을 **플레이어가 채우게** 했다(GAME_DESIGN §9 09-21 · battle_design §7-1).

## 근거

- **진형과 같은 손이다** — 편성 탭의 진형이 「클릭은 소속 · 드래그는 자리」를 쓴다(ADR-0096). 같은 탭 안에서 물약 칸이 다른 문법을 쓰면 손이 헷갈린다
- **칸 → 칸 드래그가 있어야 한다** — 앞 칸부터 마시므로 **순서가 곧 결정**이다. 비웠다 다시 넣는 것만으로는 순서를 바꾸는 데 손이 많이 간다
- **모자라도 막지 않는다** — 칸 구성은 계획이고 재고는 오르내린다. 막으면 물약을 만들 때마다 칸을 다시 채워야 한다. 대신 모자란 칸을 화면에 보인다
- **제련소는 재고를 든다** — 칸이 편성마다 서므로 제련소가 「그 칸」 하나를 보일 수 없다. 만드는 자리에서 묻는 것은 「몇 개 남았나」다. ADR-0148 의 「만드는 자리와 쓰는 자리가 같은 모양으로 읽혀야 한다」는 이제 **넣는 자리(편성 탭)와 쓰는 자리(관전)** 가 같은 칸 모양으로 잇는다
- **버린 안** — ① 칸 클릭 → 물약 고르는 작은 창: 한 칸 채우는 데 두 번 누르고 진형과 문법이 갈린다 ② 재고보다 많이 못 넣게 막는다: 위 근거
