## 결정

로그 판의 탭(전체 · 우리 · 적) 바로 아래에 **칸 머리 줄 — 이름 · 대상 · 데미지**가 선다. 그림 칸은 비운다. 데미지는 값 칸처럼 오른쪽 정렬이다. 머리 줄은 **로그 줄과 같은 칸 폭**이고 **스크롤해도 그 자리에 남는다**. 탭이 걸러도 선다.

## 맥락

같은 날 로그 한 줄이 네 칸 격자가 됐다([ADR-0189](0189-로그-한-줄은-네-칸-격자다-이름-그림-대상-값.md)). 칸마다 무엇이 서는지 알려 주는 줄이 없었고, 사용자가 화면을 보고 머리 줄을 요청했다.

그날 로그 목록은 CSS 격자 하나였고, 값 칸의 폭은 **보이는 줄 중 가장 긴 값**(최소 4em)이 정했다. 로그 판은 `padding 8px` 의 스크롤 판이었다.

## 근거

- **머리 줄은 목록 격자의 첫 줄이다** — 값 칸 폭이 로그 줄의 내용으로 정해지므로, 머리 줄을 목록 밖(탭과 스크롤 판 사이)에 따로 두면 칸 폭을 알 수 없어 줄과 어긋난다. 같은 격자 안에 두어야 모든 줄과 한 트랙을 쓴다
- **스크롤해도 제자리(sticky)** — 목록 안에 있지만 판 윗변에 붙어 있어 보이는 모습은 「탭 바로 아래」다. sticky 는 스크롤 판의 안쪽 여백 아래까지만 붙어서, 판에 위 여백이 있으면 머리 줄 위 틈으로 지나가는 줄이 비친다(그날 헤드리스 실측 — 음수 여백으로 끌어올려도 sticky 가 도로 밀어 내렸다). 그래서 로그 판만 위 여백을 0 으로 두고 그 여백을 머리 줄이 든다 — 보이는 간격은 그대로다
- **라벨은 사용자가 칸을 부른 말** — 「이름칸 · 상대 칸 · 오른쪽에 데미지」. 적이 칠 때는 대상 칸에 영웅이 서므로 「상대 몬스터」 대신 「대상」이다. 값 칸에는 회복량 · 「빗나감」 · 「처치」도 서지만 대부분이 피해라 「데미지」다
- **그림 칸은 비운다** — 18px 칸에 글자가 안 든다
- **탭이 걸러도 선다** — 주체가 없는 줄이라 거르기 대상이 아니다

**버린 안**

1. **탭과 스크롤 판 사이에 별도 줄** — 칸이 줄과 어긋난다(위)
2. **값 칸 폭을 고정해 별도 줄과 맞춘다** — ADR-0189 가 버린 안이다(영어의 긴 값이 넘친다)
