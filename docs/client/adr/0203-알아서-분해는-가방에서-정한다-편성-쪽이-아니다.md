# ADR-0203 — 알아서 분해는 가방에서 정한다 · 편성 쪽이 아니다

## 결정

알아서 분해(item_design §6-5 — 등급 선 · 아이템 레벨 선)의 설정 자리는 **보관 도구 줄의 [자동 분해]** 다. 누르면 창이 뜨고 거기서 두 선과 **[지금 인벤토리에도 적용]** 을 다룬다. 편성(출정) 창에는 두지 않는다.

- 창의 선은 **누르는 즉시 먹는다** — 저장 버튼이 없다. 다음 드롭부터 걸리고 가방의 것은 그대로다
- **[지금 인벤토리에도 적용]** 은 두 번 누른다 — 첫 누름에 그 자리가 「인벤토리의 n개가 분해된다 [확인] [취소]」로 바뀌고, [확인]이 실행한다. 걸리는 것이 없으면 버튼이 꺼진다
- 도구 줄의 [자동 분해] 는 **선이 하나라도 서 있으면 켜진 모양**이다 — 가방이 왜 덜 차는지가 같은 줄에서 읽힌다
- 레벨 선은 위험도 줄(§4-1)과 같은 버튼 줄 — `−10` `−1` 값 `+1` `+10` · 0 이면 값 자리에 「안 봄」

## 맥락

같은 날 분해 조작이 「골라서 버튼」으로 바뀌었고([ADR-0184](0184-분해는-골라서-버튼으로-한다-분해-모드-토글을-버린다.md)), 이어서 「단체 분해」와 「알아서 분해」를 **규칙 한 벌**로 합치기로 했다 — 규칙은 새 드롭에 계속 걸리고, 이미 가진 것은 버튼 하나로만. 규칙을 **어디서 정하나**가 남았고 후보가 둘이었다 — 아이템창(보관 도구 줄) · 편성창(출정 창).

그날 드롭이 들어오는 길은 원정 하나였고, 오프라인 활동의 장비 드롭(GAME_DESIGN §9 09-07)은 방향만 있었다. 관전 화면(§4-2)은 캐릭터 탭과 같은 보관 두 칸을 품고 있었다.

## 근거

- **규칙이 붙는 대상이 가방이다** — 묻는 것은 「이번 원정에서 무엇을 주울까」가 아니라 「내 가방에 무엇을 남길까」다. item_design §6-3 이 「버릴까」를 묻는 자리를 **가방 · 드롭 목록 · 자동 분해 설정**으로 이미 한 묶음으로 뒀다
- **원정 중에 고칠 수 있다** — 관전 화면에 같은 보관 칸이 떠 있어, 쓰레기가 쌓이는 것을 보며 바로 선을 옮기면 다음 드롭부터 먹는다. 편성 창은 출발할 때만 열리고, 반복 원정을 켜 두면 다시 열 일이 거의 없다
- **규칙이 한 벌로 남는다** — 드롭 출처가 원정 밖으로 늘어도(오프라인 활동) 가방에 들어오는 자리는 하나다. 편성에 붙이면 편성이 없는 출처마다 규칙이 한 벌씩 더 필요해진다 — 조사에서 필터가 두 벌인 게임은 예외 없이 불만이 나왔다([salvage_mode_survey.md](../../reference/salvage_mode_survey.md) §3-10)
- **결과와 규칙이 같은 화면에 선다** — 가방이 덜 차는 이유가 바로 위의 켜진 버튼으로 읽힌다(통제성 — 인과가 보여야 한다)
- **[지금 인벤토리에도 적용]만 두 번 누르는 이유** — [분해하기]는 칸마다 체크를 찍어 무엇이 갈리는지 눈으로 보고 누른다. 이 버튼은 체크 단계가 없어 **개수가 유일한 확인**이다(§3 「되돌릴 수 없는 행동은 두 번 누르게 한다」)
- **선은 한 번에 먹는 이유** — 선을 옮기는 것은 되돌릴 수 있고(다시 옮기면 된다) 가진 것을 안 건드린다

**버린 안**

1. **편성(출정) 창** — 스테이지마다 다른 규칙을 둘 수 있다는 장점이 있었다(RAID · 에픽세븐이 연속 전투 설정에 필터를 붙이는 모양). 버린 이유는 위 넷 — 원정 중에 못 고치고, 출처마다 규칙이 한 벌씩 늘고, 결과와 다른 화면에 선다. 스테이지별 규칙이 정말 필요해지면 「이 원정만 다르게」를 가방 규칙 위에 덧씌우는 쪽으로 늘린다
2. **창 없이 도구 줄에 바로 늘어놓기** — 도구 줄은 [분해] · 고르는 중 줄 · 칸 수가 이미 서 있어 두 선의 조작(세그먼트 셋 + 버튼 넷)이 들어갈 폭이 없다
3. **저장 버튼** — 선이 가진 것을 안 건드리므로 확정 단계가 지키는 것이 없다

## 파급

- `app.js` — 창 `autoSalvage` 신설(`MODALS`) · 보관 도구 줄 [자동 분해] 버튼 · 적용 확인은 `state.autoArm`(창을 닫으면 풀린다)
- 호출 셋 — `game.setAutoSalvage` · `game.autoSalvagePreview` · `game.applyAutoSalvage` ([INTERFACE §2-7](../INTERFACE.md))
- i18n `ch.auto.*`
- 리포트(§4-3) — 선에 걸린 드롭은 **흐린 빈 칸**으로 남는다(「가방에서 사라진 것」과 같은 문법) · 리포트에 새 칸은 없다
- ⚠ **열린 것** — 창 안에 선의 뜻(「하나라도 걸리면」 · 「새 드롭만」)을 적지 않는다(설명 문구는 도움말 · §12). 도움말이 받는다(`ch.salvageHint`)
