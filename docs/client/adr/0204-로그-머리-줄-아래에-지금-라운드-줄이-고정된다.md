## 결정

로그 판의 칸 머리 줄 바로 아래에 **지금 라운드 줄**이 고정된다 — 가장 최근 라운드 시작 줄과 같은 글(`라운드 n (종류) — 편성`)이고, 새 라운드가 시작하면 바뀐다. 머리 줄처럼 **스크롤하는 목록 밖**에 서서 스크롤해도 제자리다. 넘치면 `…` · 올리면 전체. 첫 라운드 전에는 비어 줄이 안 선다. **목록 안의 라운드 시작 줄은 그대로 선다.**

## 맥락

그날 로그 판은 탭 · 칸 머리 줄(스크롤 목록 밖 — [ADR-0201](0201-로그-머리-줄은-스크롤-목록-밖에-선다.md)) · 스크롤 목록이었다. 라운드 시작 줄은 목록 안에만 있어서, 줄이 쌓여 위로 밀려나면 지금 몇 라운드인지 판에서 안 보였다. 관전 헤드의 라운드 트랙이 칸으로 보여주지만 로그를 읽는 눈과는 떨어져 있었다.

## 근거

- **머리 줄과 같은 자리 규칙** — 목록 밖에 두면 새 줄이 와서 목록이 튈 때도 겹치지 않는다(ADR-0201 과 같은 이유)
- **글은 라운드 시작 줄 그대로** — 새 문구를 만들지 않는다. 라운드 번호 · 종류 · 편성이 한 줄에 이미 있다
- **목록 안의 라운드 줄은 남긴다** — 지난 줄을 거슬러 읽을 때 라운드 경계가 그것뿐이다. 고정 줄은 「지금」, 목록 안 줄은 「그때」다(제안 후 사용자에게 알림 — 빼는 것은 사용자 판단으로 남겼다)
- **행을 못박는다** — 판 격자의 세 행(머리 줄 · 라운드 줄 · 목록)에 자리를 정해 둔다. 첫 라운드 전 빈 라운드 줄이 빠질 때 자동 배치가 목록을 둘째 행으로 당기면 목록이 남는 세로를 못 받아 스크롤이 죽는다

**버린 안**

1. **목록 안 라운드 줄을 sticky 로 붙인다** — ADR-0201 이 버린 방식이다(재생 중 줄이 비친다)
2. **목록 안 라운드 줄을 뺀다** — 거슬러 읽을 때 경계가 없어진다(위)

## 파급

- `battle.js` — 판에 `div.lg-round`(머리 줄과 목록 사이) · `round` 이벤트가 목록 줄과 같은 글을 `pinRound` 로 건다 · 되감기 · 재렌더는 이벤트를 다시 밟아 마지막 라운드가 선다
- CSS — `.battle-side .battle-log-wrap` 행 `auto auto minmax(0, 1fr)` · `.lg-head` 1행 · `.lg-round` 2행(`:empty` 는 숨김) · `.battle-log` 3행
- i18n 새 키 없음(`log.roundStart` 를 같이 쓴다) · 탭 거르기 · 줄 수 · 칸 그대로
- `game_logic` · 세이브 · 단정 무관
