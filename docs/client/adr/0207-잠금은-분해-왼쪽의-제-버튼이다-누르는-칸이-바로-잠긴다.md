# ADR-0207 — 잠금은 분해 왼쪽의 제 버튼이다 · 누르는 칸이 바로 잠긴다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §6](../SCREEN_DESIGN.md) (§4-2) |
| **정한 사람** | 사용자 지시 (「잠금버튼을 분해에서 빼서 분해 왼쪽으로 옮겨줘」) |
| **대체** | [ADR-0185](0185-잠금은-분해와-같은-자리에-선다.md) 중 **조작 자리**(고르는 중 줄의 [잠그기]) — 잠금 자체 · 자물쇠 배지 · 분해가 잠긴 것을 건너뛰는 규칙은 그대로 산다 |
| **대체됨** | — |

## 결정

보관 도구 줄이 **[잠금] · [분해] · [자동 분해]** 순서가 된다 — 잠금이 분해의 왼쪽에 **제 버튼**으로 선다.

- [잠금]을 누르면 보관 두 칸이 **잠그는 중**이 된다. 칸을 누를 때마다 **그 칸의 자물쇠가 바로 켜지고 꺼진다** — 체크 단계도 실행 버튼도 없다
- 잠그는 중에는 도구 줄이 **[완료]** 하나로 바뀐다. 장착 · `Ctrl`+클릭 · 드래그는 이 동안 안 먹는다(고르는 중과 같다). 탭을 떠나면 풀린다
- 분해의 고르는 중 줄은 **[분해하기] · [취소]** 둘이 된다 — [잠그기]가 빠진다

## 맥락

같은 날 [ADR-0185](0185-잠금은-분해와-같은-자리에-선다.md) 가 잠금을 만들면서 조작을 분해와 같은 자리에 뒀다 — [분해]로 들어간 고르는 중에서 체크한 뒤 [잠그기]를 누르는 모양이었다. 그 모양이 화면에 선 뒤 사용자가 잠금 버튼을 분해에서 빼 [분해] 왼쪽으로 옮기라고 지시했다.

## 근거

- **잠금과 분해는 반대 방향 동사다** — 한 고르는 중에 둘이 서면 「지키려고 고른 것」과 「갈려고 고른 것」이 같은 체크를 쓴다. 잠그려고 체크해 둔 것이 [분해하기] 한 번에 갈릴 수 있다
- **잠금은 되돌릴 수 있어 체크 단계가 지키는 것이 없다** — §3 「두 번 누르게」의 대상이 아니다. 누른 칸이 바로 잠기면 한 개를 잠그는 데 [잠금] · 칸 · [완료] 세 번이다(옛 모양은 [분해] · 칸 · [잠그기] · [취소] 네 번)
- **결과가 누른 자리에 바로 선다** — 왼쪽 아래 자물쇠 배지가 누를 때마다 서고 사라져 따로 알릴 것이 없다. 그래서 잠글 때마다 뜨던 플래시를 없앤다
- **나오는 버튼이 [완료]인 이유** — 누른 것이 이미 먹었으므로 [취소]라고 적으면 되돌리는 버튼으로 읽힌다

**버린 안**

1. **[잠금]도 체크 방식으로** — [잠금] → 체크 → [잠그기]. 분해와 문법은 같지만 되돌릴 수 있는 행동에 확인 단계를 얹는다
2. **모드 없이 수정키로** — `Ctrl`+클릭은 이미 창고 ↔ 인벤토리 이동이 쓰고, 다른 수정키는 화면에 안 보여 찾을 길이 없다

## 파급

- `app.js` — `state.bagLockMode`(잠그는 중인가) 신설 · 고르는 중 줄에서 [잠그기] 삭제 · 잠그는 중의 칸 클릭 = `game.setItemLock` 한 칸
- `style.css` — 잠그는 중도 고르는 중의 파선 테두리(`.inv-cells.picking`)를 쓴다 · 새 클래스 없음
- i18n — `ch.sel.lock` · `ch.sel.locked` · `ch.sel.unlocked` 삭제 · `ch.lock.start` · `ch.lock.done` 신설 · `ch.salvageHint` 개정
- `game_logic` 무변경 — `setItemLock` 은 원래 한 개씩 받는다
- ⚠ **열린 것** — 분해의 고르는 중에서 **잠긴 칸에도 체크는 붙는다**([분해하기]가 건너뛴다). 체크 자체를 막을지는 정하지 않았다
