# ADR-0208 — 로그 목록의 높이는 줄 높이의 정수배다 · 라운드 줄과 목록 사이를 띄운다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §4-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (「그 아래 나오는 로그 글씨와 방금 만든 그 창 사이에 약간의 간격을 둬서 아래 로그 글씨가 안 짤리도록 만들어줘」) |
| **대체** | — |
| **대체됨** | — |

## 결정

로그 목록의 **모든 줄은 같은 높이**(`--lg-row-h`)이고, **목록의 높이는 그 줄 높이의 정수배**로 내림한다(남는 몇 px 은 목록 아래로 빠진다). 새 줄을 따라 맨 아래로 스크롤해 있을 때 맨 윗줄 · 맨 아랫줄이 줄 경계에 맞아 잘리지 않는다. 머리 줄 아래 **라운드 줄과 목록 사이는 6px** 띄운다.

## 맥락

같은 날 머리 줄 · 지금 라운드 줄을 스크롤 목록 밖에 두었다([ADR-0201](0201-로그-머리-줄은-스크롤-목록-밖에-선다.md) · [ADR-0204](0204-로그-머리-줄-아래에-지금-라운드-줄이-고정된다.md)). 목록은 남는 세로를 받아 스크롤했고, 목록 높이가 줄 높이와 무관해서 맨 아래로 따라가 있으면 **맨 윗줄이 라운드 줄 밑 테두리에 반쯤 걸려** 글자가 잘려 보였다(1600×800 실측 — 약 4px 잘림).

재다 보니 하나가 더 나왔다 — 목록 안의 **라운드 · 종료 줄이 높이 1.78px 로 접혀 있었다.** 목록이 높이가 정해진 스크롤 요소가 된 뒤(ADR-0201), 줄이 넘치면 격자의 자동 행이 최소 크기로 서는데 `overflow: hidden` 이 걸린 전폭 줄은 최소 크기가 0 이라 접혔다. 줄이 많아진 뒤로는 목록 안 라운드 경계가 안 보였다.

## 근거

- **간격만으로는 안 잘리게 못 한다** — 잘림은 스크롤 위치가 줄 경계에 안 맞아서 생긴다. 간격을 넣으면 잘린 줄이 간격 아래로 내려갈 뿐이다. 그래서 간격(사용자 요청)과 정수배 높이를 같이 둔다
- **정수배면 끝이 줄 경계다** — 줄이 모두 같은 높이면 스크롤 끝(내용 − 목록 높이)도 줄 높이의 배수라 맨 윗줄이 줄 경계에서 시작한다. 같은 실측에서 1600 · 1920 · 1366 모두 윗줄 · 아랫줄 어긋남이 0.5px 안쪽이었다(화면 배율의 픽셀 반올림 — 줄 아래 여백 자리라 글자가 안 걸린다)
- **줄 높이를 명시하면 접힘도 없어진다** — 행 높이가 정해져 최소 크기 규칙을 안 탄다. 라운드 줄이 다시 23px 로 섰다(같은 실측)
- **`round()` 를 모르는 브라우저** — 앞에 둔 `height: 100%` 로 선다. 정수배만 빠지고 그 전과 같다

**버린 안**

1. **간격만 둔다** — 위(잘림이 그대로다)
2. **윗가장자리를 흐리게(마스크) 한다** — 잘린 줄이 흐려질 뿐 여전히 반 줄이다
3. **스크롤 스냅(줄 시작에 맞춤)** — 목록 높이가 줄의 배수가 아니면 맨 아래 새 줄이 잘린다. 가장 중요한 줄이 새 줄이다
