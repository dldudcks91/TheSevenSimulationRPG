# ADR-0246 — 특수상단 패널은 상단 패널 아래에 선다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §8-3](../SCREEN_DESIGN.md) · §2 「박스 규격」 |
| **정한 사람** | 사용자 지시 — 「특수상단 카드를 상단카드 아래로 보내줘」 |
| **대체** | [ADR-0243](0243-특수상단은-상단-오른쪽에-따로-선-패널이다.md) 의 **자리**(상단 오른쪽 · 두 열 나란히 · 상단 폭 비율). 특수상단이 **따로 선 패널**이라는 것 · 제 제목 · 미착수 표지 둘은 그대로 산다 |
| **대체됨** | — |

## 결정

상점 탭의 패널 둘을 **위아래로 쌓는다** — 위 **상단** 패널(장비 · 재료 탭 · 아이콘 칸 · 사기 줄)은 **제 내용 높이**로 서고, 아래 **특수상단** 패널이 **남는 세로를 받아 박스 끝까지** 선다. 두 패널 모두 박스 전폭이다. 특수상단은 제 본문 안에서 스크롤하고, 상단은 박스가 모자랄 때만 제 본문 안에서 스크롤한다.

## 맥락

같은 날 [ADR-0243](0243-특수상단은-상단-오른쪽에-따로-선-패널이다.md) 이 특수상단을 상단 오른쪽의 따로 선 패널로 세웠다 — 리포트의 두 열 짜임(`.cols.c-side.page`)을 빌려 장비 네 줄이 남긴 오른쪽 폭을 썼다. 그 ADR 은 「상단 아래에 쌓기」를 버린 안으로 적었다(상단이 전폭으로 서서 오른쪽이 빈다).

## 근거

- **사용자 지시** — 버린 안 ①(아래에 쌓기)을 사용자가 골랐다. 빈 오른쪽 폭보다 위에서 아래로 읽히는 순서(상주 창구 → 가끔 들르는 손님)를 택했다
- **따로 선 패널은 유지한다** — 뒤집힌 것은 자리뿐이다. 한 패널 안의 둘째 묶음(ADR-0223 의 선술집 모양)으로 돌아가지 않는다 — 제 제목을 단 패널이라 상단의 한 칸으로 읽히지 않는다
- **아래 패널이 남는 세로를 받는다** — 탐험 탭(지도 위 · 안내가 남는 세로)과 같은 쌓인 판 짜임(`.page-stack > .fill`)을 빌린다. 새 배치 문법을 만들지 않는다. 박스 아랫변(ADR-0097)에 닿는 것은 아래 패널이다
- **상단 폭 비율 규칙은 사라진다** — 그 규칙은 탭을 바꿀 때 옆의 특수상단이 밀리지 않게 하려던 것이다. 옆에 선 것이 없어 지킬 대상이 없다
- **버린 안** — 상단 패널 폭(38%)을 그대로 두고 특수상단도 같은 폭으로 그 아래에 세우기: 박스 오른쪽이 위아래로 통째로 빈다

## 파급

- `app.js:renderShop` — 루트가 `.page-stack.c-shop.page` · 특수상단 패널에 `.fill` · `data-keep` 둘(`shop` · `shop-sp`)은 그대로
- `style.css` — `.cols.c-shop` 두 열 · `grid-template-rows` 삭제 → 쌓인 판 규칙 · 상단 패널은 모자라면 줄어든다
- SCREEN_DESIGN §2 박스 규격의 상점 행 — 위아래 둘
- ⚠ 특수상단 패널은 카드 한 장(또는 한 줄)만 들어 아래가 빈다 — 재고 테이블 · 상인 이야기가 정해지면 채울 자리다(ADR-0243 에서 넘어온 것)
