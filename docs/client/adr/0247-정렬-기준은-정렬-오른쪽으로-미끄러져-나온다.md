# ADR-0247 — 정렬 기준은 [정렬] 오른쪽으로 미끄러져 나온다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §6](../SCREEN_DESIGN.md) (§4-2) |
| **정한 사람** | 사용자 지시 (「정렬버튼 누르면 정렬 오른쪽에 솨르륵 나오도록 수정」) |
| **대체** | [ADR-0242](0242-정렬은-누를-때-한-번-줄-세운다-기준은-정렬이-도구-줄에-펼친다.md) 중 **기준이 펼쳐지는 모양**(도구 줄이 통째로 [등급순] · [레벨순] · [부위순] · [취소]로 바뀌던 것) — 한 번 줄 세우기 · 칸마다 제 [정렬] · 기준 셋 · 동점 규칙은 그대로 산다 |
| **대체됨** | — |

## 결정

[정렬]을 누르면 도구 줄은 그대로 서 있고, **[정렬] 바로 오른쪽에 [등급순] · [레벨순] · [부위순]이 차례로 미끄러져 나온다.**

- [정렬]은 **켜진 모양**이 되고, **다시 누르면 접힌다** — [취소]가 없다
- 기준 하나를 고르면 그 칸을 한 번 줄 세우고 접힌다
- 나오는 움직임은 **펼칠 때 한 번**만 돈다 — 펼친 채로 화면이 다시 그려져도(관전의 갱신 등) 다시 돌지 않는다. 접을 때는 움직임 없이 사라진다
- 인벤토리 쪽은 [잠금] · [분해] · [자동 분해]가 펼친 동안에도 그대로 선다

## 맥락

같은 날 [ADR-0242](0242-정렬은-누를-때-한-번-줄-세운다-기준은-정렬이-도구-줄에-펼친다.md) 는 [분해] → [분해하기] · [취소]와 같은 문법으로, [정렬]을 누르면 도구 줄이 통째로 기준 셋 + [취소]로 바뀌게 했다. 화면에 선 뒤 사용자가 기준을 [정렬] 오른쪽에서 펼쳐 나오게 하라고 지시했다.

화면은 상태가 바뀔 때마다 통째로 다시 그린다(ARCHITECTURE §5) — 새로 만든 요소의 CSS 움직임은 다시 그릴 때마다 처음부터 돈다.

## 근거

- **누른 자리에서 나온다** — 기준이 [정렬]에 딸린 것으로 읽힌다. 줄이 통째로 바뀌면 눈이 줄 맨 앞으로 돌아가야 한다
- **[취소]가 필요 없다** — 펼친 [정렬] 자체가 접는 버튼이다. 버튼이 하나 준다
- **나머지 버튼이 안 사라진다** — 정렬은 되돌릴 필요가 없는 순서 바꾸기라 다른 조작을 막을 이유가 없다([분해]의 고르는 중과 다르다)
- **움직임을 한 번만 돌리는 이유** — 통째로 다시 그리는 화면이라, 그냥 두면 관전 중 갱신마다 버튼이 다시 미끄러져 나와 깜빡인다

**버린 안**

1. **[정렬 ▾] 아래로 펼침 목록** — ADR-0242 의 버린 안 3 그대로(칸 위를 덮는다 · 없던 부품)
2. **접을 때도 미끄러져 들어가기** — 다시 그리기를 움직임이 끝날 때까지 미뤄야 한다. 통째로 다시 그리는 화면의 단순함을 깬다

## 파급

- `app.js` — 도구 줄 두 곳 · `state.bagSortAnim`(펼친 직후 한 번만 움직임을 단다)
- `style.css` — `.sort-fold`(펼친 기준 묶음) · 차례로 미끄러지는 움직임 · 움직임 줄이기 설정(`prefers-reduced-motion`)이면 안 돈다
- 영어 라벨을 줄인다 — 펼친 채로 한 줄에 들어가야 한다
