# ADR-0249 — 도감 몬스터 카드의 진행 줄은 처치 수 · 레벨 · 그 몬스터의 보정이다

| | |
|---|---|
| **상태** | 확정 · 2026-09-21 |
| **화면** | [SCREEN_DESIGN §9](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시(「Next at 100 이거 삭제하고 n kills - Lvn - 각 몬스터별 능력치 +0.0% 로 수정해줘」) |
| **대체** | — *(카드의 「다음 … 마리 +x%」는 ADR 없이 처치 수 모델 전환에서 섰다)* |
| **대체됨** | — |

## 결정

도감 몬스터 카드의 진행 줄은 `처치 수 · Lv.n · 계열 스탯 +x.x%` 셋이다. `+x.x%` 는 **그 몬스터가 지금 주는 누적 보정**(`game.codexBonusAt(레벨)` · 그 스테이지의 계열 · 소수 한 자리)이고, 0 레벨이면 `+0.0%`, 계열이 없는 스테이지면 `—` 다. 다음 레벨의 누적 처치 문턱(「다음 100마리」)과 다음 레벨에서 붙을 보정은 카드에서 뺀다. 최대 레벨의 「최종」 글자도 없다 — `Lv.n` 이 곧 그 답이다.

## 맥락

그날 카드의 진행 줄은 `처치 12 · 다음 100마리 +0.5%` 였고, 최대 레벨이면 `처치 N · 최종` 이었다. 보정 % 는 **다음 레벨에서 더해질 한 단계 값**이라, 그 몬스터가 지금 스테이지 보정에 얼마를 보태고 있는지는 카드에 없었다(스테이지 행은 몬스터 전부의 합만 든다). 레벨 숫자도 핍 개수로만 읽혔다.

## 근거

사용자 지시다.

- **지금 받는 값이 카드의 값이다** — 도감은 모으는 화면이고, 카드 한 장이 말할 것은 「이 몬스터를 여기까지 모았고 그래서 이만큼 받는다」다. 다음 목표는 안 켜진 핍과 진행 막대가 이미 보여 준다
- **소수 한 자리 고정** — 스테이지 행의 보정(`+x.x%`)과 같은 모양이라, 카드들의 합이 행의 값으로 그대로 읽힌다

## 파급

- `app.js:monsterCard` — 스테이지 계열(`stage.stat`)을 받는다 · 레벨 라벨은 툴팁 단계 줄이 쓰던 `cx.tip.lv` 를 그대로 부른다
- i18n `cx.next` · `cx.max` 삭제(읽는 곳이 없어졌다)
- ⚠ [ADR-0209](0209-도감-몬스터-툴팁의-단계는-레벨만-든다-칸은-선으로-가른다.md) 의 근거 「문턱은 카드가 든다」가 무너졌다 — 레벨별 처치 문턱은 이제 **레벨 핍의 작은 툴팁**(「도감 Lv.n · 처치 N」)에만 남는다
