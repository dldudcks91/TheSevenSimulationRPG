# ADR-0286 — 출정 창 두 줄은 가로 가림막이 가른다 — 칸 이름 밑줄과 함께 선다

| | |
|---|---|

| **화면** | [SCREEN_DESIGN §4-1](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (「위아래를 나눠야 할 것 같아 확인해봐」) · 옛 가림막 · 여백(48 + 48)으로 되돌린 것은 Claude |

| **대체됨** | — |

## 결정

출정 창의 두 줄(위 = 적 구성 · 이야기, 아래 = 편성 · 들고 가는 것 · 출정 방식)은 다시 **가로 가림막**이 가른다. 가림막 위아래 여백은 각 48 이다. 칸 이름 여섯의 소제목 모양(굵게 · 밝게 · 밑줄 — ADR-0285)은 그대로 산다. 그래서 아래 줄은 가림막 → 여백 48 → 칸 이름 → 밑줄 순으로 선다.

## 맥락

같은 날 ADR-0285 가 칸 이름을 소제목 모양으로 바꾸면서 가로 가림막을 걷고 줄 사이를 여백 36 으로만 떼었다. 편성 탭에서 단 사이 선을 걷은 것(ADR-0256)과 같은 이유였다 — 선 두 개 사이에 이름이 갇힌다. 세로 구분선은 두 줄을 그대로 관통했다.

## 근거

- **위아래가 한 덩어리로 붙어 보였다** — 사용자 지적. 세로 구분선만 남으니 창이 「두 줄」이 아니라 「두 열」로 읽혔다. 위 줄은 읽는 자리, 아래 줄은 누르는 자리라 줄이 곧 갈래다(ADR-0214)
- **ADR-0256 의 걱정은 여기선 안 선다** — 편성 탭에서는 단 사이 선이 이름 바로 위에 붙어 섰다. 여기서는 가림막과 밑줄 사이가 48 이라 글씨가 선 사이에 갇혀 보이지 않는다
- **여백 48 + 48** — 2026-09-14 사용자 지시(「답답해 보인다」)로 정한 옛 값 그대로다. 선이 두 줄 사이 가운데에 선다
- 가림막은 칸 이름 밑줄(`--border-primary`)보다 한 단 밝은 `--border-secondary` 다 — 창의 뼈대 선이 묶음 이름 선보다 먼저 읽힌다

## 파급

- CSS — `.dw-body > *` 아래 여백 36 → 48 · `.dw-body > .dw-r2` 윗 여백 48 · 윗선을 되살림
- 창 높이가 ADR-0285 이전으로 돌아간다(칸 이름 밑줄 몫만큼 조금 더 높다) — 폭은 그대로
