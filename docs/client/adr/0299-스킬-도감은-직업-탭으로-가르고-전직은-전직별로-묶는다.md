# ADR-0299 — 스킬 도감은 직업 탭으로 가르고 전직은 전직별로 묶는다

## 결정

도감의 스킬 세그먼트 첫 줄에 **직업 다섯** 안쪽 세그먼트를 둔다(`class.csv` 행 순 · 기본은 첫 직업). 고른 직업 하나만 펴고, 그 안에서 「{직업} 스킬」 묶음 뒤에 **전직 하나가 묶음 하나**로 선다 — 묶음 머리는 전직 이름(파이어 메이지 · 프로스트 메이지 · 썬더 메이지)이다.

## 맥락

같은 날 전직 마법사 스킬 아이콘 8장이 먼저 들어왔다. `skill.csv` 에 전직 스킬 행이 없어 직업 묶음이 세우지 못하므로, 직업 묶음 뒤에 「마법사 전직 스킬」 한 묶음으로 따로 세웠다. 그 한 줄이 늘자 스킬 세그먼트가 기준 한 장을 넘어 사제 묶음이 스크롤 아래로 밀렸다. 사용자 지시 — 「스킬 탭 안에 직업별 탭을 5개 만들고, 그 아래에 마법사 전직 스킬이라고 하지 말고 전직 마법사별로 분류해 이름을 적어」.

## 근거

- **ADR-0075 가 버린 안을 사용자가 골랐다** — 0075 는 「직업 세그먼트를 한 겹 더 얹는다」를 「직업 수만큼 눌러야 하고 스크롤을 클릭으로 바꾼 것뿐」이라며 버렸다. 그때는 묶음이 직업 다섯뿐이라 조밀 격자로 한 장에 들었다. 전직이 묶음으로 서면 직업마다 **최대 네 묶음**(직업 하나 + 전직 셋)이 되어 다섯 직업이 한 장에 들 수 없다 — 칸을 더 줄이는 길은 0075 의 48px 에서 막혀 있다
- **안쪽 세그먼트는 아이템에 선례가 있다** — [ADR-0179](0179-아이템-도감은-무기와-방어구로-가르고-방어구는-부위별로-묶는다.md) 의 무기 / 방어구 줄과 같은 자리 · 같은 모양이다. 도감 안에 새 조작 모양을 만들지 않는다
- **전직은 묶음 머리가 든다** — 전직을 탭으로 한 겹 더 세우면 세그먼트가 세 겹(자산 × 직업 × 전직)이 된다. 한 직업의 묶음은 넷이 최대라 한 장에 든다
- **「{직업} 전직 스킬」 한 묶음은 버렸다** — 세 전직의 스킬이 한 줄에 섞여 어느 그림이 어느 전직 것인지 파일명으로만 읽힌다. 전직이 곧 스킬의 출처라 묶음 머리가 그것을 말해야 한다

## 파급

- `app.js` 에 화면 상태 `codexSkillSeg` 와 개발용 `?cxs=<직업 id>` 가 생긴다 — 세이브에는 넣지 않는다
- `mock.js:SKILL_ADV_ICON_FILES` 가 직업 id → 전직 id → 그림 목록 두 층이 된다. i18n 에 전직 이름 `ix.adv.*` 가 생기고, 하루 만에 `ix.g.skillAdv` 는 사라진다
- 조밀 격자 · 확장자 떼기 · 툴팁 · 직업 묶음의 목록 SSOT(`skill.csv`)는 그대로다
- ⚠ 전직 스킬이 `skill.csv` 에 행으로 서면 이 묶음의 목록 · 이름을 CSV 로 옮겨야 한다 — 그때 전직을 가리키는 열이 필요하다(스키마는 `/client` 몫)
- ⚠ 다섯 직업 중 어느 직업이 아직 그림이 없는지는 이제 탭을 하나씩 눌러야 보인다 — 0075 가 지키려던 한눈 감사가 사라졌다
