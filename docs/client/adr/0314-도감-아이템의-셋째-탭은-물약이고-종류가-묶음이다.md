# ADR-0314 — 도감 아이템의 셋째 탭은 물약이고 종류가 묶음이다

| **대체** | — |

## 결정

도감 아이템 세그먼트의 안쪽 탭에 **물약**을 셋째로 둔다. 물약 탭은 `potion.csv` **행 순(= 단계 순)** 으로 펴고 **종류(`kind`) 하나가 묶음 하나**다. 타일 이름은 **CSV 가 든다**(`name_kr` · `name_en`)이고, 묶음 머리의 종류 이름만 `i18n:ix.pk.*` 가 든다. 그림 목록은 `mock.js:POTION_ART_IDS` 라 **등록된 그림만** 선다. 칸 배경 `slot.png` 는 싣지 않는다.

## 맥락

힐링 포션 5종 그림이 설치되어 `POTION_ART_IDS` 에 올랐다. 그림을 읽는 자리는 셋 — 관전 아레나의 물약 칸 · 편성 탭의 물약 칸 · 제련소의 재고 줄. 셋 다 **지금 가진 물약**만 그린다. 아직 안 만들어 본 단계의 병은 게임 어디에서도 볼 수 없었고, 제련소의 제작 줄조차 이름과 회복량만 찍는다. 도감의 아이템 세그먼트는 무기 · 방어구 둘로 갈려 **장비만** 싣고 있었다 ([ADR-0179](0179-아이템-도감은-무기와-방어구로-가르고-방어구는-부위별로-묶는다.md)).

## 근거

- **도감은 자산 재고를 훑는 자리다** — 무기 베이스 묶음이 「어느 개체에 무엇이 붙었는지가 아니라 **무엇이 그려져 있는지**」를 보여주듯, 물약도 재고 0 인 단계까지 전부 선다. 그림이 다섯 장 다 있는데 볼 자리가 없는 쪽이 빈 구멍이었다
- **아이템의 안쪽 탭이지 최상위 세그먼트가 아니다** — 물약은 아이템이다. 최상위(몬스터 · 캐릭터 · 아이템 · 스킬)를 다섯으로 늘리면 「아이템」이 「장비」라는 뜻으로 좁아진다
- **ADR-0179 의 「셋째 자리를 만들지 않는다」와 부딪히지 않는다** — 그 문장이 막은 것은 **무기 아닌 장비**(반지 · 목걸이)가 빠져나갈 자리였다. 물약은 장비가 아니라 소모품이라 애초에 방어구 탭에 들어갈 수 없다
- **묶는 축은 `kind` 이지 단계가 아니다** — 단계(`tier`)로 묶으면 묶음 다섯에 타일이 하나씩이라 격자가 뜻을 잃는다. `kind` 로 묶으면 지금은 묶음이 하나지만 종류가 늘 때 저절로 갈린다
- **타일 이름을 i18n 에 두 벌 두지 않는다** — 무기 베이스가 `ix.b.*` 로 이름을 드는 것은 그 묶음이 `weapon_base.csv` 행을 아직 안 읽어서 생긴 임시다([SCREEN_DESIGN §9-1](../SCREEN_DESIGN.md)). 물약은 `potion.csv` 가 이미 편성 · 제련소 · 관전에 이름을 대고 있어 같은 임시를 새로 만들 이유가 없다. 라벨 컬럼이 없는 `kind` 만 i18n 이 든다
- **칸 배경 `slot.png` 는 안 싣는다** — 빈 칸 실루엣을 싣지 않는 [ADR-0181](0181-아이템-도감은-빈-칸-실루엣을-싣지-않는다.md) 과 같은 이유다. 그것은 어느 물약도 아닌 「여기에 물약이 들어간다」는 **칸의 말**이라 도감의 축(어느 물약인가)에 설 자리가 없다

## 파급

- `app.js:CODEX_ITEM_SEGS` 가 셋이 되고 개발용 `?cxi=potion` 이 열린다 ([SCREEN_DESIGN §10](../SCREEN_DESIGN.md)) — `codexItemSeg` 는 화면 상태라 세이브에 안 들어간다
- i18n 키 둘 — `ix.seg.potion`(탭) · `ix.pk.heal`(묶음 머리의 종류 이름)
- 물약 탭은 `D.potions` 를 읽는다 — 아이템 세그먼트가 CSV 행을 **이름까지** 읽는 첫 자리다
- ⚠ 열린 채 남은 것 — 물약 5종의 색 수 실측이 아이템 합격선(35~130) 위다(135~142). 유리 반사가 원인이고 28px · 40px 가독은 통과해 재발주하지 않았다 ([art/README.md](../../../src/assets/art/README.md))
