# ADR-0317 — 출정 창 편성 초상도 띠 카드와 같은 위칸과 레벨을 단다

## 결정

출정 창 **편성** 칸의 초상 셋은 **영웅 띠 카드와 같은 얼굴**을 한다 — 초상 위 **위칸**(왼쪽 지금 하는 일 · 오른쪽 이름) · 초상 **오른쪽 아래 레벨** · 왼쪽 아래 리더. 조각은 띠 카드의 것(`.hs-band` · `.hs-doing` · `.hs-name` · `.hs-lv` · `.hs-leader`)을 그대로 쓴다. 같은 얼굴을 그리는 세 자리(캐릭터 · 편성 탭 띠 · 진형 보드 칸 · 출정 창 초상)가 **한 함수**(`app.js:heroCardHtml`)에서 나온다.

## 맥락

그날 출정 창 초상은 **그림과 리더 태그뿐**이었고 이름 · 레벨은 툴팁이 들었다. 같은 크기(`--fm-slot`)의 진형 보드 칸은 이미 띠 카드와 같은 얼굴이었다([ADR-0280](0280-진형-보드-칸은-띠-카드와-같은-위칸과-레벨을-단다.md)) — 0280 은 「출정 창 초상은 위칸이 없는 그대로다 · 지시가 가리킨 것은 편성 탭 보드다」를 그날의 사실로 적었다.

같은 날 동시 원정이 **최대 3부대**로 열렸다([ADR-0316](0316-관전-칸은-부대마다-선다-안-보는-부대도-앱-시계가-민다.md)). 출정 창에서 편성을 고를 때 그 편성의 영웅이 **이미 다른 부대로 나가 있는지**가 출발 가능 여부를 가르게 됐다(`canDepart` 의 `busy`).

## 근거

- **보내기 직전이 「누가 지금 뭘 하나」를 읽을 마지막 자리다.** 부대가 여럿이면 편성 2 의 영웅이 1부대로 이미 싸우고 있을 수 있고, 수색에 나가 있을 수도 있다. 그걸 초상 위에서 바로 읽어야 출발이 왜 막히는지 안다 — 툴팁을 하나씩 열어 보는 것은 통제성(원칙 2)에 못 미친다
- **같은 크기의 같은 영웅은 같은 얼굴이다** — 0280 의 근거 그대로다. 띠 · 보드 · 창이 같은 `--fm-slot` 한 변이라, 창에서만 글자가 빠지면 같은 영웅이 두 얼굴로 읽힌다
- **한 함수로 모은다** — 조각이 세 벌 복사돼 있으면 한 곳만 고쳐지는 사고가 난다(0197 · 0199 · 0278 이 위칸 · 레벨 자리를 여러 번 옮겼고 그때마다 두 자리를 따로 고쳤다)

## 파급

- `app.js:heroCardHtml(h, { leader })` 신설 — `heroStrip` · `formBox`(진형 칸) · `presetPick`(출정 창) 셋이 부른다
- 새 i18n 키 없음 · 새 CSS 없음 — `.pk-face` 가 이미 `position: relative · overflow: hidden` 이라 띠 조각이 그대로 얹힌다
- 초상에 올리면 뜨는 툴팁(§2 영웅 유닛 툴팁)은 그대로다
- ⚠ 「지금 하는 일」은 **어느 부대인지를 안 말한다** — 「원정 중」 하나다(`heroDoing`). 부대 번호를 붙이는 것은 띠 · 보드까지 같이 바뀌는 일이라 따로 정한다
