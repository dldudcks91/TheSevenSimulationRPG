## 결정

건설 탭 오른쪽 상세를 **셋**으로 가른다 — ① 머리(작은 그림 · 이름 · 상태 한 줄 「미건설」 / 「n랭크」 / 「최대 랭크」 · 진행 막대) ② **「다음 랭크」 절**(번호 배지 + 여는 것 태그 · 조건 전부를 ✓ / ✗ 로 · 「n랭크 비용」 **재료 칸** · 폭을 꽉 채운 [건설]) ③ **「{건물} 랭크」 목록**(사다리 — 번호 배지 · 여는 것 태그 · 안 지은 랭크의 조건 · 완료 / 준비 중). 재료 칸은 **재화 그림 칸 오른쪽 아래에 필요 수량, 칸 아래에 이름과 「보유 n」** 이다. 비용과 [건설]은 「다음 랭크」 한 곳에만 선다.

## 맥락

ADR-0321(같은 날) 직후의 상세는 띠 그림 아래 사다리였고, 비용은 다음 랭크 칸 안의 작은 칩(「골드 / 100」)이었다. **가진 양이 안 보였다** — 칩의 말풍선에만 있었다. 사용자가 Lootun 의 「Upgrade Info」 판을 보였다: 건물 머리 · **Next Rank**(무엇이 열리나 · 재료 그림 칸마다 필요 수량과 Owned · 골드 보유 / 필요 · Purchase Upgrade) · **Ranks** 목록. 재화 그림은 이날 게임에 없었다(제련소 재료 칸도 이름 글자뿐).

## 근거

- **짓는 결정에 필요한 것이 한 자리에 모인다** — 무엇이 열리나 · 무엇이 모자라나 · 얼마나 더 모아야 하나 · 버튼. 사다리 칸 안에 넣으면 칸 높이(목록 세로의 1/7)에 묶여 재료 칸을 크게 못 그린다
- **필요와 보유를 나란히** — 비용 칩의 「모자라면 붉다」는 **모자란지**만 말하고 **얼마나** 모자란지는 안 말했다. 보유가 칸 아래 서야 「골드 100 · 보유 428」이 한 눈에 읽힌다
- **재화 그림은 임시 단색 실루엣**(`mock.js:RES_ART` — 금화 · 가루 · 낙인 · 광석 · 목재 · 약초) — 건물 실루엣(`BUILDING_ART`)과 같은 처리다. 글자만 있는 칸은 참고작의 「그림 칸 + 수량」 문법이 안 선다. 아트가 오면 이 표만 갈아 끼운다
- **[건설]은 한 곳** — 목록 칸에도 두면 같은 버튼이 두 번 선다. 목록은 「무엇이 언제 열리나」를 읽는 자리로 남긴다
- **조건은 전부 · ✓ / ✗** — 「다음 랭크」 에서 모자란 것만 찍으면 선 조건이 사라져 「무엇을 이미 채웠나」가 안 읽힌다. 목록은 흐린 글씨라 경고색은 여기 한 곳이다
- **버린 안 — 띠 그림 유지** — 「다음 랭크」 절이 세로를 먹어 목록 7칸이 안 들어갔다. 참고 화면도 머리는 작은 그림 + 이름 + 상태다
