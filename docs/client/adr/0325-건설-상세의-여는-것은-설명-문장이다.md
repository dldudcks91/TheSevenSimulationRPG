# ADR-0325 — 건설 상세의 여는 것은 설명 문장이다

## 결정

건설 상세(「다음 랭크」 · 랭크 목록)에서 여는 것을 **이름이 아니라 설명 문장**으로 쓴다 — 여는 것 하나마다 「무엇을 할 수 있게 되나」 한 문장을 한 줄에 하나씩(「선술집 명단에서 영웅을 고용한다」 · 「보유할 수 있는 영웅이 {n}명 늘어난다」). 문장은 **대상마다 한 키**(`cn.t.<대상>` — 값을 이름에서 문장으로 바꿨다)라 랭크마다 따로 쓰지 않는다. 효과만 적고 조건 · 절차는 안 적는다. 이것은 **§12 「설명 문구는 도움말 탭 전용」의 예외**다.

## 맥락

ADR-0324(같은 날) 직후 여는 것은 「고용 · 수색 · 의뢰 게시판 (준비 중)」 같은 이름 잇기였다. 사용자가 보인 참고 화면(Lootun 「Upgrade Info」)은 랭크마다 「Unlock the ability to donate spare Materials for Donation Credits.」 같은 **설명 문장**이다. 사용자 지시는 상자를 걷으라는 것에 더해 「설명을 글로 쓰라」였다 — 이름만으로는 「위험도 조절」 · 「품목 층 +1」 이 무엇인지 안 읽혔다.

## 근거

- **이 화면의 일은 「이 랭크가 무엇을 여나」를 읽는 것이다** — 짓는 결정은 무엇을 얻는지를 알아야 선다. 기능 이름은 그 기능을 이미 아는 사람에게만 읽힌다. §12 가 설명을 도움말로 모은 이유(인게임 패널을 숫자 · 상태로 가볍게)는 여기서 그 결정 자체를 막는다 — 그래서 예외다
- **문장은 대상의 것이지 랭크의 것이 아니다** — construction_draft §11-6(「랭크 설명 문구를 따로 쓰지 않는다 · 표를 옮기면 설명도 따라간다」)을 지킨다. 표에서 줄을 옮겨도 문장이 따라가고, 새 랭크를 더해도 문장을 새로 안 쓴다
- **키를 새로 만들지 않고 `cn.t.*` 의 값을 바꿨다** — 짧은 이름을 읽는 자리가 이 화면뿐이었다. 두 벌을 두면 한쪽이 죽은 키로 남는다
- **버린 안 — 랭크마다 한 문장(참고작 그대로)** — 참고작은 랭크 설명을 랭크마다 쓴다. 이 게임은 여는 것이 표의 줄이라 랭크 문장을 두면 표와 문장이 두 벌이 되어 §11-6 이 깨진다

## 파급

- `i18n.js` — `cn.t.<대상>` 의 값이 이름 → 설명 문장(더하기는 `{n}` 을 그대로 쓴다)
- `app.js` — `effectText` 가 한 줄에 한 문장을 쓴다(`.cn-desc`)
- `style.css` — `.cn-desc` · 「다음 랭크」 의 「n랭크」 가 문장 위에 선다
- ⚠ §12 의 예외가 하나 늘었다 — 도움말 탭은 이 문장을 새로 쓰지 않는다(쓰게 되면 같은 키를 부른다)
