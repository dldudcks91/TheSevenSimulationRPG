# ADR-0332 — 마스터리 툴팁 효과는 「무엇이 n 증가한다」 한 문장이다

## 결정

마스터리 칸 툴팁의 효과 줄은 **「무엇이 n 증가한다」 한 문장**이다 — `최대 HP가 5% 증가한다. (랭크당 1%)` · 영어 `Max HP increases by 5%. (Per rank 1%)`. 값과 랭크당 값은 **부호 없이** 찍는다. 이름이 이미 「감소」인 축(피해 감소 · 쿨타임 감소 · 저항 감소)은 줄어드는 것을 주어로 세워 `받는 피해가 n 감소한다` · `쿨타임이 n 감소한다` · `적의 원소 저항이 n 감소한다` 로 쓴다. 이름 끝이 「증가」인 최대 저항 증가는 `최대 원소 저항이 n 증가한다`, 괄호가 붙은 강타(현재 체력)는 `강타가 n 증가한다`. 문장은 축마다 통째로 `i18n.js:sk.masteryEffect.<stat>` 이 들고, 사전에 없는 축은 `sk.masteryEffect`(`{축 이름} n 증가한다`)로 떨어진다.

## 맥락

효과 줄은 한 틀 `{stat}에 {value} 보너스를 준다. (랭크당 {perRank})` 로 모든 축을 찍었다 — `최대 HP에 +5% 보너스를 준다`. 같은 날 건설 상세의 더하기도 「대상 +n 증가」 로 바뀌었다(ADR-0329).

## 근거

- **「보너스를 준다」는 주는 쪽이 누구인지만 말하고 무엇이 변하는지는 흐린다** — 「최대 HP가 늘어난다」 는 캐릭터 창의 그 줄이 어떻게 움직이는지를 바로 말한다
- **틀 하나에 조사를 붙이는 안을 버렸다** — `{stat}이/가` 를 렌더러가 받침으로 고르면 한국어 규칙이 렌더러에 들어간다(이름 조립은 데이터 층 · ui 원칙 3). 그리고 이름이 「감소」 로 끝나는 축은 조사를 맞혀도 `피해 감소가 n 증가한다` 로 동사가 꼬인다. 축마다 문장을 통째로 두면 둘 다 풀린다
- **부호를 뺀다** — `+5% 증가한다` 는 방향을 두 번 말하고, 감소 문장에서는 `+6% 감소한다` 로 서로 부딪힌다
- **괄호 · 증가 꼬리가 붙은 이름은 주어로 안 쓴다** — `강타 (현재 체력)가` · `최대 저항 증가가 n 증가한다` 는 문장이 안 된다. 이름의 핵심 말만 주어로 세운다
- **없는 축은 문장 틀로 떨어진다** — 새 축이 `mastery_node.csv` 에 먼저 들어와도 툴팁이 키 이름을 찍지 않는다. 조사가 없는 `{축 이름} n 증가한다` 라 틀려 읽히지 않는다

## 파급

- `i18n.js` — `sk.tip.effect` 가 `{effect}. (랭크당 {perRank})` 틀이 되고, 축 문장 `sk.masteryEffect.<stat>` 과 폴백 `sk.masteryEffect` 가 선다
- `app.js:masteryTipCard` — 값을 `M.baseValue`(부호 없음)로 찍는다. 칸의 총합(`+0%`)은 그대로 `M.statValue` 다
- ⚠ 축 문장은 축 이름(`mock.js:AFFIX_LABELS` · `combat_stat.csv`)을 글자로 다시 든다 — 이름을 바꾸면 이 문장도 같이 고친다
