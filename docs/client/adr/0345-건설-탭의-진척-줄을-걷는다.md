# ADR-0345 — 건설 탭의 진척 줄을 걷는다

| | |
|---|---|
| **상태** | 확정 · 2026-09-24 |

| **대체** | — *(ADR 이 아니던 규격 — §13-1 의 「진척 — 지은 랭크 n / 전체」 행)* |
| **대체됨** | — |

## 결정

건설 탭 박스 맨 위의 진척 줄(「지은 랭크 n / 전체」)을 걷는다. 박스는 곧바로 부지 격자 | 상세 두 열로 시작한다. 걷힌 줄의 세로는 부지 네 줄이 나눠 가져 네모가 커진다(「네 줄이 박스에 딱」 규칙 그대로) · 상세 머리 그림 높이는 소제목 윗선이 부지 둘째 줄 윗변에 서도록 다시 잰다.

## 맥락

그날 건설 탭은 맨 위 영웅 띠(ADR-0342) 아래 박스 하나였고, 박스 첫 줄이 진척 줄 「지은 랭크 4 / 50」 이었다(모든 건물 랭크의 합 · `constructionState` 의 `built` · `total`). 부지는 3 × 4 이고 네모 높이는 띠 · 진척 줄 아래 네 줄이 딱 드는 137 이었다. 사용자 지시 — 「위에 지은 랭크 4/50 이거 삭제해 봐」.

## 근거

- **건물마다의 진행은 부지 막대가 이미 말한다** — 각 네모 아래 랭크 눈금이 지은 만큼 찬다(ADR-0313). 합계 한 줄은 짓는 결정(어느 건물 · 다음 랭크)에 쓰이지 않는다
- **띠가 박스 위에 서면서 세로가 모자랐다** — 진척 줄을 걷으면 그 세로가 부지와 상세로 간다
- **「값은 항상 찍는다」(§4-1) 와는 부딪히지 않는다** — 그 규칙은 결과 칸을 비워 두지 말라는 것이고, 여기는 칸째 걷는다
- **버린 안** — 진척 숫자를 상단바 crumb 옆으로 옮기기: 사용자는 삭제를 지시했고 합계가 설 자리를 따로 요구하지 않았다

## 파급

- `app.js:renderResearch` 의 `.rs-head` 줄을 뺐다 · i18n `cn.progress` 는 쓰는 곳이 없어 지운다
- `.cn-lots` 네모 높이 · `.cn-head` 의 `--cn-thumb-h`(그림 · 건설 인력 칸 높이)를 한 장 실측으로 다시 맞췄다
- ⚠ 전체 몇 랭크를 지었나는 이제 화면 어디에도 없다 — 필요해지면 도움말이나 다른 자리를 새로 정한다
