# ADR-0371 — 터치 기기의 세로 창에서는 「가로로 돌려 주세요」 막이 선다 · 한 장은 안 눕힌다

## 결정

터치 기기(`pointer: coarse`)에서 보이는 창이 세로로 길면 한 장을 눕히지 않고, 창 전체를 덮는 **「가로로 돌려 주세요」 막**(`#turn` · 한 장 밖)을 세운다. 버튼은 둘이다.

- **전체 화면 + 가로 고정** — `requestFullscreen({ navigationUI: 'hide' })` 뒤 `screen.orientation.lock('landscape')`. 브라우저가 전체 화면 API 를 안 가지면(아이폰 사파리) 버튼을 안 그린다. 성공 여부와 상관없이 누르면 막이 걷힌다
- **이대로 계속하기** — 막이 걷히고 한 장은 세로 창에 그대로(ADR-0087 공식) 작게 선다

창이 가로가 되면 막이 걷히고 걷음 기억도 지워진다 — 다시 세로가 되면 또 선다. 기억은 세이브에 안 들어간다. PC 는 창을 세로로 좁혀도 막이 안 선다.

## 맥락

- 사용자가 모바일에서 한 장이 저절로 눕는 것을 「억지로 가로로 바뀐다」고 했고, 참고작(마탑 수호기 · 웹)처럼 **주소창 · 탭 바가 사라지고 가로가 되는** 방식을 원했다
- 참고작은 세로로 들면 안내 막을 띄우고, 탭하면 전체 화면 + 가로 고정을 시도하며, 「이대로 계속하기」를 둔다 — 게임 화면 자체는 돌리지 않는다
- ADR-0109 는 이 방식을 「자동이 아니다」로 버렸었다

## 근거

- **주소창 · 탭 바를 걷는 길은 전체 화면 API 뿐이다** — 눕힘은 방향만 바꿀 뿐 브라우저 바가 세로를 계속 먹었다(ADR-0109 의 열린 것). 전체 화면에 들어가면 안드로이드는 가로 고정도 된다
- **탭 한 번은 피할 수 없다** — 전체 화면 · 방향 고정은 사용자 입력 안에서만 허락된다. 그래서 「자동」을 포기하고 버튼을 둔다
- **아이폰은 폰을 직접 돌린다** — 전체 화면 · 방향 고정이 둘 다 없다. 막이 안내 역할을 하고, 돌리면 걷힌다
- **「이대로 계속하기」는 눕히지 않고 작게 맞춘다** (사용자 선택 a) — 눕힘(선택 b)은 강제 회전을 되살리는 것이라 버렸다. 공식이 ADR-0087 하나로 돌아간다
- **막은 한 장 밖에 둔다** — 한 장 안이면 배율을 따라 글자가 세로 창에서 0.24 배로 준다

**버린 안**

1. **눕힘을 선택지로 남기기** (선택 b) — 사용자가 a 를 골랐다
2. **PWA manifest `orientation: landscape`** — 설치 · HTTPS 호스팅이 필요하고 아이폰은 무시한다(ADR-0109 와 같은 이유)
