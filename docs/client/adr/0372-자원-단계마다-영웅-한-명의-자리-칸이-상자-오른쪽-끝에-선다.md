# ADR-0372 — 자원 단계마다 영웅 한 명의 자리 칸이 상자 오른쪽 끝에 선다

## 결정

자원 탭의 단계 상자마다 **영웅 한 명이 들어가는 자리 칸**이 선다 — 채광 1 · 채광 2 가 각자 독립된 자리다. 칸은 상자 **오른쪽 끝**에 **상자 높이만큼의 정사각**이다. 찬 칸은 띠 카드와 같은 얼굴 + 오른쪽 아래 레벨(이름은 툴팁), 빈 칸은 점선 `+`. **열린 단계에만** 서고(`limitsOf.resourceTiers` — 자원 랭크가 앞에서부터 연다) 잠긴 단계에는 칸이 없다.

## 맥락

자원 파견을 「특정 영웅이 출발하는 구조」로 만들기로 했고, 사용자가 **단계마다 독립적으로 · 단계 하나에 한 명**을 정했다. 그날 단계 상자는 번호 · 이름 · 산출물 두 줄뿐이었고 상자 오른쪽 절반이 비어 있었다. 배치 · 회수 · 산출 정산은 `game_logic` 에 없었다.

## 근거

- **오른쪽 끝** — 왼쪽은 번호 → 이름 → 산출물로 읽히는 순서라 건드리지 않는다. 비어 있던 오른쪽을 쓰면 글자 칸이 좁아지지 않는다
- **상자 높이만큼** — 1600×800 에서 상자 안쪽이 50px 안팎이라 가방 칸(44px)보다 크게 선다. 「얼굴이 아주 작게 들어가나」라는 우려의 답이다. 이름은 이 크기에서 안 읽혀 툴팁으로 보내고, 누가 어디 있는지는 위 띠의 「지금 하는 일」이 한 번 더 말한다
- **한 명 고정** — 얼굴 여러 개를 가로로 세우는 안(단계마다 일꾼 칸)은 상자가 좁아진다. 자리가 단계 수만큼 늘어나므로 인원 칸이 따로 없어도 된다
- **잠긴 단계는 칸 없음** — 놓을 수 없는 곳에 빈칸을 그리면 놓으려다 막힌다
- **빈 칸은 점선** — 끌어다 놓을 곳이 보여야 한다

## 파급

- `state.limitsOf` 에 `resourceTiers`(자원 랭크의 더하기 `resource_tier` → 이 키 · 기본값 0) · INTERFACE §2
- `?slot=1` — 로스터를 열린 칸에 차례로 앉힌 **보기용 미리보기**(저장 · 판정 없음)
- ⚠ 넣기(띠에서 끌어 놓기) · 빼기(찬 칸 클릭) · 산출 정산은 `game_logic` 배치가 선 뒤 — 그때까지 칸은 전부 빈다
- ⚠ 기획 경고 — base_expedition §2-1 「단계는 파견처 안의 선택지」 · construction_draft §2 「일꾼 칸 +」와 부딪힌다. 기획서 개정은 `/game-design`
