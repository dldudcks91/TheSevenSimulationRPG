## 결정

건설 상세에서 **「현재 가능한 기능」 소제목을 뺀다.** 지은 랭크까지 연 것의 목록은 머리의 **이름 오른쪽에 만든 칸**(옅은 칸 하나 · 머리의 남은 폭 · 높이는 그림 + 눈금과 같고 넘치면 칸 안에서 스크롤)에 적는다. 랭크 진행 눈금은 이름 아래에서 **그림 바로 아래**로 옮긴다. 왼쪽 반에는 「다음 랭크」 만 남는다.

## 맥락

그날 상세 머리는 그림 · 이름 · 상태 · 눈금뿐이라 이름 오른쪽이 비어 있었고, 「현재 가능한 기능」 은 왼쪽 반의 「다음 랭크」 아래에 소제목을 달고 섰다. 사용자가 「현재 가능한 기능 글씨를 빼고 거기 있는 옵션을 오른쪽 위에 그냥 적어 줘도 될 것 같다 · 랭크별 진행도를 그림 아래로」 라고 지시했고, 자리를 고르는 질문에 「이름 오른쪽에 칸 만들어서 적어 봐」 라고 답했다.

## 근거

- **머리는 「이 건물이 지금 무엇인가」 를 말하는 자리다** — 이름 · 상태 · 눈금과 지금 연 기능이 같은 물음의 답이라 한 줄에 모인다. 왼쪽 반은 「다음에 무엇을 짓나」 하나만 든다
- **소제목 없이 칸** — 머리 안에서는 칸의 자리가 무엇인지 말한다. 소제목을 두면 머리가 두 줄로 는다
- **눈금은 그림 아래** — 이름 옆 열이 이름 · 상태 두 줄로 줄어 기능 칸이 폭을 더 받는다. 부지 네모에서도 눈금이 그림(이름 띠) 아래에 서서 같은 문법이다
- 버린 안 — 기능 목록을 이름 · 상태 바로 아래에 잇는 안(한 열). 사용자가 따로 선 칸을 골랐다

## 파급

- `app.js:buildingSide` · 옛 `nowBox` → 기능 칸 · CSS `.cn-thumb-col` · `.cn-cur` · i18n `cn.now.h` 삭제
- 그림 높이(`--cn-thumb-h`)는 그림 + 눈금이 옛 그림 높이를 넘지 않게 줄었다 — 두 소제목의 윗선이 부지 둘째 줄에 서는 규칙(SCREEN_DESIGN §13-1 「상세 머리」)은 그대로다
- ⚠ 기능이 많은 건물(제련소 최대 랭크 등)은 칸 안에서 스크롤한다
