# ADR-0385 — 개발 환경에서만 게스트로 시작한다 · `?dev=` URL 은 로그인 관문을 건너뛴다

## 결정

로그인 화면의 Google 버튼 아래에 **게스트 버튼**을 둔다 — **개발 환경(`localhost` · `127.0.0.1`)에서만** 선다. 게스트는 클라우드를 안 켠 채 이 브라우저 세이브로 들어가고, 계정 버튼(「Google 로그인」)으로 나중에 연결할 수 있다. 같은 개발 환경에서 URL 에 `?guest=1` 또는 `?dev=` 가 있으면 **세션 확인 없이** 게스트로 곧장 들어간다.

## 맥락

그날 `boot()` 는 인증될 때까지 멈춰 섰고(ADR-0112 이후 로그인이 진입 조건), 헤드리스는 Google 창을 못 연다. 그래서 `src/dev/README.md` 의 `?dev=` 검증 레시피가 전부 로그인 화면을 덤프했다(DEV_PLAN 부채 #53). 작업마다 `ui/cloud.js` 를 가짜로 갈아 끼우는 임시 하네스를 만들고 지웠고, 몇 작업은 「게임 화면 눈 확인 못 함」으로 닫혔다.

## 근거

- **버튼만으로는 헤드리스가 못 지난다** — `--dump-dom` 은 클릭하지 않는다. 그래서 URL 진입이 본체고 버튼은 사람이 쓰는 같은 길이다
- **`?dev=` 가 게스트를 겸한다** — 이미 적힌 레시피 수십 줄을 고치지 않고 그대로 살린다. `?dev=` 없이 `?tab=` 만 쓰는 경우에만 `?guest=1` 을 붙인다
- **URL 진입은 세션 확인을 건너뛴다** — 확인은 Firebase SDK 를 CDN 에서 불러오고 상한(`CLOUD_BOOT_WAIT_MS`)까지 기다릴 수 있다. 검증은 네트워크에 기대지 않아야 한다
- **버린 안: 모든 플레이어에게 게스트** — 비로그인 플레이는 「로그인은 진입 조건」(§2-1)을 뒤집는 기획 변경이라 이 결정의 범위 밖이다
- **버린 안: 가짜 클라우드 어댑터를 `src/dev/` 에 상설** — 로그인 흐름 자체를 흉내 내야 해 유지할 면이 넓고, 사람이 개발 서버에서 쓰는 길은 여전히 없다

## 파급

- i18n `cl.guest` · CSS `.login-guest` · `app.js:isDevHost` · `guestEnter`
- 게스트 세션은 계정 감시(`watchUser`)를 걸지 않는다 — 게스트에서 Google 로 연결한 뒤의 다른 곳 로그아웃은 새로고침 전까지 모른다(개발 환경 한정이라 둔다)
- 개발 환경은 호스트 이름으로만 가른다 — 배포 도메인에서는 버튼도 URL 진입도 없다
