# ADR-0388 — 건설 상세는 한 열이고 랭크 목록은 「다음 랭크」 아래에 선다

## 결정

건설 상세의 머리 아래는 **한 열**이다 — 「다음 랭크」 가 위, 「{건물} 랭크」 목록이 그 아래에서 남은 세로를 채우고 제 안에서 스크롤한다. 「다음 랭크」 의 **[건설]은 재료 칸 줄의 오른쪽 끝**에 선다. 랭크 목록의 **한 묶음 높이는 글 세 줄**이 기준이다(넘으면 는다).

## 맥락

그날 상세는 머리 아래가 반으로 갈려 왼쪽에 「다음 랭크」, 오른쪽에 랭크 목록이 섰다. 머리에서 「현재 가능한 기능」 이 빠진 뒤(ADR-0383) 왼쪽 반은 「다음 랭크」 하나만 남아 아래가 비었다. 사용자가 「다음 랭크 아래에 제련소 랭크가 들어가도록 · 건설 버튼이 오른쪽으로 · 랭크별 높이를 3줄 기준으로」 라고 지시했다.

## 근거

- **한 열** — 왼쪽 반의 빈 아래와 오른쪽 반의 좁은 폭이 함께 풀린다. 랭크 목록이 상세의 폭을 다 써 여는 것 문장이 덜 접힌다
- **[건설]은 오른쪽 끝** — 한 열이 넓어져 왼쪽에 붙은 버튼은 재료 칸과 붙어 읽혔다. 오른쪽 끝이 「결정」 의 자리다
- **세 줄 기준** — 옛 「목록 세로의 1/7」 은 목록이 반 폭 · 전체 높이일 때의 규칙이었다. 목록 높이가 「다음 랭크」 에 따라 달라져 비율이 흔들리므로 글 줄 수로 고정한다. 여는 것이 가장 많은 랭크가 세 줄 안팎이다
- 버린 안 — 목록을 위 · 「다음 랭크」 를 아래(행동이 목록 스크롤에 밀린다)

## 파급

- `app.js:buildingSide` 의 반 나눔(`.cn-split` · `.cn-col`) 삭제 · CSS `.cn-rank` 높이 규칙 · `.cn-go` 자리
- ⚠ 머리 높이 규칙(두 소제목의 윗선이 부지 둘째 줄에 선다)은 이제 「다음 랭크」 소제목 하나에 걸린다
