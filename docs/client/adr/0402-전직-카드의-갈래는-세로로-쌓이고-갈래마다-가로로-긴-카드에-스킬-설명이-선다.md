# ADR-0402 — 전직 카드의 갈래는 세로로 쌓이고 갈래마다 가로로 긴 카드에 스킬 설명이 선다

| **화면** | [SCREEN_DESIGN §16](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 「궁수를 기준으로 스나이퍼, 보우마스터, 레인저 표식을 세로로 깔고 카드를 오른쪽으로 길게 해서 각 스킬의 설명을 적어줘」 |

## 결정

전직 카드의 갈래 셋은 **세로로 쌓인다.** 갈래마다 **가로로 긴 카드 한 장**이고, 왼쪽 칸에 갈래 이름과 [전직]이 서고 오른쪽에 그 갈래의 전직 스킬 셋이 **한 줄씩** — 그림 · 이름 · **설명**(`skill.csv:desc_kr` · `desc_en` — 효과만)이 선다. 줄에 올리면 스킬 설명창이 뜬다. 전직 후에도 같은 모양의 카드 한 장(고른 갈래)이 남고 줄 끝에 [배우기] · 「배움」 + [되돌리기]가 선다. [전직] 두 번 누름 · 상태 셋(전 · 중 · 후)은 ADR-0399 그대로다.

## 맥락

그날 전직 카드는 갈래 셋이 **나란히**(각 3분의 1 폭) 서고 갈래 안에 스킬 셋이 그림 + 이름만 들었다(ADR-0399). 전직 패널이 탭의 반 폭이라 갈래 한 칸이 좁아 설명을 적을 자리가 없었고, 스킬이 무엇을 하는지는 올려 봐야 알았다. 사용자가 궁수(스나이퍼 · 보우마스터 · 레인저)를 예로 들어 배치를 바꿨다.

## 근거

- **갈래를 고르는 자리에서 스킬이 무엇을 하는지가 바로 읽혀야 한다** — 갈래는 되돌릴 수 없어 올려 보기만으로 견주면 아홉 번 올려야 한다. 설명 한 줄이 서면 셋을 훑어 역할을 비교한다(skill_design §4-2 「역할로 갈린다」)
- **세로로 쌓아야 가로 폭이 설명에 간다** — 나란히 두면 칸 하나가 패널의 3분의 1이라 이름도 빠듯했다
- **설명은 CSV 의 짧은 효과 문장이다** — 새 문구를 쓰지 않는다. 규칙 · 절차는 도움말 몫(CLAUDE.md 규칙 7 · §12)

## 파급

- CSS `.tr-adv-row` 가 세로 쌓기 · `.tr-adv-branch` 가 왼쪽 칸 + 오른쪽 스킬 줄의 두 열 · `.tr-adv-desc` 신설
- 전직 스킬 설명(`desc_kr`)의 「창 동안」을 「한동안」으로 고쳤다 — 「창」은 내부 용어(효과 창)라 화면 문장이 되면 안 읽힌다(기본 스킬 설명의 말투와 맞춤)
