# ADR-0412 — 스킬 이펙트는 코드 모양이다 · 그림은 나중에 전직 스킬에만

## 결정

스킬 이펙트의 모양은 **코드로 그린 빛과 조각**이다 — 모든 스킬, 모든 종류. 종류마다 그림 한 장이 먼저 서던 ADR-0411 을 되돌린다. **그림은 나중에 전직 스킬에만** 넣는다 — 「전직 스킬만 화려하게」. 그림을 띄우는 장치(미리 읽기 · 그림 한 장 · 움직임 넷)는 **지우지 않고 꺼 둔다**(`fx.js:ART_ON`) — 꺼진 동안은 그림을 읽지도 않는다. 뽑아 둔 타격 그림 다섯 장은 `assets/art/fx/` 에 남는다.

## 맥락

ADR-0411 로 타격 다섯 종류가 그림으로 바뀐 화면을 보고, 사용자가 그 전의 코드 모양이 「느낌이 좋았다」고 했다. 두 방식의 부하 · 메모리도 비교했다 — 코드 모양은 그림 메모리가 0 이고 이펙트 하나에 0.07~0.13ms(실측), 정지 그림 다섯 장은 풀어서 약 3MB, 코드 모양을 파일로 굳힌 플립북은 프레임 크기에 따라 10종 15~59MB(계산). 플립북은 보기에 코드 모양과 같다.

## 근거

- **코드 모양** — 사용자가 보고 고른 쪽이다. 사건마다 흩어지는 방향이 달라 같은 스킬도 매번 조금씩 다르게 보이고, 그림 메모리 · 제작 비용이 없다
- **그림은 전직 스킬에만 · 나중에** — 모든 스킬이 그림이면 「센 스킬이 나갔다」가 안 갈린다. 전직 스킬에만 그림을 주면 연출의 격이 스킬의 격을 말한다. 피해 종류마다 한 장인 지금 그림은 전직 스킬 전용으로 쓰기엔 뜻이 얕다(전직 화염 스킬 셋이 같은 그림) — 무엇을 그릴지는 그때 정한다
- **장치는 꺼 둔다** — 버린 안: 지운다. 전직 스킬 그림을 넣을 때 다시 쓴다(조건 「전직 스킬인가」만 붙이면 된다). 꺼져 있으면 읽지도 않아 404 · 메모리가 없다
- **플립북은 안 한다** — 코드 모양을 파일로 굳혀도 보기에 같고, 흩어짐의 변화만 줄고 메모리가 든다. 얻는 것은 엔진 이식 때 파일로 가져간다는 것 하나라 그때 해도 늦지 않다

## 파급

- `fx.js` — `ART_ON = false` · 미리 읽기가 꺼진 동안 아무것도 안 읽는다
- `style.css` — 그림 규칙(`.fx-stamp` · 움직임 넷)은 남고 쓰이지 않는다
- 발주 문서 [fx_art_prompt.md](../../reference/fx_art_prompt.md) · 그림 다섯 장 — 남는다(전직 스킬 그림을 정할 때의 출발점)
- ⚠ 전직 스킬 그림 — 무엇을(스킬마다 · 갈래마다 · 종류마다) 그릴지는 열려 있다
