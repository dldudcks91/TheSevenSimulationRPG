# ADR-0442 — 출정 창 편성 버튼 높이는 편성이 다 열렸을 때의 개수로 나눈다

| | |
|---|---|

| **정한 사람** | 사용자 지시(「왼쪽 파티창이 파티 개수가 1개여도 3개일 때처럼의 높이로 버튼 수정」) · 개수를 표에서 읽는 방법은 Claude |

## 결정

출정 창 아래 줄 왼쪽 「편성」의 **버튼 하나의 높이 = (초상 한 변 − 버튼 사이 틈) ÷ 편성이 다 열렸을 때의 개수**다. 다 열렸을 때의 개수는 원정 건물을 끝까지 지은 판의 편성 수(`game.limitsOf` 에 모든 건물의 최대 랭크를 넣어 물은 `presets`)다. 열린 편성이 그보다 적으면 **버튼이 위에서부터 서고 아래는 빈다**. 버튼 기둥의 폭 · 높이는 그대로 초상 한 변이다(ADR-0283).

## 맥락

「버튼 셋이 초상 한 변을 나눠 갖는다」(2026-09-21)는 편성이 늘 셋이던 때의 규칙이다. 2026-09-25 에 편성을 원정 랭크가 열게 되면서(R156 · 새 게임은 편성 하나) 기둥을 지금 개수로 나누는 식이 **버튼 하나를 초상 높이만큼** 세웠다 — 실측 1600×800 에서 편성 하나일 때 버튼 106.2px · 셋일 때 31.2px.

## 근거

- **크기는 상태에 흔들리지 않는다**(2026-08-28) — 편성이 하나 열릴 때마다 버튼 높이가 106 → 50 → 31 로 바뀌지 않는다. 다 열린 판과 같은 크기로 처음부터 선다
- **개수를 CSS 에 3 으로 박지 않는다** — 다 열린 개수는 표(`balance.csv:party_preset_count` + `building_effect.csv presets`)가 정한다. 렌더러는 그 합을 따로 셈하지 않고 상한 함수(`limitsOf`)에 다 지은 랭크를 물어 CSS 변수(`--pk-n`)로 넘긴다
- 버린 안 — **기둥 높이를 버튼 수만큼 줄이기** — 기둥이 초상보다 짧아져 편성 줄 위아래가 초상과 안 맞는다(ADR-0283 의 열 맞춤은 폭이라 그대로지만 높이가 흔들린다)

## 파급

- `app.js presetPick` — 버튼 기둥에 `--pk-n` · `style.css .pk-btns .btn` 의 높이 식
- i18n · `game_logic` · 세이브 · 단정 무관
- 실측 후(1600×800) — 편성 하나일 때 버튼 31.2px(셋일 때와 같다)
