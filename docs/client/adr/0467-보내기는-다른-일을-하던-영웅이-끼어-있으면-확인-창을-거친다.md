# ADR-0467 — 보내기는 다른 일을 하던 영웅이 끼어 있으면 확인 창을 거친다

| | |
|---|---|
| **상태** | 확정 · 2026-09-30 |
| **화면** | [SCREEN_DESIGN §4-1](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (「원정을 보낼떄는 다른 행동중인 영웅이 그안에 포함되어있으면 파티 내에 다른 행동을 실행중인 영웅이 있습니다. 그래도 출격할까요? 라는 팝업띄우고 확인 취소버튼 만들어줘」) |
| **대체** | — |
| **대체됨** | — |

## 결정

출정 창의 [보내기]를 눌렀을 때 고른 편성에 **하던 일이 있는 영웅**이 끼어 있으면, 곧바로 나가지 않고 **확인 창**이 출정 창 자리에 갈아 뜬다. 문장은 사용자가 준 그대로 「파티 내에 다른 행동을 실행중인 영웅이 있습니다. 그래도 출격할까요?」이고 버튼은 [확인] · [취소] 둘이다. [확인]은 [보내기]가 하던 일을 그대로 하고, [취소]는 출정 창으로 돌아간다.

## 맥락

이날까지 출발은 자원 자리에 앉아 있던 영웅을 **말없이** 자리에서 뺐다(벌이 없다 — base_expedition §3-2 · ADR-0373). 수색 · 전직 · 다른 부대에 나간 영웅이 든 편성은 출발이 거절됐고, 경고 줄과 플래시가 그 까닭을 말했다.

## 근거

- **사용자 지시다** — 문장과 버튼 둘을 그대로 받았다
- **나갈 수 있는 편성일 때만 묻는다** — 거절될 출발에 「그래도 출격할까요?」를 물으면 [확인]을 눌러도 안 나간다. 그래서 확인 창이 뜨는 「하던 일」은 출발이 **데려가는** 일이고(이날은 자원 자리 하나), 출발을 **막는** 일은 묻지 않고 옛 경고 그대로다. 막는 일을 [확인]으로 끊고 나가게 하는 것은 출발 규칙을 바꾸는 일이라 이 결정에 넣지 않았다
- **제 부대의 원정은 안 센다** — 도는 편성을 다시 보내면 그 부대를 끊고 나가는데(ADR-0111), 그것은 「다른 행동」이 아니라 같은 원정을 새로 여는 일이다
- **판정은 렌더러가 안 한다** — 나갈 수 있나는 `game.canDepart`, 하던 일은 `game.heroBusy` 가 답한다
- **[취소]는 출정 창으로 돌아간다** — 창은 한 번에 한 장이라 확인 창이 출정 창을 갈아 끼운다. 취소가 창을 통째로 닫으면 칸 · 편성을 고른 자리로 다시 들어와야 한다
- 버린 안: [보내기]를 두 번 누르게 하기(§3 의 무장 문법) — 지시가 팝업과 버튼 둘이었다

## 파급

- i18n — `exp.departBusy` 신설 · 머리 줄이 없다(같은 날 사용자 지시 「보내기 글자는 지워」 · 「x버튼삭제」 — 제목도 닫기 X 도 없다 · `MODALS` 의 `bare`) · 버튼은 `ui.ok` · `ui.cancel` 을 그대로 쓴다
- 상자는 해고 창의 것(`.dismiss-box` · `.dismiss-actions`)을 그대로 쓴다 — 새 CSS 가 없다
- 개발용 길 `?dev=form&busy=1` — 확인 창이 뜬 채로 연다
- ⚠ 이어 가는 런(앱 시계가 내는 다음 칸)은 이 창을 안 거친다 — 그 부대의 영웅은 칸 사이에도 나가 있어 다른 일에 붙잡힐 틈이 없다
- ⚠ 판 바깥 · `Esc` 는 출정 창으로 안 돌아가고 통째로 닫는다
