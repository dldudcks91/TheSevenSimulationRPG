# ADR-0524 — 재료 탭은 창고 칸에 선다 · 재료는 부대가 나눠 갖지 않는다

## 결정

`장비` · `재료` 탭이 **창고 칸**으로 옮겨 간다. 도구 줄은 둘 다 **이름이 왼쪽 · 버튼이 오른쪽 끝**이다.

```
창고 ───────────────── [장비|재료] [정렬]      인벤토리 [Party I][Party II][Party III] ─── [분해] [자동 분해] [정렬]
```

- 재료 탭의 칸(채광 · 채집 · 벌목 세 줄 · 일곱 단계 · 보유 수량)은 그대로다. 격자는 창고 격자와 같은 칸 수 · 같은 칸 크기다
- 재료 탭에서는 창고의 [정렬]이 안 선다. 인벤토리 쪽은 탭과 무관하게 그대로 선다 — 부대 버튼도 늘 선다
- **창고가 재료 탭일 때 인벤토리에서 창고로 보내면**(`Ctrl`+클릭 · 끌기) 그대로 들어가고 **창고가 장비 탭으로 돌아가** 들어간 것을 보인다
- 정렬 기준의 펼침은 두 칸 다 **오른쪽 끝을 [정렬]에 맞춘다** — 창고의 [정렬]도 줄 오른쪽 끝으로 갔다

## 맥락

ADR-0521 로 인벤토리가 부대마다 갈렸고 창고는 하나로 남았다. 재료(`state.materials`)는 부대가 나눠 갖지 않는 하나의 값인데 탭은 인벤토리 칸에 있어서, Party I 인벤토리를 보다가 [재료]를 누르면 Party I 의 것이 아닌 재료가 섰다 — 그래서 재료 탭에서는 부대 버튼을 숨겼다. 재료 탭을 열면 드롭이 쌓이는 인벤토리 격자도 덮였다.

## 근거

- **공용 값은 공용 칸에.** 창고는 하나고 재료도 하나다. 탭이 창고에 서면 부대 버튼을 숨길 이유가 사라진다
- **드롭이 쌓이는 칸을 덮지 않는다.** 관전 중 재료를 보아도 인벤토리는 그대로 보인다. 창고는 사람이 옮긴 것만 드는 조용한 칸이라 덮여도 놓치는 것이 없다
- **제련소에서 두 쪽이 같이 보인다.** 제작에 쓰는 재료(창고 쪽)와 만든 것이 들어갈 인벤토리가 한 화면에 선다
- **보내면 장비 탭으로 돌아간다.** 대안은 「재료 탭인 동안 창고로 못 보낸다」였다 — 거절이 늘어 손이 막힌다. 그대로 두고 받기만 하면 결과가 안 보인다(통제성). 돌아가면 보낸 것이 눈앞에 선다
- **잃는 것** — 「창고는 직접 옮긴 것만 든다」(item_design §1)는 장비 칸의 규칙으로 좁아진다. 재료는 칸을 먹는 물건이 아니라 개수를 보이는 화면이라 그 규칙과 부딪히지 않는다

## 파급

- `app.js:storageTools` — 탭은 창고 쪽 · 둘 다 `.tools-push` 빈 칸이 버튼을 오른쪽 끝으로 민다 · `storagePanel` 의 재료 격자는 창고 쪽(칸 수 = 창고 상한) · `moveToStash` 가 성공하면 창고를 장비 탭으로 · 화면 상태 `bagTab` → `stashTab`
- style.css — `.store-bag .bag-tabs` 의 밀기를 `.tools-push` 로 · `.sort-fold` 는 두 칸 다 `right: 0`
- 개발용 `&bag=equip|mat` 은 창고 칸의 탭을 고른다(§10)
