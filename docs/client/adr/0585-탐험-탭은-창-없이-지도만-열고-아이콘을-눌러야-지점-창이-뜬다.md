# ADR-0585 — 탐험 탭은 창 없이 지도만 열고 아이콘을 눌러야 지점 창이 뜬다

| | |
|---|---|
| **상태** | 확정 · 2026-10-10 |
| **화면** | [SCREEN_DESIGN §8-4](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시(「탐험 누르면 왜 정해진 게 계속 켜지는지」 → 원인을 보고 「그렇게 수정해」) |
| **대체** | SCREEN_DESIGN §8-4 의 「처음 열면 가장 뒤의 열린 장의 동굴을 고른다」(ADR 없이 규격에만 있던 규칙) |
| **대체됨** | — |

## 결정

탐험 탭에 들어오면 **아무 지점도 고르지 않은 채 지도만** 선다. 지점 창은 아이콘을 눌러야 열린다. 고른 지점이 곧 열린 창이다 — ✕ 와 지도의 빈 자리 클릭은 창을 닫으면서 고른 것을 비운다. 다른 탭으로 옮기면 고른 것이 비워져, 돌아와도 지도만 선다. 새로 켜도 같다(세이브 아님).

## 맥락

같은 날까지 탐험 탭은 고른 지점이 없으면 「가장 뒤의 열린 장의 동굴」을 저절로 골라 그 옆에 창을 띄웠다. 창을 닫은 상태(`exShut`)는 세이브가 아니라 새로 켤 때마다 같은 동굴 창이 다시 떴고, 탭을 바꿔도 고른 것 · 닫힘이 풀리지 않아 열어 둔 창이 그대로 남았다. 사용자는 탭을 누를 때마다 「정해진 것」이 켜진다고 보았다.

## 근거

- **고르지 않은 것을 고른 척하지 않는다** — 저절로 고른 동굴은 플레이어의 결정이 아니다. 창이 지도 일부를 가리고, 그 동굴에 무슨 일이 있는 것처럼 읽힌다
- **상태 하나로 줄인다** — 「고른 지점」과 「닫았나」 두 값이 따로 있으면 「골랐는데 닫힘」이라는 중간 상태가 생긴다. 고른 지점 = 열린 창 하나로 두면 닫기 = 비우기다
- **탭을 떠나면 풀린다** — 다른 탭의 고르는 중이 탭 이동으로 풀리는 규칙(ADR-0184)과 같다
- **버린 안** — ① 닫힘을 세이브한다: 새로 켰을 때만 고쳐지고 탭 이동 때 남는 창은 그대로다 ② 기본 지점은 두되 창만 닫는다: 아이콘에 「고른 지점」 겹테가 혼자 서서 같은 오해가 남는다

## 파급

- `app.js` — `state.exShut` 삭제 · `exploreSel` 이 저절로 고르지 않는다(없으면 `null`) · `exploreShut` 이 `exSel` 을 비운다 · 탭 버튼이 `exSel` · `exArm` 을 비운다
- 개발용 `?dev=explore` 는 `&sel=` 로 지점을 골라 창을 띄운다(그대로 · SCREEN_DESIGN §10)
