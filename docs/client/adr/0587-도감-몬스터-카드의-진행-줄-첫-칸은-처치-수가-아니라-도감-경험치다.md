## 결정

도감 몬스터 카드의 진행 줄은 `경험치 N · Lv.n · 계열 스탯 +x.x%` 다 — 첫 칸이 **그 몬스터의 누적 도감 경험치**(`G.codexExp[id]`)다. 레벨 핍의 작은 툴팁도 `도감 Lv.n · 경험치 N`(그 레벨의 누적 경험치 문턱)으로 같이 바뀐다. 진행 막대 · `Lv.n` · 보정 칸은 0249 그대로다.

## 맥락

그날 기획이 도감 레벨의 출처를 처치 수에서 **도감 경험치**로 바꿨다 — 처치 하나가 주는 몫을 그 런의 난이도 단이 정한다(`difficulty_tier.csv:codex_exp` · monster_design §8). 카드 첫 칸은 `처치 N`, 핍 툴팁은 `도감 Lv.n · 처치 N`(누적 처치 문턱)이었다. 문턱 표(`codex_level.csv`)가 경험치 단위가 되면서 「처치 N」은 레벨과 맞지 않는 숫자가 됐다 — 나이트메어에서 잡은 몬스터는 처치 수보다 레벨이 빨리 오른다.

## 근거

- **카드의 숫자는 레벨을 정하는 숫자다** — 핍 · 진행 막대 · 핍 툴팁의 문턱이 전부 경험치 단위인데 첫 칸만 처치 수면 「100마리 잡았는데 왜 Lv.2 냐」가 나온다. 0249 의 「지금 받는 값이 카드의 값이다」를 그대로 따르면 첫 칸은 레벨의 출처여야 한다
- **처치 수를 같이 세우지 않았다** — 처치 수는 세이브에 따로 남지 않는다(로직이 경험치 하나만 쌓는다 · INTERFACE §4). 같이 그리려면 필드를 하나 더 둬야 하고, 진행 줄은 이미 세 칸으로 차 있다
- **라벨은 「경험치」 한 마디** — 도감 화면 안이라 영웅 경험치와 섞이지 않는다. 「도감 경험치」 네 글자는 진행 줄이 좁아 줄였다(도움말은 「도감 경험치」로 적는다)

## 파급

- i18n `cx.kills` → `cx.exp`(`경험치 {n}` · `{n} EXP`) · `cx.sub` · `cx.note` 문구가 처치 수 대신 도감 경험치와 단마다의 몫을 말한다(단마다의 몫은 `difficulty_tier.csv` 에서 채운다 — 문구에 숫자를 안 박는다)
- `app.js:monsterCard` · `codexMonster` · `codexUnknownRow` · `tip.js:codexMonsterTipCard` 가 `m.kills` 대신 `m.exp` 를 읽는다
- ⚠ 그 몬스터를 몇 마리 잡았는지는 화면 어디에도 없다 — 필요해지면 로직에 처치 수 필드부터 다시 둬야 한다
