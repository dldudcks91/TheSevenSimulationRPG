## 결정

게임에서 **Google 로그인을 걷는다.** 로그인 화면 · 계정 버튼 · 계정 창 · 「다른 곳에서 이어졌다」 멈춤 창이 없어지고, 켜면 곧장 시작 화면이나 게임이 선다. 세이브는 이 브라우저에만 있다 — **다른 기기 · 브라우저로 이어 하는 길은 없다.**

대신 **배포 주소에서 켠 게임은 Firebase 익명 계정으로 기록을 한 방향으로 올린다** — 진행 요약 `players/<uid>` 와 세이브 사본 `saves/<uid>` 를 한 묶음으로. 받는 길은 없다. 플레이어에게는 계정도 연결 상태도 보이지 않는다. 개발자는 `dev/funnel.html` 에서 Google 로 로그인해(보안 규칙이 정한 관리자 uid 만 읽힌다) 전체 유저의 **퍼널**(첫 방문 → 새 게임 → 첫 승리 → 장소마다 완료 → 나이트메어 · 헬) · 기능 사용률 · 유저 목록을 본다.

- **닉네임** — `⚙` 설정 탭에 글 칸 한 줄. 퍼널 페이지가 유저를 알아보는 이름이고 게임 안에는 안 찍힌다. 비워 둬도 된다
- **장소까지 걸린 시간** — 노말 깬 칸마다 **처음 본 순간의 원정 플레이 시간**(`expMs`)을 이 브라우저가 적어 둔다(`reach`). 간격마다 보므로 한 간격만큼 늦을 수 있다
- **올리지 않는 곳** — 개발 환경(`localhost` · `127.0.0.1`) · `?dev=` 주소 · 멈춘 탭. 개발자의 시험 플레이와 헤드리스 검증이 퍼널을 더럽히지 않는다
- **실패는 조용하다** — 연결 실패 · 콘솔 설정 전(익명 로그인 꺼짐 · 규칙 안 고침)이어도 게임은 그대로 돌고 콘솔 경고만 남는다
- 다른 탭 멈춤 창(같은 브라우저의 다른 탭이 세이브를 썼다)은 그대로 산다 — 클라우드와 무관한 로컬 장치다

## 맥락

그날 게임은 GitHub Pages 에 배포돼 있었고, **Google 로그인이 진입 조건**이었다(ADR-0112 · 개발 환경만 게스트 — ADR-0385). 로그인하면 세이브 사본이 `saves/<uid>` 로 1분마다 올라가 다른 기기에서 이어졌고, 개발자는 Firebase 콘솔에서 그 문서를 열어 남의 세이브를 볼 수 있었다 — 다만 세이브 전체가 JSON 문자열 한 덩어리라 「누가 어디까지 갔나」를 읽기 어려웠다. 사용자는 로그인 관문을 걷고 싶어 했고, 그러면서도 다른 유저가 게임을 어떻게 하는지를 받아 보길 원했다. 다른 기기 이어 하기는 필요 없다고 했다.

## 근거

- **익명 계정 — 기존 Firestore · 보안 규칙을 그대로 쓴다** — 익명 계정도 `uid` 를 가져 「자기 문서만 쓴다」 규칙이 그대로 선다. 서버를 새로 두지 않는다(GAME_DESIGN 「서버를 운영하지 않는다」)
- **받기 · 충돌 처리를 통째로 걷었다** — 익명 계정은 브라우저를 따라가서(사이트 데이터를 지우면 세이브와 함께 새 계정이 된다) 받을 사본이 이 브라우저 세이브와 늘 같은 줄기다. 받기가 쓸모없으니 저장 번호(`rev`) · 연결 기록(`thesevensim.cloud`) · 「클라우드가 이긴다」(ADR-0458) · 켤 때 기다림 상한이 다 필요 없다. 켤 때 네트워크를 안 기다려 게임이 먼저 선다
- **「Google 계정 연결」 버튼(익명 → Google 승격)은 버렸다** — 다른 기기 이어 하기가 필요 없다는 사용자 판단
- **요약 문서를 세이브와 따로 둔다** — 퍼널 페이지는 유저마다 한 번씩 읽는다. 세이브 전체(수백 KB 일 수 있다)를 다 받으면 무겁고, Firestore 클라이언트는 필드만 골라 읽지 못한다. 세이브 사본은 **한 유저를 깊이 볼 때만**(그 유저의 [세이브] 버튼) 받는다 — 「왜 2-3 에서 막혔나」는 파티 · 장비를 봐야 답이 나온다
- **GA4(애널리틱스) 이벤트는 안 골랐다** — 집계는 되지만 유저 한 명의 상태를 못 보고, SDK · 동의 문제가 따라온다. 요약 문서로 퍼널과 유저 목록이 함께 나온다
- **관리자 읽기는 Google 로그인 + 규칙의 uid 목록** — 요약에 닉네임이 들어 있어 아무나 읽게 열지 않는다. 퍼널 페이지가 읽기를 거부당하면 로그인한 uid 를 보여 줘 규칙에 바로 넣게 한다
- **닉네임은 설정 탭** — 시작 화면에 두면 세이브가 있는 플레이어는 거기를 안 지난다. 설정 판은 언제나 닿는다

## 파급

- `ui/cloud.js` — Google 로그인 · 받기 · 트랜잭션 · 로그아웃 · 계정 감시 삭제 → 익명 계정 확보(`ensureUser`) · 한 묶음 올리기(`pushTrack`)
- `ui/storage.js` — 연결 기록(`thesevensim.cloud`) 삭제 → 플레이 기록(`thesevensim.track` = `{nick, reach}`)
- `app.js` — 로그인 관문(`authenticated` · `renderLogin` · `guestEnter` · `cloudResume` · `linkAccount` · `adoptRemote` · `takenElsewhere` · `cloudSignIn` · `cloudSignOut` · `leaveSession` · `cloudBtn` · `cloudBody`) 삭제 · `trackSummary` · `trackPush` · 설정 탭 닉네임 줄 · 개발용 `?dev=cloud` → `?dev=frozen` · `?guest=1` 삭제(붙여도 무시)
- `i18n.js` — `cl.*` 중 `cl.frozen.*` 둘만 남는다 · `set.nick` 추가
- `style.css` — `.login-*` · `.cloud-btn` · `.cl-account` · `.cl-row` · `.cl-actions` 삭제 · `#app.login-gate` → `#app.booting` · `.set-nick`
- `index.html` — 첫 셸이 `#app.booting` 을 든다(첫 그리기가 걷는다)
- 새 파일 `src/dev/funnel.html` · `funnel.js` — 설정법(익명 로그인 켜기 · 보안 규칙)은 [src/dev/README.md](../../../src/dev/README.md)
- INTERFACE §4 「클라우드 사본」 → 「플레이 기록」 · ARCHITECTURE §8 · GAME_DESIGN 기술 줄
- ⚠ **콘솔 설정이 있어야 기록이 쌓인다** — Firebase 콘솔에서 익명 로그인을 켜고 보안 규칙에 `players` 를 더해야 한다. 그 전에는 게임만 돌고 기록은 실패한다
- ⚠ 옛 Google 계정의 `saves/<uid>` 문서는 그대로 남는다(퍼널은 `players` 만 읽어 안 섞인다) · 옛 연결 기록 `thesevensim.cloud` 는 아무도 안 읽는다
- ⚠ 무료 한도(하루 쓰기 2만 건) — 한 번에 문서 둘, 바뀐 것이 있을 때 간격마다라 플레이 한 시간에 쓰기 120 건 남짓이다
