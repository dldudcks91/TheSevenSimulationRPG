# ADR-0640 — 스킬 도감에 막힌 업그레이드는 「최대」가 아니라 도감 레벨을 말한다

| | |

| **화면** | [SCREEN_DESIGN §17](../SCREEN_DESIGN.md) |

| **대체됨** | 0680 (2026-10-21 — 스킬 도감 레벨이 걷혀 상한은 끝 하나 · 「도감 Lv.n」을 걷는다) |

## 결정

도서관 **스킬 업그레이드** 카드의 읽기 줄 버튼은 상한을 둘로 가른다 — 그 스킬의 **스킬 도감이 연 상한**에 닿았으면 **「도감 Lv.n」**(n = 상한을 올려 줄 스킬 도감 레벨 · `plan.codexNeed` · 흐리다) · **상한의 끝**에 닿았으면 지금처럼 **「최대」**(흐리다). 거절 플래시도 `bk.err.codexCap` 으로 따로 선다(버튼이 흐려 평소엔 안 뜬다).

## 맥락

같은 날 책 업그레이드 상한이 스킬마다 갈렸다 — 스킬 도감 레벨이 처음 3 · 레벨마다 +2 · 끝 9 로 나눠 연다(monster_design §8-1 · DEV_PLAN R266). 그 전에는 상한이 하나라 「최대」 하나로 충분했다.

## 근거

- **더 올릴 수 있는데 「최대」라고 하면 틀린 말이다** — 도감이 오르면 열리는 막힘과 끝난 막힘은 플레이어가 할 일이 다르다(앞은 그 스킬을 가진 몬스터를 더 잡는다).
- **버튼 글자 하나로 말한다** — 규칙 문장은 카드에 안 쓴다(CLAUDE.md 규칙 7 · §17 「카드 · 패널에는 규칙 문장이 없다」). 어디서 도감을 올리는지는 도움말의 몫이다.
- 버린 안 — **「최대」 그대로**: 계약 변경이 없지만 위의 틀린 말이 남는다.

## 파급

- `game.bookState` 의 `plan` 에 `cap` · `codexNeed` · 거절 코드 `codexCap`(INTERFACE §2-7 · 결과 코드 표)
- `app.js` 스킬 업그레이드 버튼 글자 · i18n `bk.codexCap` · `bk.err.codexCap`
- 스킬 도감 자체의 화면(도감의 스킬 쪽 · 열린 상한 표시)은 아직 없다 — monster_design §8-1 「화면」 미정
