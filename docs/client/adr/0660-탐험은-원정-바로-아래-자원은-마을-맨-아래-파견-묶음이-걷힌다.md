# ADR-0660 — 탐험은 원정 바로 아래 · 자원은 마을 맨 아래 · 파견 묶음이 걷힌다

## 결정

탭 내비를 **묶음 셋**으로 세운다 — **전투**(원정 · 탐험 · 편성 · 캐릭터) · **마을**(건설 · 선술집 · 상점 · 제련소 · 도서관 · 자원) · **기타**(결투장 · 도감 · 도움말 · 실험실). 탐험이 원정 바로 아래로 오고, 자원이 마을 묶음 맨 아래로 들어가며, 둘만 있던 **파견 묶음은 머리째 걷힌다.** 탭 수(14) · id · 이름은 그대로다. 건설 부지 순서(§13-1 「부지 순서 = 탭 바 순서」) · 도움말 섹션 순서(§12 「탭 순서를 따른다」)는 각자의 규칙대로 새 탭 순서를 따라간다.

## 맥락

그날 탭 내비는 묶음 넷이었다 — 전투(원정 · 편성 · 캐릭터) · 마을(건설 ~ 도서관) · 파견(자원 · 탐험) · 기타(결투장 · 도감 · 도움말 · 실험실). ADR-0554 는 묶음을 세울 때 탭 순서를 건드리지 않았고, 파견 묶음은 그때 순서의 끝 두 탭을 묶은 것이었다. 탐험은 파티를 동굴에 보내 전투를 리포트로 받는 활동이고(§8-4 · 「오프라인 전투는 탐험이 든다」), 자원은 건물이 기본 생산을 하고 영웅 한 명을 배치해 효율을 올리는 탭이다(§8).

## 근거

- **탐험은 전투 쪽에 붙는다** — 파티를 꾸려 보내고 전투 결과를 받는다. 원정과 같은 「파티를 내보낸다」 결정이라 원정 바로 아래에서 같이 읽힌다
- **자원은 마을 건물의 탭이다** — 건물 생산 + 1인 배치라 건설 · 제련소 같은 마을 시설과 같은 결로 읽힌다. 두 탭이 흩어지면 파견 묶음은 남는 탭이 없다
- **버린 안 — 파견 묶음을 자원 하나로 남긴다** — 탭 하나짜리 묶음은 머리 한 줄만 늘린다. 사용자가 「마을로 편입」을 지시했다
- **부지 순서는 탭을 따라간다** — 「탭 바가 바뀌면 부지도 따라간다」가 §13-1 규칙의 본문이다(ADR-0348 의 버린 안 「부지는 옛 순서로 남긴다」와 같은 판단). 탐험 부지가 원정 바로 다음 둘째로, 자원 부지가 도서관 뒤로 간다

## 파급

- app.js — `NAV_GROUPS` 의 묶음 셋 · 탭 렌더러 사전 키 순서 · `helpSections()` 순서(탐험이 원정 뒤 · 결투장이 자원 뒤 — 「탭 순서를 따른다」를 지킨다)
- i18n — `nav.grp.dispatch` 삭제 · `nav.explore` · `nav.resource` 나열 자리(탭 바 순서와 같게 두는 관례) · 값 변경 없음
