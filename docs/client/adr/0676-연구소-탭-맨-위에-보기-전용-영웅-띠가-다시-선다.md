# ADR-0676 — 연구소 탭 맨 위에 보기 전용 영웅 띠가 다시 선다

| | |
|---|---|
| **상태** | 확정 · 2026-10-21 |
| **화면** | [SCREEN_DESIGN §8](../SCREEN_DESIGN.md) · [§5](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 — 「일단 연구소 위에 영웅 얼굴 좀 넣어봐」 · 띠 모양(보기 전용)은 구현 판단 |
| **대체** | ADR-0665 의 「맨 위 영웅 띠를 걷는다」 (자리 칸 · 선택 창 · 관전 창 · 담당 능력치를 걷는 것은 그대로) |
| **대체됨** | ADR-0677 의 「카드 위칸 = 지금 하는 일」 (2026-10-21 — 위칸 = 등록한 연구소 줄) · 나머지(보기 전용 띠 · 자리)는 그대로 |

## 결정

연구소 탭 맨 위에 공통 영웅 띠(§5)가 선다 — 탐험 탭(ADR-0556)과 **같은 보기 전용 띠**다. 카드는 초상 · 이름 · `Lv.n` · 위칸 「지금 하는 일」(원정 중 · 탐험 중 · 전직 중 · 대기)을 보여 주고, 클릭도 고른 표시도 없다(툴팁은 뜬다). 띠 아래로 줄 목록 | 고른 줄(사다리 · 고른 칸)이 남는 세로를 받는다. 영웅은 여전히 연구소에 앉지 않는다 — 생산은 칸 레벨이 정한다.

## 맥락

2026-10-18 연구소에서 영웅 배치를 빼며 자원 탭 시절의 보기 전용 띠도 같이 걷었다(ADR-0665 — 「영웅이 안 앉는데 영웅을 보여 주면 「누구를 넣을까」가 있는 것처럼 읽힌다」). 그날부터 연구소 탭은 줄 목록 | 고른 줄 두 패널이 박스 세로를 다 썼다(ADR-0669 · ADR-0674). 2026-10-21 사용자가 연구소 위에 영웅 얼굴을 넣어 보라고 지시했다. 같은 날 탐험 탭은 보기 전용 띠를 맨 위에 두고 있었다(ADR-0556).

## 근거

- **보기 전용으로 둔다** — ADR-0665 가 걱정한 것은 「누구를 넣을까」로 읽히는 것이다. 클릭도 고른 표시(파란 테두리)도 없으면 카드는 고르는 대상이 아니라 로스터의 현황판이다. 탐험 탭 띠가 이미 같은 뜻으로 서 있어 두 탭을 오갈 때 같은 띠가 같은 동작(아무것도 안 함)을 한다
- **같은 띠 · 같은 자리** — §5 「어느 탭에서든 로스터가 같은 자리」. 새 모양(작은 얼굴 줄 · 줄 목록 위 초상 몇 개)을 만들지 않는다
- **세로를 내준다** — 띠 높이만큼 사다리 일곱 줄이 짧아진다(줄이 열의 세로를 나눠 가지는 구조라 빈 상자는 안 생긴다 · ADR-0674)
- 버린 안 — ① 띠 카드를 누르면 무언가 하게(고른 영웅 표시): 누른 뒤 일어날 일이 없다 — 「눌러도 아무 변화가 없는 화면」(§5 고른 표시 규칙) ② 찾아온 영웅 줄의 「등록한 영웅」 자리로 쓰기: 등록은 아직 기획 전이다(GAME_DESIGN §10)

## 파급

- `app.js:renderResource` — 쌓인 판(`page page-stack`) 맨 위에 `heroStrip(() => {}, { view: true })`(탐험 탭과 같은 호출) · 줄 목록 | 고른 줄(`.dp-wrap`)이 `.fill`
- `style.css` — 띠와 연구소 두 패널 사이 간격 한 줄
- i18n 키 추가 없음
- §5 띠가 서는 탭 목록에 연구소가 다시 든다
- ⚠ 띠가 누르는 무언가가 되려면(찾아온 영웅 줄의 등록 영웅 등) 그때 클릭을 붙이고 이 결정을 다시 본다
