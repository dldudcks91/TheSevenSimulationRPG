# ADR-0682 — 연구소 트리 행은 한 화면에 일곱 줄 높이다 · [미니게임] 버튼을 걷는다

| **화면** | [SCREEN_DESIGN §8](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 — 「미니게임 안보이도록 모두 수정하고 연구소에 연구 아이콘이 7개정도 들어갈 수 있도록 높이 잘 맞춰봐 다시」 · 행 높이 · 노드 크기는 구현 판단 |

## 결정

연구소 트리의 행 높이가 **트리 격자 높이의 1/7**(행 사이 틈을 뺀 몫)로 고정된다 — 줄이 몇 개든 한 행의 크기가 같고, 일곱 줄까지 스크롤 없이 서며, 넘치면 트리 격자만 세로로 스크롤한다. 지금 줄(넷)은 위에서부터 서고 아래는 빈다. 행에 맞춰 단계 노드(위 `Lv n` · 그림 원 · 아래 시간당 + 게이지)와 줄 카드(위 줄 그림 · 이름 · 찾아온 영웅은 Lv / 닫힘 · 아래 영웅 칸)를 줄인다. 줄 카드의 **[미니게임] 버튼을 걷는다** — 미니게임으로 들어가는 길이 화면에서 사라진다. 미니게임 창 · 판 · 채점 · 보상(`mgRound` · `mgJudge` · `mgClaim`)은 지우지 않고 개발용 `?dev=mg` 만 연다.

## 맥락

같은 날 연구소 트리는 왼쪽 줄 카드(줄 그림 · 이름 · [미니게임] · 영웅 칸) → 오른쪽 단계 노드 일자였고(ADR-0681), 행 넷이 트리 패널 세로를 똑같이 나눠 가져 한 행이 약 130px · 노드가 약 100px 높이였다. 사용자가 미니게임을 안 보이게 하고, 연구(줄)가 일곱 개쯤 들어갈 높이로 맞추라고 지시했다. 기획은 연구소에 새 방치 보상을 줄로 더해 간다(GAME_DESIGN §9 10-18 · 장비 생산 줄 예정).

## 근거

- **행 크기는 줄 수에 안 흔들린다** — 행이 패널을 나눠 가지면 줄이 늘 때마다 모든 노드가 작아지고 지금은 넷이 과하게 크다. 일곱 줄 몫으로 고정하면 새 줄은 빈 자리에 한 행이 들어설 뿐이다(ADR-0669 「줄이 늘면 한 줄이 더해질 뿐」과 같은 뜻)
- **노드는 행 안에서 원 한가운데 = 칸 한가운데를 지킨다** — 위 · 아래 글 칸을 같은 높이로 두어 선(칸 높이 50%)이 원을 지난다(ADR-0678 짜임 그대로)
- **[미니게임]을 걷는다 · 로직은 남긴다** — 사용자 지시가 「안 보이도록」이다. 판 · 채점 · 보상 로직과 단정 · 창 그림은 다시 붙일 때 버튼 하나로 돌아온다 · 지우면 되살리는 비용이 크다
- 버린 안 — ① 행이 패널을 나눠 가지고 일곱을 넘으면 스크롤: 지금 넷이 크게 서는 문제가 그대로다 ② 노드를 가로형(원 옆에 글): 단계 열 폭(약 88px)에 글이 안 들어간다

## 파급

- `app.js` — `dpTreeLine` 의 [미니게임] 버튼 · `--dp-rows` 를 걷는다 · `mgOpen` 은 개발 경로만 부른다
- CSS — `.dp-tree-grid` 가 `grid-auto-rows`(격자 높이 ÷ `--dp-fit` = 7)와 세로 스크롤 · 노드 · 줄 카드 · 영웅 칸 크기를 줄인다 · `.dp-card .dp-mg` 를 걷는다
- i18n — `mg.play` 삭제(버튼 글자)
- ⚠ 한 줄에 영웅이 여덟 넘게 몰리면 영웅 칸이 줄을 바꿔 카드가 행보다 커진다 — 칸 상한이 서면 다시 본다(GAME_DESIGN §10 「연구소의 남은 설계」 ⑥)
