# ADR-0695 — 분해함 필터를 누르면 맞는 장비가 바로 함에 오른다 · [올리기]를 걷는다

## 결정

분해함 필터 버튼(등급 · 레벨 · 고정)을 누르면 **함이 바로 따라온다** — 필터가 올렸던 것을 내리고, 지금 고른 필터에 맞는 잠기지 않은 장비를 보고 있는 인벤토리에서 낮은 것부터 남은 칸만큼 올린다. 버튼을 끄면 그 장비는 제자리로 돌아간다. 칸을 눌러 손으로 올린 것은 필터와 무관하게 남는다. 고른 버튼이 하나도 없으면 필터는 아무것도 안 올린다. [올리기]는 걷는다. [분해하기] 뒤에는 함이 비고 **필터도 풀린다** — 다음 묶음은 필터를 다시 누른다.

## 맥락

ADR-0673 은 필터를 체크만 하는 토글로 두고 [올리기] 한 번이 적용하게 했다 — 「그리고」 결합에서 버튼이 누르는 즉시 함을 바꾸면 **누른 순서가 결과를 바꾼다**는 이유였다. 그날 함은 필터를 눌러도 비어 있었고, 무엇이 걸렸는지는 [올리기]를 눌러야 보였다.

## 근거

- **누른 것이 바로 보여야 한다**(사용자) — 버튼이 켜졌는데 함이 비어 있으면 무엇이 걸렸는지 모른다. [올리기]라는 한 단계가 더 끼어 있었다
- **순서 문제는 「다시 계산」이 없앤다** — 누를 때마다 필터가 올린 것을 전부 내리고 지금의 필터 상태로 처음부터 고른다. 결과는 고른 버튼의 집합만으로 정해지고 누른 순서와 무관하다. ADR-0673 이 즉시 적용을 버린 이유는 「누를 때마다 더한다」 방식의 것이었다
- **고른 것이 없으면 아무것도 안 올린다** — 「안 고른 열 = 조건 없음」을 그대로 쓰면 버튼을 다 끈 순간 인벤토리 전부가 걸린다
- **분해 뒤 필터가 풀린다** — 필터를 켠 채 두면 분해 뒤 다음 16개가 저절로 함에 차는데, [분해하기]를 빠르게 두 번 누르면 보지 않은 묶음이 녹는다(§3 「되돌릴 수 없는 행동은 두 번」). 풀어 두면 두 번째 누름은 빈 함이라 아무 일도 없다
- **[올리기]는 할 일이 없어진다** — 필터 누르기가 곧 올리기다

**버린 안**

1. **필터를 켠 채 두고 분해 뒤 다음 묶음을 저절로 채운다** — 묶음마다 누르는 수는 줄지만 위의 두 번 누름 문제가 생긴다
2. **[올리기]를 남겨 분해 뒤 다음 묶음을 채우게 한다** — 필터 상태와 함이 갈리는 순간(켜졌는데 빈 함)이 다시 생긴다

## 파급

- `app.js` — 화면 상태 `cubeAuto`(필터가 올린 uid · 세이브 아님) 신설 · `cubeSync` 가 필터 버튼마다 함을 다시 맞춘다 · [올리기] 버튼과 `.salv-lift` 걷음 · [분해하기] 뒤 필터를 비운다 · 칸을 눌러 내린 것은 `cubeAuto` 에서도 뺀다
- i18n — `ch.sel.lift` 삭제 · `ch.salvageHint`(도움말) 개정
- 세이브 · `game_logic` 무변동 — 분해는 그대로 `game.salvage` 를 하나씩 부른다
- 「두 번 누른다」는 그대로다 — 필터(또는 칸) 한 번 · [분해하기] 한 번
