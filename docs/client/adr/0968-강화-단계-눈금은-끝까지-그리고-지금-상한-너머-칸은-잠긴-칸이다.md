# ADR-0968 — 강화 단계 눈금은 끝까지 그리고 지금 상한 너머 칸은 잠긴 칸이다

## 결정

강화 작업 칸의 단계 눈금은 **`[balance.csv:equip_upgrade_slots]` 칸을 언제나 그린다**(`upgradeState.slots` — 상한이 그보다 크면 상한). 지금 상한(`upgradeState.max` — 기본값 + 대장간 랭크) 안의 칸은 그대로(찬 칸 = 지금 단계 · 다음 칸은 테두리만 밝다), **상한 너머 칸은 잠긴 칸**이다 — 회색 · 칸 가운데 닫힌 자물쇠(ADR-0925). 머리의 `+n / 상한` 은 그대로 지금 상한이다. 잠긴 칸에 여는 조건 글자나 툴팁은 달지 않는다.

## 맥락

그날 눈금은 지금 상한만큼 칸을 그렸다 — 대장간을 안 지었으면 3칸, 다 지으면 6칸. 칸이 박스 폭을 나눠 가져서 3칸이면 칸 하나가 길쭉하게 늘어났다. 강화의 확정 목표는 +9강이고(item_design §1), 다 지은 대장간이 여는 상한은 그보다 낮았다(`balance.csv:equip_upgrade_max` 설명 — 대장간 r2 의 +3 을 뺐다).

## 근거

- **사용자 지시** — 끝까지 그리고 안 열린 칸은 잠근다
- **칸 수는 CSV 한 곳이 든다** — 9 를 렌더러에 박지 않는다(규칙 2). 상한 판정과 같은 자리(`upgradeState`)가 칸 수도 낸다 — 렌더러는 세지 않는다
- **잠긴 칸 = 어디서나 같은 회색 자물쇠**(ADR-0925) — 새 잠금 모양을 만들지 않는다
- **버린 안 — 잠긴 칸마다 여는 대장간 랭크를 툴팁으로 단다** — 「그냥 잠금처리」였고, 지금 데이터로는 7 ~ 9칸을 여는 랭크가 없다

## 파급

- balance.csv — `equip_upgrade_slots` 신설 · game_logic `upgradeState` 가 `slots` 를 낸다(INTERFACE §2)
- app.js `forgeUpgrade` — 눈금이 `slots` 칸 · `max` 너머는 `.lock` 칸 + `lockIcon` · style.css `.fg-up-pips i.lock`
- ⚠ 상한이 칸 수보다 낮은 동안 맨 끝 칸들은 어떤 랭크로도 안 열린다 — 대장간 랭크가 상한을 다시 올리면(기획) 저절로 풀린다
