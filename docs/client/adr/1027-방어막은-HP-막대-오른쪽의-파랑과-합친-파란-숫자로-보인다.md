# ADR-1027 — 방어막은 HP 막대 오른쪽의 파랑과 합친 파란 숫자로 보인다

| | |
|---|---|
| **상태** | 확정 · 2026-11-02 |
| **화면** | [SCREEN_DESIGN §4-2](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 — 「방어막이 쳐지면 수치가 오른쪽끝에 방어막만큼 파란색이생기면서 현재체력이 그만큼증가해서 보이는걸로」 · 합이 넘칠 때 막대를 합에 맞추는 것과 파란 글자는 제안을 사용자가 받았다 |
| **대체** | — |
| **대체됨** | — |

## 결정

방어막이 있으면 HP 막대의 빨강 오른쪽에 그 양만큼 파랑이 잇고, 숫자는 HP + 방어막을 파란 글자로 찍는다. 합이 최대 HP 를 넘으면 막대 전체를 그 합에 맞춘다.

| HP / 최대 | 방어막 | 막대 | 숫자 |
|---|---|---|---|
| 600 / 1000 | 300 | 빨강 60% · 파랑 30% · 빈칸 10% | `900 / 1000` |
| 300 / 1000 | 450 | 빨강 30% · 파랑 45% · 빈칸 25% | `750 / 1000` |
| 1000 / 1000 | 450 | 빨강 69% · 파랑 31% | `1450 / 1000` |

## 근거

방어막이 버프 아이콘과 로그에만 있으면 맞아도 HP 가 안 줄어 왜 안 닳는지 못 읽는다. 합친 숫자는 실제 HP 를 가리므로(물약은 실제 HP 를 본다 · 창이 끝나면 숫자가 떨어진다) 파란 글자가 「방어막 포함」을 알린다.

거른 안 — 넘치는 파랑을 잘라 내기(방어막이 깎이는 동안 막대가 안 움직여 원래 문제가 남는다) · 흰 글자로 합산만(실제 HP 와 못 가른다).

## 파급

- 재생기가 `buff.amt` · `hit.bar` · `buffEnd` · `down` 을 읽는다(INTERFACE §6). 로직 · 세이브 변경 없음.
