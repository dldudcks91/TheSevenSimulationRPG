## 결정

배포 주소에서 켠 게임은 **켤 때** Firebase Analytics(GA4)를 켠다. **켜기만 한다** — SDK 가 스스로 보내는 첫 방문 · 세션 · 페이지 보기 · 참여 시간이 쌓이고, 게임 이벤트는 따로 안 보낸다. Firebase 콘솔 첫 화면의 「사용자 활동」 카드가 이 숫자다.

- **안 켜는 곳은 플레이 기록과 같다** — 개발 환경 · `?dev=` 주소 (`app.js:TRACK_ON` 하나)
- **게임은 기다리지 않는다** — 켜기는 뒤에서 돌고, 실패(광고 차단기 · 쿠키 막힘 · 연결 없음)는 개발자 콘솔 경고 한 줄뿐
- 플레이어에게 보이는 것은 없다

## 맥락

실제 유저가 있는데 콘솔 「사용자 활동」이 0 이었다. 그 카드는 Analytics 숫자인데 `cloud.js` 는 `app` · `auth` · `firestore-lite` 셋만 불렀다 — `measurementId` 는 설정에 있었지만 아무도 안 읽었다(ADR-0633 이 GA4 를 안 골랐다).

## 근거

- **콘솔 첫 화면에서 바로 본다** — 퍼널 페이지를 열지 않고 활성 유저 추이 · 국가 · 기기를 본다. 켜기 한 줄이라 코드가 거의 안 는다
- **무게** — SDK 와 구글 태그를 합쳐 수십 KB 대이고 게임이 선 뒤 뒤에서 받는다
- **게임 이벤트는 안 보낸다** — 유저 한 명의 진행은 `players` 요약이 이미 든다(ADR-0633 근거 그대로). 같은 사실을 두 곳에 쓰지 않는다
- **정확한 유저 수의 기준은 `players` 다** — 광고 차단기를 쓰는 유저는 Analytics 에 안 잡혀 실제보다 적게 나온다

## 파급

- `ui/cloud.js` — 앱 만들기를 한 곳(`appOnce`)으로 모았다(Analytics 와 계정 · 저장소가 같은 앱을 쓴다 — 같은 앱을 두 번 만들면 SDK 가 거부한다) · `startAnalytics` 신설
- `app.js` — 부팅에서 `TRACK_ON` 이면 `CLOUD.startAnalytics()` (안 기다린다)
- `ui/firebase_config.js` 머리 주석 · ARCHITECTURE §8 SDK 줄
- ⚠ 콘솔 카드는 하루 남짓 늦게 찬다 — 바로 보려면 Analytics 「실시간」
- ⚠ 쿠키(`_ga`)를 심는다 — 동의 창은 없다
