# ADR-1060 — 원정 관전 최대화는 브라우저 창 안에서 꽉 찬다 · 탭 열과 보관 칸만 걷고 위 줄은 남는다

## 결정

원정 관전의 최대화 버튼은 **브라우저 전체 화면을 켜지 않는다.** 누르면 **왼쪽 탭 열과 아래 보관 칸만 걷히고, 위 줄(브랜드 · 상단바)은 그대로 남는다** — 관전 판(헤드 + 아레나 · 열려 있으면 로그 열)이 위 줄 아래 한 장 폭 전체를 채운다. 한 장은 늘 브라우저 창에 맞춰 서므로 창을 줄이면 그 창 안에서 꽉 찬다. 판 안이 커진 폭만큼 통째로 커지는 배율 · 버튼 자리 · 되돌리는 길(같은 버튼 · `Esc` · 관전을 떠날 때) · 세이브에 안 드는 것 · 원정만인 것은 ADR-1059 그대로다.

## 맥락

ADR-1059 의 최대화는 탭 열 · 상단바 · 보관 칸을 다 걷고 같은 순간 브라우저 전체 화면을 요청했다. 그래서 누르면 모니터 전체가 덮였고, 브라우저 창 크기와 상관없이 화면 전체로 커졌다. 상단바가 걷혀 최대화한 동안은 부대 칸 · 골드 · 설정에 닿지 못했다.

## 근거

- **창 안에서 꽉 찬다** — 사용자가 원한 것은 모니터 전체가 아니라 「지금 브라우저 창 안」이다. 한 장(1600×800)은 이미 `fitStage` 가 창에 맞춰 줄이고 늘리므로 전체 화면 요청 하나만 빼면 된다
- **위 줄은 남긴다** — 사용자 지시. 칸 나눔은 게임 밖 화면(`#app.pregame` — 위 줄 + 메인이 한 줄 전체)과 같은 모양이라 새 칸 나눔을 만들지 않는다. 상단바의 부대 칸이 남아 최대화한 채 다른 부대로 갈 수 있다(그 부대가 관전 중이 아니면 관전을 떠나는 것이라 최대화가 풀린다)
- **배율 공식은 그대로** — `.9 × 한 장 폭 ÷ 평소 메인 칸 폭`. 판 안의 설계 폭이 평소 관전과 같다는 근거(ADR-1059)는 메인 폭이 1600 인 것으로 성립하고 위 줄 높이와는 무관하다. 위 줄이 남은 만큼 아레나 세로가 ADR-1059 보다 줄어든다
- ⚠ 한 장은 가로세로 2:1 이라 창 비율이 다르면 위아래(또는 좌우)에 바닥색 띠가 남는다 — 모든 화면과 같은 규칙이다(ADR-0087)

## 파급

- `app.js` — 브라우저 전체 화면 요청 · `fullscreenchange` 받기 · 최대화가 켠 전체 화면 표시를 걷었다 · 최대화를 켜고 끄는 것은 `state.btMax` 한 값
- `style.css` — `#app.bt-max` 가 칸 나눔을 「위 줄 + 메인이 아래 줄 전체」로 바꾸고 탭 열만 숨긴다(브랜드 · 상단바를 숨기던 줄을 걷었다)
- i18n `bt.max` · `bt.unmax` 그대로
- ADR-1059 의 ⚠「최대화한 동안은 상단바의 부대 칸도 걷힌다」는 사라졌다
