## 결정

켜면 메뉴의 [새 게임] [불러오기] 아래에 **그림 받기 막대**가 서고, 기본 화면이 쓰는 그림을 전부 미리 받는다. 받는 동안 두 버튼은 흐리고 안 눌린다. 다 받거나 제한 시간(`ui/preload.js:PRELOAD_GIVE_UP_MS`)이 지나면 막대가 걷히고 버튼이 풀린다 — 제한 시간에 못 받은 것은 뒤에서 계속 받는다. 못 받은 파일(404 등)은 받은 것으로 센다. 받을 목록은 배포판을 지을 때 `scripts/build_deploy.py` 가 쓰는 `assets/art/preload.json` 이다 — 배포 사본의 그림 중 기본이 아닌 묶음(다른 배경 그림체 · 다른 이펙트 그림체)을 뺀 것. 한꺼번에 몰지 않고 정해진 수(`PRELOAD_LANES`)씩 받는다. 받은 그림은 페이지를 닫을 때까지 쥐고 있어 화면이 그 그림을 쓸 때 다시 받지 않는다. 개발 서버는 목록이 없어 받지 않고 막대도 안 선다 — `?preload` 가 있는 주소만 목록을 찾는다(지은 사본을 로컬로 띄워 볼 때).

## 맥락

배포 주소에서 도감 · 가방을 처음 열면 그림이 한 장씩 늦게 떴다. 그날 잰 값(로컬 서버 + 지연 60ms)으로 도감 탭 처음 열기 0.45 ~ 0.9초 · 같은 탭 두 번째 0.02 ~ 0.04초 — 화면 그리기는 0.01 ~ 0.05초라 대기의 거의 전부가 처음 받는 그림이었다. 배포판 그림은 1,028장 · 36MB, 그중 기본 화면이 쓰는 것은 900장 · 24MB 였다. GitHub Pages 는 `Cache-Control: max-age=600` 을 주고, 10초 남짓에 약 3,800번 요청하자 429 로 막았다(한 번에 700 ~ 940장은 두 번씩 받아도 문제없었다).

## 근거

- **미리 받기** — 처음 늦는 이유가 「받아 본 적 없는 그림」이라 켤 때 받아 두면 처음 열어도 두 번째 속도로 뜬다. 그림을 한 장에 모으는 안은 첫 받기가 오히려 늘어(큰 한 장을 다 받아야 한다) 이 문제를 못 푼다
- **버튼 잠금** — 사용자 선택. 막대만 두면 바로 누른 사람은 처음 몇 화면이 예전처럼 늦다
- **목록은 빌드가 짓는다** — Pages 엔 폴더 목록이 없고, 손으로 둔 목록은 그림이 바뀔 때마다 어긋난다. 빌드가 그 사본의 파일로 지으면 늘 맞는다
- **동시에 받는 수 제한** — 한꺼번에 몰면 Pages 의 요청 제한에 가까워진다
- **쥐고 있기** — 놓으면 브라우저가 버릴 수 있고, `max-age` 가 지난 뒤엔 화면이 쓸 때 다시 묻는다

**버린 안**

1. **전부(1,028장) 받기** — 남는 128장 · 12MB 는 기본 화면이 안 쓰는 그림체이고 요청 수만 는다
2. **막대만 · 버튼은 바로** — 사용자가 잠금을 골랐다
3. **그림을 한 장(아틀라스)에 모으기** — 위 근거. 엔진 이식 때 엔진이 원본 PNG 로 다시 묶는다

## 파급

- `ui/preload.js` 신설(`startPreload` · `preloadState` · `PRELOAD_LANES` · `PRELOAD_GIVE_UP_MS`) · `app.js:boot` · `renderMenu` · i18n `mn.loading` · `style.css` `.mn-load`
- `scripts/build_deploy.py` 가 사본에 `src/assets/art/preload.json` 을 쓴다(빼는 묶음은 스크립트의 `PRELOAD_SKIP`) — 기본 그림체가 바뀌면 그 목록도 바꾼다
- ⚠ itch 판은 이 목록을 그대로 실으면 itch 에서 뺀 파일(스킨)이 404 로 센다 — 받은 것으로 치므로 막히지는 않는다
