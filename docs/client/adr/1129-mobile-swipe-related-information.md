# ADR-1129 — 모바일의 관련 정보는 밀어서 넘기고 행동은 눌러 실행한다

| | |
|---|---|
| **상태** | 확정 · 2026-11-14 |
| **화면** | [모바일 규격](../MOBILE_UI.md) |
| **정한 사람** | 사용자 지시 |
| **대체** | ADR-1103·1123의 기능/카드 전환을 클릭으로만 제공하던 방식 |
| **대체됨** | — |

사용자가 캐릭터 능력치에서 오른쪽 드래그로 상세를 보는 사례를 들며, 모바일에 맞는 제스처와 키우기 게임 UI 조사를 요청했다. [조사·적용 계획](../MOBILE_GESTURE_PLAN.md)에 공개 자료와 설계 판단을 나눠 기록한다.

캐릭터는 능력치로 진입한다. 물리적인 페이지 순서는 상세 II–상세 I–능력치–장비–창고–가방이다. 오른쪽으로 밀면 왼쪽에 있던 상세가 들어오고, 반대 방향으로 돌아간다. 직접 선택·키보드도 같은 순서를 따른다. 다른 기능 패널과 고용·의뢰·전술·전직 카드는 같은 넘기기 방식을 쓴다. 양옆 목적지와 현재 위치는 선택 줄 안에 표시해 본문 높이를 빼앗지 않는다.

내용이 손을 따라 움직이고 충분히 이동했을 때만 한 장 전환한다. 짧은 이동·세로 의도·pointercancel·다중 터치는 확정하지 않는다. 처음/끝은 넘어가지 않는다. 중첩된 카드에서는 안쪽 카드만 처리하며 끝에서 부모로 전파하지 않는다. PC 390×844 미리보기 축소 배율을 반영한다. 동작 감소 설정에서는 이동 애니메이션을 생략한다.

원본 상태와 행동을 재사용한다. 스와이프는 비교할 카드/정보를 고르는 일이다. 고용·강화·출전·전직 확정은 명시적 버튼으로 실행한다. 실행 버튼 위에서 끈 동작은 클릭으로 이어지지 않으며 다음의 정상 탭은 즉시 작동한다. 진형 드래그·영웅 순서 변경·입력·아이템 조작·공간 판은 기존 입력을 유지한다. 세로 목록은 스크롤하고 가로 페이지는 넘긴다. 길게 눌러 설명을 여는 조작도 유지한다.

터치의 암시적 포인터 캡처가 자식에서 페이지로 옮겨가는 것은 취소가 아니다. 세로 스크롤 컨테이너에도 touch-action을 적용해야 목록 위의 가로 동작을 브라우저가 먼저 가져가지 않는다. 실제 브라우저 입력 검증에는 이 두 경계를 포함한다.
