# ADR-1146 — 연구소 영웅은 끌어서도 넣고, 잃는 것이 있을 때만 한 번 더 묻는다

| | |
|---|---|
| **상태** | 확정 · 2026-11-14 |
| **화면** | [SCREEN_DESIGN §8](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 (확인 방식은 제안 후 승인) |
| **대체** | ADR-0676 의 「띠는 보기 전용」 — 띠가 드래그를 잡는 곳이 된다(클릭은 그대로 보기 전용) |
| **대체됨** | ADR-1154 (2026-11-14 — 전부 · 드래그 · 확인 창을 걷고 등록 창에서 고른 뒤 [적용]) |

## 결정

연구소 탭에서 영웅을 **끌어서** 등록한다 — 위 띠의 얼굴 → 줄 카드 = 등록 · 줄 카드의 얼굴 → 다른 줄 카드 = 옮기기 · 줄 카드의 얼굴 → 띠 = 해제. 줄 카드 영웅 칸의 클릭(등록 창)은 그대로 남는다. 옮기기 · 해제가 **숙련**이나 **수색 시계**를 없앨 때만 확인 창을 띄운다(무엇이 얼마나 사라지나 · [옮기기 | 빼기] [취소]) — 판단 근거는 `game.labRegLoss`.

## 맥락

같은 날 수색이 영웅마다 시계를 하나씩 갖게 됐고(GAME_DESIGN §9 11-14 · R492) 숙련은 등록 시각부터 하루에 걸쳐 찬다. 등록은 줄 카드 칸 → 등록 창 → 카드 클릭 세 걸음이었고, 등록 창에서 이 줄의 영웅을 누르면 바로 풀렸다 — 진행 중인 수색 시계 · 숙련이 말없이 사라졌다. 사용자가 드래그로 넣기와 「오른쪽 위 [등록] 버튼으로 실수 방지」를 물었다.

## 근거

- **드래그** — 「누가 어느 줄에」가 한 화면의 띠 ↔ 카드 사이 손짓 하나가 된다. 진형 드래그(`bindCardDrag` — 4px 임계 · 고스트 · 뒤따르는 클릭 삼킴)를 그대로 써서 손이 하나다. 클릭 길(등록 창)을 남기는 것은 모바일 · 처음 쓰는 사람 때문이다
- **[등록] 버튼(편집 모드)을 거른 이유** — 잃는 것이 없는 넣기(빈 칸 · 막 넣은 영웅)까지 매번 모드부터 켜야 하고, 모드가 꺼진 동안 끌기가 왜 안 먹는지 헷갈린다. 실수의 손해는 「진행 중인 것이 사라지는 순간」에만 있어 거기에만 묻는다 — §3 「되돌릴 수 없는 행동은 두 번 누르게 한다」 · 스킬 덮어쓰기 확인 창(ADR-1020)과 같은 문법
- **문턱** — 숙련 1% · 수색 시계 1분 아래는 묻지 않는다(방금 넣고 고치는 손을 막지 않는다)
