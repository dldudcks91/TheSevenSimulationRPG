# ADR-1182 — 탐험 중인 편성도 보내기는 확인 창을 거쳐 탐험을 걷고 나간다

| | |
|---|---|
| **상태** | 확정 · 2026-11-15 |
| **화면** | [SCREEN_DESIGN §4-1](../SCREEN_DESIGN.md) 「출정 확인 창」 |
| **정한 사람** | 사용자 지시 (「탐험중인 파티 원정에 보낼떄 아예 거절되는게 아니라 원정에서 다른원정보낼떄처럼 그냥 경고메세지 나오도록 수정」) · 확정 규칙과 부딪힘을 알린 뒤 「이대로 진행」 |
| **대체** | — (출정 창 경고 줄 · 플래시 `exp.departExploring` 이 그 편성 자신의 탐험을 막던 것을 고친다 — 다른 편성의 탐험으로 나간 영웅이 든 편성은 그대로 막는다) |
| **대체됨** | — |

## 결정

출정 창에서 **탐험에 나가 있는 편성**을 [보내기]하면 거절하지 않고 출정 확인 창이 뜬다 — 원정 중인 제 부대를 끊을 때(ADR-0629)와 같은 창 · 같은 버튼이다. 탐험이 진행 중이면 「이 파티는 지금 탐험 중입니다. 진행 중인 탐험을 불러들이고 출격할까요? 탐험 보상은 받지 못합니다.」(`exp.departRecall`), 끝나 결과가 기다리면 「이 파티의 탐험이 끝나 있습니다. 탐험 결과를 인벤토리에 받고 출격할까요?」(`exp.departCollect`). [확인]이면 `game.departRun` 이 그 탐험을 걷고(진행 중 = 보상 없이 불러들인다 · 끝났다 = 결과를 그 부대 인벤토리에 받는다) 출발한다. 끝난 탐험의 결과가 인벤토리에 다 안 들면 창 없이 거절한다 — 경고 줄과 플래시가 「탐험 결과를 받을 인벤토리 칸 부족」(`exp.departBagFull` · `canDepart` 의 `bagFull`).

## 맥락

- 그날 탐험 중인 편성은 원정에 못 나갔다 — `canDepart` 가 `exploring` 으로 거절하고 출정 창 경고 줄이 「편성에 탐험 나간 영웅 있음」을 찍었다. 탐험 탭에서 [불러들이기]를 누른 뒤 다시 보내야 했다
- 원정 중인 제 부대를 다른 칸으로 보낼 때는 확인 창 한 번으로 끊고 나갔다(ADR-0629)
- GAME_DESIGN §9 09-23 「원정과 탐험 사이의 전환을 한 동작으로 만들지 않는다」가 확정이었다 — 사용자에게 부딪힘을 알렸고 「이대로 진행」(탐험 → 원정만 · 원정 → 탐험은 거절 그대로)

## 근거

- **확인 창 하나** — 지시가 「원정에서 다른 원정 보낼 때처럼 경고 메시지」다. 같은 창(`departConfirm`)에 까닭 한 줄을 더해 여러 까닭이 겹쳐도 한 번에 묻는다
- **진행 중 = 보상 없이 불러들인다** — 탐험 탭의 [불러들이기](`exploreDrop`)와 같은 결과다. 잃는 것이 있으니 문장 끝에 「탐험 보상은 받지 못합니다」를 단다
- **끝났다 = 결과를 받는다** — 버리면 받을 수 있던 장비를 잃는다. 받는 것은 탐험 탭의 [받기](`exploreTake`)와 같아 다른 규칙이 생기지 않는다. 인벤토리가 모자라면 받기와 같이 거절한다 — 장비를 버리고 나가는 길을 만들지 않는다
- **원정 → 탐험은 그대로 거절** — 지시 범위 밖이다

## 파급

- 로직 — `canDepart` 의 `exploring` 은 다른 편성의 탐험으로 나간 영웅만 · 새 거절 `bagFull` · `departRun` 이 그 편성의 탐험을 걷는다 (INTERFACE §2-7 · DEV_PLAN R500)
- i18n — `exp.departRecall` · `exp.departCollect` · `exp.departBagFull` 신설 · 도움말 `help.explore` 의 「탐험 중인 편성은 원정에 낄 수 없다」 문장을 고쳤다
- 기획 — GAME_DESIGN §9 · §1-1 의 「한 동작으로 만들지 않는다」가 원정 → 탐험 쪽만 남는다
