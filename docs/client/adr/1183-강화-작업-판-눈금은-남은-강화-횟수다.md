## 결정

강화 작업 판 맨 위 줄은 **`남은 횟수` · `남은 / 전체`** 이고, 그 아래 눈금은 **칸 = 그 장비의 강화 횟수**(`upgradeState.tries.max`) · **찬 칸 = 남은 횟수**(왼쪽부터) · 쓴 칸은 빈 칸이다. 강화를 누를 때마다(성공 · 실패 모두) 한 칸이 빈다. 남은 횟수가 0 이면 다음 열 · 확률 줄 · 재료 칸이 빠지고 [강화] 글이 `횟수 소진` 으로 잠긴다(상한과 같은 꼴). 강화 단계(`+n`)는 장비 판의 이름 · 비교 줄이 든다.

## 맥락

같은 날 기획이 장비마다 강화 횟수(`[balance.csv:equip_upgrade_tries]`)를 세웠다(item_design §7-2). 강화 작업 판 맨 위는 `강화 단계 +n / 상한` 과 단계 눈금(지금 상한 너머 잠긴 칸)이었다. 사용자가 그 자리를 남은 횟수로 바꾸라고 했다.

## 근거

- **누르기 전에 읽혀야 하는 것이 바뀌었다** — 횟수가 생기면 「몇 번 더 누를 수 있나」가 누르는 판단의 첫 값이다. 단계는 장비 판 이름(`+3 액스`)과 비교 줄이 이미 든다
- **지금 상한 잠긴 칸을 걷는다** — 눈금 하나에 단계 · 상한 · 횟수를 다 실으면 읽히지 않는다. 상한은 닿는 순간 [강화] 글이 말한다

## 파급

- i18n — `fg.stage` 삭제 · `fg.tries` · `fg.noTries` · `ch.err.tries` 신설 · 도움말 `hint.forge_up` 에 횟수 한 문장
- `app.js:forgeUpgrade` — 눈금 = `tries` · 올릴 수 없음 = 상한 또는 횟수 0
- ⚠ `upgradeState.slots`(단계 눈금 칸 수)는 화면이 안 쓴다 — 계약에는 남았다
