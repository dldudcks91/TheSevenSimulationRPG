# ADR-1195 — 모바일 배치를 잠근다 · 모든 화면이 PC 배치다

| | |
|---|---|
| **상태** | 확정 · 2026-11-15 |
| **화면** | SCREEN_DESIGN §1 「모바일 배치 잠금」 · 설정 `화면` 하위 탭 · [모바일 규격](../MOBILE_UI.md) |

| **대체** | [ADR-1090](1090-screen-layout-preference.md) 의 화면 배치 고르기 · ADR-1089 의 자동 모바일 판정 — 잠근 동안만 |
| **대체됨** | — |

## 결정

모바일 배치를 쓰지 않는다. 휴대폰 · 좁은 창 · 예전에 `모바일`을 골라 둔 브라우저 모두 PC 배치(1600×800 한 장)로 선다. 설정 → 화면의 **화면 배치 줄을 걷는다.** 잠근 동안의 배치는 `자동`과 같아서 휴대폰 세로 화면엔 회전 안내막이 선다. 브라우저에 저장된 선택은 지우지 않는다 — 잠금을 풀면 그 선택이 되살아난다.

## 맥락

- 화면 배치는 설정에서 자동 · PC · 모바일을 고르고 브라우저에 저장했고(ADR-1090), 자동은 좁은 창과 휴대폰 가로를 모바일로 배치했다(ADR-1089)
- 모바일 배치 여부는 `mobile.js:isMobileLayout` 한 곳에서 판정하고, 모바일 CSS 는 그 판정이 다는 `data-mobile*` 속성에만 걸린다

## 근거

- **판정 한 곳을 잠근다** — `MOBILE_LOCKED` 하나가 `isMobileLayout` 을 늘 거짓으로 만들면 모바일 셸 · 페이지 · 밀기 · CSS 가 모두 꺼진다. 모바일 코드를 지우지 않으므로 잠금을 풀면 그대로 돌아온다
- **설정 줄을 걷는다** — 고를 수 없는 줄이 서 있으면 눌러도 안 바뀌는 버튼이 된다
- **회전 안내막은 남긴다** — 휴대폰 세로에서 1600×800 한 장은 너무 작다. 잠근 동안의 배치를 `자동`으로 두면 모바일 배치 전과 같은 안내막이 선다

## 파급

- `mobile.js` — `MOBILE_LOCKED` 신설 · 잠근 동안 `screenLayout = 'auto'` · `setScreenLayout` 무시 · `isMobileLayout` 거짓
- `app.js` — 화면 배치 줄을 `settingsLayoutRow` 로 떼고 잠근 동안 안 부른다
