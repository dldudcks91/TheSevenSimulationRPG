# ADR-1302 — 연구소 배수 지점의 값은 `+n%` 로 적는다

| | |
|---|---|
| **상태** | 확정 · 2026-11-23 |
| **화면** | [SCREEN_DESIGN §8](../SCREEN_DESIGN.md) |
| **정한 사람** | 사용자 지시 — 「오른쪽에 나오는 채광레벨, 간격레벨 이거를 게임에 맞춰서 UI를 수정해봐」 → 시안 셋 중 「전부 +n%」 |
| **대체** | — |
| **대체됨** | — |

## 결정

연구소에서 배수 하나로 그 줄의 생산 · 속도를 미는 지점(채광 · 채집 · 벌목 · 수익 · 수색 간격 · 도서관 간격)은 값을 `×n` 대신 **배수에서 1 을 뺀 몫의 `+n%`** 로 적는다 — 트리 노드 `title` · 고른 지점의 「지금 값 → 올린 뒤」 · 「{지점} 레벨」 목록이 모두 같다. 레벨 0 은 「+0%」다. 배수 자체(`labState` 지점의 `value` · `levels`)는 그대로이고 화면이 찍는 모양만 바뀐다.

## 맥락

그날 고른 지점의 레벨 목록은 `lab_node.csv` 의 `base + 레벨 × per_lv` 를 그대로 `×1.1 ~ ×2` 로 찍었다. 같은 화면의 다른 값은 이미 게임의 단위로 찍혔다 — 등록 효과 표는 `+n%`(2026-10-30 사용자 「속도 x1.1 이런게 뭔개소린지」 · ADR-0971), 품질 · 대박은 `+n%`, 오프라인 생산 시간은 `n시간`, 대기소는 `+n칸`, 훈련 속도는 `+n XP/시간`(ADR-1300). 배수 지점만 `×` 가 남아 있었다.

## 근거

시안 셋을 실제 표 값으로 굴려 보였다(철광석 기본 3/시간 · 수색 기본 4시간).

- **전부 `+n%`** — 채택. 등록 효과 표와 같은 모양이라 한 화면 안의 두 숫자를 같은 눈으로 읽는다. 화면만 고친다 — 로직 계약이 그대로다.
- 생산은 `+n%` · 간격은 실제 시간(「3시간 38분」) — 간격이라는 이름에는 시간이 맞지만, 시간을 로직이 새로 내야 하고 지점마다 단위가 갈린다. 거른 이유: 사용자가 「전부 +n%」를 골랐다.
- 전부 실제 값(채광 「3.3/시간」 · 간격 「3시간 38분」) — 등록 영웅의 인원 · 힘 · 비상 보급을 뺀 기본값이라, 고른 줄 「시간당 생산」에 찍히는 숫자와 달라 모순으로 읽힌다.

⚠ 「간격 +10%」 는 간격이 길어진다로 읽힐 여지가 있다 — 이름(`dp.node.interval`)은 기획 라벨이라 이 결정에서 바꾸지 않았다.

## 파급

- `app.js:labValText` 의 마지막 갈래(`×${labNum(v)}`)가 `+${M.pctNum(v - 1)}%` 가 되고 `labNum` 을 걷었다
- i18n 키 · CSS 는 그대로다
- SCREEN_DESIGN §8 「값 · 비용 · 시간은 `labState` 가 낸다」의 찍는 모양 목록에서 `×` 가 빠졌다
