# ADR-1305 — 연구소 고른 지점은 머리 아래에 하는 일을 적고 지점 이름의 `(?)` 를 걷는다

## 결정

연구소 오른쪽 「고른 지점」의 머리(지점 그림 · 이름 · 줄 이름 · Lv 눈금) 바로 아래에 **그 지점이 하는 일을 한두 문장**으로 적는다 — 모든 지점 · 잠긴 지점도. 자리와 글 모양은 비상 보급의 설명(ADR-1298)과 같다(흐린 작은 글). 문구 키는 `dp.desc.<줄>.<지점>` 이고, 비상 보급의 옛 키 `dp.relief.desc` 는 `dp.desc.res.relief` 로 옮긴다. 같은 머리의 **지점 이름 옆 `(?)` 를 걷는다** — 판 제목의 `(?)` 가 같은 도움말을 든다.

## 맥락

그날 고른 지점 머리 아래 설명은 비상 보급 하나에만 섰다. 나머지 지점은 이름 한 낱말(「채광」 · 「간격」 · 「범위」 · 「대박」)과 값뿐이라, 같은 이름이 줄마다 다른 일을 하는 경우(수색 「간격」 = 영웅 도착 · 도서관 「간격」 = 스킬 조각 생산)까지 이름만으로는 무엇을 미는지 읽히지 않았다. 지점 이름 옆 `(?)` 는 `hint.resource` 를 띄웠는데, 판 제목 「자원 (?)」 이 같은 도움말을 이미 띄웠다.

## 근거

- 설명을 인게임 패널에 두는 것은 「설명 문구는 도움말 탭 전용」(2026-08-26 · SCREEN_DESIGN §12)의 예외다. 비상 보급(ADR-1298)이 이미 같은 예외였고, 사용자가 그 모양을 모든 지점에 펴라고 했다.
- 키에 줄을 넣는다 — 지점 id(`interval` · `burst`)가 줄 사이에 겹쳐 지점 id 만으로는 문장을 못 가른다.
- 값은 문장에 넣지 않는다 — 「다음 레벨」 · 레벨 목록이 값을 들고, 문장에 숫자를 넣으면 CSV 가 바뀔 때 문장이 낡는다.
- `(?)` 는 판 제목과 소제목(「다음 레벨」 · 「{지점} 레벨」)에 남는다 — 사용자가 짚은 것은 지점 이름 옆 하나다.

## 파급

- i18n — `dp.desc.res.mine` · `gather` · `log` · `offline` · `relief` · `dp.desc.visit.interval` · `quality` · `waiting` · `dp.desc.train.speed` · `range` · `dp.desc.gamble.income` · `burst` · `dp.desc.lib.interval` · `burst` · `dp.relief.desc` 삭제
- `app.js:dpSide` — 비상 보급 갈래 대신 모든 지점에 설명 줄 · `dpSideHead` 의 `headingHelp` 삭제 · 렌더 뒤 `.dp-side-n` 에 `(?)` 를 한 번 더 달던 `bindSectionHelp`(대상이 이 하나뿐이었다)와 그 호출 둘(`render` · 창) 삭제
- ⚠ 새 지점이 생기면 `dp.desc.<줄>.<지점>` 키도 같이 생겨야 한다 — 없으면 키 문자열이 화면에 그대로 찍힌다
