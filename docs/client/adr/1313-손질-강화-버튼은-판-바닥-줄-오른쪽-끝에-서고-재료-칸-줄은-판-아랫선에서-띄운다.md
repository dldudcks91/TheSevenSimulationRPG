# ADR-1313 — 손질 · 강화 버튼은 판 바닥 줄 오른쪽 끝에 서고 재료 칸 줄은 판 아랫선에서 띄운다

## 결정

데스크톱에서 **[손질]**(글 = 고른 손질 이름 · 예 `달구기`)은 손질 판의, **[강화]** 는 강화 판의 **바닥 줄 오른쪽 끝**에 선다 — 재료 칸과 같은 줄이고 버튼은 재료 칸 높이의 세로 가운데에 선다(처음엔 아랫변을 맞췄다가 같은 날 사용자 「달구기 및 강화버튼도 조금 위로」로 가운데). 두 버튼은 같은 크기의 보통 버튼이다(제목 줄의 낮은 버튼이 아니다). 판 제목 줄에는 버튼이 없다. **바닥 줄(재료 칸 + 버튼)은 판 아랫선에서 판 옆 여백만큼 띄운다** — 재료 칸이 아랫선에 붙어 보이지 않게. 상한이면 [강화] 글이 `fg.upMax` 로 바뀌어 같은 자리에 잠긴다. 모바일은 그대로다(판 아래 버튼).

## 맥락

ADR-1163(11-14) 뒤로 [손질] · [강화] 는 판 제목 줄 오른쪽 끝의 낮은 버튼이었고, 재료 칸은 판 바닥에 아랫선과 약 5px 떨어져 섰다(판 아래 여백 6px). 사용자가 두 버튼을 오른쪽 아래로, 아래 재료 그림을 조금 위로 옮기라고 했다.

## 근거

- **보고 → 누르기 순서가 위에서 아래다** — 위에서 손질 카드 · 확률 줄을 보고, 바닥에서 낼 재료를 보며 바로 옆 버튼을 누른다. 비용과 버튼이 한 줄이라 「비용은 누르기 전에 보인다」(§8-2)가 한눈에 선다
- **1163 의 근거 「누르는 자리를 한 줄에」는 산다** — 두 판의 바닥 줄이 같은 높이라(ADR-1177 · 1180 — 두 판의 재료 칸이 같은 높이) 두 버튼도 같은 높이에 선다
- **ADR-0973 의 자리(재료 칸 줄 오른쪽 끝)로 돌아간 셈이다** — 다른 점은 손질 판도 같은 줄에 버튼을 둔다는 것이다
- **모바일은 그대로** — 이미 판 아래 버튼(`.fg-go-foot`)이었다. 이제 데스크톱도 같은 버튼 하나를 보인다 — 렌더러가 두 자리에 그리던 것을 하나로 줄인다

## 파급

- `app.js:forgeTemper` · `forgeUpgrade` · `forgeEnchant` — 제목 줄 버튼(`.fg-board-go`)을 안 만든다 · 판 아래 버튼(`.fg-go-foot`) 하나
- CSS — 데스크톱 `.fg-go-foot` 숨김을 걷고 손질 판 그리드 바닥 줄 오른쪽 칸 · 강화 판 `.fg-up-act` 오른쪽 끝에 세운다 · 손질 · 강화 · 인챈트 판 아래 여백을 판 옆 여백과 같게 · 재료 칸 셋 + 버튼이 영어(`Upgrade`)에서도 한 줄에 들게 데스크톱 `.fg-up-act` 의 칸 최소 폭(60px)을 걷고 틈을 좁힌다(접히면 판이 아래로 자라 아랫선이 잘렸다) · 쓰는 곳이 없어진 `.fg-board-go` 규칙을 걷는다
- 인챈트 판도 같은 자리([ADR-1314](1314-대장간-인챈트-탭은-장비-판과-인챈트-판-둘이고-현재-옵션-새-옵션을-가로로-놓고-고른다.md)) · 합성 판의 [합성] · [최대] 도 같은 날 바닥 줄 오른쪽 끝으로 갔다([ADR-1316](1316-합성-판-가운데는-낼-재료에서-만들-재료로-가는-식-한-줄이고-버튼은-바닥-줄-오른쪽-끝이다.md) — 병렬 세션)
- `app.js:mmGuideSelectors` — 메인미션 「강화」 바로가기 테두리가 [강화]를 `.fg-up-work .fg-go-foot` 으로 찾는다
