## 결정

스킬정보 칸 줄(영웅 · 습득 · 전직)의 **제목 띠 오른쪽 끝**에 그 칸 스킬의 **칩 한 줄** — **태그**(파생 포함) → **종류**(물리 · 원소) → **능력치 약어**. 스킬 설명창의 칩과 **같은 칩 · 같은 순서**다(설명창은 능력치를 이름 뒤에 두지만 도서관은 한 줄에 잇는다). 새 책을 고른 습득 줄은 새 책의 칩 · 빈 칸은 칩이 없다 · 넘치면 오른쪽에서 잘린다 · 띠 높이는 그대로다.

```
┌ 영웅            [단일][물리][STR] ┐
│ [카드] 배시                도끼 · 둔기 │
```

## 맥락

2026-11-24 스킬정보 칸 줄은 이름 · 필요 무기 · 설명 · 계산 줄 · 레벨 줄을 들었고, 태그 · 종류 · 능력치 칩은 카드에 올렸을 때 설명창에만 있었다. 같은 날 칸 줄 높이를 영웅마다 같게 고정했다(ADR-1357).

## 근거

- **태그는 고르는 데 쓰는 값이다** — 반지 · 전직 공통 줄의 보너스가 태그로 걸린다(「함성 스킬 …」 · 「냉기 스킬 …」 · `skill_tags.js`). 책을 고르는 자리가 올리기 전에는 그것을 못 보여 줬다.
- **복잡하지 않다** — 스킬마다 칩 2 ~ 5개(태그 + 종류 + 능력치 — 2026-11-24 영웅 스킬 95개 · ko · en 모두 한 줄 안)이고, 새 규칙 · 새 문구 없이 설명창의 칩을 그대로 쓴다(`tip.js:skillChipParts` 한 함수 — 두 자리가 갈리지 않는다).
- **제목 띠 오른쪽** — 띠는 출처 이름(두세 글자)만 들어 오른쪽이 비어 있었다(줄 폭 약 300px). 칩 줄을 이름 아래 새 줄로 두면 칸 줄이 한 줄(약 20px) 늘어 같은 날 고정한 높이가 커진다.
- **능력치 칩은 계수 0 도 찍는다** — 설명창 규칙 그대로다(ADR-0118 — 스킬을 미는 축이다). 지금 숫자를 실제로 바꾸는 능력치는 바로 아래 계산 줄(ADR-1338)이 말한다.
- 거른 안 — **이름 아래 칩 줄**: 높이가 는다. **이름 줄에 능력치 칩만**: 이름 줄은 필요 무기 칩이 있어 영어 이름이 더 잘린다.
