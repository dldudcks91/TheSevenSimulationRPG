## 결정

시작 파티 고르기의 **[리롤]을 누르면 새 후보 카드 세 장이 왼쪽부터 차례로 떠오른다** — 장마다 투명 → 보임 · 조금 아래에서 제자리로(0.18초) · 장 사이 0.06초라 세 장이 다 서는 데 0.3초다. **도중에 다시 누르면 곧장 다음 판이 처음부터 떠오른다** — 연출이 버튼을 막지 않는다. 리롤 말고 같은 화면을 다시 그리는 일(덮어쓰기 두 번 누르기 · 그림 받기 등)에는 안 돈다.

## 맥락

리롤은 효과 없이 카드가 그 자리에서 바뀌었다 — 연달아 누르면 바뀐 것을 놓치기 쉬웠다. 사용자가 리롤 효과를 물어 다섯 갈래를 비교했다.

## 근거

| 안 | 쓰는 예 | 왜 아닌가 / 왜 골랐나 |
|---|---|---|
| **차례로 등장 (고름)** | TFT 상점 · 하스스톤 전장 | 새로 굴렸다는 것이 한눈에 읽히고, 투명도 · 위치만 움직여 버벅임이 없다 · 그래픽을 줄인 결에 맞는다 |
| 뒤집기 | 카드 드래프트류 | 한 장이 반 바퀴 도는 동안 카드가 안 읽혀 연달아 누를 때 길다 |
| 빠지고 들어오기 | 오토배틀러 상점 | 나가는 쪽 연출만큼 다음 카드가 늦게 선다 |
| 좋은 등급만 번쩍 | 가챠 | 시작 후보의 등급 차이를 연출로 키우는 것은 따로 정할 일이다 |
| 효과 없음 | 림월드 | 그때의 모습 — 바뀐 것을 놓친다 |

- **짧아야 한다** — 리롤은 수십 번 연달아 누르는 버튼이라 0.3초 안팎이 한계다
- **막지 않는다** — 연출 동안 버튼이 잠기면 가장 짜증 나는 자리가 된다. 화면은 통째로 다시 그려지므로 다시 누르면 새 카드가 새로 떠오를 뿐 겹치지 않는다

## 파급

- `app.js:renderStart` — 리롤이 한 번 쓰는 깃발(`state.ngRollAnim`)을 켜고 그리기가 끈다 · 카드에 `ng-in` + 장 순서 `--i`
- `style.css` — `.ng-row > .ng-card.ng-in` 의 `ng-in` 키프레임 · 움직임 줄이기 설정이면 안 돈다
- 선술집 명단의 무료 교체는 이 결정 밖이다(그대로)
