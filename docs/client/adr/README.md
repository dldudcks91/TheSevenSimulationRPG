# 화면 결정 기록 (ADR)

> **결정 하나 = 파일 하나. 한 번 쓰면 고치지 않는다.**
> 여기 있는 것은 **왜 그렇게 정했나**다. **지금 화면이 무엇인가**는 [SCREEN_DESIGN.md](../SCREEN_DESIGN.md) 가 든다.

---

## 왜 갈랐나

[SCREEN_DESIGN.md](../SCREEN_DESIGN.md) 는 규격과 근거가 한 몸이었다. 2026-09-09 실측:

| 갈래 | 크기 | 비중 |
|---|---|---|
| 표 — 「보여준다 / 결정 / 규칙」 | 50.6KB | 26% |
| 산문 — 왜 그렇게 정했나 | 146.1KB | 74% |
| └ 그중 이력성 문장(취소선 · 폐기 · 개정 · 옛 · 종전) | 75.6KB | **본문의 38%** |

문서가 부푸는 메커니즘은 크기가 아니라 **폐기된 결정을 본문에서 안 내보내는 것**이었다 — 규칙이 뒤집히면 새 문장을 쓰면서 옛 문장에 취소선을 그어 **그 자리에** 남겼다. 그래서 한 절 안에서 표는 갱신되고 아래 불릿은 안 갱신되는 사고가 났다 (2026-09-09 전수 대조 — §6 착용 칸 · §2 탭 수 · §5 초상 장수).

바깥의 관행 셋이 같은 답을 낸다:

| | |
|---|---|
| **화면설계서**(국내 기획 표준) | 문서 이력은 **앞부분 별도 구획**이다 — 본문에 섞지 않는다 |
| **Diátaxis** | Reference 는 「Describe and only describe」 — 근거는 **링크**하고 섞지 마라. 「Mixing types is the most common cause of confusing documentation」 |
| **ADR / SDD** | 「The SDD records the design; the ADR records the decision and its rationale. **Do not copy the whole SDD into an ADR**」 |

## 분업

| 문서 | 무엇을 든다 | 고쳐지나 |
|---|---|---|
| [SCREEN_DESIGN.md](../SCREEN_DESIGN.md) | **지금** 화면이 무엇을 보여주고 어떤 결정을 받는가 | **계속 고친다.** 현재 상태만 적는다 |
| `adr/NNNN-*.md` (여기) | 그 규격이 **왜** 그 모양인가 | **안 고친다.** 뒤집히면 새 파일이 대체한다 |
| [SCREEN_CHANGELOG.md](../SCREEN_CHANGELOG.md) | 언제 무엇이 바뀌었나 | 최신을 앞에 한 줄씩 더한다 |

두 방향의 금지가 이 분업을 지탱한다:

- **규격은 폐기된 것을 안 적는다** — 「~~옛 규칙~~ → 개정」 문장이 SCREEN_DESIGN 에 남지 않는다. 그 자리는 **ADR 링크 한 줄**이다
- **근거는 현재 상태를 주장하지 않는다** — ADR 은 쓰인 날의 사실만 말한다. 「지금 4종이다」를 쓰면 그날로 낡는다. 개수·목록처럼 **코드가 SSOT** 인 값은 적지 말고 **가리킨다**(`mock.js:SKILL_ICON_FILES`)

## 무엇이 ADR 이 되나

**된다** — 뒤집을 수 있었던 선택. 나중에 「왜 이렇게 했지」가 나올 것.

- 배치·구조의 갈림 (관전 아레나 상하 대치 · 연구 탭을 세그먼트로 안 가른 것)
- 폐기 (출정 아웃 · 관전 카드 위칸 · 영웅의 죄종 색)
- 의도된 예외 (미착수 탭이 안내 문구를 다는 것 · 프롤로그 본문이 한국어뿐인 것)

**안 된다** — 규격 그 자체이거나 다른 문서의 소관.

| | 어디로 |
|---|---|
| 「빈 칸은 파선 네모」 같은 표기 규칙 | SCREEN_DESIGN 의 표 |
| 폭 · 배율 · px · 화면비 | [src/ui/README.md](../../../src/ui/README.md) 가 SSOT |
| 버그 수정 · 진척 | [DEV_PLAN.md](../DEV_PLAN.md) |
| 함수 계약 · 세이브 스키마 | [INTERFACE.md](../INTERFACE.md) |

## 규칙

1. **번호는 네 자리.** 한 번 쓰면 재사용하지 않는다 — 철회돼도 번호는 비우지 않는다
2. **파일명은 `NNNN-무엇을-정했나.md`** — 한국어, 짧게
3. **상태는 셋** — `확정` / `대체됨` / `철회`
4. **뒤집힐 때 옛 파일을 고치지 않는다.** 머리 표의 `대체됨` 칸에 새 번호를 적는 것 **하나만** 예외다. 본문은 그날 쓴 그대로 둔다
5. **SCREEN_DESIGN 의 해당 절에서 링크한다** — 규격에서 근거로 가는 길이 없으면 ADR 은 안 읽힌다
6. 새 ADR 은 [0000-template.md](0000-template.md) 를 복사해 쓴다
7. **인덱스는 손으로 고치지 않는다** — 아래 표의 값은 전부 각 ADR 머리표가 이미 들고 있는 것이라, 옮겨 적으면 반드시 한쪽만 낡는다. ADR 을 쓰거나 「대체됨」을 채운 뒤 `python docs/client/adr/_build_index.py` 를 돌려 다시 만든다 (2026-09-09 — ADR-0052 가 생긴 지 한 시간 만에 손으로 쓴 인덱스가 그것을 놓쳤다. 규격에서 걷어낸 중복을 인덱스가 다시 들여온 꼴이었다)
