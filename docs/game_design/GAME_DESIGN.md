## 1. 게임 정의

> **"디아블로식 아이템 게임을, 경영 시뮬레이션처럼 운영한다"**

7대 죄악 테마의 **Lootun형 방치 파밍 RPG**.
파티를 편성해 자동전투 원정을 보내고, 루팅 리포트를 확인하고, 빌드(스킬/장비)를 재구성한다.
그래픽은 최소화 — 텍스트/UI 중심. 조작이 아니라 **빌드·편성·배분 의사결정**이 게임의 본체.

- **장르**: 방치형 파밍 RPG + 로스터 운영
- **참고작**: Lootun(게임 형태·거점 경제), Diablo 2(스킬트리·아이템 철학·MF 문화), Melvor Idle(방치 숙련 — 지류 한정)
- **계보**: TheSevenRPG(아이템·몬스터·스토리 계승) + TheSevenSimulation(영웅 프레임 계승)

### 중심 선언 (핵심 합의)

**게임의 심장은 "템 떴다"(RPG 파밍)이고, 시뮬레이션은 그 심장에 피를 공급하는 혈관이다.**

| 게임의 층 | 문법 | 비중 |
|---|---|---|
| 아이템 / 전투 / 빌드 / 파밍 루프 | **완전 RPG (디아블로 언어)** — 접사, 희귀도, 세트, 유니크, 스킬트리 | **본편** |
| 거점 / 파견 / 운영 | 시뮬레이션 감각 — 재료 경제, 죄종 파견 적성, 리포트 서사 | 지류 (상한 있음) |

- 비전투 활동(채집 등)은 "콘텐츠"가 아니라 **"파이프"** — 파밍 루프에 재료를 공급하는 보급선. 유형을 늘리거나 티어 사다리를 깔지 않는다
- 유저가 "파견이 본편"이라고 느끼는 순간 = 잘못된 신호
- 사기·관계·폭주 시스템은 **미탑재** — 방치형의 계약("자리 비워도 안전")을 지킨다. 시뮬 느낌은 파견 리포트의 사건 텍스트로 전달

## 2. 타겟 유저 니즈 (설계 검증 기준)

그래픽 없이 장비·파티를 맞추는 게임(Lootun/D2 계열) 유저의 니즈. 모든 시스템 결정은 이 5개로 검증한다.

1. **드롭의 유의미함** — 접사 풀 희석 금지. 떨어지는 아이템이 내 빌드에 쓸모 있을 가능성이 항상 있어야 함
2. **숫자로 읽히는 최적화** — 장비/스킬 변경의 효과가 명확한 수치로 보여야 함
3. **병렬 가동의 만족감** — 모든 영웅이 항상 뭔가를 하고 있어야 함 (전투팀 원정 + 벤치 파견)
4. **긴 체이스** — 유니크/세트 완성이라는 장기 목표
5. **순환 구조** — 비전투 활동도 결국 전투 파밍을 가속해야 함 (재료→제작→장비→더 깊은 파밍)

## 3. 코어 루프

```
              ┌──────────── 전투 루프 (본편) ────────────┐
              │  파티 편성 → 자동전투 원정 → 루팅 리포트  │
              │      ↑                          │        │
              │      └─ 빌드 재구성(스킬/장비) ←─┘        │
              └──────────────────────────────────────────┘
                     ↑ 장비                    │ 잉여 장비·재료·낙인
              ┌──────┴──────── 운영 루프 (지류) ─┴────────┐
              │  거점: 분해 → 재료 → 건물/제작(낙인 크래프팅) │
              │  파견: 벤치 영웅 → 채집 등 → 재료 수급     │
              └──────────────────────────────────────────┘
```

- **거점은 플레이어의 경제 공장** (Lootun 모델) — 분해/제작/건물 업그레이드는 영웅 능력치 판정 없음, 플레이어가 굴린다
- **파견만 영웅이 관여** — 판정은 죄종 궁합 + 파견 숙련 (전투 스탯 무관)
- 두 루프는 병렬 가동. 비전투는 파밍 루프의 지류 (니즈 5)

## 4. 영웅

### 4-1. 획득 — 영웅도 굴림의 대상

- **선술집 영입 / 탐색 발견** (TheSevenSimulation 계승)
- 영웅은 등장 시 **죄종(7택1) + 직업 + 시작특성**을 랜덤 조합으로 갖고 나타남
- → 선술집 리롤 = 아이템 파밍의 영웅판. "뽑기"(태어나는 조합)와 "육성"(포인트 배분)의 분리
- 로스터는 **소수 정예** (파티 1~2개 + 벤치 규모, 상한: balance.csv 예정) — 영웅마다 빌드를 만지는 게임이므로 대군 로스터 금지

### 4-2. 정체성 3요소

```
영웅 = 죄종(7택1) + 직업(3택1) + 시작특성(1개)   ← 등장 시 굴려짐, 영구 불변
```

**직업 3종 확정 (2026-08-21)**: **전사**(물리 딜러) / **기사**(탱커·수호) / **마법사**(마법 딜러). 무기군 배정·전직 정체는 미정 — hero_design.md 참조.

| 축 | 담당 | 담당하지 않는 것 |
|---|---|---|
| **죄종** | 스킬 탭1 + 아이템 궁합(죄종 접사/세트) + 파견 적성 + 리포트 성격 | 직업/무기 (분리됨) |
| **직업** | 스킬 탭2(마스터리)·탭3(전직) + 무기군 + 전투 역할 | 아이템 죄종 축, 파견 |
| **시작특성** | 소소한 다축 보정(전투/파견/유틸) + 리포트 사건 변주 | 핵심 파워 (양념) |

> TheSevenSimulation의 "이름 1:1 고정"은 폐기 — 죄종×직업×특성이 자유 조합되므로 이름은 별도 풀에서 부여 (처리 방식 미정).

### 4-3. 기본 스탯 7개 (Simulation 계승 + 전투 역할 배정)

| 스탯 | 담당 |
|---|---|
| 힘 | 물리 데미지, 중갑/힘 무기 요구치 |
| 민첩 | 공속/회피, 원거리·경무기 요구치 |
| 지능 | 마법 데미지, 지팡이 요구치 |
| 건강 | HP/회복 |
| 감각 | 치명타/명중 |
| 통솔 | 파티 시너지 (리더 지정 시 통솔 비례 파티 버프 — 세부 미정) |
| 매력 | **비전투 전용** — 고용 비용 할인, 상점 가격, 파견 보너스 |

- **밸런스 규칙**: 감각/통솔처럼 장비 접사와 출처가 겹치는 축은 **스탯 기여 소, 장비 기여 대** — 파워의 원천은 장비 (장비가 주인공)
- **수동 스탯 분배 없음** — 자동 성장 (D2의 교훈: 스탯 찍기는 정답이 정해진 가짜 선택)
- 히든 파라미터 계승: 스탯별 성장률·상한선 (같은 조합 영웅도 개체차)

### 4-4. 스킬 — 독립 트리 3탭 (D2 방식)

```
[분노][마법사] 영웅의 스킬 탭:
├── 탭1: 분노 트리          (죄종에서 옴 — 모든 분노 영웅 공유)
├── 탭2: 마법사 마스터리 트리 (직업에서 옴 — 무기 숙련 등 기초 골격)
└── 탭3: 마법사 전직 트리    (직업 심화 — 레벨 해금)
```

- **포인트 풀 공유, 배분 완전 자유** — 3택1 같은 선택 없음. 같은 [분노][마법사]라도 어디에 몰았느냐로 다른 영웅이 됨. **개성은 "선택"이 아니라 "배분"에서 나온다**
- **전직 탭은 레벨 해금**: `[balance.csv:advance_unlock_level]` (방치형 마일스톤 — "전직까지 N레벨"이 접속 동기)
- 트리 콘텐츠 수 = **죄종 7 + 마스터리 N + 전직 N = 7 + 2N** (덧셈 구조 — 직업 추가 비용이 선형)
- 탭1(죄종 트리)에는 죄종 접사/세트와 시너지 나는 노드 배치 (예: "분노 세트포인트당 치명타 보정") — 스킬과 아이템 축의 연결고리

### 4-5. 성장

- 레벨 + XP (전투 원정) — 레벨업 시 스킬 포인트 지급 + 스탯 자동 성장
- **파견 숙련**: 파견 유형별 독립 숙련 — 하면서 자람 (Melvor 방식, 벤치 영웅의 성장 축)

## 5. 아이템 (TheSevenRPG 계승)

### 5-1. 계승하는 것

| 시스템 | 내용 |
|---|---|
| **접사 매트릭스** | 7죄종 × 슬롯별 접사 (prefix/suffix), 지역 죄종 드롭 편향으로 타겟 파밍 |
| **희귀도 = 통제 가능성의 계단** | 매직(완전 RNG) → 레어 → 크래프트(낙인으로 죄종 지정) → 유니크(고정 효과) |
| **세트포인트** | 접사 1개 = 죄종 1포인트, 브레이크포인트 2/4/6. 폭식 역세트·오만 올오어낫씽 등 죄종 성격의 메커니즘 번역 유지 |
| **무기군 Implicit** | 수치가 아니라 전투 규칙을 바꾸는 무기군 고유 효과 (마스터리 탭의 무기 숙련과 연결) |
| **낙인(stigma)** | 보스 드롭 재료로 크래프팅 시 접사 죄종 선택 — "통제권에 대한 프리미엄" |
| **베이스 고정 철학** | 성장은 레벨업이 아니라 **더 좋은 굴림의 재파밍** |

### 5-2. 유틸리티 접사 (Lootun/D2 계승 — 신규 축)

- 드랍률 / 골드 획득 / 파견 시간 단축 등 (Lootun의 Luck·Fortune·Wealth·Fate, D2의 MF 계보)
- "전투력 vs 파밍 효율" 스왑 결정을 만드는 것이 목적
- **시뮬레이션형 행동 보정(채집 효율 등)은 일반 접사 풀에 넣지 않는다** — 접사 풀 희석 방지 (니즈 1)

### 5-3. 폐기/변경

- **코스트(장비 용량) 폐지** — 유니크 희소성은 드롭률이, 트레이드오프는 "고정 효과 대신 접사 없음 → 세트포인트 0"이 대체. 착용 제약은 요구 스탯/레벨 게이트만
- 영웅은 파생 전투 수치(공격력/치명타 등)를 직접 보유하지 않음 — 스탯은 원천(§4-3), 파워는 장비+스킬

## 6. 죄종 — 하나의 축, 네 개의 직업

7대 죄악이 게임 전 층을 관통하는 단일 축. 축은 하나, 일은 넷:

| 층 | 죄종의 역할 | 출처 |
|---|---|---|

## 7. 거점 · 파견

- **거점 (플레이어 경제, Lootun 모델)**: 분해(잉여 장비→재료) / 제작·강화(낙인 크래프팅 포함) / 건물 건설·업그레이드(기능 해금). 영웅 스탯 판정 없음
- **파견 (벤치 영웅의 일)**: 채집 등 소수 유형. 판정 = 죄종 궁합 + 파견 숙련 + 유틸 옵션. 배치 후 방치, 관리 요구 없음
- **파견 리포트**: 결과 수치 + 죄종/특성이 만드는 사건 텍스트 — 사건은 리포트 안에서 완결, 로스터 파괴 없음

### 방치형 계약 (불변 원칙)

1. **자리 비워도 안전** — 오프라인/방치 중 로스터가 파괴되는 사건은 발생하지 않는다
2. 오프라인 진행 지원 (범위 미정)
3. 모든 사건은 리포트로 읽는다 — 실시간 개입 요구 금지

## 8. 기술 방향

**2단계 전략 확정 (2026-08-21)** — 상세 규칙은 [CLAUDE.md](../../CLAUDE.md) 기술 스택 참조.

| | Phase 1 (현재) | Phase 2 (추후) |
|---|---|---|
| 목적 | 코어 루프 검증 — 버릴 각오로 빠르게 | 스팀 출시 |
| 방식 | **무빌드 웹** — index.html + ES Modules + 순수 DOM/CSS | Godot 또는 Unity (엔진·시점 미확정) |
| 이유 | 그래픽 최소화 선언(§1)으로 엔진 강점을 안 씀. 텍스트/표/툴팁 UI는 DOM이 유리, F5 반복이 가장 빠름 | 네이티브 빌드·스팀 SDK. 기획 검증 후 판단 |

- 서버 없음 — 싱글플레이어. 이식 시 서버 마이그레이션 부담 없음
- 데이터: CSV(SSOT) — **엔진 이식 시에도 그대로 사용**, 변환 금지
- 이식 대상은 `game_logic/` + CSV뿐. **UI는 재작성 전제** (기획 확정 후 어차피 다시 짬)

> **참고작 조사 결과 (2026-08-21)**: Melvor Idle = JS+HTML/CSS, 스팀은 NW.js 래핑. Lootun = **Unity**(브라우저판은 WebGL 빌드), 에셋스토어 스프라이트 구매 사용.
> 두 대표작이 정반대 답 → **장르가 정답을 정해주지 않는다.** Lootun이 엔진 값을 한 이유는 스프라이트가 있었기 때문이므로, 본작이 §1의 "그래픽 최소화"를 유지하는 한 Phase 1은 웹이 유리.
> **뒤집히는 조건 (2026-08-21 정정)**: 처음엔 "전투 스프라이트를 넣으면"이라고 적었으나 과장이었다.
> 스프라이트 시트 애니메이션·유닛 이동·생성/삭제·데미지 숫자 정도는 DOM으로 충분하다 (동시 엘리먼트 수십 개 수준).
> 실제로 뒤집히는 조건은 **동시 애니메이션이 수백 개를 넘거나, 파티클·셰이더·블렌드 효과가 필요해질 때** —
> 그 전 단계로 **전투 화면만 `<canvas>` 하나로 빼는 선택지**가 있고, 그래도 나머지 UI는 DOM으로 남는다.
