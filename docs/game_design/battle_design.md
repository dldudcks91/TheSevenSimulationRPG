# 전투 설계

## 1. 전투의 형태

- 파티 `[balance.csv:party_size_max]`인 vs 적 1~`[balance.csv:wave_monster_max]`, 라운드 진행 (원정 = 스테이지 런 — base_expedition_design.md §1)
- **유저 조작 없음** — 편성·장비·스킬 배분이 입력의 전부
- 라운드 간 HP 자동 회복 없음 (부상/치료 모델은 base_expedition_design.md §1-1)

### 결정론적 시뮬레이션 (기술 원칙)

**같은 시드 + 같은 입력 = 같은 결과.** 관전으로 본 전투와 오프라인 즉시 계산이 반드시 일치한다.

- 관전 화면은 시뮬레이션의 **재생**일 뿐 — 배속은 재생 속도만 바꾼다
- CLAUDE.md 이식성 규칙(난수 주입)과 직결 — Phase 2 엔진 이식의 검증 수단

## 2. 행동 주기 — 단일 시계

**모든 유닛(영웅·몬스터)은 행동 주기 하나만 갖는다.** 물리/마법 구분 없음 — 마법사의 "시전 간격"도 같은 변수다.

- 출처: **무기군 기본 속도** 바탕 + 장비 공속 옵션 + 민첩 계수
- 근거: 직업마다 시계가 다르면 로직에 직업 분기가 생기고, 지팡이 Implicit이 성립하지 않는다
- 몬스터도 `monster.csv:action_period`(초)로 같은 축을 쓴다
- **피격 경직 없음** [확정 2026-08-25] — 맞아도 행동 주기가 밀리거나 끊기지 않는다. 시계를 방해하는 것은 **상태이상**(스턴·빙결 등)뿐이고, 그 대응 축은 `combat_stat.csv:fhr`(상태이상 회복 속도) 하나다
  - 근거: 경직은 "맞을수록 못 때린다"는 이중 처벌이라 방치형의 통제성(인과 읽기)을 해친다. 행동을 막는 규칙을 상태이상 한 곳으로 모으면 카운터도 한 곳으로 모인다

### 2-1. 공격 타입 — 물리 / 원소 4종

한 번의 공격이 상대의 어느 방어를 상대하는지 정하는 **플래그** (축·게이지·주기 아님).

```
attack_type = physical | fire | cold | lightning | poison
```

- **`magic` 은 값이 아니다** [확정 2026-08-26] — 마법 공격은 반드시 원소 하나를 갖는다. physical → 물리 방어 · 원소 → 그 원소의 저항 (마법 방어는 08-25 폐지)
- **몬스터**: `monster.csv:attack_type` — 배정 규칙은 monster_design.md §2
- **영웅**: 무기군이 물리/마법을 정하고(`weapon_group.csv:attack_type`), 마법이면 **무기 개체가 원소를 든다**. 스킬은 자기 원소 태그를 갖고, 없으면 무기 원소를 따른다 — §9-5
- 원소는 죄종과 **다른 축**이다 (7 ≠ 4). 두 축을 잇지 않는다 — §9-5

## 3. 발동 규칙

행동 주기가 도래하면 다음 순서로 **하나**를 실행한다.

```
1. 준비된 액티브 스킬 중 가장 오래 기다린 것
2. 동시에 준비됐으면 슬롯 순서가 앞선 것
3. 준비된 것이 없으면 기본 공격
```

- **한 차례에 하나.** 스킬은 그 차례의 공격을 **대체**한다 — 버프·힐도 예외 없음
- **마나 없음 — 행동 1회가 스킬의 유일한 비용**
- 1차 기준이 "가장 오래 기다린 것"인 이유: 슬롯 순서만 쓰면 쿨 짧은 스킬이 영구 독점한다. 슬롯 순서는 동률 결정자로 남아 플레이어 통제를 유지
- 동시 발동 불채택 이유: 비용 축이 사라진다 — 쿨감이 딜 배율화되고, 버프·힐이 공짜가 되어 사제 서약이 깨진다. 순차는 행동 주기가 **구조적 천장**이라 콘텐츠 추가에 안 깨진다

## 4. 기본 공격

- **무기군이 결정한다** — 무기군 Implicit과 같은 출처 (예: 창=선제타). 계승의 **둔기=경직은 경직 폐지(§2)로 무효** — 둔기 차별화는 다시 짠다
- 마법사의 기본 공격 = 지팡이의 기본 마법 공격
- 액티브가 준비되지 않은 차례를 메운다 — 빈 턴 없음

## 5. 액티브 슬롯

- **3개 — 출처 고정**: 죄종 트리 / 전직 트리 / **착용 무기군** (skill_design.md §3). 배분(트리)과 편성(슬롯)의 분리는 유지 — 편성 = 각 출처에서 어느 것을 + 어떤 순서로
- 슬롯 순서 = 동시 준비 시 우선순위. **순서 변경 무료** (리스펙 압력 완화)
- 슬롯은 선택지가 아니라 **상한** — 무제한이면 다 넣는 게 정답이라 밸런싱 불가

## 6. 쿨타임

- **실시간(초)으로 돈다** — 공속을 올려도 스킬 빈도는 늘지 않는다 (공속 이중 스케일링 차단)
- 쿨이 끝나도 다음 행동 주기까지 대기:

```
실효 쿨 = ceil(표기 쿨 ÷ 행동 주기) × 행동 주기   (+ 충돌 시 밀린 만큼)
```

- 쿨이 행동 주기의 정수배일 때 손실 0 → **정렬 최적화** 발생 (D2 공속 브레이크포인트 계보). 손잡이는 장비의 쿨감 옵션
- **UI에 실효 쿨 표시 필수** — 안 보이면 재미가 아니라 함정
- 쿨 하한 지침: `행동 주기 × 슬롯 수` 근처 — 그보다 짧으면 표기 쿨이 거짓말이 된다

## 7. 버프·힐

- **행동 1회를 소모한다** — 딜 포기가 비용. 예외 없음
- 버프는 지속시간으로 콤보를 만든다 — 최적화 대상은 "버프 지속 안에 공격 스킬을 몇 번 넣나" (버프 쿨 · 지속 · 공격 쿨 · 행동 주기의 정렬)
- 짧은 전투에서는 손해일 수 있어 판단이 생긴다 — 버프는 손해가 아니라 투자

## 8. 전투 능력치 — SSOT: `combat_stat.csv` (24종)

영웅은 이 수치들을 직접 보유하지 않는다 — 전투 진입 시 합산한다.

```
전투 능력치 = ( 장비(베이스+Implicit+접사) + 스킬(노드+고유 패시브) ) × 기본 능력치 계수
기본 능력치 계수 = 1 + (능력치 × [balance.csv:attr_bonus_per_point])
```

- **곱셈이라 장비가 0이면 능력치도 0을 곱한다** — "장비가 주인공"의 수치적 표현
- 행동 주기만 방향이 반대(낮을수록 빠름) — 계수로 나눈다
- 역방향(장비 → 기본 능력치)은 없다 — `[balance.csv:attr_equip_bonus]` = 0
- 계수가 붙는 것은 24종 중 **6종**뿐 — 물리 공격력(힘) · 마법 공격력(지능) · 명중·회피(감각) · 행동 주기(민첩) · 상태이상 회복 속도(건강). 나머지는 장비·스킬 전담

| 카테고리 | 수치 (**굵은 것 = 계수 있음**) | 비고 |
|---|---|---|
| offense | **물리 공격력**(힘) · **마법 공격력**(지능) · **명중**(감각) · 치명타 확률 · 치명타 피해 · 방어 무시 · 타입 특효 · 사이즈 특효 | 치명타는 계수 없음. 상태이상 적중은 08-25 삭제 |
| defense | 최대 HP · 물리 방어 · **원소 저항 4종**(전기·불·냉기·독) · **회피**(감각) · 피해 감소 · 반사 피해 | 마법 방어 → 원소 저항 4종으로 대체 (08-25) |
| sustain | 흡혈 · HP 재생 | 라운드 간 회복이 없어 **런 깊이를 결정** |
| tempo | **행동 주기**(민첩) · **상태이상 회복 속도**(건강) · 쿨타임 감소 | 건강 = 상태이상을 털어내는 축 (08-25 재배정) |
| utility | 드랍률 · 골드 획득 | **전투 계산 밖** — 전투력 vs 파밍 효율 스왑 축. 파견 시간 단축은 08-25 삭제 |

- **최대 HP 시작값은 전 영웅 공통** `[balance.csv:hero_hp_base]` — 능력치와 무관, 레벨·장비로만 성장. 몬스터 수치 절대 앵커링의 기준점
- 전투 능력치는 계산 결과이므로 **세이브에 저장하지 않는다**
- **회복량은 스탯이 아니다** — 회복 스킬의 회복량은 **마법 공격력에 비례**한다 (08-25). 사제의 파워 출처 = 마법 공격력 = 지능
- **파티 보정은 스탯이 아니라 스킬 효과** · 스킬 레벨 가산 옵션 없음 (08-25)
- **상태이상은 저항이 아니라 회복으로 상대한다** [08-25] — 확률로 막는 스탯(저항)은 없다. 걸리는 것은 확정이고, `fhr`(상태이상 회복 속도)로 **얼마나 빨리 털어내는가**만 겨룬다. 막느냐 못 막느냐의 이진 도박 대신 연속량이 되어 장비 투자량이 그대로 체감된다

### 몬스터는 부분집합만 갖는다

| | 보유 | 출처 |
|---|---|---|
| 상시 | HP · 공격력 · 물리 방어 · 원소 저항 · 행동 주기 | `monster.csv` 소재값 × `spawn_grade.csv` 배율 × 전역 스케일. 저항은 `resist` 단일 컬럼 = **4원소 공통** (원소별 차등은 후속 — §9-9) |
| 정예만 | 회피 · 명중 · 치명 · 반사 · 재생 · 흡혈 등 | `elite_trait.csv` — 런타임에 얹힌다 |
| 없음 | 유틸 | 플레이어 전용 축 |

비대칭이 정상이다 — 정예가 "평소엔 없는 수치를 얻는" 구조라서 정예 특성이 수치 강화가 아니라 **규칙 변화**로 읽힌다.

## 9. 피해 계산 — 직격 1회 [2026-08-26 초안 · 확정 대기]

> 구현: `game_logic/formula.js` (순수 함수 — 엔진 이식 대조 검증의 핵) · 계수는 전부 `balance.csv` ⚠제안 키 · 검증: `dev/test.html` 단정 + 캘리브레이션 표

한 번의 직격은 **명중 대결 → 타격 피해 → 감쇠** 세 단계다. 곱셈뿐이라 **항의 순서가 없다** — 전투 로그와 툴팁에 한 줄의 곱으로 보여줄 수 있고, 어느 항을 올려도 결과가 그 비율만큼 움직인다 (인과 읽기).

### 9-1. 공격력 — 시트에 찍히는 값

```
공격력 = ( 무기 공격력 + Σ 공격력 flat ) × ( 1 + Σ 공격력 % ) × 능력치 계수
```

- **무기 공격력은 밑수가 아니라 항 하나다** — 장갑·반지·목걸이의 flat 접사와 스킬 노드가 같은 괄호에 더해진다. "운 좋게 먹은 무기 하나"가 피해 전체를 곱하지 않는다 (skill_design.md §3 무기 지배력 손잡이)
- 능력치 계수 = 무기군 공격 타입이 physical 이면 힘, magic 이면 지능 (§8). 괄호 전체에 곱한다 — 장비가 0이면 능력치도 0
- 몬스터: `monster.csv:attack` × 등급 배율 × `[balance.csv:monster_atk_scale]` 이 곧 공격력 (능력치 계수 없음)

### 9-2. 타격 피해 — 직격 한 번의 굴림

```
타격 피해 = 공격력 × 편차 × 스킬 배율 × ( 1 + Σ 조건부 % ) × 치명 배율
```

| 항 | 출처 | 규칙 |
|---|---|---|
| 편차 | 무기군 `weapon_group.csv:variance_pct` (없으면 `[balance.csv:dmg_variance_pct]`) | ± 균등 분포. 무기군 3축(편차 · 행동 주기 · 한손/양손)의 하나 — hero_design.md §2 |
| 스킬 배율 | 스킬 정의 (기본 공격 = 1) | 스킬 세기 = 배분 + 전투 능력치 — 무기 개체는 여기 없다 (skill_design.md §3) |
| 조건부 % | 타입 특효(대상 타입 일치) · 사이즈 특효 · 도감 보정 · 버프 | **전부 덧셈** — 한 괄호에 합산 |
| 치명 배율 | 치명 확률(상한 `[balance.csv:crit_cap_pct]`) 굴림 성공 시 치명타 피해 % | 능력치 계수 없음 (§8) |

- **덧셈 공격** — 공격력의 `Σ%` 도, 조건부 `Σ%` 도 각 괄호 안에서는 덧셈이다. 곱셈 층은 편차 · 스킬 · 치명 셋뿐. 접사를 겹칠수록 선형으로 커지고 폭발하지 않는다 (lootun_reference.md §5-2 · dragoncliff_reference.md 검토 #5)
- 회복 스킬 = 마법 공격력 × 스킬 배율 — 08-25 "회복량 스탯 삭제"의 자리가 여기다
- 편차가 무기군 속성인 이유 — 둔기·도끼(큰 편차)와 창·완드(작은 편차)가 같은 평균으로도 다른 무기가 된다. 몬스터·맨손은 전역 기본값

### 9-3. 감쇠 — 곱셈 방어

```
K         = [balance.csv:def_curve_k] × 공격자 레벨        영웅 = 레벨 · 몬스터 = 스테이지 `dlvl`
감쇠율    = D ÷ ( D + K )                                  D = 물리 → 방어 / 원소 → 해당 원소 저항 (소재값)
최종 피해 = max( [balance.csv:dmg_min] , 타격 피해 × ( 1 − 감쇠율 ) × ( 1 − 피해 감소 % ) )
```

- physical → `defense` · 원소 → `res_<원소>` — 영웅은 해당 원소 저항 + 전 원소 공통 저항의 합, 몬스터는 `monster.csv:resist` 단일 소재값 × 등급 배율 × `[balance.csv:monster_def_scale]`
- **K 는 공격자 레벨에 비례한다** — `def_curve_k` 의 뜻은 "**레벨 1당 감쇠 50% 에 필요한 방어값**"이다 (D = K 일 때 정확히 50%). 고정 K 면 방어 소재값이 챕터마다 커지는 만큼 감쇠가 100% 로 수렴해 후반에 방어 1점이 무의미해진다 — 레벨로 나눠 **감쇠율을 챕터 전체에서 같은 대역에 붙든다**. 방어 접사의 체감이 1챕터와 7챕터에서 같아야 "장비가 주인공"이 끝까지 성립한다
- **방어 무시**(`def_ignore`)는 변환 **전** D 를 비율로 깎는다 — "방어 n% 무시"는 감쇠율의 n% 가 아니라 소재값의 n% 다. 같은 곡선 위라 인과가 한 줄
- **피해 감소**(`damage_reduction` — 타입·사이즈 조건부 `vs_*_dr`)는 원래 % 라 변환 없이 별도 곱
- 곡선의 성질 — **면역 없음**(감쇠율이 1에 닿지 않는다) · **무의미 없음**(0 근처가 가장 가파르다) · 상한 규칙 불요. K 하나가 물리·원소 공통 — 원소 저항 4종을 따로 조율하지 않는다
- 몬스터 방어·저항의 전역 손잡이 `[balance.csv:monster_def_scale]` — `monster_hp_scale` / `monster_atk_scale` 과 같은 자리 (monster_design.md §5 "전역 배율 1번")

**감산(공격 − 방어) 불채택 이유** — 08-25 프로토타입 임시식이었다:

1. 공격·방어 두 곡선을 7챕터 내내 **동조**시켜야 한다. 벗어나면 한쪽은 면역(최소 피해 바닥), 다른 쪽은 무의미. 현재 소재값에 프로토타입 성장 계수를 그대로 얹으면 5챕터에서 영웅·몬스터 양쪽 다 바닥에 붙는다
2. 타격마다 빼므로 **다단타 · 고공속이 방어 앞에서 두 번 벌** 받는다 — 민첩·공속 접사의 가치가 상대 방어에 따라 뒤집혀 인과를 못 읽는다
3. 치명·편차가 감산 앞이면 방어 앞에서 비선형 증폭(치명이 "방어 뚫기"로 변질), 뒤면 표기 배율과 어긋난다. 곱셈 감쇠는 순서가 없어 둘 다 사라진다
4. 최소 피해 바닥이 밸런스 장치가 되고, 바닥에 붙은 전투가 제한시간 룰과 얽힌다

**직접 %(Lootun 식) 대신 소재값 곡선인 이유** — 방어·저항은 이미 소재값으로 존재한다(방어구 고유값 ilvl 비례 · `monster.csv` 소재값 · 계승 접사 `fixed`). % 로 바꾸면 면역 방지 상한이 따로 필요한데 곡선은 상한을 내장한다. 대신 화면에는 변환된 **감쇠율 %** 를 소재값과 나란히 보여준다 — 소재값만 보이면 "방어 +10 이 얼마인가"를 못 읽는다 (§6 실효 쿨 표시와 같은 원칙)

### 9-4. 명중 대결 — 타격 전 한 번

```
적중률 = clamp( 100 − 회피 + 명중 , [balance.csv:hit_floor_pct] , 100 )        단위: %p
```

- 명중·회피 모두 감각 계수 (§8). 몬스터의 기본 명중·회피는 **0** — 정예 특성(날랜 · 정확한)과 상태이상(매혹)만 값을 만든다 (§8 "몬스터는 부분집합만")
- 따라서 명중은 평소엔 놀고 **회피 · 매혹의 카운터**로 산다 — D2 AR 계보의 보험 스탯. 감각이 죽는 것은 아니다: 회피 쪽은 항상 걸린다
- 하한 `hit_floor_pct` 가 회피 상한을 겸한다 — "어떤 공격도 이만큼은 맞는다". 회피 몰빵 면역 차단. (프로토타입 `evasion_cap_pct` 퇴역)
- 빗나감도 행동을 소모한다 — 스킬도 빗나간다 (한 차례 하나, §3)

### 9-5. 원소 — 죄종과 독립인 축

- **원소 ≠ 죄종.** 죄종 7은 정체성(스킬 탭1 · 접사 카테고리 · 상태이상), 원소 4는 "마법 타격이 어느 저항을 상대하나"다. 7→4 를 억지로 접으면 죄종 셋이 원소를 잃거나 둘이 겹친다 — 두 축을 잇지 않는다. 물리 직업도 죄종은 있지만 원소는 없다
- **영웅** — 마법 무기군(스태프 · 완드) **개체**가 드롭 시 원소 하나를 굴린다 → 기본 공격의 원소. 액티브 스킬은 정의에 원소 태그를 갖고, 태그가 없으면 무기 원소를 따른다. "장비 결정이 곧 스킬 결정"의 연장 — 무기군이 슬롯을, 무기 개체가 원소를 정한다. 원소는 세기가 아니라 상대할 저항의 선택이라 개체 귀속 금지(skill_design.md §3)와 충돌하지 않는다
- **몬스터** — `monster.csv:attack_type` 값 확장: `physical` / `fire` / `cold` / `lightning` / `poison` (`magic` 퇴역 — 마법 공격은 반드시 원소 하나를 갖는다). 배정 규칙은 monster_design.md §2. 저항은 `resist` 단일 소재값(4원소 공통) — 원소별 차등 컬럼은 후속
- 물리의 대응 축은 하나(방어), 원소는 넷(저항)이다 — 원소 저항이 챕터·지역별로 "갈아 끼우는" 장비 결정을 만든다 (지역 드롭 편향과 같은 자리 · D2 저항 계보). 비대칭은 의도

### 9-6. 직격과 비직격 — 반사 · 도트 격리

| | 직격 | 비직격 |
|---|---|---|
| 무엇 | 행동 주기로 실행된 기본 공격 · 스킬 타격 | 반사 피해 · 도트(중독 등 상태이상 틱) · 사망 폭발 — "행동이 아닌 피해" |
| 명중 대결 | 한다 | 없음 |
| 편차 · 스킬 배율 · 조건부 % · 치명 | 받는다 | **받지 않는다** |
| 감쇠 | 받는다 | 반사: **없음**(이미 감쇠된 최종 피해의 비율) · 도트: **부여 시 한 번**(원소 저항) 확정 후 틱 고정 |
| 유발하는 것 | 흡혈 · 반사 · 타격 발동 효과 | **아무것도 유발하지 않는다** |

- 반사 = 받은 최종 피해 × 반사 % → 공격자 HP 직접 차감. 반사는 반사를 부르지 않는다
- 흡혈은 직격의 **최종 피해**에만 비례한다
- 반격(정예 '보복의' · 나태 계열)은 **직격**이다 — 단, 반격은 반격을 유발하지 않는다 (연쇄 차단)
- 왜: 두 참고작이 독립적으로 같은 장치를 갖는다 — Lootun 은 Thorns 를 별도 축으로 격리, Dragon Cliff 는 Direct/Non-direct 게이트 (dragoncliff_reference.md §4-4 · 검토 후보 #2 ★). 나태=반격 / 폭식=흡수가 위험 구간이라 지금 세운다

### 9-8. 화면 요구 (후속)
