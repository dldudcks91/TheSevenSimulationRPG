# 전투 설계

> 상위: [GAME_DESIGN.md](GAME_DESIGN.md) §3 · SSOT: `combat_stat.csv` · `balance.csv` · `round_budget.csv`

## 1. 전투의 형태

- 파티 `[balance.csv:party_size_max]`인 vs 적 1~`[balance.csv:wave_monster_max]`, 라운드 진행 (원정 = 스테이지 런 — base_expedition_design.md §1)
- **유저 조작 없음** — 편성·장비·스킬 배분이 입력의 전부
- 라운드 간 HP 자동 회복 없음 (부상/치료 모델은 base_expedition_design.md §1-1)

### 결정론적 시뮬레이션 (기술 원칙)

**같은 시드 + 같은 입력 = 같은 결과.** 관전으로 본 전투와 오프라인 즉시 계산이 반드시 일치한다.

- 관전 화면은 시뮬레이션의 **재생**일 뿐 — 배속은 재생 속도만 바꾼다
- CLAUDE.md 이식성 규칙(난수 주입)과 직결 — Phase 2 엔진 이식의 검증 수단

## 2. 행동 주기 — 단일 시계

**모든 유닛(영웅·몬스터)은 행동 주기 하나만 갖는다.** 물리/마법 구분 없음 — 마법사의 "시전 간격"도 같은 변수다.

- 출처: **무기군 기본 속도** 바탕 + 장비 공속 옵션 + 민첩 계수
- 근거: 직업마다 시계가 다르면 로직에 직업 분기가 생기고, 지팡이 Implicit이 성립하지 않는다
- 몬스터도 `monster.csv:action_period`(초)로 같은 축을 쓴다
- **피격 경직 없음** [확정 2026-08-25] — 맞아도 행동 주기가 밀리거나 끊기지 않는다. 시계를 방해하는 것은 **상태이상**(스턴·빙결 등)뿐이고, 그 대응 축은 `combat_stat.csv:fhr`(상태이상 회복 속도) 하나다
  - 근거: 경직은 "맞을수록 못 때린다"는 이중 처벌이라 방치형의 통제성(인과 읽기)을 해친다. 행동을 막는 규칙을 상태이상 한 곳으로 모으면 카운터도 한 곳으로 모인다

### 2-1. 공격 타입 — 물리 / 마법

한 번의 공격이 상대의 어느 방어를 상대하는지 정하는 **플래그** (축·게이지·주기 아님).

- 몬스터: `monster.csv:attack_type` — 영웅: 무기군이 결정 (지팡이 = magic)
- physical → 물리 방어 · magic → **원소 저항 4종(전기 · 불 · 냉기 · 독)** 중 하나 — 마법 방어는 08-25 폐지. 공격이 어느 원소인지(몬스터 `attack_type` 확장 / 영웅 스킬·무기)는 **미정**

## 3. 발동 규칙

행동 주기가 도래하면 다음 순서로 **하나**를 실행한다.

```
1. 준비된 액티브 스킬 중 가장 오래 기다린 것
2. 동시에 준비됐으면 슬롯 순서가 앞선 것
3. 준비된 것이 없으면 기본 공격
```

- **한 차례에 하나.** 스킬은 그 차례의 공격을 **대체**한다 — 버프·힐도 예외 없음
- **마나 없음 — 행동 1회가 스킬의 유일한 비용**
- 1차 기준이 "가장 오래 기다린 것"인 이유: 슬롯 순서만 쓰면 쿨 짧은 스킬이 영구 독점한다. 슬롯 순서는 동률 결정자로 남아 플레이어 통제를 유지
- 동시 발동 불채택 이유: 비용 축이 사라진다 — 쿨감이 딜 배율화되고, 버프·힐이 공짜가 되어 사제 서약이 깨진다. 순차는 행동 주기가 **구조적 천장**이라 콘텐츠 추가에 안 깨진다

## 4. 기본 공격

- **무기군이 결정한다** — 무기군 Implicit과 같은 출처 (예: 창=선제타). 계승의 **둔기=경직은 경직 폐지(§2)로 무효** — 둔기 차별화는 다시 짠다
- 마법사의 기본 공격 = 지팡이의 기본 마법 공격
- 액티브가 준비되지 않은 차례를 메운다 — 빈 턴 없음

## 5. 액티브 슬롯

- **3개 — 출처 고정**: 죄종 트리 / 전직 트리 / **착용 무기군** (skill_design.md §3). 배분(트리)과 편성(슬롯)의 분리는 유지 — 편성 = 각 출처에서 어느 것을 + 어떤 순서로
- 슬롯 순서 = 동시 준비 시 우선순위. **순서 변경 무료** (리스펙 압력 완화)
- 슬롯은 선택지가 아니라 **상한** — 무제한이면 다 넣는 게 정답이라 밸런싱 불가

## 6. 쿨타임

- **실시간(초)으로 돈다** — 공속을 올려도 스킬 빈도는 늘지 않는다 (공속 이중 스케일링 차단)
- 쿨이 끝나도 다음 행동 주기까지 대기:

```
실효 쿨 = ceil(표기 쿨 ÷ 행동 주기) × 행동 주기   (+ 충돌 시 밀린 만큼)
```

- 쿨이 행동 주기의 정수배일 때 손실 0 → **정렬 최적화** 발생 (D2 공속 브레이크포인트 계보). 손잡이는 장비의 쿨감 옵션
- **UI에 실효 쿨 표시 필수** — 안 보이면 재미가 아니라 함정
- 쿨 하한 지침: `행동 주기 × 슬롯 수` 근처 — 그보다 짧으면 표기 쿨이 거짓말이 된다

## 7. 버프·힐

- **행동 1회를 소모한다** — 딜 포기가 비용. 예외 없음
- 버프는 지속시간으로 콤보를 만든다 — 최적화 대상은 "버프 지속 안에 공격 스킬을 몇 번 넣나" (버프 쿨 · 지속 · 공격 쿨 · 행동 주기의 정렬)
- 짧은 전투에서는 손해일 수 있어 판단이 생긴다 — 버프는 손해가 아니라 투자

## 8. 전투 능력치 — SSOT: `combat_stat.csv` (24종)

영웅은 이 수치들을 직접 보유하지 않는다 — 전투 진입 시 합산한다.

```
전투 능력치 = ( 장비(베이스+Implicit+접사) + 스킬(노드+고유 패시브) ) × 기본 능력치 계수
기본 능력치 계수 = 1 + (능력치 × [balance.csv:attr_bonus_per_point])
```

- **곱셈이라 장비가 0이면 능력치도 0을 곱한다** — "장비가 주인공"의 수치적 표현
- 행동 주기만 방향이 반대(낮을수록 빠름) — 계수로 나눈다
- 역방향(장비 → 기본 능력치)은 없다 — `[balance.csv:attr_equip_bonus]` = 0
- 계수가 붙는 것은 24종 중 **6종**뿐 — 물리 공격력(힘) · 마법 공격력(지능) · 명중·회피(감각) · 행동 주기(민첩) · 상태이상 회복 속도(건강). 나머지는 장비·스킬 전담

| 카테고리 | 수치 (**굵은 것 = 계수 있음**) | 비고 |
|---|---|---|
| offense | **물리 공격력**(힘) · **마법 공격력**(지능) · **명중**(감각) · 치명타 확률 · 치명타 피해 · 방어 무시 · 타입 특효 · 사이즈 특효 | 치명타는 계수 없음. 상태이상 적중은 08-25 삭제 |
| defense | 최대 HP · 물리 방어 · **원소 저항 4종**(전기·불·냉기·독) · **회피**(감각) · 피해 감소 · 반사 피해 | 마법 방어 → 원소 저항 4종으로 대체 (08-25) |
| sustain | 흡혈 · HP 재생 | 라운드 간 회복이 없어 **런 깊이를 결정** |
| tempo | **행동 주기**(민첩) · **상태이상 회복 속도**(건강) · 쿨타임 감소 | 건강 = 상태이상을 털어내는 축 (08-25 재배정) |
| utility | 드랍률 · 골드 획득 | **전투 계산 밖** — 전투력 vs 파밍 효율 스왑 축. 파견 시간 단축은 08-25 삭제 |

- **최대 HP 시작값은 전 영웅 공통** `[balance.csv:hero_hp_base]` — 능력치와 무관, 레벨·장비로만 성장. 몬스터 수치 절대 앵커링의 기준점
- 전투 능력치는 계산 결과이므로 **세이브에 저장하지 않는다**
- **회복량은 스탯이 아니다** — 회복 스킬의 회복량은 **마법 공격력에 비례**한다 (08-25). 사제의 파워 출처 = 마법 공격력 = 지능
- **파티 보정은 스탯이 아니라 스킬 효과** · 스킬 레벨 가산 옵션 없음 (08-25)
- **상태이상은 저항이 아니라 회복으로 상대한다** [08-25] — 확률로 막는 스탯(저항)은 없다. 걸리는 것은 확정이고, `fhr`(상태이상 회복 속도)로 **얼마나 빨리 털어내는가**만 겨룬다. 막느냐 못 막느냐의 이진 도박 대신 연속량이 되어 장비 투자량이 그대로 체감된다

### 몬스터는 부분집합만 갖는다

| | 보유 | 출처 |
|---|---|---|
| 상시 | HP · 공격력 · 물리 방어 · 원소 저항 · 행동 주기 | `monster.csv` 소재값 × `spawn_grade.csv` 배율 — ⚠ `monster.csv` 는 아직 `magic_defense` 단일 컬럼. 원소 배정과 함께 이관 |
