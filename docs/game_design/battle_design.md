## 1. 전투의 형태

- 파티 `[balance.csv:party_size_max]`인 vs 적 1~`[balance.csv:wave_monster_max]`, **라운드 진행** (원정 = 스테이지 런, 스테이지 구조는 base_expedition_design.md §1-2)
- **유저 조작 없음** — 편성·장비·스킬 배분이 입력의 전부
- 웨이브 간 HP 자동 회복 없음, 부상/치료 모델은 base_expedition_design.md §1-1

### 결정론적 시뮬레이션 (기술 원칙)

**같은 시드 + 같은 입력 = 같은 결과.** 관전으로 본 전투와 오프라인 즉시 계산의 결과가 반드시 일치해야 한다.

- 관전 화면은 시뮬레이션을 **재생**하는 플레이어일 뿐 — 배속 1/2/4는 재생 속도만 바꾼다
- 근거: 방치형이라 오프라인 진행이 있고, 두 경로의 결과가 갈리면 신뢰가 깨진다
- CLAUDE.md 이식성 규칙 2번(난수 주입, 동일 시드 결과 대조)과 직결 — Phase 2 엔진 이식의 검증 수단

## 2. 행동 주기 — 단일 시계

**모든 영웅은 행동 주기 하나만 갖는다.** 물리/마법 구분 없음.

- 출처: **민첩 + 무기군 기본 속도** (+ 장비 공속 옵션)
- 마법사의 "시전 간격"도 같은 변수다 — 이름만 다르고 축은 하나
- **근거**: 직업마다 시계가 다르면 ①`game_logic`에 직업 분기가 생기고 ②밸런싱 축이 둘로 갈리며 ③**지팡이 Implicit이 성립하지 않는다**(무기군 Implicit이 마법사를 커버 못 함)

## 3. 발동 규칙 (확정)

행동 주기가 도래하면 다음 순서로 **하나**를 실행한다.

```
1. 준비된 액티브 스킬 중 가장 오래 기다린 것
2. 동시에 준비됐으면 슬롯 순서가 앞선 것
3. 준비된 것이 없으면 기본 공격
```

- **한 차례에 하나.** 준비된 스킬이 여러 개여도 나머지는 대기한다 (동시 발동 불채택 — §3-2)
- 스킬은 그 차례의 공격을 **대체**한다. 버프·힐도 예외 없음
- 마나·자원 없음 — **행동 1회가 스킬의 유일한 비용**

### 3-1. 2단 정렬이 필요한 이유

슬롯 순서만으로 우선순위를 정하면 **쿨이 행동 주기보다 짧은 스킬이 영구 독점**한다. 그 스킬은 매 차례 항상 준비 상태이기 때문이다.

```
주기 5초 / 쿨 A=3 B=8 C=10 / 슬롯 순서만 적용
t=0 A → t=5 A → t=10 A → t=15 A ...   B와 C는 영원히 발동하지 않음
```

"가장 오래 기다린 것"을 1차 기준으로 두면 해소된다. 슬롯 순서는 동률일 때의 결정자로 남아 **플레이어 통제**를 유지한다.

```
2단 정렬 적용 시
t=0 A(동률→슬롯순) → t=5 B → t=10 C → t=15 A → t=20 B → t=25 A → t=30 C
60초 기준 A 5회 / B 5회 / C 3회 — 고르게 순환
```

### 3-2. 동시 발동 불채택 근거

준비된 스킬을 전부 발동시키는 안을 검토했으나 **비용 축이 사라진다**는 이유로 불채택.

| | 순차 (채택) | 동시 (불채택) |
|---|---|---|
| 초당 스킬 상한 | 행동 주기가 천장 | 천장 × 슬롯 수 |
| 쿨감 옵션 | 천장까지만 유효 → 자연 체감 | **딜 배율화** — 항상 최우선 옵션으로 수렴 |
| 버프·힐 | 그 차례 딜을 포기 (투자) | 공짜 — 안 넣을 이유가 없음 |
| 상한의 성격 | **구조**(행동 주기) — 콘텐츠 추가에 안 깨짐 | **숫자 캡** — 추가할 때마다 합계 검증 필요 |

- 12초 기준 총 딜 시뮬(주기 2초, 쿨 12초 3개, 평타 100/스킬 250): 순차는 쿨감 50%에서 1,500으로 천장, 동시는 쿨감 90%에서 4,500까지 상승
- 사제 서약("사제 없이도 최전선 성립", hero_design.md §5)이 동시 발동에서는 지켜지지 않는다

## 4. 기본 공격

- **무기군이 결정한다** — 무기군 Implicit과 같은 출처 (창=선제타, 둔기=경직 등)
- **마법사도 기본 공격이 있다**: 지팡이가 주는 기본 마법 공격. 계승 갭 **G3(마법 공격 부재)**가 채워질 자리
- 액티브가 준비되지 않은 차례를 메운다 — 빈 턴은 발생하지 않는다

## 5. 액티브 슬롯

- **3개 확정**
- 슬롯 순서 = 동시 준비 시 우선순위. **순서 변경은 무료** (리스펙 압력 완화)
- 트리에서 배운 스킬 중 셋을 고른다 — **배분(트리)과 편성(슬롯)의 분리**
- 슬롯은 선택지가 아니라 **상한**이다. 무제한이면 배운 스킬을 다 넣는 게 정답이라 밸런싱이 불가능해진다
- 실제 빌드 결정은 "몇 개 넣나"가 아니라 **스킬 포인트를 1개에 몰빵할지 3개에 분산할지** — D2의 시너지 대 분산 구조

## 6. 쿨타임

- **실시간(초)으로 돈다.** 공격 횟수 기준이 아니다
  - 결과: 공속을 올려도 스킬 발동 빈도는 늘지 않는다 → **공속의 이중 스케일링 차단**. 공속이 딜과 스킬 빈도를 동시에 올렸다면 모든 빌드가 공속 몰빵으로 수렴했을 것

### 실효 쿨 > 표기 쿨

쿨이 끝나도 **다음 행동 주기까지 대기**한다.

```
실효 쿨 = ceil(표기 쿨 ÷ 행동 주기) × 행동 주기   (+ 충돌 시 밀린 만큼)
```

- 쿨이 행동 주기의 **정수배일 때 손실 0** → 여기서 **정렬 최적화**가 발생한다 (D2 공속 브레이크포인트 계보)
  - 예: 쿨 12초 / 주기 2.0초 → 실효 12초(손실 0) · 주기 2.2초 → 실효 13.2초(손실 10%)
- **UI에 실효 쿨 표시 필수.** 안 보이면 재미가 아니라 함정이 된다 (표기 12초 / 실효 13.2초 병기)
- **쿨 하한 지침**: `행동 주기 × 슬롯 수` 근처. 그보다 짧게 잡으면 슬롯끼리 발동 기회를 나눠 갖느라 표기값이 거짓말이 된다
- 정렬을 맞출 손잡이로 **쿨감 옵션**을 장비에 둔다 (item_design.md §3). 정렬 재미가 장비 파밍으로 돌아온다

## 7. 버프·힐

- **행동 1회를 소모한다** — 딜 포기가 비용. 마나 없는 구조에서 유일한 비용 축이므로 예외를 두지 않는다
- 버프는 **지속시간**으로 콤보를 만든다. 버프를 건 다음 차례부터 강화된 공격이 나간다

```
t=0   버프 발동 (지속 6초)   딜 0
t=2   공격 스킬  250 × 1.5 = 375
t=4   평타       100 × 1.5 = 150
t=6   평타       100          버프 종료
```

- 최적화 대상 = **버프 지속 안에 공격 스킬을 몇 번 밀어넣나** (버프 쿨 · 버프 지속 · 공격 쿨 · 행동 주기 4개의 정렬)
- 이 구조에서 버프는 손해가 아니라 **투자**가 된다 — 짧은 전투에서는 손해일 수도 있어 판단이 생긴다
