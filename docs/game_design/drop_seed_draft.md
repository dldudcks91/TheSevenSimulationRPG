## 1. 콜로세움 서버 [초안 2026-10-26]

### 1-1 서버가 하는 일

콜로세움 = 온라인 ELO 탭(코드 id `arena` — [arena_design.md](arena_design.md) §0). 상대가 올린 팀 스냅샷과 비동기 자동전투 단판이고, 관전은 정해진 결과의 재생이다. 10-03 확정 「본편은 오프라인 · 결투장만 가벼운 고스트 서버」 안쪽이다.

| 함수 | 하는 일 |
|---|---|
| 방어 팀 올리기 | 스냅샷 → `arena.validateTeam` → 한 사람 한 팀 저장 |
| 상대 셋 받기 | 내 레이팅 아래 · 비슷 · 위 (`[balance.csv:arena_pick_spread]` · `[balance.csv:arena_pick_jitter]`) |
| 대결 | 서버가 시드를 정해 `battle.simulateTeams` → ELO 갱신 → 시드 · 결과를 돌려준다. 게임은 같은 시드로 연출만 한다 |
| 순위표 | 읽기 전용 |

- **공격 팀도 싸울 때마다 검사한다** — 방어 팀만 검사하면 공격 쪽이 구멍이다
- **레이팅의 주인은 서버**가 된다 — 로컬 값은 표시용 사본 ([arena_design.md](arena_design.md) §5)
- 서버는 받은 원재료(레벨 · 포인트 · 스킬 · 장비 줄)로 능력치를 다시 계산한다 — `arena.importTeam` 이 이미 그렇게 한다

### 1-2 서버를 고르는 조건

**서버는 JavaScript 를 돌려야 한다.** 서버가 같은 `game_logic` 으로 전투를 돌려야 승패 보고 위조가 사라지고, 다른 언어면 전투를 한 벌 더 짜서 비트 단위로 맞춰야 한다(SSOT 위반).

| 후보 | `game_logic` 그대로 | 지금 붙어 있나 | 걸리는 점 |
|---|---|---|---|
| Firebase Cloud Functions + Firestore | ○ (Node) | ○ 익명 계정 · Firestore · `ui/cloud.js` | 종량제(Blaze) 필요 · 요금 상한 없음 · 데스크톱용 App Check 공급자 없음 |
| Cloudflare Workers + D1 | ○ | × | 무료판의 요청당 CPU 한도가 짧다 — 전투 한 판이 넘으면 유료 |
| Steam 리더보드 | × (점수만) | × | 스팀 판에서만 · 판정자가 못 된다 → 순위 표시 보조로만 |
| VPS + 형제 TheSevenRPG FastAPI | × (Python) | × | 전투 한 벌 더 · 운영을 혼자 |
| Supabase | △ (Deno) | × | 백엔드가 둘이 된다 |

- 요금 · 한도의 실제 값은 조사 문서 [idle_server_authority_survey.md](../reference/idle_server_authority_survey.md) 에 있다(2026-10 기준)
- **고르기 전에 잴 것** — 전투 한 판의 CPU 시간(`dev/sim` headless) · Node 에서 `game_logic` 을 돌려 골든과 같은 답이 나오는지(아직 한 번도 안 해 봤다)
- 스팀 판 계정은 Steam 인증 티켓(`AuthenticateUserTicket`)을 서버 함수가 확인해 서버 계정으로 바꾼다 — publisher 키가 필요해 서버 함수 하나는 어차피 선다
- 유료 게임이라 밴의 무게가 크다 — 새 계정 = 게임을 다시 산다

### 1-3 서버 없이도 지금 할 것 — 어느 길로 가든 필요하다

1. **검사기 구멍 셋** — 아이템 레벨 위 상한이 없다(`arena.js` `validateTeam` 의 `within(it.ilvl, 1, Infinity)` — 옵션 범위 · 무기 데미지가 아이템 레벨을 따라 커져 같이 통과한다) · 옵션 표에 없는 줄은 검사 없이 통과한다(`if (!r) return`) · 옵션 줄 수 · 희귀도를 안 본다. 지금의 친선전(팀 코드 붙여넣기)도 이 구멍으로 뚫린다
2. **팀 코드에 전술 · 물약 칸이 없다** — 서버가 전투를 돌리려면 실어야 한다
3. **콜로세움 규칙의 빈칸** — 방어 결과가 방어자 레이팅을 움직이나(움직이면 「자리 비워도 안전」과 충돌 — 접속 안 한 사람의 레이팅이 깎인다) · [새 상대] 횟수(지금 공짜 — 게임 안 시뮬로 후보마다 승률을 재서 레이팅이 과소평가한 상대만 골라 먹을 수 있다) · 시즌
4. **엔진 차이 함수** — `formula.js` `statCoef` · `hero.js` `speedCoef` · `skill_effects.js` 다중 감쇠의 `Math.pow`, `item.js` `lean` 의 분수 지수, `hero.js` 능력치 굴림의 `Math.log` · `Math.cos`. 표준이 엔진마다 끝자리가 달라도 되게 둔 함수다. 서버 판정이 기준이면 연출 불일치로 끝나지만, Godot · Unity 이식에선 비트 일치가 깨진다

## 2. 출처 검증의 한계 — 「정말 주웠나」 [초안 2026-10-26]

### 2-1 적법성과 출처는 다른 질문이다

| 층 | 묻는 것 | 잡는 것 | 못 잡는 것 |
|---|---|---|---|
| 적법성 | 게임에서 나올 수 있는 값인가 | 범위 밖 값 · 만렙 초과 · 없는 옵션 · 포인트 초과 | 범위 안에서 지어낸 최고 굴림 |
| 출처 | 이 사람이 정말 주웠나 | 지어낸 최고 굴림까지 | — |

### 2-2 해시 · 서명 · 드롭 시드 붙이기로는 출처를 못 잡는다

- 해시 · 서명은 「누가 만들었나」를 증명한다 — 만드는 쪽이 유저 컴퓨터면 열쇠도 유저 손에 있다. 웹 게임은 원본 코드가 그대로 보인다
- 아이템에 「막타 영웅 · 레벨 · 사냥터 · 몇 번째 처치」로 만든 시드를 붙여 나중에 재현하는 안 — 재료가 전부 유저 쪽 값이라 **시드 캐기**가 된다(생성 함수를 직접 불러 재료를 바꿔 가며 굴리고 제일 좋은 결과의 재료를 붙인다 · 서버 재현은 통과한다). 유저가 고를 수 있는 재료는 하나 늘 때마다 다시 굴릴 손잡이가 하나 는다
- 막으려면 **유저가 못 고르는 값(운 · 시간)을 서버가 쥐어야 한다**

### 2-3 서버가 운을 쥐는 「인증 장비」 안과 그 구멍

시드는 로그인 때 한 번이 아니라 **런을 출발할 때마다** 준다. 로그인 때 한 번이면 시드를 쥔 순간 앞으로의 굴림을 미리 다 계산해 고르거나(미리 보고 고르기) 안 한 전투를 지어낸다.

1. 출발 때 게임이 **파티 · 장비 · 전술 · 물약 · 찾기 스탯 · 칸 · 난이도를 먼저 서버에 보낸다** — 시드를 받은 뒤 입력을 바꿔 가며 미리 돌려 보는 것을 막는다(⚠ [arena_design.md](arena_design.md) §4 의 2단계는 「판이 끝난 뒤 스냅샷을 올린다」 — 이 순서면 뚫린다)
2. 서버가 시드를 만들어 장부에 「n번 발급」으로 적는다 — 버린 판은 버린 판 · 다음 시드는 그 판의 실제 전투 시간이 지난 뒤(출시판 배속 ×1 — 서버가 판 길이를 안다)
3. 서버가 같은 `game_logic` 으로 그 런을 재현해 드롭을 확정한다 — 인증 장비는 서명보다 **서버에 저장**하는 쪽이 단순하다(업계 표준과도 맞다 · 서명은 강화 · 기기 이동 처리가 붙는다)

**구조적 구멍** — 그래서 지금은 하지 않는다

- **반쪽이다** — 골드 · 재료로 하는 일(강화 · 제작 · 상점 · 도박) · 주점 영웅 · 꺼진 동안 도는 연구소 산출은 못 묶는다. 강화 · 제작을 빼면 인증 리그는 다른 게임이 되고, 경제까지 서버가 쥐면 본편 온라인(10-03 과 정면 충돌)이다
- **원정 중 온라인 필수** — 오프라인 유저는 빠진다. 10-03 에 거른 「캐릭터 분리」가 다른 이름으로 돌아온다
- **비용이 PvE 플레이 시간 전체에 비례한다** — 판매형은 매출이 한 번이다. Firestone(매출이 계속 드는 무료 게임)도 메인 전투를 서버로 옮기지 않았다
- **선례가 없다** — 로컬 세이브 아이템의 출처를 증명한 출시작을 조사에서 찾지 못했다
- **지키는 대상이 곁가지다** — 보상은 칭호 · 꾸밈 · 콘텐츠 비중도 곁가지(GAME_DESIGN §1)

### 2-4 적법성만으로 버틸 수 있나 — 숫자 하나가 가른다

- 옵션 재굴림은 어디에도 없다(08-31 확정 — [item_design.md](item_design.md) §7) — 굴림 값을 끌어올리는 길은 드롭 운뿐이다
- 줄 수 `[balance.csv:item_random_lines_*]` · 아이템 레벨 치우침 `[balance.csv:item_roll_skew]` · 드롭 확률 `[balance.csv:drop_chance_pct]` × `[spawn_grade.csv:drop_chance_mult]` · 희귀도 `[gear_rarity.csv]` 로 거칠게 추정하면, **모든 줄이 범위 상위권인 레어 이상 한 개는 헬에서도 수백 시간 단위**다(추정 — 목표 시간대로 다 이김 · 부대 하나 · 찾기 0 가정)
- 그래서 「합법 최고치 팀」은 정직하게는 사실상 닿을 수 없고, [arena_design.md](arena_design.md) §2 의 「치팅 = 파밍 생략」 논리는 절반만 성립한다 — 최상위 구간의 정직한 유저가 위조 팀에게 질 때마다 레이팅이 직접 깎인다
- **먼저 잴 것** — 「같은 빌드에서 옵션만 최대치로 바꾼 팀」 대 「`dev/sim` 으로 오래 파밍한 팀」을 `simulateTeams` 로 수백 판 붙인 승률. 격차가 작으면 적법성으로 충분하고, 크면 그때 대책(탐지 · 인증)을 고른다

## 3. 드롭 로직 진단 — 지금 구조 [초안 2026-10-26]

### 3-1 「최적」의 기준

| 기준 | 뜻 |
|---|---|
| 되굴림 금지 | 껐다 켜기 · 다시 보내기로 결과를 다시 뽑을 수 없다 — 강화의 회차 번호 · 「켤 때 남은 라운드를 마무리하지 않는다」([base_expedition_design.md](base_expedition_design.md) §1)가 이미 지키는 원칙 |
| 읽히는 인과 | 「저 보스가 레전더리를 입었다 → 잡으면 그중 하나가 떨어진다」가 보인다 (R79) |
| 자리 비워도 안전 | 손을 대야만 손해를 피하는 구조가 없다 |
| 결정론 | 같은 시드 + 같은 입력 = 같은 드롭 — 시뮬 비교 · 서버 검증의 바탕 |
| 서버 준비 | 나중에 바뀌는 곳이 입구 한 곳 |
| 단순함 | 새 게이지 · 새 수치 없음 |

### 3-2 잘 돼 있는 것

- 몬스터 장비는 이미 몬스터마다 제 줄(차림 씨앗 · 라운드 · 자리)에서 굴린다 (`battle.js` `spawnRound` 2단 · 09-22)
- 떨어지는 것은 그 몬스터가 입은 장비이고 툴팁에 보인다 (R79 · `ui/tip.js` `monsterTipCard`)
- 강화 · 상자 · 제작 · 상점 · 도박은 「세이브 시드 ^ 종류 + 회차 번호」 줄이라 되돌려도 같은 결과다

### 3-3 문제

1. **다시 보내기가 공짜 되굴림이다 (가장 크다)** — 몬스터 장비는 스폰 순간 툴팁에 보이고(Alt 면 옵션 값까지), 다시 보내기는 비용 · 대기 없이 새 회차 번호 = 새 시드를 받는다(`state.js` `departRun` — 도는 런을 먼저 끊는다). 이긴 라운드 몫은 철수해도 남으니 **어느 라운드든 「장비가 나쁘면 다시 보내기」로 건너뛰는 비용이 사실상 0**이다
   - 가장 심한 곳은 챕터보스 칸 — 한 라운드짜리라 출발하자마자 보스 · 정예 호위가 보이고 보스는 드롭이 보장된다(`[balance.csv:boss_guaranteed_drop]`). 클릭 한 번 · 몇 초마다 보스를 다시 굴려 레전더리를 많이 입은 보스만 골라 잡으면, 보스 한 마리당 레전더리 확률이 몇 배가 된다
   - 조작 도구 없이 툴팁만 보면 된다 — 최적 플레이가 지루한 반복 클릭이 된다(「조작이 아니라 빌드 · 편성 · 배분 의사결정이 본체」 — GAME_DESIGN §1 과 충돌)
   - 「껐다 켜기로 라운드 빨리 돌리기」를 막은 것과 같은 종류의 구멍인데, 가속이 아니라 **골라 먹기**라서 빠져 있었다
   - 매크로 · 콘솔로 자동화하는 것은 세이브 편집과 같은 급이라 오프라인에선 어차피 못 막는다 — 여기서 막을 대상은 **정직한 유저가 손으로 하는 골라 먹기**다
2. **전투가 드롭 운을 민다** — 둘째 라운드부터의 몬스터 편성 · 정예 특성 · 떨어지나 판정 · 장비냐 도안이냐 · 어느 부위 · 재료가 전투와 같은 줄(런 rng)에서 나온다. 무기를 바꿔 공격 횟수가 한 번만 달라져도 그 뒤에 서는 몬스터와 드롭 판정 카드가 밀린다
3. **한 몬스터 안에서 앞 부위가 뒤 부위를 민다** — 희귀도마다 굴림 횟수가 달라(`item.js` `build`), 매직찬스가 조금만 달라도 한 부위의 희귀도가 바뀌고 나머지 부위 값이 통째로 바뀐다
4. **부대끼리 엮여 있다** — 도감 보너스(라운드마다 공유 상태를 읽는다) · 물약 재고(라운드마다 공유 재고에서 다시 채운다) · 회차 번호(출발 순서) — 지금은 괜찮지만 서버가 런 하나를 혼자 재현할 수 없게 만든다

### 3-4 참고작은 어떻게 하나

- **Melvor Idle** — 매번 새 난수(`Math.random`) · 세이브에 난수 상태 없음 · 드롭은 처치 순간 · 처치 전에 보이는 것은 몬스터별 드롭 표뿐(코드 확인). 막는 장치는 없고, 세이브 되돌리기로 상자 결과를 다시 뽑는 것이 통한다(스팀 토론 — 「싱글 게임이라 본인 문제」)
- **Lootun** — 드롭은 처치 순간 · 보스 상자. Nemesis 등급만 스폰 순간 정해지고(드물다) 처치하면 Nemesis 아이템이 최소 하나(개발자 답변). 미션 재시작으로 스폰을 다시 뽑을 수는 있지만 보이는 정보가 적고(등급뿐) 재시작이 비싸서(처음부터) 문제가 안 된다
- **결론** — 둘 다 막는 장치가 없다. 구멍이 생기는 구조(입은 장비가 미리 보인다 + 다시 뽑기가 싸다)가 애초에 없어서다. 「보이는 장비」를 지키려면 우리가 직접 막아야 한다

## 4. 드롭 로직 제안 [초안 2026-10-26]

### 4-1 규칙 ① 운을 두 갈래로 — 만남 / 전투 [채택 2026-10-27 — 규칙 ② 의 부품]

| 갈래 | 정하는 것 | 무엇이 바꿀 수 있나 |
|---|---|---|
| **만남** | 누가 나오나 · 정예 죄종 · 특성 · 보스 셋째 스킬 · 무엇을 입었나 · 떨어지나 · 장비냐 도안이냐 · 어느 부위 · 재료 | 찾기 스탯 · 도감 보너스가 **문턱만** 옮긴다 (많이 끼면 좋아지기만) |
| **전투** | 명중 · 치명 · 데미지 · 대상 · 상태이상 · 등장 지연 | 파티 · 장비 · 전술 · 물약 |

- 만남은 `deriveSeed` 로 「시드 + 용도 표시 + 라운드 + 자리」를 섞어 만든 제 줄에서 굴린다 — 강화 · 도박이 이미 쓰는 방식이다. 서버가 시드 하나만 줘도 게임 · 서버가 같은 식으로 쪼개 같은 덱을 얻는다
- 전투가 정하는 것은 「이겼나 · 잡았나」뿐이 된다 — 같은 시드에서 무기만 바꿔 비교할 때 몬스터 · 드롭이 같아 시뮬 비교가 깨끗해진다(09-22 몬스터 장비 분리와 같은 이유)

### 4-2 규칙 ② 라운드마다 「다음 판」 번호 — 이겨야 넘어간다 [채택 2026-10-27]

- 칸 · 난이도 · 라운드 번호마다 판 번호가 하나씩 있고, **그 라운드를 이겨야** 다음 번호로 넘어간다
- 철수 · 다시 보내기 · 게임 끄기 · **패배** → 다음에 같은 판(같은 몬스터 · 같은 장비 · 같은 드롭 카드)이 나온다. 전투 시드는 출발마다 새로 받으니 아깝게 진 판은 다시 하면 이길 수 있다
- 이긴 판은 다시 안 나온다 — 앞 라운드를 이기고 뒤 라운드에서 철수하면, 다음 런의 앞 라운드는 새 판이고 철수한 라운드만 같은 판이다(드롭 복제 없음)
- 부대 여럿이 같은 칸에 가면 서로 다른 판 번호를 잡고, 놓은 판(철수 · 패배)은 다음에 가는 부대에게 돌아온다 — **판을 건너뛸 수 없고 순서만 바꿀 수 있다**
- 유저가 느끼는 것 — 「같은 칸은 이길 때까지 같은 적」 · 레전더리를 입은 보스는 건너뛸 대상이 아니라 강해져서 잡으러 가는 목표가 된다 · 매직찬스 장비를 끼고 다시 오면 그 보스의 장비가 좋아질 수는 있어도 나빠지지 않는다
- 패배도 같은 판이다 [2026-10-27 결정 — §7 D4] — RPG 의 보스 재도전과 같고 · 진 이유가 읽히고 · 규칙이 한 문장이고 · 「일부러 지기」 구멍이 없다
- 규칙 ① · ③ 은 이 규칙의 부품이다 — ① 이 없으면 무기만 바꿔도 뒤 라운드의 판이 달라지고, ③ 이 없으면 매직찬스 장비를 바꿔 끼는 것만으로 다른 부위가 다시 굴려진다

### 4-3 규칙 ③ 부위마다 제 줄 [채택 2026-10-27 — 규칙 ② 의 부품]

몬스터 한 마리의 장비를 부위마다 제 줄에서 굴린다 — 한 부위의 희귀도가 다른 부위 값을 안 민다. 매직찬스는 그 부위의 희귀도 문턱만 옮긴다.

### 4-4 규칙 ④ 보스의 첫 판은 모두에게 같다 [보류 2026-10-27 — 승률을 잰 뒤]

- **할지부터 보류** [사용자 2026-10-27 「스테이지보스별로 고정은 나중에 정해도 되잖아」] — 규칙 ② 가 들어가면 처음 걸린 보스 판이 넘어갈 때까지 남는 관문이 된다. 그 판의 세기가 사람마다 얼마나 갈리는지(보스 판 승률 분포 — `/qa-fun`)를 잰 뒤에 정한다. 아래는 채택할 때의 안이다

- 스테이지보스 · 챕터보스 라운드의 **첫 판(판 번호 0)** 은 세이브 시드 대신 **모두에게 같은 시드**로 굴린다 — 난이도마다 따로. 깬 뒤의 파밍 판부터 세이브 시드로 랜덤이다
- 이유 — 넘어가는 칸의 난이도가 모두에게 같아져 「운 나쁜 첫 판에 갇히는 사람」이 사라지고 밸런스를 그 판 하나에 맞출 수 있다 · 이름 · 직업 · 고유 스킬이 있는 장 보스의 첫 대면이 사람마다 다를 이유가 없다 · 「그 보스는 이걸 입고 나온다」가 공유되는 정보가 된다
- 검수 — 고정된 첫 보스의 세기가 랜덤으로 굴린 보스 분포에서 어디쯤인지 시뮬로 한 번 재고, 튀는 판만 덮어쓰는 칸을 단다
- 주의 — CSV(장비 표 · 희귀도 가중치)가 바뀌면 같은 시드라도 다른 첫 보스가 나온다 · 「고정」은 같은 데이터 판 안에서만이고 밸런스 패치 뒤엔 검수를 다시 돈다 · 첫 처치 드롭 후보(입은 장비)도 모두 같아진다 — 첫 클리어 상자가 따로 있어 보상이 겹치지는 않는다
- 범위 — 보스 라운드만. 일반 · 정예 라운드 첫 판까지 고정하는 것은 이득이 작다
- ⚠ 방법은 열린 결정이다(§7 D5) — 고정 시드(추천 · 만들 양 없음) vs 직접 설계(보스 × 장 × 난이도만큼 CSV 에 장비 · 특성을 적는다)

### 4-5 그대로 두는 것

09-21 찾기 시점(매직찬스 = 적이 나타나는 순간 · 아이템 · 골드 찾기 = 처치 순간)과 막타 직전 교체 · 「떨어지는 것은 입은 장비」(R79) · 처치당 최대 하나 · 보스 보장 · 철수 규칙 · 몬스터 장비 툴팁

### 4-6 대가 · 부딪히는 것

- ⚠ [base_expedition_design.md](base_expedition_design.md) §1 「리듬은 익히되 런은 매번 다르다」 — 새 판은 여전히 매번 다르지만, 진 판을 다시 하면 같은 적이 나온다. 운으로 쉬운 판을 낚는 길이 사라진다
- **같은 적 벽** — 내 빌드와 상성이 나쁜 정예 조합에 걸리면 강해지거나 편성을 바꿔야 넘어간다. 자리를 비운 사이 너무 센 판에 걸린 부대는 계속 진다(지금도 제 세기보다 높은 칸에선 대부분 진다). 실제로 문제인지는 「같은 판 연속 패배 수」로 잰다 — 문제면 「목표 시간(`[round_budget.csv:time_target_sec]`) 이상 버티다 진 판만 새 판」 조건 하나를 더한다(판 번호 구조는 그대로)
- **난수 순서가 바뀐다** — 골든 지문 · INTERFACE §5(rng 순서 계약)가 바뀐다. 한 번에 묶어야 골든을 한 번만 다시 쓴다 — 엔진 차이 없는 굴림(`item.js` `lean` 을 정수 · 비교 연산으로)도 같은 묶음에 넣을 수 있다
- **세이브 스키마** — 판 번호 장부(칸 · 난이도 · 라운드마다 다음 번호 + 놓은 판 목록)가 세이브에 든다

## 6. 같이 발견한 것 [2026-10-26]

- 자동 분해의 레벨 조건이 원정에 굳힌 편성이 아니라 **지금 편성**을 읽는다(`state.js` 자동 분해 판정의 `partyMinLevel`) — 원정 중 편성을 고치면 분해 판정이 바뀐다

- 문서 불일치 — 가방이 찼을 때 [base_expedition_design.md](base_expedition_design.md) 「넘친 드롭은 버린다」 vs [item_design.md](item_design.md) 「가루로 분해」 · 매직찬스가 곱하는 범위 「레어 가중치만」 vs 「레어 이상」
- `balance.csv` 의 무기 · 방어구 베이스 옵션 키 설명은 「균등 굴림」인데 코드는 아이템 레벨 치우침(`lean`)을 쓴다

## 9. 구현 계획 — 규칙 ① ② ③ [2026-10-27 · 미착수]

### 9-1 난수 — 라운드마다 만남 씨앗 하나

- 원정은 세이브 시드 + 칸 + 난이도 + 라운드 + 판 번호로 그 라운드의 만남 씨앗을 만든다 — 새 소금 하나(INTERFACE §5-3 에 등재)
- 시뮬 · 단정처럼 장부가 없는 실행은 지금처럼 런의 첫 굴림을 씨앗으로 쓴다
- 만남 씨앗에서 갈라 굴리는 것

| 갈래 | 굴리는 것 |
|---|---|
| 편성 | 누가 나오나 · 정예 죄종 · 특성 · 소환 채움 |
| 차림 | 몬스터마다 · **부위마다 제 줄** (규칙 ③) |
| 보스 셋째 스킬 | 몬스터마다 |
| 처치 드롭 | 몬스터마다 제 줄 — 떨어지나 · 장비냐 도안이냐 · 어느 부위 · 어느 도안 · 재료 |

- 전투 줄에 남는 것 — 등장 지연 · 전투 전부. 무기를 바꿔도 다음 라운드의 몬스터 · 드롭이 안 밀린다 (규칙 ①)
- 찾기 스탯은 문턱만 옮긴다 — 희귀도 굴림(`item.js` `rollRarity`)이 누적 문턱 비교라, 같은 굴림이면 매직찬스가 올라도 희귀도는 같거나 오르기만 한다

### 9-2 판 번호 장부 — 세이브에 든다 (세이브 버전 하나 올림)

- 세이브 전체 — 칸 · 난이도 · 라운드마다 다음 번호와 놓인 판 목록
- 런마다 — 그 런이 잡은 판 번호 (이긴 라운드는 비운다)

| 때 | 하는 일 |
|---|---|
| 출발 | 라운드마다 놓인 판 중 가장 작은 번호, 없으면 새 번호를 잡는다 |
| 라운드 승리 | 그 번호를 쓴다 — 다시 안 나온다 |
| 패배 · 시간 초과 | 진 라운드와 못 간 라운드의 번호를 놓는다 |
| 끊기(철수 · 다시 보내기 · 게임 끄기 — 모두 `state.js` `cutRun` 한 곳을 지난다) | 이기지 못한 번호를 전부 놓는다 |

- 탐험 · 결투는 장부를 타지 않는다 — ⚠ 탐험 동굴은 원정 규칙을 쓰는데, 일찍 부를 때 표를 돌려주나가 아직 미정이다([base_expedition_design.md](base_expedition_design.md) 탐험 절). 그게 정해질 때 같이 본다

### 9-3 고칠 곳 — 이 순서로

### 9-4 추가할 단정

- 철수 뒤 다시 보내면 같은 판이 나온다
- 1라운드를 이기고 철수하면, 다음 런의 1라운드는 새 판이고 2라운드는 같은 판이다
- 지면 같은 판이 나온다
- 두 부대가 같은 칸에 가면 다른 판을 받고, 놓은 판은 다음에 가는 부대에게 돌아온다
- 전투 시드가 달라도 같은 판 · 같은 드롭이 나온다
- 매직찬스를 올리면 각 부위의 희귀도는 같거나 오르고, 다른 부위는 바뀌지 않는다
- 장부가 세이브 왕복을 견디고, 켤 때 끊긴 런의 판은 장부로 돌아간다
