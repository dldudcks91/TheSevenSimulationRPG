## 0. 이 문서가 계승본에서 바꾼 것 (2026-08-22)

계승분을 그대로 쓰면 깨지는 지점 5개를 고쳤다. 배경은 §7 결정 로그.

| # | 계승본의 문제 | 조치 |
|---|---|---|
| 1 | 몬스터에게 **마법 공격이 없음** — 영웅 마방이 사문화, 베이스 절반(Lich/Imp/Succubus/Ghost)의 컨셉이 데이터에 부재 | `attack_type` 컬럼 신설 (physical/magic) |
| 2 | 등급 배율이 **이중 적용** — 보스 행이 이미 부풀려진 절대값인데 `spawn_grade_config` 에도 배율이 있음. 챕터마다 적용 여부도 불일치 | `monster.csv` = **일반 등급 소재값 단독**, 배율은 `spawn_grade.csv` 가 단독 적용 |
| 3 | "1스테이지 = 1타입" 규칙과 **챕터 풀 랜덤이 충돌** — 그냥 뽑으면 한 스테이지에 3타입이 섞여 `vs_type` 옵션이 무의미해짐. 4스테이지 타입도 미정의 | 스테이지 타입을 `stage.csv` 에 고정 배정 + **2단 랜덤**(§4) |
| 4 | 등급 배율과 **시간 예산이 각자 놂** — 정예 라운드 총 HP는 5배인데 목표시간은 2배, 챕터보스는 단독으로 런 예산을 초과 | 배율(`spawn_grade.csv`)과 시간(`round_budget.csv`)을 **다른 테이블로 분리** |
| 5 | `size_type` 이 채워져만 있고 **쓰는 규칙 없음** | 보존 — 진형·타겟팅 논의에서 결정 (§6) |

부수적으로 정리한 것:
- **공속 축 통일** — 계승본은 Ch1(0.25~0.75)과 Ch2+(0.4~1.6)가 서로 다른 스케일이었다. `action_period`(초)로 단위를 바꿔 **영웅의 행동 주기와 같은 시계**를 쓴다 (battle_design.md §2)
- **스테이지보스 플레이스홀더 9종 명명** — Ch5~7 (§3)
- **4스테이지 일반몹 신설** — 계승본은 Ch2~7 의 4스테이지에 잡몹이 0마리였다 (원작이 보스 1마리 웨이브였기 때문). 9라운드 구조에는 1~8라운드를 채울 몹이 필요하므로 챕터당 3종씩 신규 작성
- **dlvl 곡선 선형화** — 계승본은 Ch5 이후 dlvl 이 정체(40→49)해 최종 3챕터의 아이템 진행이 멈췄다. 28스테이지에 걸쳐 단조 증가로 재작성

## 1. 타입 3종 (monster_type)

| 타입 | 설명 | 용도 |
|---|---|---|
| Normal | 자연 생물·피조물 | 장비 공통옵션 `vs_Normal_damage` 대상 |
| Demon | 지옥/마법 계열 (고블린·오크 포함) | `vs_Demon_damage` |
| Undead | 죽어서 되살아난 존재 | `vs_Undead_damage` |

- 속성 상성 시스템 **없음** — 타입은 장비 옵션의 대상 분류 전용 ("드롭 편향"과 "전투 속성"의 분리)
- **1스테이지 = 1타입 단일.** 이게 `vs_type` 옵션이 실질 의미를 갖는 유일한 조건이고, 그래서 §4의 2단 랜덤이 필요하다

## 2. 공격 타입 2종 (attack_type) — 신설

**몬스터의 `attack` 이 영웅의 어느 방어 스탯을 상대하는지 지정하는 플래그.** 새 게이지도 새 수치 축도 아니다.

- `physical` → 영웅 방어력이 감산
- `magic` → 영웅 마법방어가 감산

**베이스가 기본값을 주고, 인스턴스가 덮어쓸 수 있다.**

- 기본 magic 베이스: **Imp · Succubus · Ghost · Lich** (마법 컨셉 4종)
- 인스턴스 예외 ①: 역할이 `caster` 면 베이스와 무관하게 magic (도마뱀 주술사, 가고일 주술사 등)
- 인스턴스 예외 ②: 챕터보스 일부를 명시 지정 — 물리/마법이 챕터마다 번갈아 나오도록

> **왜 필요한가**: 이게 없으면 영웅의 마법방어 스탯과 그 접사 풀이 통째로 죽는다. 그리고 `Ghost`(물방↓마방↑)·`Lich`(마법 극대) 같은 베이스 컨셉이 "attack 수치만 다른 물리 몹"으로 뭉개진다. 계승 갭 **G3의 몬스터 측 절반**이 여기서 채워진다 (영웅 측은 지팡이 기본 마법 공격 — battle_design.md §4).

**보장 조건**: 챕터마다 마법 공격을 만나는 스테이지가 최소 1개 있어야 하고, **챕터보스는 물리/마법이 고르게 섞여야 한다.** 몬스터 데이터를 고칠 때 이 조건을 깨지 않았는지 확인한다.

## 3. 베이스 16종 (monster_base)

- **Normal (6)**: Wolf(고속 딜러) · Yeti(강타) · Troll(방어) · Lizardman(균형) · Golem(극단 방어) · Human(균형 전사)
- **Demon (5)**: Imp(빠른 마법) · Goblin(집단) · Succubus(디버프) · Gargoyle(방어) · Orc(강타)
- **Undead (5)**: Skeleton(밸런스) · Zombie(느린 고체력) · Ghost(물방↓마방↑) · Vampire(흡혈) · Lich(마법 극대)

원칙: **베이스 = 내부 분류(스탯 성향·attack_type 기본값·드롭 기준), 인스턴스 = 챕터별 고유 이름·외형.** 같은 Skeleton도 챕터마다 다른 존재로 보이게 한다.

> 아트 현실: 베이스 16종 중 실제 일러스트가 있는 건 Goblin·Skeleton 2종뿐이다 (`src/assets/inherited/faces/README.md`). 인스턴스 94종은 베이스 16종의 색조 변형으로 커버 가능한 구조이므로, **아트 병목은 인스턴스가 아니라 베이스 16장이다.**

### 스테이지보스 명명 (2026-08-22)

계승본에서 `플레이스홀더` 였던 Ch5~7 스테이지보스 9종에 이름을 부여했다. 기존 12종(아바돈·레기온·둘라한·사마엘·아비주·밴시·다곤·카론·메피스토펠레스·유키온나·아스타로스·파주주)과 같은 계보 — **신화/악마학 고유명사 + 그 챕터 죄종의 번역**. 목록은 `monster.csv` 참조.

## 4. 스테이지 구성 규칙 — 2단 랜덤 (신설)

계승본의 "챕터 풀에서 시드 랜덤"을 그대로 쓰면 §1의 타입 단일 규칙이 무너진다. 2단으로 나눈다.

```
1단 (고정) : 스테이지 → monster_type 1개          [stage.csv:monster_type]
2단 (랜덤) : 그 스테이지 소속 일반몹 풀에서 라운드별로 뽑기
             풀 = monster.csv 에서 (chapter, stage_num, spawn_grade=normal) 로 필터
```

- **1단이 고정이므로 타입 단일이 구조적으로 보장된다** — 생성기가 실수할 여지가 없다
- 2단이 스테이지 소속으로 한정되는 이유: 몬스터 스탯은 인스턴스별 절대값이라 **다른 스테이지 몹을 섞으면 티어 곡선이 깨진다**
- 1~3스테이지 타입은 계승 `chapter_info.stage_type_order` 를 그대로 계승. **4스테이지 = 챕터보스의 타입**으로 채웠다 — 계승본에서 유일하게 4스테이지 잡몹이 있던 Ch1이 이미 그 규칙(Demon/Imp + Demon 챕터보스)을 따르고 있었다
- 런의 다양성은 타입이 아니라 **정예 특성 랜덤(§5)**과 라운드별 조합에서 나온다
- 계승 `chapter_monster_pool.csv` 는 **대체됨** — (chapter, type, base) 관계가 `monster.csv` 에서 직접 파생되므로 별도 테이블은 드리프트 위험만 남는다

## 5. 스폰 등급 4종

일반 → 정예 → 스테이지보스 → 챕터보스.

**`monster.csv` 의 스탯은 전부 "일반 등급 소재값"이다.** 보스 행도 예외 없다. 실제 전투 스탯은:

```
전투 스탯 = monster.csv 소재값 × spawn_grade.csv 배율
```

> **왜 배율을 단일화했는가**: 정예는 런타임 랜덤 생성이라 CSV에 행이 없다 — **어차피 배율 경로를 탈 수밖에 없다.** 보스만 절대값으로 두면 등급 축이 두 갈래로 갈리고, 재밸런싱 때 보스 28종을 개별 수정해야 한다. 계승본이 정확히 그 상태였고 Ch1과 Ch2의 보스 배율이 서로 달랐던 것도 그래서다.

- 배율·드롭롤 횟수: [`spawn_grade.csv`](../../src/data/spawn_grade.csv)
- **목표 전투시간은 여기 없다** — 등급이 아니라 라운드 단위 예산이므로 `round_budget.csv` 로 분리했다
- 드롭롤 횟수 차이가 파밍 동선(보스 러시 가치)을 만든다

### 소재값 산출 규칙

`monster.csv` 는 손으로 튜닝하는 SSOT지만, 최초 작성은 아래 규칙으로 일관되게 뽑았다. 행을 수정할 때 이 규칙에서 벗어나도 되지만 **왜 벗어나는지가 있어야 한다.**

```
소재값 = 티어(통산 스테이지) × 베이스 아키타입 가중 × 역할 가중
```

- **티어**: 통산 스테이지 1~28에 걸친 단조 증가 곡선. 챕터가 아니라 스테이지 단위라 챕터 경계에서 점프하지 않는다
- **베이스 아키타입 가중**: HP/공격/방어/마방/행동주기 5축. 컨셉(§3)의 수치 번역 — Wolf는 DPS 최상·HP 최하, Golem은 그 반대
- **역할 가중**: `skirmish` / `line` / `ranged` / `caster` / `heavy` / `elite_line` / `boss`. 한 스테이지의 일반몹 3종은 서로 다른 역할을 갖는다 (`role` 컬럼)
- 절대 스케일은 **미확정** — 영웅 스탯·무기 데이터가 나오면 전역 배율 1개로 앵커링한다 (§8)

## 6. 정예(Elite) 특성 시스템 — 런타임 랜덤 생성

```
정예 = 스테이지 일반몹 1종 + 죄종 고유 특성 1 + 공통 특성 2  (+ spawn_grade.elite 배율)
네이밍: [죄종 접두사] [몬스터 이름] [역할]   (예: "분노의 고블린 전사")
```

**죄종 고유 7종** — 각 죄종 성격의 전투 번역 + 명확한 카운터 존재:

| 접두사 | 특성 | 개념 | 카운터 |
|---|---|---|---|
| 분노의 | 격분 | 저체력 시 폭주 | 임계 전에 끝내기 |
| 나태의 | 태만 | 느리지만 한 방 | 한 방 버티는 몸 |
| 색욕의 | 유혹 | 공격력 흡수 스택 | 회피·속전속결 |
| 시기의 | 박탈 | 치명/회피 무효화 | 순수 공방 |
| 오만의 | 불가침 | 상태이상 면역 | 스탯 압도 |
| 폭식의 | 탐식 | 타격마다 공격력 누적 | 속전속결 |
| 탐욕의 | 도박 | 피해 랜덤 + 드롭 보너스 | 체력 여유 |

**공통 16종**: 스탯 강화 8(강인한/단단한/거대한/날랜/흉포한/민첩한/정확한/치명적인) + 전투 규칙 8(재생하는/가시의/경화의/선제의/보복의/폭발하는/저주받은/흡혈의). 효과 수치는 계승 `elite_trait.csv`.

- "저주받은"은 상태이상 7종(story_chapter_design.md)을 소스로 사용
- 조합 다양성: 7 × C(16,2) = 840가지 — **콘텐츠를 곱셈으로 얻는 구조**. 스테이지 타입이 고정(§4)이어도 런이 매번 다른 이유가 여기다
- 정예의 `attack_type` 은 소재가 된 일반몹을 그대로 따른다
