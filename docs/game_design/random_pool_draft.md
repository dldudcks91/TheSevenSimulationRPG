## 0. 사용자 방향 [2026-10-20]

- 「랜덤줄로 왜 이거밖에 못붙어 다른 죄종에 있는애들도 랜덤하게 붙을 수 있지않나?」 — **랜덤 줄은 모든 부위에서 다른 죄종의 옵션도 고른다.** 지금은 무기 · 갑옷만 그렇다(§1)
- 「투구,신발 그거 예전에 같이 한 계열표로 하자는거 진행해」 — 10-09 확정(item_design.md §1 「10-09 옵션 개정」)을 데이터 · 코드에 넣는다(DEV_PLAN R229 ☐). 같이 바뀌는 것(§3)은 사용자 확인 대기
- 「(반지 · 목걸이도) 맞음 그렇게 해야해」 — 09-21 「세 층 — 죄종 칸 + 공통 풀」을 바꾼다. 후보 모양은 미정(§2 D2) · 장갑도 계열표를 정할 때 같은 원칙(GAME_DESIGN.md §10 「10-06 옵션 개정의 남은 칸」 ④)
- 「대신에 죄종에서 붙는건 1.5배 더 좋게 붙기로 햇었나?」 — **정한 적 없다.** 10-04 「메인 줄 = 나머지 × 약 1.5배」(`sin_line_band_mult` · 미발행)는 10-05 사용자 「1.5배 같은 거 넣지 말고」로 걷혔고(item_design.md §1 「대역은 하나다」), 10-18 「매직 고점 1.5배」는 희귀도 이야기로 10-20 폐기됐다. 되살릴지는 §2 D1

## 1. 지금 부위별 굴림 [10-20 코드 기준]

뼈대는 전 부위 같다 — 고정 옵션 → 죄종 줄(일반 0 · 매직 1 · 레어 2 · 반드시) → 랜덤 칸 `[balance.csv:item_random_slots]`(매직 · 레어 · 칸마다 붙을지 굴림). 갈리는 것은 **랜덤 줄이 어디서 고르는가**다.

| 부위 | 고정 | 죄종 줄 | 랜덤 줄이 고르는 곳 | 기획과 |
|---|---|---|---|---|
| 무기 | 무기 데미지 % | 그 죄종 계열 ①②③ 중 하나 | **계열표 전체**(일곱 죄종 × 셋) 중 안 붙은 것 · 오만 제외 | 같다(10-05) |
| 갑옷 | 방어력 % | 같은 방식 | 같은 방식 | 같다(10-05 · R209) |
| 투구 | 방어력 % | 죄종마다 칸 하나(09-17 옛 표) | 갈래별 공통 풀 — 플레이트 원소 저항 · 피해 감소 · 경험치 / 가죽 공격 속도 · 치명타 확률 · 경험치 / 티아라 쿨타임 감소 · 경험치 | **다르다** — 10-09 계열표 미반영(R229) |
| 장갑 | 방어력 % | 죄종마다 칸 하나(옛 무기 행을 옮긴 ⚠임시) | 공통 풀(옛 장갑 풀 ⚠임시) | 계열표 미정 |
| 신발 | 방어력 % | 죄종마다 칸 하나(09-18 옛 표) | 공통 풀 — 빙결 · 중독 시간 감소 · 최대 HP · 경험치 | **다르다** — 10-09 계열표 미반영(R229) |
| 반지 | 없음 | 죄종마다 칸 하나 | 반지 · 목걸이 공통 풀 — 원소 저항 · 피해 감소 · 상태이상 시간 감소 · 버프 지속 · 경험치 | 같다(09-21) — §0 으로 바뀐다 |
| 목걸이 | 발동 스킬 | 같은 방식 | 반지와 같은 풀 | 같다(09-21) — §0 으로 바뀐다 |

- 세 층 부위(투구 · 장갑 · 신발 · 반지 · 목걸이)는 **다른 죄종 칸의 옵션이 랜덤 줄로 절대 안 붙는다** — 공통 풀이 죄종 칸과 따로 있다
- 투구 티아라는 옛 공통 풀이 칸 수보다 작아 끝 칸이 비어 남는다(GAME_DESIGN.md §10 「희귀도 개정의 남은 칸」 ③) — R229 가 들어가면 사라진다

## 2. 정할 것

| # | 질문 | 후보 · ⚠제안 |
|---|---|---|
| D1 | **죄종 줄을 랜덤 줄보다 높게 굴리나** | ⚠제안 **지금대로 — 같은 범위.** 범위가 둘로 갈리면 Shift 범위 표시와 결투장 몰빵 상한을 두 벌로 본다 · 되살리면 10-05 「1.5배 같은 거 넣지 말고」를 뒤집는다 |
| D2 | **반지 · 목걸이의 랜덤 줄 후보** | (가) ⚠제안 **다른 죄종 칸 옵션 + 지금 공통 풀을 합친다** — 공통 풀(원소 저항 · 상태이상 시간 감소 등)은 다른 갈 곳이 없어 남긴다 / (나) 죄종 칸 옵션만 · 공통 풀 폐기. 어느 쪽이든 ⚠제안 **오만은 랜덤 후보 밖**(무기 · 갑옷의 오만 규칙 — 10-06 — 과 같게) · 같은 옵션은 한 번 |
| D3 | **R229 에 같이 바뀌는 것 넷의 확인** | §3 ⓐ ~ ⓓ — 컬럼 이름 변경 · 컬럼 추가 · 행 삭제 · 새 능력치라 사용자 확인이 따로 필요하다 |
| D4 | **새 능력치 둘의 빈 값** | 행동 게이지가 넘칠 때 — ⚠제안 **한 바퀴 직전까지만 찬다**(라운드 시작과 동시에 행동하지 않는다 · battle_design.md §6) / 처치 시 체력 회복의 양 — ⚠제안 **처치할 때마다 최대 HP × 값** |

## 3. R229 를 넣으면 같이 바뀌는 것 — 사용자 확인 대기

투구 · 신발 표(item_design.md §1 「10-09 옵션 개정」)는 아래 넷이 있어야 선다.

- ⓐ **스킬 풀 컬럼** — `skill.csv` 의 `armor_pool` → `defense_pool`(이름만 · 값 · 갑옷 동작 그대로) + `attack_pool` · `buff_pool` · `debuff_pool` 신설. 기본 스킬의 분류는 skill_design.md §11-5 표를 그대로 옮긴다. 투구 오만 ①(버프 풀 특정 스킬 +n)이 이것을 읽는다
- ⓑ **갈래 컬럼** — `armor_sin_option.csv` 에 갈래를 더한다. 투구 · 신발은 ① 칸이 갈래마다 다르다(투구 나태 ① = 플레이트 · 가죽 · 티아라가 각각 다른 옵션)
- ⓒ **옛 공통 풀 행 삭제** — `armor_common_option.csv` 의 투구 · 신발 행. 장갑 행은 계열표가 서기 전까지 남는다
- ⓓ **새 능력치 둘 — 전투 코드**
  - 「전투 시작 시 행동 게이지 +%」(신발 분노 ①) — 원정은 시작 + 라운드가 바뀔 때마다 · 결투장은 판 시작 한 번 · 몬스터는 등장한 라운드에 한 번
  - 「처치 시 체력 회복」(투구 색욕 ① 가죽 · 티아라)

## 4. 묻지 않고 처리할 것 — 기획서 그대로

- **빈칸은 빈 채로 넣는다** — 투구 폭식 ① 가죽 · 티아라(「빈칸 그대로」 · 사용자가 대안을 넘어갔다) · 신발 오만 ①(사용자 「신발은 일단 스킬 패스」). 그 갈래는 그 칸의 옵션이 없다
- **새 옵션 행의 수치는 같은 능력치를 쓰는 다른 부위의 범위를 옮긴다**(⚠제안) — 반지 · 목걸이 표를 채울 때와 같은 방식(09-21)
- 투구 오만 ② ③(레벨당 체력 · 레벨당 방어력)은 10-06 초안의 ⚠제안 그대로
