# 스킬 설계

> 상위: [GAME_DESIGN.md](GAME_DESIGN.md) §4 · 발동 규칙: [battle_design.md](battle_design.md) §3

---

## 1. 구조 — 독립 트리 3탭 (D2 방식)

포인트 풀 공유, 배분 완전 자유.

```
[분노][마법사] 영웅의 스킬 탭:
├── 탭1: 분노 트리           — 죄종에서 옴 (모든 분노 영웅 공유)
├── 탭2: 마법사 마스터리 트리 — 직업에서 옴 (기초 골격)
└── 탭3: 마법사 전직 트리     — 직업 심화 (레벨 해금)
```

- **3택1 같은 선택 없음** — 개성은 "선택"이 아니라 **"배분"**에서 나온다. 같은 조합이라도 어디에 몰았느냐로 다른 영웅
- 포인트는 레벨업으로 지급. 전직 탭 해금: `[balance.csv:advance_unlock_level]` — 방치형 접속 동기
- **고유 패시브(유니크 영웅)는 탭 밖** — 스킬 포인트 불요, 3탭 구조와 포인트 경제 불변

## 2. 탭별 성격

| 탭 | 성격 | 내용물 방향 |
|---|---|---|
| **[죄종]** | 정체성 + 아이템 연결 | 죄종 고유 메커니즘 + **죄종 접사 시너지 노드** (예: "분노 접사 수당 치명타 보정"). 세트포인트 기반 노드는 세트효과와 함께 **보류** — item_design.md §4 |
| **[마스터리]** | 기초 골격 | 무기 숙련(직업별 무기군) · 방어구 숙련 · **무기군 스킬 강화 노드** — 액티브 자체는 무기군이 준다 (§3) |
| **[전직]** | 빌드의 본체 | 직업 심화 액티브 킷 |

## 3. 액티브 슬롯 — 출처 고정 3칸

**[2026-08-25 확정]** 슬롯은 "배운 액티브 중 아무 셋"이 아니라 **출처가 정해진 세 칸**이다. 순서(우선순위)는 자유.

| 칸 | 출처 | 결정의 성격 |
|---|---|---|
| **죄종** | 탭1 죄종 트리 액티브 | 내가 누구인가 — 영웅에 박힌 죄종 |
| **전직** | 탭3 전직 트리 액티브 | 뭘 배웠나 — 빌드의 본체 |
| **무기군** | **착용 무기군이 준다** (트리에서 배우지 않음) | 뭘 들었나 — 장비 결정이 곧 스킬 결정 |

- 슬롯 순서 = 동시 준비 시 우선순위 (발동 규칙: battle_design.md §3). **출처는 고정, 순서는 자유** — 우선순위는 플레이어 통제로 남긴다
- 전직 해금 전엔 죄종 + 무기군 2칸으로 돈다. 무기는 항상 들고 있으므로 무기군 칸은 시작부터 찬다
- 각 출처에 액티브가 **2개 이상** 있어야 그 칸이 "결정"이 된다 — 1개뿐이면 결정이 아니라 표시다
- 슬롯은 상한이다 — 무제한이면 다 넣는 게 정답. **배분(트리)과 편성(슬롯)의 분리**는 유지 — 편성 = "각 출처에서 어느 것을" + "어떤 순서로"
- 실제 빌드 결정은 포인트 배분 — 1개 몰빵 vs 분산 (D2의 시너지 대 분산 구조)
- 쿨 설계 지침: 하한은 `행동 주기 × 슬롯 수` 근처 (battle_design.md §6)

### 무기군 스킬 — 무기군에 붙고, 개체에 붙지 않는다

- **무기군이 스킬의 종류를 정하고, 세기는 정하지 않는다.** 흰 도끼든 레어 도끼든 도끼 스킬은 같다. 세기 = 마스터리 배분 + 전투 능력치(9슬롯 전체 파생). 무기 개체의 접사는 기본 공격에 기여하는 만큼만 스킬에 기여하고, **스킬 전용 파워 축을 갖지 않는다**
- 왜: "운 좋게 먹은 무기 하나"가 스킬을 주는 일이 없어야 한다. 무기군은 직업 전속 범위 안의 **선택**이지 드롭 운이 아니다. 무기 지배력의 손잡이는 여기가 아니라 피해 공식(무기공을 밑수가 아닌 항 하나로)과 나머지 부위의 역할(쿨감·생존·명중)에 있다
- 고유 패시브 규칙("어떻게 싸우는가는 패시브가, 얼마나 강한가는 장비가" — hero_design.md §1)을 무기에 뒤집어 적용한 것
- 예외 후보는 **유니크 무기**뿐(스킬 교체/변형). 허용하려면 "유니크 ≤ 잘 굴린 레어" 가드레일을 아이템 쪽에 먼저 세운다 — 세트효과 보류로 유니크 vs 레어 긴장이 드롭률 하나뿐인 상태 (item_design.md §1)
- 규칙형(선제타·경직 등)은 무기군 Implicit과 같은 이유로 진형·타겟팅 확정 전엔 못 짠다 — 수치형(다단타·피해 편차·행동 주기 활용)부터
- "슬롯3 = 스킬 카드(몬스터 카드 제작)" 안은 **불채택** — 새 시스템 4~5종 · 드롭 운 · 카드는 낡지 않아 몰빵이 영구화 · 초반 빈칸. 카드의 가치(파밍 동기·제련소·수집)는 슬롯과 무관한 별개 결정

## 4. 콘텐츠 수량

```
트리 수 = 죄종 7 + 마스터리 N + 전직 N = 7 + 2N   (본편 N=5 → 17개)
```

- 직업 1개 추가 비용 = 트리 2개 — 선형 확장. 조합 다양성(곱셈)은 유저 쪽에서 발생
- **무기군 스킬 = 무기군 수** — 본편 7 / 확장 9 (hero_design.md §2). 트리 밖의 액티브 정의
- 본 프로젝트 최대의 콘텐츠 부채 — 노드 규모를 정할 때 총량 감각을 먼저 잡을 것

## 5. 보류 — 스킬 카드 합성

**[2026-08-25]** 비전투 활동 논의에서 나온 "합성"은 시설 활동이 아니라 **스킬 카드 합성**이라는 별개 개념이다. 후속 과제 — 스킬 카드가 무엇인지(3탭 트리 · 액티브 슬롯 3과의 관계)부터 정의한다. 넣을 때 별도 시설(공방)을 세우지 않고 **제련소 기능**으로 들어간다. 정의 전까지 다른 문서에서 참조하지 않는다.
