# 북방 생존 방치 게임 기획

> **이전 작업 공간의 보관본 · 2026-10-04 이관.** 현재 기획은 새 프로젝트의 [GAME_DESIGN.md](../../../northward-idle/docs/design/GAME_DESIGN.md)에서 관리한다. 이후 합의와 변경은 새 작업 공간에 저장한다. 아래 내용은 이관 전 논의의 보관본이다.

Melvor Idle을 참고하는 새 게임의 현재 기획이다. 캐릭터의 숙련과 장비를 발전시키면서 북방의 지역들을 차례로 탐험하고, 계속 다가오는 위협을 자동 수비로 막아낸다. 접속을 종료한 동안에도 습격과 수비가 진행되며, 돌아오면 결과를 확인한다.

현재 대화에서 합의한 방향과 실행자가 제안한 세부안을 구분해 기록한다. 정식 게임 이름과 새 프로젝트의 구현 위치는 아직 정하지 않았다. TheSevenSimulationRPG의 기존 기획과 코드를 변경하는 문서는 아니다. 논의 과정은 [대화 요약](DISCUSSION_LOG.md)에 있다.

## 확정한 방향

| 항목 | 현재 방향 |
|---|---|
| 게임 형태 | 생존 테마의 텍스트 중심 방치 게임. Melvor Idle의 숙련 누적과 채집·가공·보급의 연결을 참고한다. |
| 주인공과 성장 | 캐릭터 한 명의 숙련·장비·제작 능력과 야영 생활을 발전시킨다. |
| 배경 | 북방의 지역들을 차례로 탐험한다. 기본 화면의 바탕색은 파란색 계열로 한다. |
| 지역 진행 | 지역별 챕터로 진행한다. 다음 지역에 필요한 도구·장비·보급을 준비하며 성장한다. |
| 야영지 | 여정을 보여주는 배경으로 사용한다. 야영지 이사와 시설 재건을 핵심 반복 작업으로 만들지 않는다. |
| 생존 | 음식과 장비가 탐험할 수 있는 범위와 지속 시간을 결정한다. 생존 준비와 보급을 중심으로 한다. |
| 전투 | TheSevenSimulationRPG의 Focus Stop 연출을 사용하는 자동전투와 비슷한 관전 화면을 채택한다. |
| 접속 중 진행 | 탐험은 장비·제작·도감 등 다른 화면을 살펴보는 동안에도 계속 진행된다. 관전 여부가 진행 속도를 바꾸지 않는다. |
| 수비 | 위협은 접속 중과 오프라인 모두 다가온다. 자동 수비를 진행하고, 복귀하면 결과를 보여준다. |
| 작업 방식 | 중요한 핵심은 사용자와 함께 정한다. 나머지 세부 설계는 실행자가 판단해 구체화한다. |

## 게임의 목표와 활동 연결

목표는 북방의 지역을 탐험하면서 계속 다가오는 위협을 감당할 힘을 기르는 것이다. 탐험은 새로운 자원·제작법·장비를 제공하고, 채집과 제작은 탐험과 수비에 필요한 준비를 만든다. 수비가 안정되면 다음 지역에 도전할 수 있다.

접속했을 때 플레이어는 결과를 확인하고, 장비와 보급을 개선하고, 다음 활동과 탐험 목표를 선택한다. 진행과 자동전투는 그 준비에 따라 이루어진다.

최종 챕터의 도전, 이야기의 결말, 이후 반복 콘텐츠는 아직 정하지 않았다. 수집과 숙련의 전체 완성을 장기 목표로 두는 것은 제안 상태다.

## 생존과 성장 보존

합의한 기본 방향은 안전한 일상 작업과 준비가 필요한 탐험이다. 야영지의 채집·제작은 필요한 입력 재료가 떨어지면 멈춘다. 탐험은 보급을 자동 소비하고, 보급이 부족하면 귀환하는 방향으로 잡는다.

탐험 실패의 기본안은 일부 보급을 잃고 귀환하는 것이며, 숙련과 핵심 장비는 유지한다. 오프라인 습격이 추가되어 야영지에서도 수비 전투가 발생하므로, 수비 패배의 손실과 회복·재개 규칙은 별도로 구체화해야 한다.

## 지역과 야영지

챕터마다 새로운 자원과 제작법이 열리고, 준비한 도구와 장비가 다음 장소의 탐험으로 이어지게 한다. 숙련·장비·작업 기능은 지역 진행에 따라 이어간다.

북방의 계곡·침엽수림·얼어붙은 호수·폐광·설산·유적은 후보 지역이다. 실제 지역 수와 순서, 이름, 자원 배치는 실행자가 초안을 만든다. 지역별 환경 차이를 우선하는 안을 논의했으며, 계절 시스템의 구체 규칙은 확정하지 않았다.

이전 지역의 활동을 계속 선택할 수 있게 하는 것은 기본 설계안이다. 새 지역으로 넘어갈 때 반복적인 이사 비용보다 새로운 활동과 성장의 보람을 중심에 둔다.

## 접속과 오프라인 진행

| 활동 | 접속 중 | 오프라인 |
|---|---|---|
| 채집·제작 | 선택한 활동이 진행된다. | 선택한 활동이 진행된다. |
| 탐험 | 관전 화면을 벗어나도 진행된다. | 신규 지역 탐험과 이미 돌파한 지역의 반복 탐험을 어떻게 나눌지는 미정이다. |
| 습격과 자동 수비 | 계속 발생하고 진행된다. | 계속 발생하고 진행되며 결과를 기록한다. |

‘보고 있을 때’라는 표현은 탐험 화면을 계속 열어두어야 한다는 뜻으로 사용하지 않는다. 접속 중에는 다른 화면을 살펴봐도 탐험이 이어진다는 사용자의 설명을 기준으로 한다. 화면을 바꾸는 것과 진행할 활동을 바꾸는 것은 구분해야 한다.

신규 지역과 챕터 돌파는 접속 중에, 이미 돌파한 지역의 반복 탐험은 오프라인에도 진행하게 하자는 제안이 있었다. 사용자가 명확히 확인한 것은 접속 중의 지속 진행이다. 오프라인 탐험의 정확한 범위는 이 제안을 확정 사항으로 간주하지 않고 남겨둔다. 오프라인 수비는 확정 사항이다.

접속 중 관전·다른 화면·오프라인의 자동 수비는 같은 준비와 같은 경과 시간에 대해 같은 규칙으로 계산한다. 오프라인 계산 상한과 복귀 요약의 보관 범위는 아직 정하지 않았다.

## 전투와 관전 화면

전투 전의 무기·방어구·스킬·보급 준비가 입력이고, 시작한 전투는 자동으로 진행한다. 한 유닛이 행동할 때 다른 전투 진행을 잠깐 세우고, 앞으로 나감·타격·복귀를 보여주는 Focus Stop 방식의 박자를 채택한다.

화면은 기존 게임을 참고해 위쪽에 적, 아래쪽에 주인공을 배치하고, 초상·체력·행동 게이지·스킬 칸·피해 숫자·피격 반응을 보여주는 안으로 구체화한다. 주인공 한 명의 신작에 맞는 카드 크기와 적의 수는 세부 설계에서 정한다.

현재 기존 게임의 Stop 구현은 관전 중 정지한 만큼 실제 진행을 늦춘다. 신작은 관전 여부로 전투 속도와 보상이 달라지지 않도록 설계해야 한다. 정지 박자를 공통 전투 시간에 반영하는 안을 논의했다. 전투 공식과 콘텐츠를 기존 게임에서 어느 범위까지 가져올지는 아직 정하지 않았다.

참고: [기존 Stop 구현](../../src/ui/battle.js), [기존 화면 규격](../client/SCREEN_DESIGN.md)의 전후 비교 버튼 절.

## 오프라인 수비의 세부 설계안

다음은 합의한 수비 방향을 구체화하기 위해 실행자가 제안한 안이다. 발생 간격·난이도 곡선·손실 수치는 아직 정하지 않았다.

- 습격이 발생하면 진행 중인 활동을 잠시 멈추고 수비한다. 수비가 끝나면 원래 활동을 이어간다.
- 공세의 강도는 현재 지역을 기준으로 정한다. 같은 지역에서는 준비를 갖출수록 안정적으로 버티고, 다음 지역에 진입하면 더 강한 공세를 상대한다.
- 패배의 손실은 보급품과 일부 재료에 두고, 누적 손실에 한도를 둔다. 숙련·핵심 장비·야영지 기능은 유지하는 방향으로 구체화한다.
- 복귀 요약은 습격 횟수, 수비 성공과 실패, 소모한 보급, 얻은 전리품, 중단된 작업 시간을 보여준다.

온라인 탐험 중에 습격이 발생했을 때 주인공이 어떻게 수비에 참여하는지, 패배 뒤 어떻게 회복하고 활동을 재개하는지는 이 안에서 이어서 설계한다.

## 실행자가 이어서 구체화할 내용

- 새 프로젝트의 이름과 구현 위치, 첫 프로토타입의 범위.
- 첫 챕터의 실제 활동과 해금 흐름, 스킬·자원·레시피·장비 구성.
- 오프라인 탐험의 범위, 캐릭터 활동의 동시 진행 여부와 습격에 따른 중단·재개 규칙.
- 습격 간격과 지역별 공세, 패배 손실·누적 한도·회복 모델.
- 음식의 탐험 보급과 전투 회복 역할, 야영지 작업 기능의 성장.
- 최종 챕터와 장기 목표, 저장·복귀 계산·복귀 요약의 구체 규칙.

핵심 방향을 바꾸는 선택은 사용자와 다시 논의한다. 그 외 세부안은 실행자가 판단해 만들어 제안과 확정을 구분해서 기록한다. 수치는 구조를 정한 뒤 데이터 표로 구체화한다.
