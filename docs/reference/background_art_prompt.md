## 2. 도트를 101·102 처럼 작게 보이게 하는 법

**도트가 커 보이는 원인은 해상도가 아니라 그림 방식이다** — 큰 물체 몇 개를 가깝게 그린 구도 + 굵은 검정 외곽선 + 평평한 칠.

- **첨부는 101 · 102 만** (101 → 102 순). 다시 그릴 대상 그림은 첨부하지 않는다 — Gemini 가 원래 격자 · 구도를 그대로 따라간다
- STYLE 에 넣을 것:
  - 칸 크기를 숫자로 — 가로 약 700칸(「두 번째 첨부처럼」)
  - 굵은 검정 외곽선 · 평평한 칠 금지 → 빛 · 색 · 디더링 명암으로 형태
  - 멀리서 본 원경 — 작은 물체 여럿, 랜드마크는 폭 1/5 이하
- 결과는 칸 수를 재서 확인한다(§5) — Gemini 의 「두 배로 그렸다」 같은 답변은 믿지 않는다

## 3. 프롬프트 구조

- **챕터 공통 블록**(STYLE · VIEW · LAYOUT · WORLD · AVOID) + **스테이지 블록**(SCENE · LIGHT & COLOR)
- **스테이지 블록에는 내용과 조명만** — muted · dusty · dulled 같은 색 누르는 말을 넣으면 그림체가 튄다(305 가 세피아 단색으로 나왔다)
- **배치** — 가운데는 비운 공터 · 랜드마크 아래쪽 절반이 높이 40~75% · 위 12% 는 하늘(천장)만 · 아래 20% 는 비운 바닥(워터마크가 높이 81~88% 에 박혀 잘라 낸다)
- **실내 스테이지**는 스테이지 블록 AVOID 에 `palm trees, wells, sand dunes, windows, sky` — 공통 WORLD 의 바깥 풍경 문장이 새어 든다
- **챕터보스 방(스테이지 5)** — 대칭 · 높은 단 · 온전한 건축으로 위엄. 벽 구멍 · 폐허 금지. 단 새것 · 매끈함도 금지(먼지 · 그을음 유지)
- **글자 금지** — 묘비 · 계약서 · 두루마리에 글씨가 잘 생긴다. 봉인 · 빈 이름판으로 대신
- **죄종 색은 스테이지 1 → 5 로 짙어진다** · 언데드 스테이지는 챕터에서 가장 차갑게
- 이야기 요소는 `stage.csv:story_kr` 기준, 없는 장면만 `docs/game_design/story/ch*_*.md` 원고에서

## 4. 해 봤고 안 되는 것

| 시도 | 결과 |
|---|---|
| 파일 해상도 올리기 · 2배 확대 | 게임 화면이 픽셀까지 같다 (Edge 헤드리스 1:1 실측) |
| 그림을 첨부해 「픽셀 잘게 · 2×2 분할」 편집 | 두 번 모두 가로 480칸 그대로, 파일만 2배 |
| 코드로 가로 720칸 격자 맞추기 | 칸 수는 정확하지만 체감 차이가 작다 — 외곽선 · 구도가 그대로 (103 시험 후 되돌림) |
| 64색 이하로 색 줄이기 | 불빛 · 붉은 깃발 같은 드문 강조색이 사라진다 |

## 5. 설치 · 측정

1. `source/` 의 Gemini 파일을 판별해 `background_stage_<id>.png` 로 개명
2. 워터마크 위치 확인 → 높이 80%(`615 * H // 768`)로 잘라 `backgrounds_clean/` 에 WebP q92
3. 설치본 오른쪽 아래 확대로 ✦ 제거 확인
4. `stage.csv:bg=1` · README 표 갱신 · `bg=1` 과 파일 존재 일치 검사
5. 필요하면 Edge 헤드리스로 게임 CSS(`cover` · `center 95.2%` · `pixelated`)를 입혀 1:1 촬영 비교

**칸 수 측정** — 열(행)마다 인접 색 차이를 더한 신호의 FFT 봉우리로 격자 간격을 구하고 파일 폭 ÷ 간격. 분석 범위는 1.9~14px(2px 칸을 놓치지 않게). 「1px 색 변화 개수」처럼 파일 배율에 따라 달라지는 잣대는 쓰지 않는다.
실측 기준: **101 = 480칸** · **102 ≈ 690~790칸(칸 크기 불규칙)** · 신규 13장 = 480칸
