## 1. FFXIV 인게임 로그 필터

### 1-1. 설정 위치와 구조
`Character Configuration(캐릭터 컨피그) → Log Window Settings(로그 창 설정) → Log Filters(로그 필터)` 아래 **General(일반) / Battle(전투) / Announcements(공지)** 3개 탭으로 나뉘고, 탭마다 체크박스 매트릭스로 표시 항목을 켜고 끈다.
출처: [SE 공식 UI 가이드 — 채팅을 끄고 싶을 때](https://jp.finalfantasyxiv.com/uiguide/communication/communication-chat/chat_turnoff.html), 다수 공략 블로그(ff14ayu.blog, eoryman.com)가 이 구조를 반복 인용.

⚠ **정확한 체크박스 원문 전체 목록은 확보 실패(N/F)** — 공식 가이드 페이지는 설정 화면 스크린샷(이미지)으로만 항목을 보여주고 본문 텍스트에는 항목명을 적지 않는다. 텍스트 검색·포럼 스레드 다수를 확인했으나 라이브 UI의 체크박스 원문을 그대로 옮긴 텍스트 자료를 찾지 못했다.

대신 SE 공식 포럼의 배틀 로그 개선 요청 스레드가 **현재 필터축의 구조**를 (비판하면서) 그대로 드러낸다:
> 출처: [Make these changes to the Battle Log](https://forum.square-enix.com/ffxiv/threads/218911)

글쓴이가 제안하는 재구성안이 오히려 기존 필터의 골격을 보여준다 — **주체(자신/파티원/몬스터) × 사건 종류(가한 피해/받은 피해/시전한 회복/받은 회복/버프·디버프·이펙트/DoT 틱)** 의 교차 매트릭스:

| 주체 축 | 사건 축 |
|---|---|
| Self(자신) | 적에게 입힌 피해 |
| Party Member(파티원) | 플레이어가 받은 피해 |
| Monster(몬스터) | 받은 회복 / 시전한 회복 |
| (다른 플레이어·펫 등도 별도 축으로 존재한다고 다수 포럼 글이 언급) | 버프/디버프/이펙트 부여·해제 |
| | DoT(도트) 틱 데미지 |

→ **"업계에서 가장 잘게 갈려 있다"는 전제와 일치**: 주체×사건의 곱집합으로 체크박스가 늘어나는 방식이라 "자신이 준 피해"와 "파티원이 준 피해"와 "몬스터가 준 피해"가 전부 독립적으로 켜고 끌 수 있는 別항목이다. 다만 라이브 게임의 정확한 항목 명칭 원문은 이번 조사로 확정하지 못했다 — 인게임에서 직접 캡처하는 것이 유일한 확정 방법.

### 1-2. 빠르게 읽게 하는 장치 — 색·아이콘
FFXIV 공식 UI 가이드에서 확인:
- **플라잉 텍스트(피해 팝업) 색상**: 내가 적에게 준 피해 = **주황색**, 나 또는 파티원이 받은 피해 = **빨간색**, 회복된 HP/MP = **초록색**.
- **치명타**: 더 큰 글자 크기 + **느낌표(!)** 하나. **크리티컬 다이렉트 히트**(치명타+직격 동시 발생)는 **느낌표 두 개(!!)**.
- **패치 6.3부터** 피해 숫자 옆에 **피해 유형 아이콘**(물리/마법 등)이 추가로 붙는다.
- Battle Effects(전투 이펙트) 설정에 `Show All / Show Limited / Enemy PC / Show None` 옵션이 있어 혼잡한 다인전에서 이펙트 자체를 줄여 가독성·프레임을 지킨다.

출처: [na.finalfantasyxiv.com UI Guide — What is flying text?](https://na.finalfantasyxiv.com/uiguide/battle/battle-ftpt/battle_flyingtext_about.html), [How do I adjust the graphical effects displayed in battle?](https://na.finalfantasyxiv.com/uiguide/faq/faq-other/setting_bteffect.html)

**본작 시사점**: 색은 "누가 준·받은 피해인가"라는 **주체** 축을 인코딩하고, 문자 크기·느낌표 개수는 "얼마나 특별한 사건인가"(치명타/직격)라는 **강도** 축을 인코딩한다. 두 축을 분리해서 인코딩하는 방식은 좁은 세로 열에서도 재사용 가능.

### 1-3. ACT 애드온 쪽 원본 로그 스키마 (참고용 — 네이티브 UI 아님)
FFXIV 자체는 유저에게 raw 로그를 노출하지 않지만, ACT/OverlayPlugin(cactbot) 생태계가 네트워크 패킷을 파싱해 만든 **Network Log Line** 포맷이 사실상 업계의 "무엇을 한 줄에 담아야 하는가" 표준 답안이다.

출처: [cactbot LogGuide.md](https://github.com/OverlayPlugin/cactbot/blob/main/docs/LogGuide.md) (⚠아래 필드 순서는 문서 구조상 맞으나, 예시 줄의 정확한 16진수 값까지는 재검증 못함 — 필드 존재·순서만 신뢰)

**Line 21/22 (NetworkAbility / NetworkAOEAbility)** 필드 순서:
```
Type, Timestamp, SourceId, SourceName, AbilityId, AbilityName,
TargetId, TargetName, Flags, Damage,
[효과 8쌍], TargetCurrentHp, TargetMaxHp, TargetCurrentMp, TargetMaxMp,
TargetX, TargetY, TargetZ, TargetHeading,
CurrentHp, MaxHp, CurrentMp, MaxMp, X, Y, Z, Heading,
Sequence, TargetIndex, TargetCount, OwnerId, OwnerName, ...
```
**Line 25 (NetworkDeath)**:
```
Type, Timestamp, TargetId, TargetName, SourceId, SourceName
```
→ 사망 이벤트는 **"누가 무엇에게 죽었나"** 단 4개 필드로 충분히 표현된다는 점이 눈에 띈다. 본작의 "죽음 원인" 로그 줄 설계에 참고할 만한 최소 스키마.

**본작 시사점**: 한 줄에 "누가(주체) → 무엇을(스킬) → 누구에게(대상) → 얼마나(수치) → 어떤 조건에서(플래그=치명/직격/블록 등)"가 고정 순서로 들어간다. 우리 전투 로그 한 줄도 이 5요소 순서(주체·스킬·대상·수치·플래그)를 그대로 채용하면 다국어 템플릿 문장 생성이 쉬워진다.

## 2. ACT + FFLogs — rDPS/aDPS/nDPS와 딜미터 컬럼

### 2-1. 기여도 보정(rDPS 계열) 산식과 취지
출처: [FFLogs 공식 — A Guide to rDPS, aDPS and nDPS](https://www.fflogs.com/help/rdps)

| 지표 | 산식(요지) | 목적 |
|---|---|---|
| **DPS** | 순수 관측 피해량/시간 | "화면에 뜬 그대로"의 딜 |
| **rDPS** (raid-contributing) | `DPS − (남의 버프로 내가 더 받은 피해) + (내 버프로 남이 더 준 피해)` | **"이 사람이 공격대에 실제로 기여한 피해"** — 버프/디버프를 준 사람에게 그 효과의 몫을 되돌려주는 회계 |
| **nDPS** (neutral) | `DPS − (남의 버프로 얻은 이득만 제거)` | 내가 남에게 준 버프 기여는 남겨두고, **순수 내 로테이션 실행력**만 보고 싶을 때 |
| **aDPS** (adjusted) | `DPS − (특정 단일 대상 강화 스킬 이득만 제거)` (예: 무희 Devilment, 점성 카드, 좌안 등) | 단일 대상 몰아주기(패딩)만 걷어내고 광역 버프 활용은 그대로 인정 |

**왜 생겼나**: 버프/디버프를 주는 서포트 계열 직업(무희·시노비 등)은 "내가 화면에 낸 숫자"가 아니라 "내가 남에게 준 숫자"가 진짜 기여인데, 순수 관측 DPS는 이걸 못 잡는다. rDPS는 **버프를 준 사람 쪽으로 피해를 재분배하는 회계 규칙**이다 — 본작이 겪을 "버프/회복 영웅이 딜 0으로 보이는 문제"와 **정확히 같은 문제의 이 장르 표준 해법**.

### 2-2. 딜미터/로그 사이트 컬럼 구성
출처: [icy-veins — FFLogs Breakdown](https://www.icy-veins.com/ffxiv/fflogs-breakdown), [icy-veins — FFLogs Death Information](https://www.icy-veins.com/ffxiv/fflogs-death-information)

| 컬럼/탭 | 내용 |
|---|---|
| Damage Done | 스킬별 사용 횟수 + 전체 피해 기여 비율(막대그래프) |
| Healing Done | 힐러 툴킷별 총 힐량 기여 |
| Casts | 피해·힐과 무관한 시전까지 포함한 전체 스킬 사용 로그 |
| Timeline | 가로 시간축에 스킬 사용 시점을 점으로 배치 — 다른 플레이어 로테이션과 시간 정렬 비교 |
| HPS / Overhealing | 초당 회복량 / **오버힐(낭비된 회복)** — 힐량 그래프에서 오버힐 구간을 채워진 색으로 별도 시각화 |
| Damage Taken | 인카운터 중 받은 피해 총량 |
| Deaths 탭 | 사망 시점 + **사망 직전 받은 피해·받은 힐 요약**을 함께 보여줌 → 사망 원인 역추적 |
| Mitigation Uptime | 피해 경감기 가동률(%) |

**세그먼트 경계**: 인카운터는 전투 시작~종료(또는 전멸)로 자동 분리되고, 그 안에서 페이즈는 보스 기믹 트리거를 기준으로 리포트가 임의 구간을 잘라 보여준다(픽·풀 단위 비교가 핵심 사용 패턴).

### 3-3. 기여도 회계 — 가동률 vs 유효율 (본작 핵심 참고)
출처: [인벤 — 전투분석기 정리 글(가동율과 유효율)](https://www.inven.co.kr/board/lostark/5350/169085), [루리웹 — 가동률과 유효율의 차이](https://bbs.ruliweb.com/community/board/300143/read/71623520)

서포터(버퍼/힐러)는 "딜량 0" 문제를 딜미터 지표 하나가 아니라 **성격이 다른 두 지표로 분리**해서 푼다:

- **가동률(uptime)**: 버프 효과가 적용된 시간 ÷ 총 전투 시간. **서포터 자신의 실력만 반영**(스킬을 제때 넣었는가) — 파티원 딜러의 실력과 무관.
- **유효율(effective rate)**: 버프 영향을 받은 피해량 ÷ 파티 총 피해량. **딜러의 실행력에 크게 의존** — 버프를 잘 넣어도 딜러가 그 타이밍에 못 때리면 낮게 나옴.

→ FFXIV의 rDPS가 "버프 기여를 한 숫자(딜)로 환산해 돌려주는" 방식이라면, 로스트아크는 **"내 몫"(가동률)과 "파티 곱셈 효과"(유효율)를 애초에 숫자를 합치지 않고 나란히 보여주는** 방식. 두 장르 모두 "서포터를 딜러와 같은 자로 재지 않는다"는 결론은 같되, **FFXIV=환산 통합, 로스트아크=분리 병기**라는 서로 다른 해법을 택했다.

### 3-4. 운영사가 겪은 부작용과 유저 요구
출처: 나무위키 문서, 인벤 뉴스

- **반대 논리**: 사이버불링(강퇴·비난), "정치질" 심화, 직업간 밸런스 갈등 표면화
- **찬성 논리**: 고난도 레이드에서 객관적 정보 필요, **어차피 사설 프로그램(메테오 등)·스펙 사이트로 이미 현실화**되어 있어 공식 미제공이 정보 격차만 키움
- 도입 후에도 "서포터 유효율 계산 세부 개선 요청", "특정 직업(아르카나 등) 버프 측정 한계" 같은 시스템적 한계가 커뮤니티에서 계속 제기됨 — **완전한 만능 해법은 아님**

## 4. 보조 — GW2 / 검은사막의 절충

**Guild Wars 2 (arcdps, 비공식 애드온)**: 공식은 딜미터를 안 만들고, 커뮤니티 애드온 `arcdps`가 사실상 표준이 됐다. 기본 표시는 `총 광역(cleave) 피해 + 초당 광역 피해`이며, 상단 바를 우클릭해 컬럼 포맷 코드(`@1 (@2 @3)` 등)를 직접 조합해 단일 대상 DPS·점유율 등을 끼워 넣는 **완전 커스텀 텍스트 포맷** 방식을 취한다(운영사가 만들지 않았기에 표준 UI가 없다). 로그는 `.evtc` 파일로 저장돼 사후 사이트(dps.report)로 심층 분석. 부작용은 로스트아크와 판박이 — "낮은 딜량으로 프랙탈에서 강퇴당했다"는 포럼 불만이 다수 확인되며, 공식 입장은 "허용은 하되 만들지 않는다"는 방임형.
출처: [Snow Crows — Reading Logs](https://snowcrows.com/guides/arcdps/reading-logs), [GW2 포럼 강퇴 스레드](https://en-forum.guildwars2.com/topic/42427-in-raids-i-get-kicked-everytime-by-people-using-arcdps-why-are-they-allowed-to-see-my-dps/)

**검은사막**: 정반대 극단 — **피해 숫자 자체를 공식적으로 표시하지 않고, 앞으로도 안 만들겠다는 입장을 명시**했다. 유저는 표준화된 조건(같은 더미·같은 시간)에서 사설 도구로 직접 측정해 비교하는 수밖에 없다. "정보 자체를 안 준다"는 이 극단은 본작과는 거리가 멀지만(본작은 이미 누적 데미지 판이 있음), "정보를 안 주면 사설 스펙 문화가 대신 채운다"는 로스트아크 사례와 대칭을 이뤄 반면교사로 유효하다.
출처: [나무위키 — 검은사막/문제점](https://namu.wiki/w/검은사막/문제점)
