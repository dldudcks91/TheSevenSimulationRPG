# 00. 범위와 주요 발견

## 연구 목적

사용자가 제시한 출발점은 “열차가 계속 움직이고, 정류장에서 물건을 싣고, 서부영화처럼 카우보이가 등장하는 게임”이다. 먼저 원작 《Frostrain 2》가 움직이는 열차를 어떤 시스템으로 바꾸었는지 분석하고, 그 뒤 우리의 아이디어에 적용할 부분을 분리했다.

대상은 전편 《Frostrain》, 체험판, 오래된 얼리 액세스 공략을 섞은 합성 게임이 아니다. **현재 기능은 1.0.4까지의 공식 변경 기록을 우선하고, 과거 자료는 변경 이유를 이해하는 데 사용한다.** 최종 실행 파일 전체를 검증한 것은 아니므로, 공지 이후의 미공지 수정 가능성은 남아 있다.

## 작품의 정체성

**공식 확인:** 개발·배급은 nemonan이다. 정식 출시일은 2026-07-16이다. 상점은 시너지 구성 중심의 로그라이크에 경영 요소를 더한 게임으로 설명한다. 객차와 유물, 노선, 차장의 선택이 핵심이다. [상점](https://store.steampowered.com/app/3690490/Frostrain_2/)

**해석:** 가장 유용한 관점은 **“움직이는 열차 위에서 생산 빌드를 만드는, 실시간 압력이 있는 로그라이크”**다. 상점의 장르 태그만으로 방치형 게임이라고 단정할 근거는 없다. 시간은 흐르지만 보급 선택·객차 교체·경로 결정·사건·결단에 계속 개입한다. 플레이 화면에 일시정지와 배속 버튼이 있으며, 중요한 선택 화면을 자동으로 멈추는 개선도 공식적으로 이루어졌다. [N066](11_SOURCES.md#n066), [N102](11_SOURCES.md#n102), [화면 기록 V01](10_OBSERVATION_LOG.md)

방치형과의 차이는 클릭 수 하나로 결정되지 않는다. 떠나 있는 동안 성장하는 것이 중심인지, 판 안에서 압력이 증가하고 선택을 해결해야 하는지가 중요하다. 이번 자료에는 오프라인 수익 기능을 확인한 근거가 없으므로 원작에 그런 기능이 있다고 쓰지 않는다.

## 핵심 발견

### 1. 열차는 생산 설비이면서 빌드의 시각화다

열차의 객차는 화면 속 장식과 카드가 대응한다. 객차가 늘고 층이 높아지는 모습, 탑승자의 이동, 행복 수치의 변화가 구성의 성장과 연결된다. **해석:** 추상적인 덱 성장을 이동하는 생활 공간으로 보여 주는 것이 중요한 매력이다. 단순히 카드 그림을 열차로 바꾸는 것만으로 같은 감각을 얻기는 어렵다. [공식 화면 SS02·SS06](10_OBSERVATION_LOG.md)

### 2. 한 가지 중심 자원에 다양한 원인을 연결한다

행복은 객차 생산의 결과인 동시에 생존 압력을 받아내는 여유다. 승객·업그레이드·시너지·유물·결단은 이 중심 자원에 연결되지만 보급품, 이동 속도, 시나리오별 위험은 별도 선택을 만든다. **해석:** 표시해야 할 핵심 결과는 단순하게 유지하면서 결과를 만드는 원인은 다양하게 하는 구조다. 그렇다고 복잡성이 자동으로 줄어들지는 않는다. 보조 시스템이 많으면 중심 수치 하나를 이해하는 데도 큰 학습 비용이 든다. [03](03_ECONOMY_AND_FAILURE.md), [05](05_CONDUCTORS_AND_DECISIONS.md)

### 3. 경로는 배경 선택이 아니라 성장과 시간의 교환이다

노선에는 보급과 랜드마크가 있고, 영상에서는 경로를 확인하러 지도 화면으로 전환한다. **해석:** 추가 보상을 얻는 우회와 더 빨리 진행하는 선택은 같은 빌드를 다른 위험에 노출시킬 수 있다. 원작의 보급 거점이 곧 우리가 원하는 매매·하역 정류장이라는 뜻은 아니다. 화물 가격표와 재고 거래를 확인하지 못했다. [04](04_MAP_AND_EVENTS.md), [V01 03:00·19:00](10_OBSERVATION_LOG.md)

### 4. 조작을 많이 요구하는 규칙을 실제로 고쳤다

개발자는 보급 획득 직전의 객차 교체를 줄이려고 운송 시너지를 승객 탑승 누적에 연결했다. 원정·언론 시너지에도 도착 순간의 교체를 줄이려는 변경 이력이 있다. **해석:** 플레이어가 최적화하게 만드는 행동은 시스템 설계의 결과다. “귀찮으면 하지 말라”보다 보상이 쌓이는 조건을 바꾸는 방식이 중요하다. [N070](11_SOURCES.md#n070), [N085](11_SOURCES.md#n085), [02](02_CARRIAGES_AND_SYNERGIES.md)

### 5. 해금은 보상인 동시에 후보군 희석을 만든다

유물 해금으로 선택지가 늘면 원하는 조합이 덜 나올 수 있다. 이에 대응하는 페이지 완성 특전, 특전 토글, 유물 잠금이 순차적으로 추가됐다. **해석:** 콘텐츠를 많이 추가하는 것이 매 판의 재미를 반드시 늘리지는 않는다. 콘텐츠 확대와 원하는 선택을 만드는 통제 수단을 함께 설계해야 한다. [N082](11_SOURCES.md#n082), [N085](11_SOURCES.md#n085), [N103](11_SOURCES.md#n103)

### 6. 세 차장의 차이는 초상화보다 위험 구조에 있다

최순자·임석대·조미미는 같은 객차 기반 시스템 위에서 행복, 긴장, 경제·정치·군사 안정성의 다른 제약을 가진다. **해석:** 이는 높은 재사용성을 만들지만 별도의 결단·사건·경제·밸런스 검증을 요구한다. 1인 개발 초기에 세 종류를 동시에 만드는 근거로 삼으면 안 된다. [N_MAY](11_SOURCES.md#n_may), [05](05_CONDUCTORS_AND_DECISIONS.md)

## 이번 자료의 범위와 한계

| 항목 | 수행한 확인 | 남은 한계 |
|---|---|---|
| 현재 기능·변경 이유 | 공식 상점, 33개 뉴스의 목록, 관련 공지 본문 | 공지와 실행 파일이 모든 세부 규칙에서 일치하는지 미검증 |
| 화면·플레이 흐름 | 공식 이미지 9개, 공개 영상 프레임 관찰 | 직접 조작, 연속 영상 관찰, 선택되지 않은 분기 결과 미검증 |
| 숫자 | 버전별 공식 수치, 보이는 툴팁 | 곱셈 순서·반올림·난이도별 전체 공식 없음 |
| 평가 | 언어·날짜·추천 여부가 다른 리뷰 사례 | 표본 선택 편향, 해당 시점과 현재 버전 차이 |
| 제작 비용 | 기능 의존성에 기초한 작업 분해 | 개발사 내부 인력·기간·예산 추정 아님 |
| 서부 적용 | 별도 문서의 가설과 실험안 | 확정된 게임 장르·일정·상품 기획 아님 |

## 설계를 시작할 때의 결론

**해석:** 참고할 가장 작은 단위는 “열차 전체가 보이고 → 이동 중 누적되는 상태를 읽고 → 다음 정류장에서 조합을 바꾸고 → 다음 구간에서 결과를 확인하는 경험”이다. 방대한 유물 목록이나 복수 시나리오부터 따라갈 필요는 없다.

서부 게임에서 중심 재미가 **화물 거래**라면 생산 효율 빌드를 그대로 이식하는 것보다, 적재 공간·배달 기한·다음 목적지의 관계를 먼저 검증해야 한다. 반대로 중심 재미가 **객차 시너지**라면 거래는 빌드 재료를 공급하는 역할로 좁혀야 한다. 두 방향의 실험 방법은 [09](09_WESTERN_TRAIN_APPLICATION.md)에 기록했다.
