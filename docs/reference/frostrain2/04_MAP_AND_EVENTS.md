# 04. 지도·거점·사건

## 화면에서 확인한 지도 구조

V01 03:00에는 연결된 지점, 지형, 가려진 영역, 열차 위치, 다음 도착 시간이 표시된다. 지점 툴팁에서 지형과 보급 거점 종류, 시야·경험치·보급품·유물 보급, 도착 시간을 읽을 수 있다. [관찰 M01](10_OBSERVATION_LOG.md)

**해석:** 지도는 이동할 곳을 정하는 기능과 다음 보상에 대한 정보를 함께 제공한다. 단순한 배경 지도와 달리 현재 빌드가 필요한 보상을 선택하는 공간이다. 경로를 결정하기 전에 어떤 정보가 보이는지가 선택의 공정성을 좌우한다.

**관찰한 최순자 판은 목적지에 도달하면서 승리하는 유한 여정**이다. V01 마지막 사건은 목적지 발견을 제시하고, 결과 화면에 이동 경로와 승리가 나타난다. “열차가 영원히 원형 선로를 순환하는 게임”으로 원작 전체를 설명할 근거는 없다. 다른 모드의 모든 지도 구조·재방문 규칙은 별도 검증 대상이다. [V01 48:20·48:40](10_OBSERVATION_LOG.md)

## 서로 다른 세 종류의 공간·선택

| 구분 | 확인한 역할 | 구별해야 하는 것 |
|---|---|---|
| 보급 거점 | 지도상에서 경험치·보급품·보급 카드를 얻는 지점 | 상점의 화물 매입·매각 기능과 같다고 볼 수 없음 |
| 랜드마크 | 특정 장소의 보상·고유 효과·선택 | 일반 보급 거점의 등급 차이만으로 설명되지 않음 |
| 사건 | 이야기와 선택, 즉시·지속 결과 | 모두 지도 도착으로 발생하는 것은 아님 |

공식 기록에는 고정 배치된 랜드마크, 시나리오별 지도 확대, 고유 유물·보상 수정이 있다. [N070](11_SOURCES.md#n070), [N080](11_SOURCES.md#n080), [N086](11_SOURCES.md#n086), [N104](11_SOURCES.md#n104)

**미확인:** 보급 등급별 전체 확률, 모든 지점의 보상 목록, 같은 지점 재방문 시 보상, 정차 중 각 타이머의 작동, 최적 경로의 수학적 조건은 확보하지 않았다.

## 지도 선택의 비용을 분해하기

노선 선택을 평가할 때는 “어느 지점의 보상이 더 큰가” 외에 다음을 따로 본다. 이는 **분석 틀**이며 원작이 해당 값을 모두 표시한다는 뜻은 아니다.

| 비교 항목 | 확인할 질문 |
|---|---|
| 현재 필요한 보상 | 슬롯·성장·유물·보급품 중 무엇이 부족한가? |
| 도착 시점 | 위험이 커지기 전에 도착할 수 있는가? |
| 우회에서 생산한 양 | 추가 이동 시간 동안 벌어들이는 행복은 얼마인가? |
| 우회에서 발생한 손실 | 일수·상태·추격으로 추가 부담이 발생하는가? |
| 이후 경로 | 지금의 선택이 다음 좋은 지점으로 연결되는가? |
| 보상의 확실성 | 정해진 효과인지, 후보 선택인지, 무작위 하나인지? |
| 정보 비용 | 지형·보상·부정 효과를 미리 알 수 있는가? |

```text
경로 A: 적은 경유 보상 + 빠른 목표 도달
경로 B: 더 많은 성장 기회 + 더 긴 위험 노출

실험 질문: B의 보상이 추가 위험을 상쇄하는가?
           현재 구성에 따라 A/B의 우열이 바뀌는가?
```

이 예시는 지도 구조의 **개념 비교**다. 특정 원작 지점 두 곳의 실제 데이터가 아니다.

## 랜드마크가 단순 보상과 다른 이유

1.0.4의 Frozen Streets는 조미미에게 주는 Ancient Drone을 영구 효과로 바꾸고, 경제·정치 안정성 보상을 20/12에서 35/10으로 조정했다. [N104](11_SOURCES.md#n104)

**해석:** 랜드마크의 가치는 합산 자원량 하나로 판단되지 않는다. 영구 효과인지 일시 효과인지, 어떤 안정성을 주는지에 따라 이후 가능한 결단이 달라진다. 같은 지점이 다른 시나리오에서 다른 중요도를 갖게 만드는 방법이기도 하다.

0.8.6에서 개발자는 랜드마크 고유 유물과 보상의 무작위성을 조정하고, 일부 유물 보상을 무작위 하나에서 선택 방식으로 바꿨다. [N086](11_SOURCES.md#n086)

**해석:** 장소마다 고유한 이유가 있어야 지도 선택이 기억에 남는다. 동시에 특정 장소가 언제나 같은 완성 빌드를 보장하면 반복 판의 긴장이 줄 수 있다. 고유 보상과 선택·무작위의 비율이 그 사이를 조절한다.

## 사건의 기본 구성

공식 이미지와 V01·V02에서 다음 구조가 관찰된다.

```text
사건 발생
→ 삽화·짧은 상황 설명
→ 선택지
→ 선택지 툴팁에 자원·상태 변화
→ 결과 또는 후속 대화
→ 주행 화면으로 복귀
```

선택 결과가 모두 한 페이지에서 끝난다고 단정하지 않는다. V02의 시위 사건은 군중 장면에서 조미미 대화로 이어진다. [V02 29:00~29:30](10_OBSERVATION_LOG.md)

### 사건의 수치와 이야기 연결

SS05는 강경한 방법을 고르는 상황에 승객 손실과 반발을 연결한다. V02 29:20의 선택지 툴팁은 긴장 3, 승객 3 손실, 반발 2를 보여 준다. 후자는 **1.0.1-build-1 녹화의 표시값**이다. [SS05·V02](10_OBSERVATION_LOG.md)

**해석:** 사건은 자원 교환에 이유를 부여한다. 선택이 반복될 때 기계적인 “좋은 보상/나쁜 보상”으로만 보이지 않으려면 인물·문제·후유증이 연결되어야 한다. 동시에 분위기 있는 문장만 있고 결과를 알 수 없으면 전략 선택이 운으로 느껴질 수 있다.

### 즉시 손실과 후유증을 구분하기

한 선택에 승객 손실과 반발이 함께 있으면 서로 다른 장부에 기록한다. 승객은 생산 조건에, 반발은 초당 손실에 영향을 줄 수 있다. 사건 기록에 “행복이 줄었다”만 쓰면 이후 다른 구간의 변화를 설명하기 어렵다. [03](03_ECONOMY_AND_FAILURE.md)

### 조건과 확률

조미미 개발자 서신에는 안정성이 도전의 성공 확률에 영향을 주고, 공약이 연속으로 제시되는 구상이 있다. 이 내용은 **출시 전 설명**이므로 최신 모든 사건의 조건표로 사용하지 않았다. [N_MAY](11_SOURCES.md#n_may), [05](05_CONDUCTORS_AND_DECISIONS.md)

## 사건이 만드는 제작 비용

**해석:** 사건 하나에는 본문 외에도 발생 조건, 선택 가능 조건, 효과, 지속 상태, 후속 사건, 삽화, 번역, 저장 복원 규칙이 필요할 수 있다. 사건 수를 늘리는 비용은 문장 수보다 크다.

| 사건 유형 | 필요한 검증 |
|---|---|
| 단순 자원 교환 | 자원 부족·0·최대치일 때 선택 가능 여부 |
| 확률 결과 | 성공·실패 분기, 표시 확률과 실제 규칙 |
| 지속 상태 부여 | 중첩·제거·기간·저장 불러오기 |
| 객차 조작 | 빈 슬롯·빈 손패·성장 상태·후보군 고갈 |
| 분기 이야기 | 이미 본 사건, 후속 조건, 차장·난이도 변화 |
| 시간 뒤 효과 | 정지·배속·동시 도착·판 종료와의 충돌 |

공식 패치의 카드 후보 고갈·저장·효과 누적 오류 수정은 이런 조합의 실제 부담을 보여 준다. [N073](11_SOURCES.md#n073), [N101](11_SOURCES.md#n101)

## 서부 정류장 아이디어와의 관계

**제안:** 원작에서 참고할 것은 “장소가 다음 구간의 빌드를 바꾼다”는 관계다. 사용자가 원하는 정류장은 여기에 매입·하역·계약·호위 선택을 추가할 수 있다. 단, 화물을 싣는 연출만 추가하면 같은 보급 선택 화면으로 남을 수 있다. 적재 공간과 목적지, 가격 또는 기한 중 무엇이 선택을 바꾸는지 실험해야 한다. [09](09_WESTERN_TRAIN_APPLICATION.md)
