# 방치형 업계는 경쟁이 닿는 곳만 서버로 지킨다

방치형 업계의 「서버 권위」는 하나가 아니라 둘로 갈린다. 모바일 F2P 방치 RPG(AFK Arena · 메이플 키우기 류)는 계정 · 재화 · 뽑기 확률을 서버 DB 와 서버 RNG 에 두고, 전투는 기기가 돌린 뒤 서버가 같은 로직으로 다시 돌려 검증한다. 방치 보상은 상한이 있는 상자에 쌓였다가 접속할 때 지급되고, 결투장은 상대가 저장해 둔 방어 편성을 AI 가 조종하는 비동기 티켓제다. 반대로 세이브를 기기에 두는 방치형(Tap Titans 2 · Egg, Inc. · Melvor Idle · Lootun)은 진행을 서버에서 다시 계산한 사례가 하나도 확인되지 않았다. 이들은 치트를 막지 않고, 오프라인 이득을 「이미 증명한 최고치」에 묶거나 경쟁 콘텐츠만 서버 계정에 묶어 사후에 밴했다. 서버를 필수로 만든 기준은 과금 모델이 아니라 **다른 플레이어와 나누는 자원(시장 · 길드 · 순위 보상)이 있느냐**였다. Steam 유료 싱글인데 필요 없는 상시 접속을 택한 Melvor 는 서버 장애 때 리뷰로 값을 치렀다. 그래서 본작의 구상(본편 로컬 · 콜로세움만 서버 · 업로드 시 적법성 검사 · 보상은 칭호와 꾸밈만)은 Eslabong · Leaf Blower Revolution · Idle Slayer 가 쓰는 조합, 즉 근거가 가장 단단한 조합과 같다. 남은 약점은 둘이다. 첫째, 적법성 검사는 아이템이 정말 드롭됐는지 증명하지 못한다. 디아블로식 굴림 게임에선 ELO 최상위 구간이 세이브를 고친 팀으로 채워질 수 있다. 둘째, 입력이 없는 자동전투라 서버가 두 스냅샷과 시드만으로 결과를 직접 계산할 수 있다. 그런데 지금 `game_logic` 의 데미지 · 공속 · 아이템 굴림 공식이 쓰는 `Math.pow` · `**` · `Math.log` · `Math.cos` 는 ECMAScript 표준이 엔진마다 값이 달라도 되는 함수로 정해 둔 것이다. 서버 비용 자체는 작다. Cloudflare Workers 유료 요금제는 월 $5 에 3천만 CPU-ms 를 주므로, 한 판을 50 ms 로 잡아도 월 60만 판을 서버가 계산한다.

*표기는 넷이다. **[확인]** = 개발사 · 운영사 공지, 표준 문서, 게임 코드 원문. **[보도]** = 언론 · 공략 사이트 · 위키. **[커뮤니티]** = 유저 · 포럼 증언, 클라이언트 역분석, 원문을 못 열고 검색 요약으로만 본 것. **[추론]** = 조사자 해석. 조사일은 2026-10-26.*

## 모바일 키우기는 계정 · 확률 · 전투 판정을 서버가 쥔다

중국 · 한국 상위 모바일 방치 RPG 의 기본형은 **「클라이언트가 전투를 돌려 보여 주고, 서버가 같은 로직으로 다시 돌려 검증한다」**이다. 개발자 본인이 밝힌 자료 중 가장 단단한 것은 AFK Arena 주프로그래머의 2021년 글이다. 이 글에서 전투 검증(战斗校验)은 「서버에서 도는 전투 로직 코드로, 클라이언트가 올린 전투에 부정이 있는지 검증하는 것」이고 출시 전부터 있었다 [확인]. 같은 글이 비용도 밝힌다. 프레임 단위 계산이라 CPU 가 매우 크고, 5v5 는 1v1 의 약 5배다. **매일 리셋 직후가 최고점이고 밤과의 CPU 차이는 약 10배**여서, 고점 10분 전에 Pod 를 10개에서 100개로 미리 늘리고 실패한 요청은 FaaS 로 다시 돌렸다 ([腾讯新闻 转载](https://news.qq.com/rain/a/20211002A0ACIL00)). 검증이 전량인지 표본인지, PvE 를 포함하는지는 공개되지 않았다.

이 방식을 실제로 구현하는 비용은 2016년 《塔防大师》 개발팀 글에 가장 자세히 나온다 [확인]. 클라이언트는 수동 조작 기록과 종료 상태(남은 HP · 골드)만 올린다. 그중 **공격 측이 이긴 판만** 게임 서버와 분리된 비동기 검증 클러스터로 넘어간다. 검증 서버는 클라이언트와 같은 C++ 소스를 Linux 로 컴파일해 전투를 통째로 다시 돌린다. 클라이언트를 릴리스할 때마다 버전별 `.so` 를 따로 올려, 옛 버전 판은 그 버전 로직으로 돌린다. 막힌 곳은 결정론이었다. 플랫폼마다 `RAND_MAX` 가 달라 같은 시드로도 다른 수열이 나와서 자체 LCG 로 바꿨다. float · int 를 섞은 연산이 Linux 에선 20, Win32 에선 19 로 갈렸다. 렌더 코드가 로직과 엉켜 있어 4분짜리 판을 다시 돌리는 데 약 1분이 걸렸는데, 로직이 아닌 코드를 걷어내 **ms 단위**로 줄였다. 처벌은 첫 적발이면 경고, 반복하면 3일 정지 + 자원 롤백, 해제 뒤 다시 걸리면 영구 정지였다. 팀의 회고는 「개발 시간 대부분이 C++ 이식과 플랫폼 간 결과 맞추기에 들었으니, 다음엔 공유 스크립트로 짜라」였다 ([GameRes](https://www.gameres.com/483354.html) · [博客园](https://www.cnblogs.com/bambomtan/p/5108008.html)).

뽑기 · 강화 확률을 서버가 굴린다는 정황이 가장 뚜렷한 것은 메이플 키우기 사건이다 [보도]. 어빌리티 최대 수치 조건이 「이하」가 아니라 「미만」으로 잘못 설정돼, 2025-11-06 부터 12-02 까지 최대 수치가 한 번도 나오지 않았다. 운영사는 12-02 에 **클라이언트 업데이트 없이, 공지도 없이** 이를 고쳤다. 대표 명의 사과문은 「외부 개발사와 협업하는 구조 탓에 **실시간 확률 모니터링 시스템**의 실측 확률이 적용되지 않아 초기에 탐지하지 못했다」고 설명했다 ([byline](https://byline.network/2026/01/27-546/) · [뉴시스](https://mobile.newsis.com/view/NISX20260126_0003490902)). 같은 게임의 공격속도 사건은 반대로 **전투는 기기가 계산한다**는 증거다. 공격 모션의 초당 최대 프레임을 묶어 둔 탓에 공속 66.76% 와 99.99% 가 실제로는 같았다. 운영사는 프레임을 올리면 「기기 발열과 끊김」이 생긴다고 해명했다 ([디지털투데이](https://www.digitaltoday.co.kr/news/articleView.html?idxno=624043)). 2026-04 에는 챕터를 반복 이동해 처치 수를 1.5~2배로 불리는 매크로와 스펙 미달 통과가 통했다 ([나무위키](https://namu.wiki/w/%EB%A9%94%EC%9D%B4%ED%94%8C%20%ED%82%A4%EC%9A%B0%EA%B8%B0)) [보도]. 서버가 클라이언트가 보고한 전투 결과를 받아 주는 구조였다는 뜻으로 읽힌다 [추론]. AFK Journey 에서 재화 값을 메모리로 바꾸면 화면 숫자만 바뀌고 구매는 실패한다는 치트 포럼 관찰도 같은 그림이다 ([FearLess](https://fearlessrevolution.com/viewtopic.php?t=28412)) [커뮤니티].

방치 보상과 결투장은 이 구조 위에 얹은 **운영 장치**다. AFK Arena 의 방치 상자는 **최대 12시간치**까지 쌓이고, VIP 가 상한을 늘리며, 접속해 눌러야 받는다 ([appgamer](https://www.appgamer.com/afk-arena/strategy-guide/afk-rewards)). AFK Journey 는 처음 12시간에서 진행에 따라 24시간으로 늘어난다 ([prydwen](https://prydwen.gg/afk-journey/guides/tips-and-tricks)) [보도]. 「서버 시각으로 계산한다」는 공식 문장은 찾지 못했다. 재화가 서버에 있는 구조라 기준 시각도 서버가 기록한 마지막 수령 시각일 가능성이 높다 [추론]. 결투장은 조사한 모든 작품이 **비동기**다. 상대가 저장해 둔 방어 편성을 AI 가 조종하고, 하루 무료 횟수와 티켓으로 횟수를 묶는다. AFK Arena 는 무료 2회 + 티켓, 시즌 2주, 리플레이를 둔다 ([afk.guide](https://afk.guide/arena-of-heroes)). AFK Journey 는 후보 셋 중 하나를 고르고 새로 고침은 5~7회다. 여기서는 **방어 쪽이 시간 초과로 버티면 방어 승이고, 방어 결과도 점수에 들어간다.** 무료 티켓은 하루 4장이다 ([dotgg](https://dotgg.gg/afk-journey/arena-guide/)). 세븐나이츠 키우기도 실시간이 아닌 비동기 대전이고 입장권이 매일 충전된다 ([게임뷰](https://www.gamevu.co.kr/news/articleView.html?idxno=29124)) [보도].

이 관행 중 본작이 그대로 들여오면 안 되는 것이 둘 있다 [추론]. 첫째, 방어 결과가 점수를 움직이면 **접속하지 않은 사람의 레이팅이 깎인다.** 키우기 류는 이것을 받아들였지만, 본작의 「자리 비워도 안전」 계약과는 정면으로 부딪힌다. 지금 설계 문서에도 방어 결과가 방어자의 레이팅을 움직이는지는 아직 적혀 있지 않다 ([arena_design.md](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/docs/game_design/arena_design.md)). 둘째, 상자 상한(12 · 24시간)은 치트 대책이 아니라 「하루 한두 번 접속」을 만드는 리텐션 장치다. 반대로 들여올 만한 것은 티켓과 새로 고침 횟수 제한이다. 서버 부하와 「유리한 상대 골라 먹기」를 한 번에 묶는 장치이기 때문이다(5절).

## 로컬 세이브 방치형은 치트를 막지 않고, 경쟁으로 가는 길을 끊는다

세이브를 기기에 두는 방치형에서는 모바일이든 PC 든 **서버가 진행을 다시 계산한 사례가 하나도 확인되지 않았다.** Egg, Inc. 클라이언트 프로토콜을 역분석한 정의 파일을 보면, 협동 계약 기여는 클라이언트가 생산량 · 버프 등 약 30개 필드를 **스스로 보고**한다. 같은 메시지에 `time_cheats_detected` 도 실어 보낸다 ([ei.proto](https://raw.githubusercontent.com/carpetsage/egg/main/protobuf/ei.proto)) [커뮤니티 · 역분석]. Clicker Heroes 는 「레이드 데미지를 보고하는 방식」을 고쳐 이미 잡힌 보스가 되살아나던 문제를 해결했다는 업데이트 노트를 냈다. 레이드 데미지를 클라이언트가 보고한다는 뜻이다 ([App Store](https://apps.apple.com/us/app/-/id911107930)) [커뮤니티 · 검색요약]. 이런 게임에서 서버가 쥐는 것은 계정, 백업, 공유 콘텐츠의 시계와 마감, 클라이언트가 올린 숫자뿐이다.

오프라인 시간 조작에 대한 대응은 세 갈래다. 첫째, Idle Miner Tycoon 은 **기기 시각을 서버 시각과 대조해 어긋나면 이벤트 · 일일 상품 같은 시간 기반 기능을 막는다.** 시계를 고친 뒤에도 영향이 남을 수 있다는 공식 FAQ 가 따로 있을 만큼, 정상 유저를 지원하는 비용이 붙는다 ([Kolibri FAQ](https://kolibri-games.helpshift.com/hc/en/3-idle-miner-tycoon/faq/347-how-do-i-fix-my-time-date-issues/?hpn=1&p=ios&han=1&l=en)) [확인]. 둘째, Egg, Inc. 는 시계 되감기를 클라이언트가 감지해 세이브에 `total_time_cheats_detected` · `time_cheat_debt` 로 적고 협동 동료에게 보이게 한다. v1.11 부터는 「시간 치터는 누구나 추방할 수 있다」 ([ei.proto](https://raw.githubusercontent.com/carpetsage/egg/main/protobuf/ei.proto) · [Softpedia 1.11 패치노트](https://mobile.softpedia.com/apk/egg-inc/1.11/)) [커뮤니티]. 셋째이자 가장 깔끔한 것은 Tap Titans 2 다. **오프라인 진행은 최고 스테이지의 99% 까지만** 간다. 토너먼트에선 토너먼트 최고치의 99% 까지이고, 첫 판에는 오프라인 진행이 아예 없다 ([TT2 FAQ](https://gamehive.helpshift.com/hc/en/3-tap-titans-2/faq/84-why-am-i-not-getting-any-offline-progression/)) [확인]. 시계를 아무리 당겨도 경쟁 지표인 최고치는 못 올리므로, 탐지 없이 이득으로 가는 경로를 끊는다. PC 쪽 Melvor Idle 의 실제 코드는 더 단순하다. 기기 시계(`Date.now()`)의 차이를 쓰고, 음수는 0 으로 자르고, **24시간에서 자른다**(`MAX_OFFLINE_TIME = 86400000`) ([game.js](https://melvoridle.com/assets/js/built/game.js)) [확인].

경쟁 콘텐츠를 지키는 방식은 대부분 사후 처리다. AdVenture Capitalist 개발사는 이벤트 리더보드 **상위 100명을 사람이 한 명씩** 확인해 지운다고 밝혔다 ([Steam 개발사 답변 2018-12-06](https://steamcommunity.com/app/346900/discussions/0/1745605598705827571/)) [확인]. 하지만 유료 타임워프 같은 가속 아이템 때문에 「정상 플레이로 낼 수 있는 점수 상한」을 그을 수 없어 불만 스레드가 계속됐다 ([Steam](https://steamcommunity.com/app/346900/discussions/0/3563973555478210168/)) [커뮤니티]. Tap Titans 2 는 의심 계정에 「Teapot」 플래그를 붙이고, 「모든 밴은 영구」다 ([TT2 FAQ](https://gamehive.helpshift.com/hc/en/3-tap-titans-2/faq/72-teapot/)) [확인]. Steam 의 Firestone 은 얼리 액세스 때 클라이언트 중심이라 Cheat Engine 이 다 통했다. 구조를 바꾼 뒤엔 「게임의 99% 가 서버」라고 하면서도 **메인 전투 진행만은 「서버에서 그 엄청난 양의 계산을 하는 건 말이 안 돼서」 클라이언트에 남겼다.** 대신 진행 데이터로 「레벨과 안 맞는 스테이지」 같은 불가능한 진행을 걸러 **Steam 신규 유저의 거의 1% 를 매일 밴**한다. 모더레이터 오판은 500건 중 1건 미만이고, 24시간 안에 영구 밴하고 리더보드에서 지운다고 했다 ([Firestone 개발사 글 2024-05-14](https://steamcommunity.com/app/1013320/discussions/0/4363502774085386591)) [확인].

조사한 게임 전체를 가로질러 보면, 서버를 필수로 만든 기준은 **과금 모델이 아니라 「다른 플레이어와 나누는 자원」**이다. 무료 + 인앱이어도 사회 요소가 없는 NGU IDLE · Soda Dungeon 2 · Idle Slayer 본편은 로컬 세이브다. 시장 · 길드 · 순위 보상이 있는 Firestone · Shop Titans · IdleOn 은 서버 계정이다 [추론 — 3절 표]. AdVenture Capitalist 는 백엔드 없이 출시했다가 라이브 이벤트 · 리더보드를 위해 PlayFab 을 나중에 붙였고, 이 일은 GDC 2016 포스트모템의 주제가 됐다 ([GDC Vault](https://www.gdcvault.com/play/1023119/-Adventure-Capitalist-Postmortem-or)) [커뮤니티 · 검색요약]. 서버는 나중에 붙여도 되지만, 붙일 자리는 처음부터 비워 둬야 한다는 교훈이다 [추론].

본작에 대입하면 오프라인 시간은 서버까지 쓸 대상이 아니다 [추론]. 「꺼진 동안은 연구소만 돈다」는 규칙 덕에, 시계를 당겨 얻을 수 있는 최대치는 이미 **연구소 줄이 다 끝난 상태**로 묶여 있다. 그 이득도 결국 「파밍 생략」이라, 콜로세움 적법성 검사가 다루는 위협과 같은 종류다. 개발자 포럼의 통념은 Melvor 수준(기기 시계 · 음수 차단 · 상한)에 「지금까지 본 가장 늦은 시각」을 기록해 되감기만 잡으면 충분하다는 것이다 ([Unity Discussions](https://discussions.unity.com/t/how-to-discourage-offline-cheating/761906)) [커뮤니티]. Steamworks 의 `GetServerRealTime` 으로 Steam 서버 시각과 대조할 수도 있다. 다만 클라이언트가 읽는 값이라 OS 시계를 바꾸는 것만 막는다 ([ISteamUtils](https://partner.steamgames.com/doc/api/ISteamUtils)) [확인].

본작과 구조가 가장 가까운 2026년 두 작품은 결과가 갈렸다. **Partyforge Idle**($6.99 · 2026-09)은 로그인과 세이브를 Google 서비스에 묶은 온라인 필수 게임이다. 그래서 중국 본토에선 로딩 화면에서 멈췄다 ([2026-09-20](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1844115010499899)). 아레나 상대의 전투력은 「그 플레이어의 현재 클라우드 세이브」에서 가져오고 ([2026-09-21](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1844115010500262)), 출시 한 달 안에 「Fair Play」 보호 강화와 「놓친 날의 보상 적립」 패치가 연달아 나왔다 ([2026-09-28](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1844751498231940) · [2026-10-07](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1846018067925346)) [확인]. **Eslabong**(얼리 액세스 2026-08)은 캠페인 세이브를 로컬에 두고 서명 · 무결성 검사를 건다. 서버는 비동기 PvP(Challenge Tower)에만 Cloudflare 로 붙였다. 중국 본토에서 그 서버가 안 닿는 문제는 같았지만, 막힌 것은 PvP 뿐이었다 ([2026-10-08](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1846018067929837) · [0.70.1](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1846018067932861)). Eslabong 은 순위 제출에 **「성장 검증」을 붙여 불가능하거나 변조된 능력치가 순위에 못 오르게** 했고, 별도의 정규화 사다리도 둔다 ([0.61.1](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/1844751498232917)) [확인]. Leaf Blower Revolution 은 온라인 시즌을 **본편과 분리된 시즌 캐릭터**로 돌린다. 후원팩 구매자와 무료 유저의 리더보드도 갈랐고, 매크로 · Cheat Engine 은 모든 시즌 영구 밴이다 ([Season #4](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/4348797798075357169)). Idle Slayer 는 카지노 확률만 「운 조작을 막기 위해」 서버로 옮겼다 ([5.0.0](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/6557848386954335041)) [확인].

Steam 자체 도구의 쓰임새는 의외로 좁다. 14종 중 Steam 상점에 「Steam Leaderboards」를 단 게임은 **하나도 없고**, 리더보드는 전부 자체 서버다. Steam Cloud 도 백업 용도로만 쓰인다 ([Steam appdetails API](https://store.steampowered.com/api/appdetails?appids=1013320)) [확인]. Steam 리더보드는 쓰기를 「Trusted」로 설정하면 클라이언트가 점수를 못 쓰고 서버의 `SetLeaderboardScore` WebAPI 로만 기록된다. 점수에 리플레이 · 고스트 파일도 붙일 수 있다 ([Steam Leaderboards](https://partner.steamgames.com/doc/features/leaderboards)). Steam 계정으로 신원을 확인하려면 클라이언트가 `GetAuthTicketForWebApi` 로 받은 티켓을 서버가 `AuthenticateUserTicket` 으로 검증해야 한다. 이때 publisher Web API 키가 필요하고, 이 호출은 반드시 보안 서버에서 해야 한다 ([ISteamUserAuth](https://partner.steamgames.com/doc/webapi/ISteamUserAuth)) [확인]. Steam 이 신원은 공짜로 주지만, 그 확인조차 서버 함수 하나를 요구한다는 뜻이다. 외부 의존성도 위험 요인이다. 유료 Clicker Heroes 2 는 Flash SDK 를 더는 구할 수 없어 2024-03-13 판매를 중단했다 ([Retiring Clicker Heroes 2](https://steamstore-a.akamaihd.net/news/externalpost/steam_community_announcements/5686429670869220975)) [확인].

본작에 주는 뜻은 분명하다 [추론]. 유료 로컬 게임의 리뷰 위험은 근거상 **강제 접속과 세이브 소실이 치트보다 크다.** 본편 오프라인은 이미 맞는 선택이다. 남은 일은 콜로세움 서버가 죽거나 지역 차단을 당해도 본편과 결투장(층 사다리)이 그대로 도는지 지키는 것이다. 마침 「서버가 서기 전까지 레이팅에 맞춘 AI 팀이 그 자리를 채운다」는 지금 구조([arena_design.md](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/docs/game_design/arena_design.md) §0)가 장애 시 대체 경로로 그대로 쓰일 수 있다. 다만 서버가 레이팅의 주인이 된 뒤에는, AI 상대와의 판이 서버 레이팅을 움직이지 않도록 갈라야 한다.

## 적법성 검사는 「파밍 생략」까지만 막고, 출처는 아무도 증명하지 못했다

로컬 세이브를 온라인 대전에 들인 게임 중 **「이 아이템을 정말 얻었는가」를 증명한 출시작은 찾지 못했다.** 버틴 대표 사례는 Pokémon 이다. VGC 규칙은 외부 장치로 「만들거나 고친」 포켓몬을 금지하고, 교환으로 받았어도 실격시킬 수 있다 ([esportslegal.news](https://esportslegal.news/2025/03/21/legal-implications-of-hacked-pokemon/)). 2023 월드 챔피언십에서는 세이브 편집기로 생성한 포켓몬 때문에 프로 선수 여럿이 실격됐는데, 탐지 방법은 공개되지 않았고 처벌도 들쭉날쭉했다고 보도됐다 ([Kotaku](https://kotaku.com/pokemon-scarlet-violet-world-championship-hack-cheat-1850729929)) [보도]. Sun/Moon 은 2017-01 「세이브 데이터 변조」로 5,954명의 온라인 이용을 막았고, 제재 단위는 변조된 세이브 파일이었다 ([Nintendojo](https://www.nintendojo.com/?p=161528)) [보도]. 이 체계가 25년 넘게 버틴 이유는 세계 챔피언 Wolfe Glick 의 말에 담겨 있다. 「해킹이고 규칙 위반이지만, 부정행위는 아니다. 불공정한 이점을 주지 않는다.」 생성한 개체는 합법 개체와 성능이 같고, 다른 것은 모으는 데 드는 비용과 시간뿐이라는 것이다 ([Dot Esports](https://dotesports.com/pokemon/news/pokemon-champion-wolfe-glick-breaks-silence-on-vgc-hacking-genning-issue)) [커뮤니티 · 검색요약].

깨진 곳은 「얼마나 모았나」를 재는 순위였다. Last Epoch 개발사는 「지금 세이브는 전부 오프라인이라 신뢰할 수 없고, 멀티 환경으로 옮길 수 없다」고 밝혔다 ([Steam](https://steamcommunity.com/app/899770/discussions/0/3791506319061956157)) [확인]. 멀티 이전의 래더는 메모장으로 고친 세이브로 채워졌다는 항의를 받았고 ([LE 포럼](https://forum.lastepoch.com/t/do-the-devs-plan-to-keep-allowing-cheaters-on-their-leaderboards/52121)) [커뮤니티], 1.0 부터는 오프라인과 온라인 캐릭터를 생성할 때 고르고 어느 쪽으로도 옮길 수 없게 했다 ([Destructoid](https://www.destructoid.com/can-you-transfer-an-offline-character-to-online-in-last-epoch/)) [보도]. Diablo 2 의 Realm 도 Diablo 1 의 로컬 캐릭터 치팅을 막으려고 캐릭터를 서버에 둔 것이다 ([PlanetDiablo](https://gamespy-archives.quaddicted.com/sites/www.planetdiablo.com/features/articles/cheating/index.html)) [보도]. FromSoftware 의 「소프트밴된 사람끼리만 만나는」 격리 풀은 다른 경로로 탈이 났다. **치터가 떨군 아이템을 주운 무고한 유저**가 같이 걸렸고, 해커가 이것을 남을 일부러 가두는 무기로 썼다 ([Kotaku](https://kotaku.com/dark-souls-3-pc-players-dont-know-why-theyre-getting-ba-1772288791) · [Vice](https://vice.com/en/article/elden-ring-players-are-getting-banned-for-picking-up-hacked-panties)) [보도]. 서명 쪽으로 가장 가까운 것은 Activision 특허다. 이 특허는 서버가 로드아웃을 **서버에 남은 획득 이력**(구매 · 이전 경기 기록)과 대조한 뒤 서명한다 ([US10463971B2](https://patents.google.com/patent/US10463971B2/en)) [확인]. 서명이 의미를 가지려면 아이템이 생기는 순간 서버가 그 생성을 봐야 한다는 뜻이다 [추론].

이 근거를 본작에 대 보면 설계 문서의 「상한 논리」는 절반만 성립한다 [추론]. 문서의 논리는 이렇다. 치터가 만들 수 있는 최강 팀은 「합법 만렙 + 최상옵 장비」에서 멈추고, 그것은 오래 한 정직한 유저도 닿는 자리이니, 치팅으로 얻는 것은 「파밍 생략」뿐이다 ([arena_design.md](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/docs/game_design/arena_design.md) §2). Pokémon 에서는 개체값 상한에 정상 유저도 비교적 쉽게 닿으니 이 논리가 맞다. 디아블로식 아이템 굴림의 「모든 칸 최고 굴림」은 정직한 유저가 거의 보지 못하는 값이다. 그래서 위조 팀과 정상 팀의 격차가 Pokémon 보다 훨씬 크다. 문서는 레이팅 매칭이 치터를 최상위에 모아 일반 유저와 떼어 놓는다고 본다(§3). 그런데 그 최상위가 바로 가장 오래 한 정직한 유저가 사는 곳이다. 그들이 비용을 전부 지고, 위조 팀에게 지는 판마다 **레이팅이 직접 깎인다.** 리더보드 오염보다 피해가 직접적인 이유다.

보완책은 비용이 싼 순서로 넷이다 [추론]. 첫째, 합법 범위를 진행 단계에 묶어 좁힌다. 「아이템 레벨 ≤ 도달한 난이도 · 챕터」는 이미 검사 목록에 있다. 다만 「도달한 난이도」 자체도 로컬 세이브가 주장하는 값이다. 그래서 서버가 할 수 있는 것은 안의 숫자들이 서로 맞는지 보는 것과, **직전 제출과 비교해 불가능한 급성장을 잡는 것**(Activision 특허 · Firestone 「레벨과 안 맞는 스테이지」 판정의 축소판)이다. 둘째, 레벨 · 강화를 고정한 **정규화 판**을 둔다. Eslabong 의 정규화 사다리, Pokémon VGC 의 레벨 50 고정과 같은 방향이고, 문서의 인증 리그 질문 ②와 같은 답이다. 셋째, 「검증된 판 / 자유 판」을 **유저가 고르게** 나눈다. Deep Rock Galactic 의 Sandbox 세이브, Last Epoch 의 오프라인 캐릭터처럼 유저가 스스로 고르는 분리는 논란이 거의 없었다. FromSoftware 식 자동 강제 격리는 오탐 원성이 컸다. 넷째, 보상을 칭호와 꾸밈으로 둔다. 본작은 이미 그렇게 정했다. Taskbar Hero 는 Steam 장터 거래가 붙자 골드 파머와 「비정상 아이템 생성 요청」이 폭증해 서버 장애까지 겪었다 ([Inven Global](https://labs.invenglobal.com/articles/22394/popular-idle-game-taskbar-hero-hits-140k-concurrent-users-but-gold-farmers-and-cheaters-leave-players-paying-the-price)) [보도]. 보상이 바깥 경제로 새면 치팅 압력이 급등한다는 반대쪽 증거다. 본작은 고스트 팀이 상대로 보일 뿐 남의 세이브로 넘어가지 않으므로, FromSoftware 식 「주운 아이템 감염」 경로는 구조적으로 없다. 「아이템 고유 ID 유지」 원칙은 Pokémon HOME tracker 처럼 **같은 아이템이 여러 계정 팀에 동시에 나타나는 것**(생성 팀 공유)을 잡는 데 쓸 수 있다 ([Project Pokémon 포럼](https://projectpokemon.org/home/forums/topic/67933-home-tracker-issue-need-help/)) [커뮤니티 · 활용은 추론].

1인 개발자의 처벌 정책도 근거가 가리키는 쪽이 있다 [추론]. 수동 검토를 감당할 수 없다면 재량 밴보다 **업로드 순간의 결정적 거부**(「이 값은 이 진행 단계에서 불가능」)가 설명하기 쉽고 오탐 논란이 적다. 의심스럽지만 확정할 수 없는 경우는 《塔防大师》가 첫 적발을 경고로 끝낸 것처럼 「보상 보류 + 두 값 기록 + 검토」에 둔다. 조작된 세이브와 결정론 버그는 겉으로 똑같이 보이기 때문이다.

## 입력 없는 자동전투는 서버 판정을 싸게 만들지만, JS 수학 함수가 걸림돌이다

본작은 업계 선례보다 유리한 위치에 있다. 《塔防大师》와 AFK 가 검증해야 했던 것은 플레이어 조작이 섞인 전투였다. 본작 전투에는 진행 중 입력이 없다. 그래서 「입력 로그」는 **(두 팀 스냅샷 + 시드 + 로직 · CSV 버전)** 한 덩어리다 [추론]. 방어 팀 스냅샷은 어차피 서버에 있으므로, 클라이언트 결과를 다시 돌려 대조할 것 없이 **서버가 결과를 직접 계산하고 클라이언트는 그 시드로 연출만 하는** 권위형이 더 단순하다. 중국 실무 글들이 권하는 부속 규칙도 그대로 옮겨진다. 첫째, 이미 정산된 판을 다시 제출하면 원래 결과를 돌려주고 보상을 다시 주지 않는다 ([掘金](https://juejin.cn/post/7695776667336851496)) [커뮤니티 · 검색요약]. 둘째, 판마다 로직 버전을 붙여 그 버전으로 계산한다(《塔防大师》의 버전별 `.so`). 밸런스 패치 뒤에 패치 전 스냅샷을 새 CSV 로 돌리면 정상 플레이가 이상하게 보인다. 이것이 가장 흔한 함정으로 보인다 [추론].

자동전투 결정론이 만드는 고유한 구멍도 하나 있다 [추론]. 지금 콜로세움은 상대 후보 셋을 보여 주고 고르기 전에 「이기면 + · 지면 −」을 보여 준다. 그리고 [새 상대]는 공짜다 ([arena_design.md](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/docs/game_design/arena_design.md) §8). 클라이언트에는 `game_logic` 전체가 들어 있고, 본작의 `dev/sim` 이 보여 주듯 headless 로 수백 판을 도는 것은 쉽다. 그러면 플레이어는 후보마다 실제 승률을 재서, **ELO 가 예상한 승률과 실제 승률이 가장 크게 어긋난 상대만** 골라 레이팅을 부풀릴 수 있다. 시드까지 알면 결과를 아예 미리 본다. 이를 막는 순서는 셋이다. 서버는 **상대 선택을 잠근 뒤에 시드를 발급**하고, 새로 고침 횟수를 AFK Journey 처럼 제한하고(5~7회 — [dotgg](https://dotgg.gg/afk-journey/arena-guide/)), 필요하면 고르기 전에는 팀 요약만 보여 준다. 업계가 쓰는 provably-fair 패턴(시드를 먼저 약속하고 판마다 nonce 를 올리는 방식)도 같은 원리다 ([Chainlink](https://chain.link/article/provably-fair-randomness)).

결정론의 진짜 걸림돌은 수학 함수다. ECMA-262 는 `pow`(와 `**`) · `exp` · `log` · `sin` · `cos` · `tanh` 등을 「정확히 규정하지 않는다」고 명시한다. fdlibm 사용은 **권고일 뿐 의무가 아니고**, 플랫폼의 C 수학 라이브러리를 그대로 써도 된다. 반면 사칙연산과 `Math.sqrt` 는 정확히 반올림된 값으로 규정한다 ([ECMA-262 §21.3.2](https://tc39.es/ecma262/multipage/numbers-and-dates.html)) [확인]. MDN 도 「같은 엔진이라도 OS 나 아키텍처가 다르면 결과가 다를 수 있다」고 적는다 ([MDN Math](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Math)) [확인]. 실제 사례로는 2026년 Chromium 148(V8 14.8.57)에서 `Math.tanh` 가 내장 fdlibm 포트 대신 OS 의 `std::tanh` 를 부르도록 바뀌었다는 보고가 있다. 그 결과 `Math.tanh(0.8)` 이 Linux · macOS · Windows 에서 마지막 자리가 달라졌다는 것이다 ([drweb.de](https://www.drweb.de/seit-chromium-148-verraet-die-funktion-math-tanh-das-betriebssystem-des-nutzers/)) [보도 — V8 커밋 원문은 미확인]. Gaffer on Games 의 결론도 같다. 사칙연산 · 제곱근은 플랫폼 간 일치하지만, 초월함수는 안전하지 않다 ([Gaffer on Games](https://gafferongames.com/post/floating_point_determinism/)) [확인].

본작 코드를 직접 grep 하면 이 함수들이 핵심 경로에 있다 [확인 — 2026-10-26 grep]. 능력치 데미지 계수(모든 평타 · 스킬 타격, [formula.js:207](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/src/game_logic/formula.js))가 `Math.pow` 를 쓴다. 공속 계수([hero.js:527](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/src/game_logic/hero.js))와 다중 대상 감쇠([skill_effects.js:203](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/src/game_logic/skill_effects.js))도 `Math.pow` 다. 아이템 레벨에 따라 치우친 굴림([item.js:340](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/src/game_logic/item.js))은 분수 지수 `u ** (1 / a)` 를 쓴다. 영웅 기본 능력치 굴림의 정규분포([hero.js:315](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/src/game_logic/hero.js))는 `Math.log` · `Math.cos` 를 쓴다. 반면 RNG 인 mulberry32 는 32비트 정수 연산만 써서 엔진이 달라도 같은 결과를 낸다 [추론 — 표준상 근사 목록에 없음]. V8 버전 사이에서 이 입력값들이 실제로 다른 값을 내는지는 확인하지 못했다. 1 ULP 차이는 반올림 경계에 걸릴 때만 정수 결과를 바꾸지만, 한 판에 타격이 수백 번이면 한 번 뒤집힌 HP 가 판 전체를 바꿀 수 있다 [추론]. 대응은 둘 중 하나다. 첫째, 서버만 판정하고 클라이언트는 서버가 낸 결과를 그대로 보여 준다. 그러면 엔진 차이는 연출 불일치로 끝난다. 둘째, 정수 지수 거듭제곱은 반복 곱셈이나 표로, 분수 지수는 표로 바꾼다. 그런 다음 `golden.json` 을 서버 런타임(Node · Cloudflare workerd)에서도 돌려 비트 일치를 확인한다. Phase 2 에서 Godot · Unity 로 옮긴다면 첫째가 사실상 필수다. Unity C# 은 기본이 32비트 `float` 이고, Burst 의 결정론 모드는 64비트 아키텍처 한정이다 ([Unity Burst](https://docs.unity3d.com/Manual/burst/float-precision-determinism.html)) [확인]. 언어가 다른 두 구현을 비트 단위로 맞추는 일은 《塔防大师》가 개발 시간 대부분을 쓴 바로 그 작업이다 [추론].

서버 비용은 걸림돌이 아니다. **Cloudflare Workers** 무료 요금제는 하루 10만 요청에 요청당 CPU 10 ms 다. 유료는 월 $5 에 1천만 요청과 3천만 CPU-ms 를 주고, 넘으면 백만 CPU-ms 당 $0.02, 요청 하나에 최대 5분까지 쓸 수 있다 ([Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/) · [Limits](https://developers.cloudflare.com/workers/platform/limits)) [확인]. 한 판을 50 ms 로 가정하면 $5 안에서 월 60만 판이다. 하루 2,000명이 10판씩 하면 월 60만 판이니 딱 맞는 셈이다 [추론 — 가정한 산수. JS 한 판의 실제 CPU 시간은 `dev/sim` 으로 재야 한다]. 무료 요금제의 10 ms 는 JSON 파싱과 모듈 초기화까지 포함한 값이라 빠듯할 것이다. **Firebase** Cloud Functions 는 종량제(Blaze) 전용이고, 월 무료 몫은 호출 200만 · CPU 20만 초다 ([Firebase Pricing](https://firebase.google.com/pricing)) [확인]. **PlayFab** 개발 모드는 타이틀당 평생 계정 1,000개가 한도이고, 무료 Foundation 모드는 Xbox 출시가 자격 요건이라 Steam 단독 출시와 맞지 않는다 ([PlayFab Modes](https://learn.microsoft.com/en-us/gaming/playfab/get-started/mode-overview)) [확인]. AFK 를 괴롭힌 「리셋 직후 10배 피크」는 요청 수로 과금하는 서버리스에서는 비용 문제가 아니다 [추론]. 정말 비싼 것은 문서의 **인증 리그**다(서버가 원정 시드를 발급하고 드롭에 서명) ([arena_design.md](C:/Users/user/Desktop/python_text/git/TheSevenSimulationRPG/docs/game_design/arena_design.md) §4). 콜로세움 판정 비용은 PvP 판 수에 비례하지만, 인증 리그 비용은 **PvE 플레이 시간 전체**에 비례한다. 매출이 계속 들어오는 F2P 인 Firestone 조차 메인 전투만은 서버로 옮기지 않았다. 판매형 게임이 이를 택한다면 표본만 검증하거나, 《塔防大师》처럼 「순위를 움직이는 판만」 검증하는 축소판이 현실적이다 [추론].

| 방어 결과의 레이팅 반영(미정) | AFK Journey · 메이플 키우기는 반영 | 반영하면 결석을 처벌한다. 「자리 비워도 안전」과 충돌하니 정해야 한다 |

## 결론

업계의 「전부 서버」는 기술적 모범 답안이 아니라 **나눠 쓰는 경제와 뽑기를 가진 F2P 사업 모델의 부산물**이다. 같은 장르라도 그 경제가 없는 게임은 모바일이든 Steam 이든 로컬에 남았다. 그래서 판매형 싱글에 맞는 질문은 「무엇을 서버에 둘까」가 아니라 **「어떤 숫자가 다른 플레이어에게 닿는가」**이고, 본작에서 그 숫자는 팀 스냅샷과 레이팅 둘뿐이다. 본작은 선례 어디에도 없는 조건 하나를 갖고 있다. 입력이 없는 완전 결정론 전투가 클라이언트에 통째로 들어 있다는 점이다. 이 조건은 양날이다. 서버는 거의 공짜로 PvP 의 최종 판정자가 될 수 있지만, 클라이언트도 결과를 미리 볼 수 있다. 그래서 **시드는 클라이언트가 선택을 잠그기 전에는 가질 수 없는 유일한 값**이어야 한다. 반대로 로컬 세이브와 비동기 PvP 를 몇 년 운영한 방치형 선례는 이번 조사에서 하나도 찾지 못했다. Eslabong 도 2026-08 얼리 액세스라, 본작은 사실상 앞서가는 쪽에 선다.

남는 결정은 기술이 아니라 기획이다. 콜로세움의 ELO 가 「같은 상한 안에서 누가 더 잘 짰나」를 재면 Pokémon 처럼 적법성 검사만으로 버틸 수 있다. 「누가 더 많이 파밍했나」를 재면 Last Epoch 래더처럼 무너지고, 그 경우 선례의 답은 서버 쪽 캐릭터나 인증뿐이었다. 그런데 「모든 밸런스의 기준은 PvP」라는 원칙은 콜로세움을 빌드 실력을 재는 판으로 볼 근거가 된다. 그러면 장비 · 레벨을 정규화하는 판이 서버 인증보다 훨씬 싸게 같은 신뢰를 산다. 오프라인 시간 조작은 연구소 줄이 이미 상한이라 서버를 쓸 대상이 아니다. 출시 전에 서버를 세울 필요도 없다. 다만 스냅샷에 버전을 박는 것, 레이팅의 주인이 서버라는 것, 시드 발급 순서, 수학 함수 정리는 서버보다 먼저 정해 두는 편이 AdVenture Capitalist 처럼 나중에 다시 뜯는 것보다 싸다.
