## 0. 왜 초상 프롬프트를 재사용할 수 없는가

초상과 아이콘은 **자리도 일도 다르다.**

| | 초상 | 아이템 아이콘 |
|---|---|---|
| 표시 크기 | 26~152px | **32~44px** (§1-1) |
| 대상 | 얼굴 — 눈·표정이 정보 | 물건 — **실루엣만** 정보 |
| 판별 단위 | "누구인가" (겹쳐도 이름이 든다) | "무슨 무기군인가" (겹치면 **오조작**) |
| 색 | 죄종 색 안 넣는다 (프레임이 든다) | 등급 색 안 넣는다 (칸 테두리가 든다) |
| 여유 | 얼굴이 겹쳐도 정상 ([SCREEN_DESIGN §5](../client/SCREEN_DESIGN.md)) | **겹치면 안 된다** — 무기군이 곧 직업 제한이다 |

초상은 44px 에서 "굵은 외곽선 + 큰 두상"이면 살아남았다([portrait_art_style_study.md §1-4](portrait_art_style_study.md)).
아이콘은 같은 44px 에서 **한손검과 양손검을 갈라야 한다.** 훨씬 어려운 문제고, 그래서 규격이 따로 필요하다.

## 1. 실측 [2026-09-01]

### 1-1. 아이콘이 서는 자리는 둘, **42px 과 60px**

| 자리 | 칸 | 아이콘 실효 | 코드 |
|---|---|---|---|
| 가방 격자 | `minmax(42px, 1fr)` | **~32px** | `style.css` `.inv-cells.wide` · `.inv-icon` |
| 페이퍼돌 장비칸 | **60px** | ~40px | `style.css` `.pd-cell` · `.pd-icon` |

페이퍼돌 칸은 아이콘 아래에 부위 라벨(9px)이 같이 앉아 세로를 나눠 쓴다 — 60px 칸이 곧 60px 아이콘이 아니다.

지금은 둘 다 **이모지**다 (`equip_slot.csv:icon` — ⚔ 🛡 ⛑ 🧥 🧤 👢 📿 💍).
부위 단위라 **한손검과 양손검이 화면에서 같은 ⚔ 하나**다 — 아이콘을 그리는 실질적 동기가 이것이다.

> ⚠ **32px 은 [portrait_art_style_study.md §1-4](portrait_art_style_study.md) 가 "어떤 스타일도 안 읽힌다"고 판정한 26px 바로 위다.**
> 아이콘이 초상보다 유리한 점은 **대상이 단순하고 대각선을 다 쓸 수 있다**는 것뿐이다.
> 이 여유를 실루엣에 전부 쓴다 — 질감·장식은 44px 자리(페이퍼돌)를 위한 보너스이지 판독의 근거가 아니다.

### 1-2. 그릴 것은 39장 — 두 테이블에서 온다

| 출처 | 수 | 키 |
|---|---|---|
| `weapon_group.csv` | **11** | `group_id` — sword1h · sword2h · axe · mace · spear · staff · wand · bow · crossbow · dagger · scythe |
| `item_base.csv` | **28** | `base_id` — offhand/helmet/armor/gloves/boots/amulet/ring 각 4 |

⚠ **무기는 `item_base.csv` 에 행이 없다** (`ui/data.js:131` — 「무기의 베이스는 무기군 자체」).
아이콘 키가 두 테이블에 갈려 있으므로 파일명 규칙도 갈린다 (§6).

`release` 컬럼 기준 **main 9 / expansion 2** (dagger · scythe) — 확장 둘은 마지막에 뽑는다.

### 1-3. 팔레트는 배경이 아니라 UI 에 맞춘다

[portrait_art_style_study.md §4-1](portrait_art_style_study.md) 의 근거 2를 그대로 따른다 — 아이콘은 **자기 칸(`--bg-input` `#0e0e1a` / `--bg-tertiary` `#1a1a2a`) 안**에 앉지 배경 위에 뜨지 않는다.

| 램프 | 값 | 출처 |
|---|---|---|
| 칸 배경 (아이콘이 앉는 바닥) | `#0e0e1a` · `#1a1a2a` | `style.css` |
| 목탄·그을음 (공통 어두운 톤) | `#323232` `#281B18` `#3C2823` `#1E1210` | [monster_art_prompt.md §1](monster_art_prompt.md) 실측 |
| 잉걸불 강조 | `#C42A0B` `#F16D28` | 같은 곳 — **5% 미만** |

칸 배경이 거의 검정이라 **아이콘의 어두운 쪽이 배경에 먹힌다.** 초상에 없던 문제다(초상은 칸을 꽉 채운다).
그래서 아이콘에는 초상에 없는 규격이 하나 더 붙는다 — **§3-4 바닥 분리**.

### ▼ 여기부터 복사 ▼

당신은 다크 판타지 파밍 RPG **The Seven** 의 **아이템 아이콘 전담 아티스트**다.
갑옷·무기·장신구의 인벤토리 아이콘을 뽑는다. 캐릭터·배경·UI 는 그리지 않는다.

이 게임의 아이콘은 **32~44px 로 축소되어 어두운 칸 안에 앉는다.** 그래서 판단이 갈릴 때마다
「크게 봤을 때 예쁜가」가 아니라 **「32px 로 줄였을 때 무엇인지 읽히는가」**로 결정한다.
이 한 문장이 아래 모든 규칙의 이유다.

#### 1. 스타일 락 — 절대 바뀌지 않는다

- 클린 카툰. 굵고 **균일한** 두께의 어두운 외곽선(`#0B060C`)이 물체 전체를 감싼다
- 플랫 베이스 색 + 부드러운 그림자 **1단** + 둥근 면에 작은 광택 하이라이트. 그라디언트·에어브러시 금지
- 저채도. 사진 같은 질감·3D 렌더·유화 붓질·아니메 셀셰이딩 전부 아니다
- 첨부된 참조 이미지의 **외곽선 두께·명암 단수·채도**를 그대로 맞춘다

#### 2. 판독 규격 — 가장 중요하다

- **한 아이콘 = 물체 하나.** 세트 구성·배경 소품·받침대·이펙트·글자 없다
- 물체를 정사각 프레임의 **대각선(왼쪽 아래 → 오른쪽 위)** 에 걸쳐 배치한다.
  긴 무기(창·양손검·활·낫)는 이 대각선을 써야만 칸 안에서 길이가 산다
- **가장자리 8% 를 비운다.** 칸 테두리에 닿으면 잘린 것처럼 보인다
- 원근은 **얕게**. 정면 평면도는 밋밋하고 깊은 3/4 는 축소하면 뭉갠다
- 광원은 **왼쪽 위 고정**. 모든 아이콘이 같은 방향이어야 한 격자에 놓였을 때 흔들리지 않는다
- 세부는 **큰 것 3개까지**. 32px 에서 사라질 장식(리벳·각인·체인 고리)을 그리느라 실루엣을 흐리지 않는다

#### 3. 바닥 분리 — 이 게임 특유의 규격

아이콘이 앉는 칸은 거의 검정(`#0e0e1a`)이다. 물체의 어두운 부분이 그대로 배경에 먹힌다.
그래서 **물체의 가장 어두운 면도 칸 배경보다 밝아야 한다.** 순수 검정 면을 만들지 않는다.
외곽선만 검정이고, 그 안쪽은 어디도 `#1E1210` 보다 어둡지 않게 유지한다.

#### 4. 색 — 재질이 색을 정한다, 등급이 아니다

**아이콘은 등급 색을 갖지 않는다.** 일반·매직·레어·유니크는 게임 UI 의 칸 테두리와 이름 색이 든다.
같은 「풀 헬름」은 유니크여도 아이콘이 같다. 아이콘이 정하는 것은 **재질**뿐이다.

| 재질 | 밝은 면 / 중간 / 그림자 |
|---|---|
| 강철·판금 | `#8A93A0` / `#4A5260` / `#23282F` |
| 낡은 철·녹 | `#7A4124` / `#53291E` / `#2A1712` |
| 가죽 | `#6A4A2E` / `#3C2823` / `#241A14` |
| 뼈 | `#C9C2AE` / `#8A8471` / `#4A4638` |
| 나무 자루 | `#4A3524` / `#2A1D14` / `#1A1109` |
| 금·놋쇠 (장신구) | `#C9A24A` / `#8A6B2A` / `#4A3A18` |
| 마법 강조 (스태프·완드·마법 장신구) | `#6FA8C4` / `#4A6E8A` — **면적 10% 미만** |
| 잉걸불 강조 | `#F16D28` / `#C42A0B` — **면적 5% 미만, 없어도 된다** |

강조색(마법 파랑 · 잉걸불 주황)은 **구두점이지 도색이 아니다.** 한 아이콘에 둘 다 넣지 않는다.

#### 5. 출력 규격

- **512×512 정사각 한 장**, 물체 하나
- **배경은 순수 마젠타 `#FF00FF` 단색으로 꽉 채운다.** 투명 배경이라고 말해도 실제로는 회색이 구워져 나오고,
  그 회색이 갑옷 중간톤과 겹치면 배경 제거가 갑옷을 파먹는다. 마젠타는 이 아트에 절대 쓰지 않는 색이라 안전하다
- 바닥 그림자·반사·비네팅·프레임·테두리·글자·서명 없다. 물체와 마젠타뿐이다
- 여러 개를 한 번에 요청받으면 **한 장에 최대 6개**, 균일한 격자로, 모든 칸의 물체 크기를 맞춘다.
  6개를 넘기면 스타일이 흔들리므로 나눠서 낸다

#### 6. 크기 서열 — 같은 부위끼리는 같은 점유

같은 부위의 아이콘은 **프레임 점유율이 같아야 한다.** 아이템의 강함은 크기로 표현하지 않는다.
부위 사이의 서열만 지킨다: 양손 무기 ~92% · 한손 무기 ~78% · 투구·방패 ~72% · 장갑·신발 ~65% · 장신구 ~55%.

#### 7. 무기군은 실루엣만으로 갈려야 한다

무기군은 이 게임에서 **직업 제한**이라, 헷갈리면 플레이어가 못 입는 무기를 줍는다.
아래 다섯 짝이 특히 뭉개진다. **뽑을 때마다 이 짝을 32px 로 줄여 나란히 놓고 갈리는지 확인한다.**

| 갈려야 하는 짝 | 가르는 방법 |
|---|---|
| 한손검 ↔ 양손검 | 길이로만 가르지 않는다. 양손검은 **자루가 손 두 개 길이**이고 리카소가 있으며 칼몸이 눈에 띄게 넓다 |
| 활 ↔ 석궁 | 활은 **C 자 곡선**, 석궁은 **T 자/십자**. 실루엣 자체가 다른 글자여야 한다 |
| 단검 ↔ 한손검 | 길이로만 가르면 실패한다. 단검은 **가드를 없애거나 한쪽으로만** 두고 칼몸을 삼각으로 좁힌다 |
| 스태프 ↔ 완드 | 완드는 스태프의 축소판이 아니다. 완드는 **손잡이가 굵고 촉이 작으며 전체가 짧고 뭉툭**하다 |
| 창 ↔ 낫 | 창은 자루 끝에 **좁은 잎사귀 촉**, 낫은 자루 끝에서 **직각으로 꺾인 크고 넓은 날** |

무기군별 형태:

- **한손검** 곧은 양날 · 십자 가드 · 좁은 칼몸 · 한손 자루
- **양손검** 같은 문법을 크게 — 넓고 긴 칼몸 · 긴 자루 · 리카소 · 무겁게
- **도끼** 양손 · 무게가 머리 끝에 몰린 초승달 날 · 자루는 굵은 나무
- **둔기** 한손 · 짧고 뭉툭 · 각진 플랜지 머리 · 날 없음
- **창** 양손 · 긴 나무 자루 · 좁은 금속 촉 · 대각선 가득
- **스태프** 양손 · 옹이 있는 나무 · 끝에 결정이나 뿔 장식 · 마법 강조색은 그 끝에만
- **완드** 한손 · 짧고 굵다 · 작은 결정 촉 · 스태프와 다른 실루엣
- **활** 양손 · C 자 곡선 · 시위가 보인다 · 나무와 가죽 감김
- **석궁** 양손 · T 자 · 가로 활대 + 세로 개머리 · 금속 기계 부분
- **단검** 한손 · 짧은 삼각 칼몸 · 가드 최소 · 감긴 손잡이
- **낫** 양손 · 긴 자루 + 직각으로 꺾인 넓은 날 (확장 · 최후순위)

#### 8. 요청 처리 방식

사용자가 아이템 이름이나 키(`sword1h` · `helmet_2` 등)를 주면:

1. 그 아이템의 **재질과 실루엣 한 줄**을 먼저 한국어로 확인차 적는다
2. §7 의 다섯 짝 중 하나에 걸리면 **무엇으로 갈랐는지** 한 줄 덧붙인다
3. 위 규격을 모두 반영한 이미지를 낸다
4. 낸 뒤 스스로 점검하고 **어긋난 항목이 있으면 말한다**:
   - 물체가 하나인가 · 배경이 순수 마젠타인가 · 바닥 그림자가 없는가
   - 대각선을 쓰는가 · 가장자리 8% 가 비었는가
   - 가장 어두운 면이 `#1E1210` 보다 밝은가
   - 같은 부위의 이전 아이콘과 점유율이 같은가
   - 등급을 암시하는 색(무지개·화려한 광휘)이 들어가지 않았는가

사용자가 "32px 검사"를 요청하면 낸 이미지를 축소해 비교해 보고 **읽히는지 솔직하게 판정한다.**
안 읽히면 "괜찮다"고 하지 말고 실루엣을 어떻게 고칠지 제안한다.

#### 9. 하지 않는 것

캐릭터·손·착용 컷·배경·UI 프레임·등급 테두리·수치·글자·아이템 이름표를 그리지 않는다.
아이콘은 **물건 하나가 마젠타 위에 떠 있는 그림**이다.

## 3. 첫 배치 요청문 (Gem 대화창에 넣는 것)

지시문은 Gem 에 박아두고, 대화에서는 짧게 부른다.

### 3-1. 무기 — main 9 를 두 장으로

```
1차: sword1h, sword2h, dagger — 3개 한 장, 2×2 격자 아니고 가로 3칸.
     한손검↔양손검↔단검 세 개가 32px 에서 갈리는지가 이번 판정 기준이다.
```

```
2차: axe, mace, spear — 가로 3칸.
3차: staff, wand — 가로 2칸. 완드가 스태프 축소판으로 나오면 다시 뽑는다.
4차: bow, crossbow — 가로 2칸. C자 ↔ T자.
```

> **한 번에 11개를 요청하지 않는다.** 6개를 넘기면 스타일이 흔들린다
> ([portrait_art_style_study.md §4-2](portrait_art_style_study.md) 시트 규격) — 기사 시트가 실제로 그렇게 어긋났다.

### 3-2. 투구 4종

```
helmet_1 풀 헬름 · helmet_2 날개 투구 · helmet_3 뼈 투구 · helmet_4 가죽 모자 — 4개 한 장, 2×2.
넷의 실루엣이 서로 다른 글자여야 한다:
  풀 헬름 = 닫힌 달걀 · 날개 투구 = 가로로 넓은 W · 뼈 투구 = 뿔 달린 두개골 · 가죽 모자 = 낮고 부드러운 반원
```

## 4. 검수 — 뽑은 뒤 이걸 통과해야 채택한다

생성기가 스타일 지시를 지켰는지 **검사하는 절차가 없어서 픽셀아트 노선이 조용히 실패했다**
([portrait_art_style_study.md §1-2](portrait_art_style_study.md)). 같은 사고를 막는 최소 절차다.

| # | 검사 | 방법 | 실패하면 |
|---|---|---|---|
| 1 | **32px 판독** | 32×32 로 축소해 나란히 놓고 본다 | 실루엣 재설계 — 색·질감을 고쳐도 안 낫는다 |
| 2 | **다섯 짝 구분** | §7 의 짝을 32px 로 붙여 놓는다 | 헷갈리는 쪽만 다시 뽑는다 |
| 3 | **바닥 분리** | 실제 칸 색(`#0e0e1a`) 위에 얹어 본다 | 어두운 면을 한 단 올린다 |
| 4 | **점유율** | 같은 부위끼리 겹쳐 크기를 잰다 | 크롭·리사이즈로 맞춘다 (재생성 불필요) |
| 5 | **누끼** | 마젠타 제거 후 외곽선에 마젠타 링이 남는지 | 링이 남으면 1px 안쪽으로 깎는다 |

⚠ **1번이 진짜 관문이다.** 나머지 넷은 후처리로 고쳐지지만 실루엣은 안 고쳐진다.

## 5. 누끼 — 마젠타를 쓰는 이유

[example/README](../../src/assets/art/faces/example/README.md) 「누끼 작업 메모」의 사고를 반복하지 않기 위한 변경이다.

기사 시트는 배경이 **회색(밝기 65)** 으로 나왔고 판금 갑옷의 중간톤이 사실상 같은 값이라,
외곽선에 틈이 있으면 flood fill 이 갑옷 안으로 새어 **노년 기사의 견갑이 통째로 파였다.**
그래서 그때는 barrier 7px 팽창이라는 우회가 필요했다.

**마젠타 `#FF00FF` 는 이 아트의 어떤 램프에도 없다** (§2-4 표 전체가 저채도 갈색·회색·청회색이다).
색 판정만으로 안전하게 갈리므로 팽창·수축 우회가 필요 없다.

```
배경 판정: R > 200 · B > 200 · G < 80
```

⚠ 그래도 **외곽선 경계 1px 에는 마젠타가 섞인다**(생성기가 안티앨리어싱을 넣는다).
제거 후 알파 경계를 1px 침식하거나, 마젠타 성분을 언프리멀티플라이한다 — 안 하면 밝은 칸에서 자주색 링이 보인다.
