## 1. 트리거는 일곱 갈래뿐이다

40여 종을 훑었더니 분해를 일으키는 조작은 이 일곱으로 전부 수렴했다.

| # | 트리거 | 쓰는 게임 | 개당 클릭 |
|---|---|---|---|
| ① | **우클릭 즉시** | Lootun(드롭 자리) · Hypixel SkyBlock 제단 | 1 |
| ② | **Shift · Ctrl + 클릭** | 던전앤파이터(Ctrl 다중) · Legends of IdleOn(Shift 파기) · Lootun **유저 요청 중** | 1 |
| ③ | **드래그 투입** | Lootun Scrapper · Last Epoch · Dragon Cliff | 1~3 + 화면 이동 |
| ④ | **체크 후 [분해] 버튼** | Torchlight Infinite · ESO(100개 배치) · Idle Heroes | N + 1 |
| ⑤ | **설정 1회 + 일괄 버튼** | Melvor · Soda Dungeon 2 · Clicker Heroes · 버섯커 키우기 · Diablo 3 등급버튼 | 세팅 후 1 |
| ⑥ | **조건 저장 → 신규 유입 자동** | 로스트아크 · Lootun Auto Scrap · 버섯커 키우기 | 이후 0 |
| ⑦ | **트리거 없음(넘치면 자동)** | Loop Hero · Progress Quest | 0 |

> ⚠ **「모드를 먼저 켜고 그 상태에서 클릭」은 조사 대상 어디에도 없었다.** 가장 가까운 Melvor 「Toggle Sell Mode」도 **다중 선택을 위한 모드**다 — 본작 현행은 **단일 클릭 하나를 위해** 모드를 켠다. 표본 0 인 형태다.

## 2. 관점별 비교

### 2-1. 자리 — 찾아가게 하나, 그 자리에서 하나

| 갈래 | 게임 | 결과 |
|---|---|---|
| **찾아가는 쪽**(NPC · 건물 · 전용 가구) | D3 · D4 · PoE2 · Last Epoch · 던파 · ESO · Dragon Cliff · Soda Dungeon 2 · AFK Journey | 「죽이고 · 줍고 · 텔레포트 · 분해 · 복귀 · 반복」이라고 D4 커뮤니티가 직접 이름 붙인 분절 루프. 시간제한 콘텐츠(Helltide)에서 손해로 느껴 **펫 자동분해**를 요청 중 |
| **그 자리에서** | 로스트아크 · Torchlight Infinite · WoW · Melvor · 버섯커 · Loop Hero · IdleOn | 흐름이 안 끊긴다 |

- 파밍 ARPG 쪽은 **찾아가는 쪽이 다수**지만 전부 **사람이 실시간으로 조작하는 세션형**이다
- 그 갈래에서 **방치형 성격이 있는 유일한 사례(로스트아크 자동분해)만** 「자리 없음 · 즉시 · 신규 유입 자동」으로 수렴했다
- 옹호 근거도 있다 — PoE2 는 「기능을 한 곳에 모아야 정체성이 명확해지고 NPC 에 기능이 무한정 붙는 걸 막는다」

### 2-2. 층 — 개별만 / 일괄만 / 둘 다

| 갈래 | 게임 | 커뮤니티 반응 |
|---|---|---|
| **개별만** | Dragon Cliff · IdleOn · PoE2 · Last Epoch · WoW | 「decompose all same type 달라」 · 「어떻게 버리나」 **불만 · 요청 스레드 실재** |
| **일괄만** | Clicker Heroes | 「하나씩은 왜 안 되냐」 **불만 스레드 실재** |
| **둘 다** | D3 · D4 · 던파 · ESO · Melvor · Soda Dungeon 2 · 버섯커 | — |

- **한쪽만 두면 반대 방향 불만이 반드시 나온다** — 양 극단이 둘 다 실증됐다
- **일괄의 트리거는 거의 예외 없이 ⑤ 「설정 1회 + 버튼 1회」로 수렴**한다

### 2-3. 안전 — 확인창 · 되돌리기

- **되돌리기 제공 사례 — 조사 전체에서 0건**
- **확인창은 드물고, 있는 곳은 예외 없이 「미리보기 수치」와 묶여 있다** — Soda Dungeon 2(예상 골드) · AFK Journey(예상 Casting Shard) · Idle Heroes(confirm 단계). D3 는 레어+ 개별에만 있고 그마저 숙련 유저가 **폐지를 요청**하는 상태다
- **트리거가 없는 쪽도 안전하지 않다** — Loop Hero · IdleOn 은 둘 다 「어떻게 지우나 · 버리나」 반복 질문을 낳았다. **조작이 없는 것이 방치형에 자동으로 맞는 것은 아니다** — 최소 하나의 명시적 트리거가 있어야 플레이어가 제 결정권을 인지한다
- **사고 선례** — D4 시즌4(2024-05) 가 일괄 분해의 보호 범위를 줄이자 마스터워크 장비가 갈리는 사고가 다발했다

### 2-4. 비용 · 시간 · 성장을 붙이나

| 형태 | 게임 | 조사 결과 |
|---|---|---|
| **소모품 요구** | Last Epoch(Rune of Shattering) | 커뮤니티는 **소모품 자체를 호평**한다(벤더 무한구매라 실질은 골드 비용). 욕먹는 것은 **결과의 확률성**(접사당 0~n개 · 0개도 나온다)과 비가역성이다. 소모품의 순기능은 관문이 아니라 **위험도가 다른 분기 장치**(Shattering = 파괴 · 확률 / Removal = 비파괴 · 확정) |
| **내구도 소모** | 던파 해체기 | 처리량이 아니라 **수리비**가 상위 레벨의 보상 축이 된다 |
| **성장 축** | 던파 해체가 · WoW 인챈팅 · ESO 제작 | ⚠ **「분해 효율(반환량)이 성장으로 는다」는 사례는 조사 전체에서 0건이다.** 성장이 만드는 결정은 ①**접근 게이팅**(「아직 이 등급은 못 뺀다」 — 던파 · WoW) ②**기회비용 · 시장 참여**(분해할까 팔까 · 남에게 맡길까) 둘뿐. ESO 는 방향이 반대로 **분해가 성장의 재료**다 |

## 3. 본작 현행의 자리 (조사 시점 2026-09-21 스냅샷)

> 현황은 바뀐다 — 지금 상태는 [SCREEN_DESIGN.md](../client/SCREEN_DESIGN.md) · 코드에서 다시 확인한다.

- **조작** — 가방 상단 **「분해 모드」 토글**을 켜고 칸 클릭. 리포트 「획득 장비」 칸에 **독립된 토글이 하나 더** 있다(모드를 켜 둔 채 오클릭하는 사고를 막으려 분리)
- **자리 없음 · 개별 클릭만 · 일괄 없음 · 필터 없음 · 확인창 없음 · 되돌리기 없음 · 즉시 · 무료 · 성장 축 없음**

**조사에 비춘 위치**

| 항목 | 다수파인가 | 비고 |
|---|---|---|
| 자리 없음(가방 안에서 바로) | **방치형 다수파** · ARPG 에서는 소수파 | 방치형 성격이 있는 유일한 MMO 사례(로스트아크)와 같은 방향 |
| 모드 토글 트리거 | **표본 0** | §1 |
| 개별만 · 일괄 없음 | **소수파** | 그 소수파는 전부 요청 스레드를 갖고 있다(§2-2) |
| 확인창 없음 | 다수파 | 이례적이지 않다 |
| 되돌리기 없음 | 전원 일치 | — |
| 관전 화면에서 분해 | **대조군 없음** | 「관전하며 분해」라는 구도 자체가 참고작에 드물다 — 좋다 / 나쁘다를 잴 표본이 없다는 뜻 |

⚠ **현행 토글이 근거로 삼은 「되돌릴 수 없는 행동은 두 번 누르게 한다」([SCREEN_DESIGN.md](../client/SCREEN_DESIGN.md) §3)는 조작 실태와 어긋난다** — 토글을 한 번 켜 두면 그 뒤 개별 클릭은 몇백 번이라도 무확인으로 진행된다. 참고작의 이중 확인은 **되돌릴 수 없는 잠금 해제**(Melvor 탭 잠금)나 **자동화 최초 설정**(버섯커 톱니바퀴)에 걸리지, **매 분해 행위 자체**에 걸리는 사례는 없었다. 실태는 오히려 Lootun 우클릭 즉시분해(0~1클릭 무확인)에 가깝다.

### 3-1. 화면에 남은 입력 자리

| 입력 | 현재 쓰임 | 비었나 |
|---|---|---|
| 좌클릭 | **장착**(창고에서도 바로) | 참 |
| `Ctrl` + 클릭 | **창고 ↔ 인벤토리** (ADR-0103) | 참 |
| `Alt` | **툴팁 세부 옵션** (ADR-0114 · 0171 · 0176) | 참 |
| **드래그** | **「자리를 옮기는 동사」로 예약** — 진형 보드(ADR-0096) · 영웅 띠(ADR-0136). 규약이 **「클릭은 소속 · 드래그는 자리」** | 참 (쓰면 규약과 부딪힌다) |
| **우클릭** | 전역에서 브라우저 메뉴를 막아 뒀고, 마스터리 트리에서 **「망각」**으로 이미 쓴다 | **비었다** — 이미 **「되돌리는 · 파괴하는 동사」**라는 뜻이 붙어 있다 |

**[ADR-0026](../client/adr/0026-강화는-이-탭에-없다.md) 이 같은 문제를 한 번 풀었다** — 2026-09-03 에 **강화 모드 토글을 버리면서** 「가방에서 바로 강화하는 길은 나중에 연다 — 아이템 **우클릭 → 강화** 메뉴가 후보다. 지금 그리지 않는 이유는 컨텍스트 메뉴 자체가 이 화면에 없어서다」를 남겼다. 분해 토글만 그 정리에서 살아남았다.

## 4. 후보 비교 (조사자 의견 — 결정 아님)

| 후보 | 개당 클릭 | 오클릭 위험 | 방치형 적합 | 우리 입력 자리 | 평 |
|---|---|---|---|---|---|
| **A. 현행 — 모드 토글 + 좌클릭** | 1 (+토글) | **높다 — 모드 상태가 남는다** | 중 | — | 표본 0 · 토글을 둘로 쪼갠 것이 위험의 증거 |
| **B. 우클릭 즉시 분해** | **1** | **낮다 — 상태가 없고 손이 갈린다** | 상 | **비었고 뜻도 맞는다** | 개별 층의 후보 |
| **C. 우클릭 → 메뉴(장착 · 분해 · 잠금)** | 2 | 가장 낮다 | 중 | 비었다 | 컨텍스트 메뉴를 새로 만들어야 한다 — 항목이 셋 이상일 때 |
| **D. 체크 다중선택 + 버튼** | N + 1 | 낮다 | 하 — 손이 많이 간다 | 새 상태 필요 | 방치형 물량에는 과하다 |
| **E. 설정 1회 + 일괄 버튼** | 세팅 후 1 | 중 | **상** | 리포트 「획득 장비」 칸 | 일괄 층의 후보 |
| **F. 조건 저장 자동(신규 유입만)** | 이후 0 | 중 — 보호 장치가 전제 | **상** | 가방 도구 줄 | 오프라인 장비 드롭(09-07)이 들어올 때 |
| **G. 넘치면 자동만** | 0 | — | 상 | — | 단독으로는 부적합 — §2-3 「트리거 부재도 혼란」 |
| **H. 제련소로 옮긴다** | 이동 + N | 낮다 | **하** | 제련소 | 제련소는 「**세 작업의 버튼은 접속해서 누른다**」([base_expedition_design.md](../game_design/base_expedition_design.md) §2-5)라 **접속 층이 두꺼워진다** — 「① 이 가장 얇은 층이고 얇은 것이 사양」([GAME_DESIGN.md](../game_design/GAME_DESIGN.md) §3-1)과 부딪힌다 |

**조사자 의견 — 층 셋을 쌓고, 트리거는 빈 자리를 쓴다**

```
개별  ①  우클릭 = 즉시 분해                ← 모드 토글 폐기
일괄  ⑤  리포트에서 「설정 1회 + 버튼 1회」
자동  ⑥  조건 저장 · 신규 유입만            ← 오프라인 드롭이 들어올 때
```

- **개별을 우클릭으로** — ⓐ 모드 토글은 표본 0 ⓑ `Ctrl` · `Alt` · 드래그는 이미 찼고 우클릭만 비었으며 **「파괴하는 동사」라는 뜻이 게임 안에 이미 서 있다** ⓒ ADR-0026 이 남긴 후보와 같은 자리 ⓓ **모드 상태가 사라져 리포트의 둘째 토글이 통째로 불필요해진다** — 지금 둘로 쪼개 막고 있는 사고가 원인째 소멸한다
- **확인창 대신 미리보기** — 되돌리기는 표본 0 이라 만들지 않고, 확인은 툴팁의 「분해 → 가루 +n」 한 줄로 대신한다(§2-3 — 확인창이 있는 게임은 전부 미리보기와 묶여 있었다)
- **비용 · 시간 · 성장 축은 붙이지 않는다** — 반환량이 성장하는 사례가 0 이고, 접근 게이팅은 **「분해 못 하는 구간」**을 만들어 방치형 계약([base_expedition_design.md](../game_design/base_expedition_design.md) §4)과 부딪힌다. 본작 분해는 **정리 수단**이지 이득 기회가 아니라 비용을 붙이면 정리가 막힌다

### 4-1. 「분해가 아닌 형태」는 전부 걸러졌다

| 형태 | 게임 | 왜 안 맞나 |
|---|---|---|
| **장비를 장비에 먹인다** | AFK Arena · 원신 | **성립은 한다**(원신은 개체 굴림이 있어도 「재료로 들어가는 순간 등급값만 쓴다」로 푼다). 다만 잉여 장비 → 강화라는 **제3의 경로**가 생겨 「가루는 분해에서만」([item_design.md](../game_design/item_design.md) §5-1)과 충돌한다 |
| **의식형 제물** | Hypixel SkyBlock Draconic Altar | ⚠ **실패 사례로 유효** — 하나씩 우클릭 + 연출이라 커뮤니티가 「일괄이 없어 못 견디겠다」고 한다. 방치형 물량 앞에서 현행 토글보다 더 나쁘게 무너진다 |
| **소모형 컬렉션 등록** | 카발 온라인 | 「**소모해서 기록**」이라 본작 도감(**기록만 · 소모 안 함** — [monster_design.md](../game_design/monster_design.md) §8)과 계약이 정반대다. 어휘가 충돌한다. 지정 희귀템 한정이라 일상 잉여의 처리 수단도 못 된다 |
| **판매 · 상인 레시피** | Melvor · PoE1 · Progress Quest | 잉여 장비 → 재화 경로가 둘이 되면 분해가 죽는다는 경고가 이미 있다([GAME_DESIGN.md](../game_design/GAME_DESIGN.md) §10 상단 행) |
| **무한 창고** | Firestone Idle RPG | 그대로 오면 분해의 존재 이유가 없어진다. 다만 질문을 **「가방 용량 자체가 빡빡한 것 아닌가」**로 옮기는 값은 있다. ⚠ 본작은 LocalStorage · JSON 이라 수천 개 누적이 **세이브 크기 · 목록 렌더링**의 실제 제약이 된다 |

**하나만 건질 것 — Loop Hero 의 「칸 순서가 곧 보호 순위」.** 잠금 태그라는 새 필드 없이 **기존 가방 배치만으로** 우선순위를 표현한다. 「새 게이지 없이 기존 축으로」(CLAUDE.md 철학 3)에 맞는 발상이라, 넘침 처리 순서를 정할 때 후보로 남길 값이 있다.
