### 4-1. 분할 순서 (갈래 보고의 제안을 합친 것)

- **app.js** — 공용 헬퍼를 `ui/kit/` 로(시간 · 등급 · 그림 · 아이템 칸 · 영웅 카드) → 가변 전역(`G` 재할당 · `stopBattle` · `clockRender` 등)을 `core` 컨텍스트 하나로 → 시계 · 셸을 탭 등록식(`registerTab(id, {render, tick})`)으로 → 탭을 하나씩 → 개발 라우팅은 `dev/routes.js` 동적 import. `let G` 재할당이 여러 곳이라 `getG/setG` 같은 감싸기가 먼저다.
- **state.js** — 결합이 없는 조각부터: `codex` → `minigame` → `activity`(상태 읽기 전용 — party · expedition · explore 의 순환을 끊는 자리) → 나머지. 가장 큰 걸림돌은 `deserialize` · `construct` 가 도메인 순서를 엮는 지휘자라는 점 — 모듈별 `fitOnLoad` 파이프라인으로 순서를 명시한다.
- **battle.js** — 런 상태를 객체 하나로 빼고 보상 · 물약 · 오오라 · 틱 단계 · 갈아입기를 모듈 함수로. 순수 이동이면 rng 불변 — **단, M1(골든 복구)이 먼저다.**

## 6. 결정이 필요한 것

1. **배포판에 Admin · 실험실 · ⚙ Save 를 일부러 열어 둔 것인가** — 플레이테스터용이면 퍼널 요약에 표시를 싣고, 아니면 배포 호스트에서 안 붙인다.
2. **배속(×16) · Focus · 공격 흔들림이 시간당 보상을 바꾸는 것이 의도인가** — 지금은 보는 부대를 ×16 으로 두면 16배로 돈다(안 보는 부대는 ×1). 의도라면 그 규칙은 이식 대상(`game_logic/`)으로 옮겨야 하고, 설정 하나(흔들림)가 수확 속도를 바꾸는 것은 플레이어가 읽기 어렵다.
3. **무빌드 원칙 아래 배포 때만 주석 제거를 허용할지** — 개발은 그대로 두고 GitHub Pages 올릴 때만 한 단계.
4. **Firestore 보안 규칙의 실제 배포본** — 저장소에 규칙 파일이 없어 확인할 수 없다(`src/dev/README.md` 의 본문은 「본인 문서 쓰기」만 본다 · 문서 크기 · 모양 · 빈도 검사 없음 ○).
5. **PvP 등장 규칙을 대칭으로 바꾸면 결투장 rng 수열과 골든이 바뀐다** — 골든 재촬영과 같은 날 묶는 것이 싸다.
