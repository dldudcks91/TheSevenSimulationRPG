### A01 — 멈춘 탭에서 활성 세이브 삭제

두 탭 A/B를 같은 격리 브라우저에서 실행한다. B가 저장해 A에 `frozen` 창이 뜬 뒤, A에서 Tab/Enter로 창 뒤의 [새 게임]과 두 번의 시작 확인을 실행한다. 검증 표본에서는 Tab 20회, Enter, Tab 4회, Enter, Tab 4회, Enter였다.

`startGame()`은 멈춤 상태를 검사하지 않고 `clearSave()`부터 실행한다. 이어지는 `save()`는 `frozen`이어서 저장하지 않는다. 실제로 저장소가 `null`이 되고 B도 삭제 이벤트로 멈췄다. 2.1초 후에도 저장소가 비어 있었고, B를 새로고침하면 [불러오기]가 비활성화됐다. 상태를 직접 조작하여 만든 삭제가 아니라 실제 키보드 입력으로 재현했다. 메인 담당도 별도로 재실행했다.

권장 수정: 멈춤 상태에서 저장 데이터를 바꾸거나 삭제하는 진입점을 거절하고, 잠긴 창이 배경 포커스와 키보드 실행을 차단하게 한다. 새 세이브를 성공적으로 저장하기 전에 기존 세이브부터 삭제하는 순서도 바꿔야 한다.

증거: [재현 스크립트](ui/repro_frozen_keyboard_delete.py), [결과](ui/repro_frozen_keyboard_delete.json), [삭제 후 화면](ui/frozen_keyboard_deleted_after_reload.png).

### A02 — 저장 실패를 사용자에게 알리지 않음

격리된 localStorage를 실제 한도까지 채우고 새 게임 버튼을 누르면 Chromium의 `QuotaExceededError`가 발생한다. `writeSave()`는 `false`를 반환하지만 `save()`가 무시하여 프롤로그로 진행한다. 화면 경고는 없고 세이브는 `null`이다. 새로고침 후 이어하기도 불가능했다.

권장 수정: 저장 성공 여부를 호출자에 전달하고 실패를 화면에 알린다. 새 게임의 저장 실패 시 복구 가능한 상태와 기존 세이브를 보존한다.

발생 조건은 저장소가 가득 찬 환경이다. 조사한 실제 QA 세이브 116개의 현재 형식 재직렬화 최대 크기는 46,103자였으므로, 일반 플레이만으로 쉽게 한도에 닿는다고 판단할 증거는 없다.

증거: [실제 한도 재현](ui/repro_save_quota.py), [결과](ui/repro_save_quota.json).

### A03 — 동시 원정의 물약 중복 사용

정상 시작 영웅 둘을 서로 다른 편성에 넣고, `minor_healing` 재고를 1병만 둔다. 두 편성이 해당 물약을 넣고 1013에 출발하면 각각 3.4초에 1병씩 마셔 HP 50을 회복한다. 총 2병의 효과를 받고도 재고는 `1 → 0 → 0`이다.

출발 시 `fillSlots()`가 재고의 사본을 각 런에 따로 넣으며, 실제 재고는 라운드 정산 후에 줄인다. 두 번째 차감의 음수는 키 삭제로 가려진다. 부대 사이의 예약·배정 또는 실제 사용 시점의 공통 재고 검증이 필요하다. 철수한 미정산 라운드의 소비를 취소하는 기존 규칙도 보존해야 한다.

증거: [상태 재현 스크립트](state/run_state.py), [결과](state/results.json)의 `concurrent-potion-stock-overspend`.

### A04 — 오프라인 연구와 방문객의 시간 순서 오류

앱이 `visitSettle(now)`로 먼저 끝 시각까지 방문객을 생성한 후, `labSettle(now)`이 연구 완료 시점으로 돌아가 시간 구간을 다시 처리한다.

- 대기 칸 연구: 1시간에 연구 완료, 10시간 후 복귀. 기대는 4h/8h의 2명인데 실제는 4h/8h/5h의 3명이다. 도착 순서도 역전된다.
- 간격 연구: 45분에 연구 완료, 7.8시간 후 복귀. 기대는 4h/7.636h의 2명인데 실제는 4h의 1명이다.
- 품질 연구: seed 63에서 연구 완료 후 도착할 영웅이 기대 레어 대신 매직으로 생성된다.

권장 수정: 연구 완료를 포함한 시간순 정산을 한 곳에서 수행한다. 단순히 두 호출을 바꾸는 것만으로 끝내면 내부에서 이미 생성한 방문객의 UI 갱신 신호를 놓칠 수 있으므로 반환값도 함께 정리해야 한다.

증거: [상세 보고](state/FINDINGS.md), [결과](state/results.json)의 `visit-before-lab-*` 3개.

### A06 — 스웜 광역 피격의 음수 피해 표시

광역 공격의 `hit.dmg`는 파리 한 마리 몫인데, `ov`는 파리 전체 초과 피해 합이다. 관전은 `dmg - ov`를 더하므로 음수가 된다.

능력치·HP를 조작하지 않은 정규 생성팀 seed 50512로 노말 5051을 실행했다. HP 330인 파리 3마리를 인페르노 2964로 처치할 때 `dmg=2964`, `ov=7902`가 기록됐다. 관전은 해당 타격을 **−4938**, 영웅의 누적 피해를 **−3661**로 계산했다. 결과 리포트의 실제 기여는 2267이다. 보스 HP 차감 자체는 정상이다.

권장 수정: 다중 파리 타격 이벤트에서 피해·초과 피해·실제 적용 피해를 같은 단위로 전달하고 리포트와 재생기의 집계를 대조한다.

증거: [결과](combat/results.json)의 `natural_team_swarm_negative_replay_damage`, `swarm_spread_contrib`.

### A07 — 장비 교체로 시전 누적 삭제

`refit()`가 자신의 무기한 오오라를 지울 때, 같은 조건을 만족하는 조용한 시전 누적 창 `cx:cast_stack`도 지운다. 무기·스킬은 유지하고 방어만 100→101로 바꿨는데, 누적으로 10→11이었던 마법 공격력이 다시 10으로 내려갔다. 다음 시전까지 누적의 효과가 사라진다.

같은 파일의 다른 오오라 제거 경로는 이미 `quiet` 창을 제외한다. refit도 제거 대상을 구분하고, 라운드 동안 유지하는 창의 보존을 검증해야 한다.

증거: [결과](combat/results.json)의 `refit_erases_cast_stack`.

### A08 — 정신 집중 중 평타 반격

반격 조건이 `target.chan`을 검사하지 않는다. 스나이프를 모으는 동안 평타 반격이 3회 발생했다. 별도의 정규 팀 PvP 600판에서도 래피드 샷·리프 어택 중 반격이 4회 관찰됐다.

정신 집중 동안 평타·다른 행동을 하지 않는 현재 규칙과 다르다. 반격 가능 조건에 정신 집중 상태를 포함하고 충전·연속 공격 양쪽을 확인해야 한다.

증거: [결과](combat/results.json)의 `counter_while_channeling`, [정규 생성 대전](combat/fuzz_results.json)의 `counter_during_channel`.

### A09 — 부활한 이형의 재사망 효과 누락

이형의 사망 기믹이 최초 처치 보상용 `onKill()` 안에 있어, 이미 보상받은 개체가 부활 후 다시 쓰러지면 호출되지 않는다.

정규 champion 팀 `partySeed=50388`, `battleSeed=90078`로 헬 5031을 실행했다. 4라운드 21.0초에 스카라브 병사가 처음 쓰러지며 화염 저항이 0.5→0.45로 감소했다. 21.7초 부활 후 26.1초 재사망에는 0.45 그대로였고, 기대값은 0.4였다. HP·능력치·장비 조작 없이 재현했다.

`monster_design.md:113`은 여왕이 이형을 거듭 되살리므로 5겹 상한이 필요하다고 명시한다. 최초 1회 보상과 매 사망 기믹을 분리해야 한다.

증거: [자연 사례 결과](combat/revive_natural_results.json), `python output/2026-10-30_code_audit/combat/run.py revive_natural`.

### A10 — 사제 고정 피해의 공격 약화 무시

페니턴스의 최종 피해 −25%가 파이어볼은 320→240으로 줄이지만 심판은 70→70으로 유지한다. 공격자에게 걸린 감소를 방어자 피해 감소 항에 합친 뒤, 고정 피해의 조기 반환이 둘 다 건너뛴다.

최신 설계는 방어자의 방어·저항·피해 감소 면제와 공격자에게 걸린 최종 피해 감소를 구분한다. 후자는 모든 직격에 적용하고 심판도 직격이다. 두 담당자가 관련 설계·인터페이스를 독립 대조한 뒤 결함으로 분류했다. 수정 시 공격자 배수를 방어자 방어 우회와 분리해야 한다.

증거: [결과](combat/results.json)의 `fixed_damage_ignores_outgoing_debuff_interpretation`, [독립 규칙 검토](state/FIXED_DAMAGE_REVIEW.md).

### A11 — 관전의 현재 능력치 반영 누락

`stat` 이벤트가 `u.live`만 갱신하며 행동 게이지·속도 제목·스킬 설명은 예전 필드를 읽는다.

- 헤이스트 적용 후 실제 주기는 2.449→1.6327초인데 속도 제목은 2.45초, 게이지는 20.4165%였다. 다음 실제 행동 뒤 구간에서 현재 주기로 계산하면 30.6241%다.
- 그레이스 후 공격력은 8~14→10~17.5인데 배시 툴팁은 29~51을 표시했다. 현재 공격력으로 계산한 같은 툴팁은 36~64다.

엔진 계산은 현재 값을 사용한다. 표시 계층이 현재 능력치를 공통으로 읽도록 맞추되, 이미 예약된 다음 행동을 유지하는 규칙도 고려해야 한다. 두 현상을 같은 동기화 누락으로 묶었다.

증거: [주기 재현](ui/repro_battle_live_display.py), [주기 결과](ui/repro_battle_live_display.json), [스킬 피해 결과](ui/repro_skill_damage_display.json).

### A12 — 친선전 코드의 타입 검증 누락

정상적으로 내보낸 팀 코드를 바탕으로 필드 타입만 바꾸고, 실제 친선전 입력창의 [불러오기]를 클릭했다.

- `item.affixes={}`: `(it.affixes ?? []).forEach is not a function`.
- `hero.skillOrder={}`: `order is not iterable`.
- `hero.name={ko:{toString:1},en:{toString:1}}`: 검사와 import를 통과한 후 렌더링에서 `Cannot convert object to primitive value`. 메인 화면이 빈 상태가 된다.
- 대조군인 정상 팀 코드는 오류 없이 창을 닫고 친선전 상대를 표시했다.

권장 수정: 외부 코드의 배열·요소·문자열 타입을 전체 검사하고, UI 경계에서도 import 실패를 거절 안내로 복구한다. 옵션 줄 수·기본 능력치 대역처럼 이미 미구현이 명시된 검증은 신규 결함으로 세지 않았다.

## 검증 도구 문제 1건 — 미니게임 스크립트의 선행 건물 누락

`scripts/verify_resource_minigames.py:41`은 `?dev=mg`만 사용한다. 현재 자원 줄에는 연구소 외에 창고가 여는 `lab_res`도 필요하지만, 이 개발 경로는 연구소만 짓는다. 따라서 플레이 버튼은 `locked`로 거절되고 `.mg-ready` 대기에서 30초 타임아웃된다. 격리 컨텍스트에서 세 미니게임 모두 실제 거절을 확인했다. 숨겨진 개발 경로/검증 준비 문제이며 플레이어 게임 오류 12건에는 포함하지 않았다.

원본 스크립트는 변경하지 않았다. 감사용 실행기에서 `&cn=max`로 현재 선행 조건을 충족시킨 뒤 **규칙 4개와 실제 입력 33개가 모두 통과**했다. 마우스·키보드·네이티브 터치, 탭 숨김, 재시작, 창 닫기, 중복 수령, 한영 화면을 포함한다.

증거: [원래 조건의 거절](minigame_probe.json), [감사용 실행기](run_minigames.py), [조건 보완 후 결과](minigames/validation.json). `run_minigames.py --original-setup`으로 이전 준비 조건의 실패를 다시 확인할 수 있다.

## 소스 고정과 재실행

다른 작업이 진행 중이어서 시작 시 텍스트 소스 222개를 `snapshot/`과 [시작 manifest](source_manifest.json)에 보존했다. 이후 다른 작업으로 `commission_fame.csv`, `stage.csv`, `dev/test.js`, `game_logic/state.js`, `ui/i18n.js`, `ui/style.css`가 바뀌었다. 최종 회귀는 최신 파일을 다시 고정해 실행했고 **검사 도중 소스 변경 0, 732/732 통과**였다. 변경 파일 사본은 `latest_changed_files/`, 최종 해시는 [latest_source_manifest.json](latest_source_manifest.json)에 있다. 상태 결함도 최신 소스에서 재현했으며 UI 담당의 마지막 소스 대조 105개 역시 일치했다.

검증은 Playwright와 설치된 Edge를 사용했다. 외부 통신은 차단했으며 배포 호스트 검사에서 클라우드 업로드 함수는 메모리 스텁으로 대체했다. 실제 클라우드 서비스 쓰기는 수행하지 않았다.

재현 스크립트는 프로젝트 루트에서 실행한다. 대부분 감사 서버 주소 `http://127.0.0.1:8921/`를 사용하므로, 필요하면 별도 터미널에서 다음 서버를 띄운다.

```powershell
python serve.py 8921
```
