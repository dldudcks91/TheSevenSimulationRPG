# 신규 플레이 재미 QA — 10분·60분·1일

- D1: 오류 유무보다 재미를 검증한다. 관찰한 사실과 재미에 대한 해석을 구분하고, 새 게임 10분·60분·24시간 시점마다 목표·보상·의사결정·정체·다음 동기를 평가한다.
- D2: 제품 소스·밸런스·사용자 세이브는 바꾸지 않는다. 시작 때 코드·CSV·스타일을 사본으로 고정하고 모든 분석과 실행이 이 기준을 사용한다. 생성 결과와 해시를 보존한다.
- D3: 같은 시작 조건을 서로 다른 플레이 정책에 짝지어 비교한다. 출정 후 무관리, 주기적 기본 관리, 막혔을 때 이전 칸 파밍으로 대응하는 정책을 구분한다. 시간은 실제 pace.js 기준 기본 배속의 가상 접속 경과 시간이다.
- D4: 레벨·진행 거리뿐 아니라 첫 보상·첫 장비 개선·첫 건설·첫 의뢰·새 해금 시각, 보상/개선 간격, 연속 미클리어, 전진 없는 최장 구간, 물약·골드 소모, 사용하지 못한 성장 수단, 획득 장비의 실제 교체 비율을 기록한다.
- D5: 자동 플레이는 유저의 즐거움을 직접 측정하지 못한다. 실제 브라우저에서 일반 새 게임과 대표 체크포인트의 목표 가독성·장비 비교·안내·선택 경로를 확인하고, 정상 정책 및 보상 경험을 과장하지 않는다.
- D6: 메인은 독립 재현·개입 비교·통합 보고서를 작성한다. 시뮬레이션 담당은 harness/와 simulation/, 브라우저 담당은 browser/, 설계·경험 분석 담당은 analysis/를 사용한다. 제품 소스에 대한 작업은 없다.
- D7: 수치는 CSV에서 읽고 비용·문턱·실패를 모두 적용한다. 무료 건설·무료 강화·추가 재화·임의 레벨은 진행 측정에서 사용하지 않는다. 별도의 구조 fixture는 명시하고 진행 결과와 섞지 않는다.
- D8: 1일은 계속 켜 둔 하루와 실제 세션 후 껐다가 돌아오는 하루를 구분한다. 새 원정 준비 안내가 나타나는 시점, 알아차릴 수 있는지, 그에 대응한 파밍이 얼마나 도움이 되는지를 따로 확인한다.

산출물: 원시 로그·정책과 제한·재현 코드·대표 세이브/화면·시점별 표·재미 저해 요인의 우선순위·효과를 검증할 다음 실험.
