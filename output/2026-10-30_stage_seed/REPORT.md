# 원정 시드 발급·드롭 분리 구현 결과

2026-10-30 · DEV_PLAN R405

## 구현 결과

스테이지 출발 때 로컬 발급안 또는 같은 형식의 외부 발급안을 받아 전투를 시작한다. 발급안은 전투 시드와 라운드별 만남 시드·판 번호를 담는다. 첫 보스 공통 판은 보류했다.

- `game.stageSeedRequest(state, stageId, no?, diff?)`: 다음 출발의 로컬 발급안을 읽기 전용으로 조회한다.
- `game.departRun(..., diff, seedGrant?)`: 외부 발급안을 검증하고 사용한다. 생략하면 로컬 발급안을 사용한다. 잘못되거나 오래된 발급안은 상태를 바꾸기 전에 거절한다.
- 몬스터 편성·장비·보스 추가 스킬·처치 드롭을 전투 난수에서 분리했다. 몬스터 장비는 무기군·선택 착용·부위별 수열도 분리했다.
- 같은 스테이지·난이도·라운드의 판은 승리해야 소진한다. 철수·패배·시간 초과·재출발·재접속은 미완료 판을 기존 시드와 함께 반환한다.
- 여러 부대는 서로 다른 판을 예약한다. 반환한 판 중 가장 작은 번호를 다음 부대가 가져간다. 이긴 라운드의 보상과 소진 기록은 유지한다.
- 처치 순서가 바뀌어도 같은 후보를 지급하며, 지급 순서는 몬스터 스폰 순서로 고정한다. 매직찬스는 희귀도 문턱을, 아이템 찾기는 드롭 성공 문턱을 바꾼다.
- 세이브를 v44로 올렸다. v38~v43은 순차 이관하고, 기존 자원·장비·진행·보상을 보존한다. 이전 버전에서 출발한 원정은 재접속 때 종료한 뒤 새 장부를 사용한다.
- 저장 장부의 중복·누락·범위·미완료 소유권과 라운드 진행을 검사한다. 불러온 상태에 이전 메모리의 전투 핸들을 넘겨도 정산·철수·이어 가기를 거절한다.
- 계약·기획 본문·한영 원정 도움말을 함께 갱신했다.

주요 구현: [stage_seed.js](../../src/game_logic/stage_seed.js), [state.js](../../src/game_logic/state.js), [battle.js](../../src/game_logic/battle.js). 정확한 입력·저장·난수 계약은 [INTERFACE.md](../../docs/client/INTERFACE.md)에 있다.

## 기준선과 골든

수정 전 기준선은 **740/743**이었다([baseline.json](baseline.json)). 기존 실패는 `arc_rapid` 표본 1개와 골든 2개였다. 새 만남 난수에서는 해당 표본도 통과하며, 이 작업에서 연타 스킬 로직을 고치지는 않았다.

편성·장비·드롭의 난수 계약이 의도적으로 바뀌어 60런 골든을 다시 기록했다. 재촬영 전 비골든 단정과 브라우저 예외가 없는지 검사하고, 저장한 골든으로 새 브라우저에서 전체 단정을 다시 통과했다. 시작 파티 지문에는 작업 시작 전부터 적용되어 있던 `start_weapon_atk_pct = 1`의 시작 무기 보정도 반영했다. 이전 골든은 [golden_before.json](golden_before.json)에 보존했다.
