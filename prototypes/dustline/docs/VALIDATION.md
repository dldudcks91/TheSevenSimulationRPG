## 확인한 결과

**엔진 38개 검사 통과.** 개별 조건만 읽는 검사와 실제 연속 운행을 함께 사용했다.

- 정차·일시정지·사건에서 시간/기한/생산 정지.
- 중간 저장 이후 같은 시드 진행 결과 재현.
- 거래의 현금·재고·공간·수량 제한과 같은 역 무한 차익 방지.
- 의약품 변질과 냉장칸 보호.
- 목적지 납품·중복 지급 방지·동행 공간·나침반·기한 초과 정리·현상금 승리 조건.
- 객차 제거 조건, 보관·합성의 상태 보존, 3층 제한, 보관함 재활용, 태그의 개수 계산.
- 실제 탑승한 칸만 생산, 첫 탑승 순환, 공간 부족 공방의 준비 보존.
- 결단 선행·배타·취소 환급·완료 정지. 완료와 사건이 같은 순간에 발생해도 완료 정지를 유지.
- 예약 자동 출발과 도착 정지 설정.
- 사건의 지불 조건·화물 손실·반발 지속·휴식 복구, 호위 패배의 일일 손상·정비 해제.
- 긴급 지원 횟수, 실라스 긴장, 클라라 안정 실패와 회복.
- 레벨 성장, 시간 변형 유물, 유물 효과 연결, 보급 비용 증가·후보 소진, 다음 판 후보 스냅샷.
- 페이지 특전·유산 사용 설정·효과 고정.
- 종료 보상 중복 방지, 정상 난수/음수 유산/결과 기록 저장, 손상된 중첩 저장 거부.
- **기관사 3명 × 혹독함 4단계**로 실제 출발·사건·보급·거래를 거치는 횡단 완주.
- 실제 순환 복귀 및 시장 갱신.
- 자원을 주입하지 않고 **계약≥4·현금≥500의 상단 목표 달성**.
- **60개 시드**에서 여러 갈림길과 사건을 운행하고 모든 도착 상태를 저장 검증.

## 실제 브라우저에서 확인한 경로

**파일 직접 실행:** 첫 화면 → 시작 → 곡물3개 매입 → 계약 수락 → 보안관칸 연결 → 화물칸 강화 → 공동 식탁 결단 → 출발·10× → 사건 선택 → 자동정지 결단 재개 → 보리평원 도착 → 납품 → 저장 → 새로고침 → 같은 여정 복원 → 음향 설정 → 390px 화면 → 기록실.

**로컬 서버 실행, UI만 조작:** 첫 화면 → 곡물 납품+로언 동행 수락 → 결단 → 4구간 출발·사건·도착 → 계약 완료 → 새벽항 완주 → 동행 결말 → 보상 → 실라스 해금 → 기록 조회 → 실제 저장 파일 다운로드 → 손상된 파일 거부 → 정상 파일 가져오기 → 실라스 새 여정 → 긴장 패널 → Space 정지·C 편성 → 320/390/768/1024/1920px 가로 넘침 검사.

엔진 상태에 자원·목표를 주입해 브라우저 완주를 만든 것이 아니다. 화면의 실제 버튼으로 운행했고, 테스트는 상태를 읽어 결과를 확인했다. 위 경로에서 JavaScript page error는 0이었다.

스크린샷과 JSON 요약은 실행 시 `test-results/`에 생성된다. 여정 화면·사건·편성·좁은 화면·첫 화면·결과 화면을 저장하며, 개발용 산출물이므로 Git에서 제외했다.

**오프라인·입력 회귀 검사:** 주행 중 포커스가 0.9초의 진행 갱신에도 유지, 정지 키 P로 변경·작동, 저장 시각만 60초 이전으로 설정한 새 브라우저에서 오프라인 계산, 첫 사건에서 정지, 사건 자동 선택 없음, 일시정지 복원. 실제 게임 자원을 변경하지 않고 외부 경과 시간만 입력했다. 해당 검사도 page error 0.

## 검사 중 고친 연결 문제

- 저장 검사에 일반 자원 상한을 난수 상태에도 적용하던 오류: uint32 전체 범위를 인정.
- 판매 보너스가 큰 상태에서 같은 역 저가 상품을 무한 차익 거래할 수 있던 경로: 매각가 상한으로 방지.
- 390px 화면에서 상단 메뉴가 가로로 넘치던 문제: 좁은 화면 헤더 크기 조정.
- 유물 후보 제외/해금이 현재 여정에도 적용되던 문제: 여정 시작 후보군 스냅샷.
- 도착 자동정지 설정이 실제 운행에 연결되지 않던 문제: 노선 예약과 조건부 자동 출발 연결.
- 역장의 종 설명에 있던 도착 경험치가 계산에서 빠진 문제: XP 효과 연결.
- 결단 완료 직후 사건을 해결하면 완료 정지가 사라지는 경로: 사건 이전 정지 상태 복구.
- 결과 지도가 끝 역 대신 시작 역을 현재 위치로 강조하던 문제: 결과 경로의 마지막 목적지 적용.
- 자원 갱신이 주행 버튼까지 교체해 포커스를 잃을 수 있던 문제: 상태 변경과 진행 표시 갱신 분리.

## 검증 범위와 다음 관찰

확인한 실행 환경은 Edge다. 최신 Chrome/Firefox를 고려한 표준 API로 작성했지만, 그 브라우저에서 동일한 테스트를 실행하지는 않았다. 소리는 설정·오디오 API 연결을 검사했으며 음악·전문 음향 믹싱은 없다. 최소 한 여정과 초기 순환·상단 경제를 검사했으며 수십 시간의 장기 경제·모든 조합의 최적 밸런스는 확정하지 않았다.

다음 실제 플레이에서 기록할 질문:

1. 곡물·약품·부품 중 무엇을 왜 실었는가? 다음 역의 선택 이유를 설명할 수 있는가?
2. 화물 공간과 객차 공간의 차이를 읽을 수 있었는가?
3. 호위에 쓴 돈·보안관칸이 위험 선택을 바꾸었는가?
4. 생산 빌드가 다음 경로·거래·결단을 바꾸었는가, 숫자만 늘렸는가?
5. 식당이 계약용 곡물을 쓰는 관계가 흥미로운가, 설명을 읽어도 불편한가?
6. 사기 생산이 너무 쉬워 위험이 무의미해지는가? 높은 난이도에서 사기·석탄 관리가 합리적인가?
7. 순환 후 시장·계약·호위 교체가 새 선택을 만드는가?
8. 해금·후보 제외·유산이 열차 운영의 재미를 확장하는가?

이 문서는 자동 검사의 통과를 재미의 입증으로 표시하지 않는다. 실행과 연결은 확인했으며, 재미와 장기 균형은 사용자의 실제 플레이로 평가할 단계다.
