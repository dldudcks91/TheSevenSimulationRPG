**2026-08-31 부터 기본 스타일이고, 2026-09-17 부터 유일한 스타일이다** (`FACE_STYLES` 의 첫 항목 = 기본값 — `ui/mock.js`). ~~`?face=pixel16`~~ 은 폴더가 사라져 죽은 이름이다 — `?face=` 는 목록에 없는 이름을 무시한다. 고른 스타일은 localStorage 에 남는다.

원본 PNG는 [`../source/ready/`](../source/ready/)에 영웅·몬스터 id별로 보관한다. 이 폴더의 61장은 그 원본을 축소한 **게임용 WebP**다. 원본 시트와 스타일 앵커도 `../source/`에 남는다.
몬스터는 256×256, 영웅은 320×320, WebP 품질 90이다. 내보내기 명령은 [`scripts/export_face_portraits.py`](../../../../../scripts/export_face_portraits.py)에 있다.
**정예 전용 초상은 `monster/<idx>_elite.webp`** [2026-09-17] — 있는 몬스터만 `monster.csv:face_elite = 1` 이고, 0 이면 정예도 기본 `<idx>.webp` 를 그대로 쓴다.

새 파일 열은 2026-09-14 폴더 분리 뒤의 이름이다 — 09-07 ~ 09-14 사이에는 `hero_<직업id>_<k>.png` 였다(이력 문단의 `hero_priest_2` 같은 이름).

키잉 절차(초록 배경 전용 · 기사·해골 시트의 flood fill 과 다르다): `g − max(r,b)` 40~120 을 알파 경사로, 남는 픽셀은 `g ≤ max(r,b)` 로 눌러 번짐 제거(despill), premultiply 상태로 LANCZOS 축소 후 되돌린다 — 인물이 전 층 저채도라 오검출이 구조적으로 없다.

## 규격

- 512×512 · 투명 배경 · **몬스터 17 + 영웅 18 = 35장** — ⚠ `hero/warrior_1`(검투사)만 배경 불투명(누끼 보류)
- **256색 팔레트(P + tRNS) · 장당 15~64KB · 합계 1.08MB** [실측 2026-09-16] — 새로 까는 장도 같은 형식으로 맞춘다
  (`Image.quantize(256, FASTOCTREE)` · RGBA 원본은 `../source/` 가 든다). 언제 RGBA 에서 갈렸는지는 이 문서에 안 남아 있다
  (커밋 `1353671` 시점 · 그전 기록은 「512² RGBA 장당 150~360KB · 양자화는 화질 확인이 먼저라 보류」였다)
- ⚠ **「화면에서 깨져 보인다」를 해상도 문제로 읽지 말 것** (2026-09-01) — 원인은 `image-rendering: pixelated` 가 이 스타일에도 걸려 있던 것이었다. 512는 가장 큰 칸(152px @ DPR2 = 304px)을 덮는 정상 해상도다. 줄이는 것은 **용량**을 위한 선택이지 화질을 위한 선택이 아니다 (`../../README.md` 규격)
