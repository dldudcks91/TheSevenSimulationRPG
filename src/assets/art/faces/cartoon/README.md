## hero_*.png 는 이름이 고른다 — ⚠ 지금은 한 장뿐이라 해시가 죽어 있다

`mock.js:heroFace` 가 **영웅 이름의 안정 해시**로 `hero_1..HERO_FACE_MAX.png` 중 하나를 준다 — uid 가 아니라 이름인
이유는 시작 화면·선술집의 후보가 아직 uid 가 없어서다(뽑을 때 본 얼굴과 고용 뒤 얼굴이 갈리면 안 된다).
직업과는 무관하다.

**⚠ 영웅 초상은 7장 · `HERO_FACE_MAX = 7` 다** [2026-09-05 저녁 — 기사 2장을 **같은 시트의 2판**으로 갈아끼웠다(인물은 그대로 · 흉상이 프레임에 다 들어오고 갑옷 오염이 늘었다). 장수가 안 변해 **얼굴 배정은 그대로다**.] [2026-09-05 낮 — Gem 기사 2종 추가: `hero_6` = `../example/knight_gold_bald`(민머리 · 금테 견갑 · 붉은 서코트) · `hero_7` = `../example/knight_sun_greybeard`(백발백염 · 태양 문장). 2×2 시트(`../example/source_sheet_knight_gem.png`)에서 **위 두 타일만** 땄다 — 아래 두 장은 사용자 지시로 안 썼다. ⚠ `HERO_FACE_MAX` 가 5 → 7 이라 **기존 영웅 전원의 얼굴이 재배정된다**]. 이전 상태 ↓ [2026-09-04 저녁 — 무안면 로마군 3종 추가: `hero_3..5` = `../example/roman_mane_red / roman_mane_black / roman_band_red` 키잉 512². 2×2 시트 발주 1차 산출물(`../example/source_sheet_roman.png` · 우하단 타일은 ✦ 워터마크로 버림)]. 이전 상태 ↓ [2026-09-04 사용자 지시 · 같은 날 세 번째 개편] — `hero_1` = 검투사(`../example/gladiator_helm.png` 512 축소 · **누끼 보류라 배경 불투명**), `hero_2` = 신판 바바리안(`../example/barbarian.png` 초록 키잉 → 투명 512²). 구판 바바리안 변주 3장은 스타일 불합격(밝기 중앙 116 · 밝은 영역 3배 — 글레디에이터 기준 이탈)으로 **원본·사본 모두 삭제**했다(커밋된 적 없어 git 에도 없다). 신판(맨몸 문신판 · 같은 날 재교체)은 밝기 중앙 97 · 밝은 영역 41% — 문신이 어둡지만 맨살 면적이 넓어 수치는 되레 기준(81 · 13%)에서 멀다. 화면 판단으로 채택.

스타일·비율 확인용 잠정 세트고, 직업 대응은 여전히 없다 — 마법사·궁수도 이 일곱 얼굴 중 하나를 이름 해시로 받는다.

키잉 절차(초록 배경 전용 · 기사·해골 시트의 flood fill 과 다르다): `g − max(r,b)` 40~120 을 알파 경사로, 남는 픽셀은 `g ≤ max(r,b)` 로 눌러 번짐 제거(despill), premultiply 상태로 LANCZOS 축소 후 되돌린다 — 인물이 전 층 저채도라 오검출이 구조적으로 없다.

## 규격

- 512×512 RGBA · 투명 배경 · 장당 150~360KB (몬스터 10 + 영웅 7 = 17장) — ⚠ `hero_1`(검투사)만 배경 불투명(누끼 보류)
- 용량은 최적화 전이다. 플랫 카툰이라 256색 양자화가 잘 먹을 것으로 보이나 **화질 확인이 먼저**라 원본 그대로 뒀다
  (참고: `pixel16` 은 8장 합계 250KB)
- ⚠ **「화면에서 깨져 보인다」를 해상도 문제로 읽지 말 것** (2026-09-01) — 원인은 `image-rendering: pixelated` 가 이 스타일에도 걸려 있던 것이었다. 512는 가장 큰 칸(152px @ DPR2 = 304px)을 덮는 정상 해상도다. 줄이는 것은 **용량**을 위한 선택이지 화질을 위한 선택이 아니다 (`../../README.md` 규격)
