# src/ui — DOM 렌더러

**Phase 2(엔진 이식)에서 버려질 레이어.** 계산·난수 없음 — 상태(G)를 읽고 `game_logic` 시스템(SYS)을 부르고 `save()` 한다.

## 파일별 역할

| 파일 | 역할 |
|---|---|
| `app.js` | 화면 렌더링. 계산·난수 없음 |
| `battle.js` | 전투 관전 = `game_logic/battle.js` 타임라인 **재생기** (계산하지 않는다) |
| `data.js` | CSV fetch → `game_logic` 시스템 조립(주입). 수치 미러 없음. `D.csvText` 에 **원문**도 남긴다 — 읽는 곳은 `dev/golden.js` 의 CSV 해시 하나뿐이고 게임 로직은 안 본다 (2026-08-31) |
| `storage.js` | localStorage 어댑터 — 저장소를 만지는 **유일한** 파일 |
| `tip.js` | 툴팁 — **기계장치 한 곳**(표시 · 따라다니기 · 넘침 보정 · 겹친 툴팁 복귀). 두 렌더러가 함께 쓰는 **영웅 카드 · 스킬 카드**도 여기. 스킬 카드는 **문장을 조립한다**(2026-09-08 · SCREEN_DESIGN §4-2) — 틀은 `kind`×`target`, 파생값(실효 쿨·피해)과 **식 재료**는 `game_logic/skill.js:previewOf`(`.parts`)가 낸다. **Alt 계산식 상태도 여기 든다** — 누르는 동안만 켜지고 떠 있는 **스킬 카드만** 같은 인자로 다시 그린다. 숫자 자리는 기본 / Alt(값 + 괄호 식) / 값 없음(식만) 셋이고, 스킬 창 줄 문장(`skillLineHtml`)은 Alt 를 안 본다 (2026-09-10 · SCREEN_DESIGN §2 「스킬 설명창 규격」 · ADR-0089). 아이템 비교 카드는 `app.js` (app 헬퍼를 많이 탄다) |
| `i18n.js` | 한/영 사전 `STRINGS` + 언어 상태 |
| `mock.js` | 화면 전용 사전 — 죄종·희귀도 색 · 접사 **표기**(`AFFIX_LABELS` — ⚠ 19개 중 12개가 `combat_stat.csv` 와 이름·단위 중복이다. 08-31 에 `reflect_damage` 가 갈려 한 탭에서 다르게 찍히는 사고가 났다) · 페이퍼돌 배치(`PAPERDOLL`) · 마스터리 판 프레임(`MASTERY_GRID` — 티어 3 × 노드 3) · 자산 경로(`faceDir()`·`BG_DIR`·`stageBg`·`slotArt` — 미장착 칸의 부위 실루엣 · `itemArt` — 아이템 그림, ⚠ 방어구는 임시로 부위당 한 장) · **얼굴 아트 스타일 전환**(`FACE_STYLES`·`setFaceStyle`·`applyDocumentFace` — 폴더 하나 = 스타일 하나. 고른 스타일은 `<html data-face>` 로도 나간다 — CSS 가 **초상 축소 보간**을 가르는 신호다, 아래 「초상 보간」) · 액티브 표시 사전(`SKILL_DISPLAY` — 아이콘·설명만. 이름·쿨은 `skill.csv`). **직업·슬롯·아이템 베이스·접사 정의·영웅 이름/특성 풀은 2026-08-31 로 CSV 로 나갔다**(`class`·`equip_slot`·`item_base`·`affix`·`hero_name`·`hero_trait` → `data.js` 의 `D.classes`·`D.slots`/`D.equipSlots`·`D.itemBases`·`D.affixDefs`·`D.heroNamePool`·`D.heroTraitPool`). 이름 ko/en·얼굴 유무·기본 능력치 7·전투 능력치 25·도감 보정은 08-28 로 나갔다 — 헬퍼는 `data.js` (`monsterName`·`monsterFace`·`monsterSin`·`stageName`·`stageBgOf`·`chapterOf`·`eliteName`). **남은 게임 데이터는 죄종(`SINS`)·정예 특성(`SIN_TRAITS`·`COMMON_TRAITS`) 셋뿐** — 죄종 매핑 확정을 기다린다 |
| `style.css` | 스타일 — **색 리터럴 0개**. 아래 「색 토큰」 |
| `devpalette.js` | **개발 장치** — 상단바 `⚙` 의 색 피커 ([SCREEN_DESIGN §10-1](../../docs/client/SCREEN_DESIGN.md)). 게임 기능이 아니다: 이 파일과 `app.js` 의 import 한 줄을 지우면 사라진다 |

- **공통 영웅 띠** (`app.js heroStrip`) — 캐릭터 탭 상단(스킬은 탭을 잃고 **창**이 됐고, 창은 띠를 다시 그리지 않는다 — SCREEN_DESIGN §7), 원정은 **출정 창 안 하나**(`departBody` — 스테이지를 골라야 열린다, `{flat:true}` 로 패널 껍데기를 벗는다 · 탭 최상단에 두던 판은 2026-09-10 에 걷었다 · ADR-0085). 창 안의 것만 `{deployed:true}` 라 파티 카드가 흐리다 — 흐림의 뜻이 「바로 아래 진형 보드에 내려가 있다」이기 때문이다(ADR-0058). 둘 다 같은 띠: 초상(`.hero-face` — 관전 유닛 카드와 같은 네모 박스 · 그림은 `mock.js heroFace` 가 **이름**으로 고르고 없으면 밑에 깔린 직업 글리프 `mock.js classGlyph` 가 드러난다, [SCREEN_DESIGN §5](../../docs/client/SCREEN_DESIGN.md))이 카드 전체, 그 위 위칸(`.hs-band`)에 지금 하는 일(출정 아웃 / 전투 파티 / 대기) + 이름. 직업·레벨·죄종·등급은 툴팁

## 다국어 (한/영) — 필수

화면에 나가는 모든 문자열은 한 곳에 ko/en 이 **나란히** 있어야 한다.

| 종류 | 위치 | 사용 |
|---|---|---|
| UI 문구 | `i18n.js` 의 `STRINGS` — 키 하나에 `{ko, en}` | `t('key')` |
| 데이터 문자열 | CSV 의 `_kr`/`_en` 컬럼 쌍 → `{ko, en}` (로더·헬퍼가 조립) · 아직 CSV 로 안 간 것은 `mock.js` | `L(value)` |

- **렌더러(`app.js` / `battle.js` / `tip.js`)에 한국어 리터럴 금지** — 주석 제외. 이게 누락 검증 기준이다
- 아이템·스킬 이름은 **영어가 원본**이고 한글은 **직역**이다 — 의역 금지 (`Morning Star` → 모닝스타, ~~별철퇴~~) [2026-09-09 사용자 확정] — `_en` 을 먼저 짓고 `_kr` 이 그것을 따라간다. UI 문구(`STRINGS`)는 이 규칙 밖이다 — 문장이라 직역이 성립하지 않는다. 규약 본문은 [src/data/README.md 공통 규약](../data/README.md)
- 이름 조립 규칙(어순·조사)은 렌더러에 두지 않는다 — **`game_logic/naming.js`** 가 든다 (`composeName` · `eliteName`, 2026-08-31 이관). `data.js:eliteName(sin, monsterId)` 은 id → 이름 조회만 하고 조립은 넘긴다
- **설명 문구는 도움말 탭 전용** — 인게임 패널에 안내 문장 금지 (2026-08-26 사용자 지시). 패널에는 숫자·상태·오류·버튼·툴팁만 남기고, 규칙 문구는 `app.js` 의 `helpSections()` 에 **기존 키를 재사용해** 넣는다 ([SCREEN_DESIGN §12](../../docs/client/SCREEN_DESIGN.md))

## 색 — 토큰만 쓴다 [2026-09-14]

**`style.css` 의 규칙 안에 색 리터럴을 적지 않는다.** 값은 전부 `:root` 의 토큰이고, 규칙은 `var()` 로만 받는다.

- **표면 계단** `--surface-0`~`--surface-7` — 밝기 순 사다리 하나. 배경 · hover · 선택이 **전부** 여기서 값을 받는다. 의미 이름(`--bg-card` 등)은 사다리의 한 단을 가리킬 뿐이다
- **채널 변수** `--surface-0-rgb` · `--veil-rgb` · `--shadow-rgb` · `--tint-rgb` — `rgba()` 는 hex 를 알파와 못 섞는다. 투명하게 깔리는 표면은 여기서 받는다. **그림자는 테마와 무관하게 검정**이라 사다리를 안 따라간다
- **역할 토큰** `--btn-primary-*` · `--danger-*` · `--enemy-*` · `--boss-*` · `--elite-*` · `--ally-*` · `--info-*` · `--heal-*` · `--toggle-*` · `--rarity-*` — 값이 아니라 **쓰임**으로 이름 짓는다
- **등급색의 SSOT 는 `data/hero_tier.csv` · `mock.js:RARITY`** 다. `--rarity-*` 는 그 사본이라 **하나를 바꾸면 셋 다** 바꾼다
- 상태색 4종(`--color-success` 등)과 죄종 7색(`mock.js:SINS`)은 **별개 축**이라 위 계열에 없다
- **투명도 토큰** `--art-opacity` · `--vignette` · `--chrome-alpha` · `--panel-alpha`(`-soft` · `-deep`) — 배경 아트가 UI 뒤로 얼마나 비치나. 셋이 따로 논다(아트 자체 / 패널 불투명도 / 가장자리 비네트). 비네트는 `rgba(..., calc(.68 * var(--vignette)))` 처럼 **알파 자리의 calc** 으로 다섯 단을 배율 하나가 민다

왜 이렇게 모았나 — 색이 규칙마다 흩어져 있으면 **테마를 바꿀 수가 없다.** 실제로 바닥 값만 갈았을 때 좌측 탭 열 · 상단바 · 패널이 옛 색으로 남는 사고가 났다(값이 `rgba(…)` 로 박혀 있었다). 사다리 하나로 모은 뒤로는 `⚙` 피커가 여덟 개만 밀면 화면 전체가 따라온다.

## 글씨 크기 — 토큰만 쓴다 [2026-09-03]

- 계단은 **`--fs-2xs` 9 · `--fs-xs` 12 · `--fs-sm` 13 · `--fs-md` 15 · `--fs-lg` 18 · `--fs-xl` 24** 여섯 단이다. 새 리터럴을 쓰지 않는다 — 같은 역할인데 크기가 갈리는 것이 이 화면에서 실제로 났다(등급 칩 9px ↔ 죄종 칩 12px)
- **`--fs-2xs` 는 칸 안 초소형 라벨 전용** — 능력치 약어 배지 · 마스터리 칸의 랭크/값 · 페이퍼돌 라벨 · 라운드 트랙 숫자 · 관전 특성 줄. 9px 와 10px 리터럴이 열 군데 흩어져 있던 것을 한 단으로 모았다. ⚠ **창 뱃지(`.buff-chip`)는 2026-09-03 에 빠졌다** — 칩이 그림을 들면서 16 → 24px 로 커졌고 글씨는 그림이 없을 때의 폴백이라 `--fs-xs` 로 올렸다
- **같은 줄에 서는 칩은 같은 규격이다** — 크기 · 줄높이 · 좌우 여백까지. 등급 칩과 죄종 칩은 둘 다 「이 영웅이 무엇인가」라 한쪽만 작으면 덜 중요한 것으로 읽힌다
- **예외는 아이콘 크기뿐이다** — `.cd-slot` 19 · `.inv-icon` 20 · `.pd-icon` 22 · `.unit .sprite` 38 은 **담는 칸 크기**(32 · 44 · 60 · 76px)가 정하는 값이라 한 단으로 못 모은다. 글자가 아니라 그림 자리다
- **스킬 아이콘은 2026-09-03 부터 진짜 그림이다** — 이모지가 들던 칸 다섯(`.cd-slot .cd-g` 32 · `.buff-chip` 16 · `.act-slot .ico` 28 · `.sk-card .ico` 40 · `.ng-skill .ico` 44 · `.tip-sk-ico` 22)에 `<img>` 가 들어간다. 크기를 정하는 것은 **칸**이고 그림은 `object-fit: contain` 으로 맞춰진다 — 그래서 위의 글씨 크기 계단과 무관하다. 경로 조립은 `mock.js:skillIcon` 한 곳 ([SCREEN_DESIGN §2](../../docs/client/SCREEN_DESIGN.md) · 자산은 [assets/art/README.md](../assets/art/README.md))
- **미장착 착용 칸도 그림이다** [2026-09-03] — 페이퍼돌의 빈 칸(`.pd-cell.art .pd-art img`)이 부위 실루엣을 옅게(`opacity`) 깐다. 축은 **부위**(`equip_slot.csv:part`)라 반지 두 칸이 같은 그림을 들고, 조립은 `mock.js:slotArt` 한 곳이다. 그림이 없는 부위(투구·목걸이)는 옛 이모지로 남는다 — **해시 폴백을 안 쓴다**(부위는 틀린 그림이 곧 틀린 정보다). ⚠ **CSS `background: url()` 이 아니라 `<img>`** 다: 상대 경로를 커스텀 프로퍼티에 담으면 `style.css` 기준(`/ui/assets/…`)으로 풀려 404 가 난다 ([SCREEN_DESIGN §6](../../docs/client/SCREEN_DESIGN.md))
- **아이템도 그림이다** [임시 2026-09-03] — 이모지가 들던 칸 넷(`.pd-icon`(착용) 34 · `.inv-icon` 34 · `.fg-row .fg-ic` 22 · `.fg-head .fg-ic` 30)이 `<img>` 를 받는다. ⚠ 이 칸들은 **크기를 새로 줘야 했다**: 이모지는 글씨라 `font-size` 가 칸을 정했지만 img 는 부모가 정한다. 조립은 `mock.js:itemArt` 한 곳이고, **무기는 제 그림 · 방어구는 임시로 부위당 한 장**(개체가 `base_id` 를 안 들고 다닌다) · 투구·목걸이는 이모지로 떨어진다 ([SCREEN_DESIGN §2](../../docs/client/SCREEN_DESIGN.md))

## 화면 크기 정책

- **화면은 1600×800 한 장이다** [2026-09-10 · [ADR-0087](../../docs/client/adr/0087-화면은-1600x800-한-장이다.md)] — 크기의 SSOT 는 `style.css` 의 `#stage` 하나이고, `app.js:fitStage` 가 창에 맞춰 **통째로** 줄이고 늘린다. 배율 `s = min(창 폭 / 1600, 창 높이 / 800)` — **상한 · 하한 없음** · 한 장은 창 가운데 · 남는 가장자리는 `body::before/::after` 배경이 채운다
  - **창 크기를 읽는 CSS 를 쓰지 않는다** — `vw` · `vh` · 미디어 쿼리는 한 장이 아니라 실제 창을 봐서, 창마다 한 장 안의 크기가 흔들린다. 그 자리는 1600×800 에서의 값으로 고정돼 있다
  - **마우스 좌표는 `tip.js:stagePoint` 를 거친다** — 툴팁 · 진형 드래그 고스트. `transform` 이라 고정 위치 자손(툴팁 · 창 레이어 · 고스트)의 기준이 한 장이다
  - **검증은 1600×800(배율 1)** 으로 찍는다 — 배율 확인은 1280×700 · 1920×1080 한 번씩
- **메인은 한 번 더 줄인다** [2026-09-10 · [ADR-0090](../../docs/client/adr/0090-메인은-한-번-더-줄인다-줄어든-폭은-탭-내비가-갖는다.md)] — `#app:not(.pregame) > .main { zoom: .9 }` · 탭 내비 **330px**(`#app` 첫 열). 메인 칸 1270×752 안에서 내용이 **1411×836** 으로 레이아웃된다 — 설계 폭은 줄이기 전(1412)과 같고 세로만 84px 늘었다. **아래 탭 줄들의 실측 px 는 이 설계 크기다**(화면에는 90%)
  - **안 줄이는 것** — 브랜드 · 상단바 · 내비 · `#tooltip` · 내비가 없는 화면(`#app.pregame` — 시작 · 프롤로그). 재생기 안의 로그 · 누적 창은 메인 안이라 같이 준다
  - **창(`#modal` · 한 장 직속)은 메인 배율을 안 물려받고 창마다 정한다** [2026-09-11 · [ADR-0099](../../docs/client/adr/0099-창의-배율은-창마다-정한다-출정-창은-한-단-줄인다.md)] — 출정 창은 아래 「출정 창」 · 스킬 트리 · 해고 창은 100%
  - **`transform` 이 아니라 `zoom`** — 칸 폭 안에서 레이아웃이 설계 크기로 돈다(`transform` 은 레이아웃에 안 걸려 감싸는 칸이 따로 든다). 메인 안에는 마우스 좌표를 쓰는 코드가 없다 — 툴팁은 한 장 직속 · 진형 드래그는 출정 창
  - **배율은 세로가 정한다** — 메인 칸 752 ÷ 가장 긴 탭의 설계 세로. 캐릭터 탭은 박스 안에서 **여유 1px 안팎**이다 — 세 단이 자라면 가방 칸이 가방 안에서 스크롤한다(아래 「탭 내용은 박스다」). 내비 폭은 따로 고르는 값이고 설계 폭을 1412 에 맞춘 것이 330 이다
  - **글자는 한 장 배율에 곱해진다** — `--fs-2xs` 9px 가 1600×800 에서 8.1px · 1366×768 에서 약 6.5px
